# 核心功能（不可回退）

本文档记录跑批链路里**一旦被改弱就会复现整批失败**的行为契约。排查时若怀疑「最近某次改动把保护拆掉了」，按本节对照代码与 log；**修复方向是补回约束，而不是再放宽 guard**。

设计背景见 [03-常见问题排查.md](03-常见问题排查.md) §3（前置登录态）、[CASE_RUN_FIXES.md](../基础框架/CASE_RUN_FIXES.md)。

## 1. 前置「已登录」不得空收工（`case-3de03811` 类）

### 1.1 现象

- 前置写 **登录态：已登录**，Turn 1 模型 `signal_done`，prep 显示 **skipped**（表示收工成功，不是 guard 拦）。
- `session_block` 为 `session=unknown` + `required=logged_in`。
- 进入 do 后点「我的」落到 **全屏登录页**，步骤 1 校验失败。

### 1.2 根因链（连续改动的典型回退）

| 环节 | 正确行为 | 回退后会发生什么 |
|------|----------|------------------|
| `ensure_case_scene` | 前置含「已登录/登录成功」→ `required_session=logged_in`，**`session_prep=skip`**（只核验，不在 prep 内登录） | 误设 `session_prep=relogin` → 与「已登录」语义冲突 |
| `prep_resource_gate_issues` | `device_app.required_session=logged_in` 时对照 **登记簿** / `effective_device_session` | `defer_device_session_gate` 在 relogin 且无登录宏时仍 defer → **prep 收工不查机态** |
| prep `signal_done` | `require_session` + `resource_claim_gate` 未通过则 **continue**，不 `finish_prep` | `session_mismatch_reason` 对 `unknown` 返回 None → **空 session 也收工** |
| prep 截图 | `required_session` 为 `logged_in` 时也 **`refresh_session_block(..., force=True)`** | 仅 guest 刷新 → logged_in 用例长期 unknown |
| do 登录 scope | 步骤未写登录前 **`block_login_flow_unless_step_scope`**；协议页 **`accept_legal_consent` 豁免** | 误拦 consent 或 prep 误走登录链 |

### 1.3 Log 特征

- Turn 1：`llm/response` → `tool_name=signal_done`；`turn/end` → `decision_cap=signal_done`, `decision_status=skipped`（prep 成功路径）。
- **没有** `guard/block` + `require_session`（旧版 bug）。
- `context/slots` → `session=unknown` + `required=logged_in`。
- 随后 do：`accept_legal_consent` / `input_text`，`session_block` 仍可能 unknown。

### 1.4 代码锚点（改这些文件前先读本节）

- `mino_nexus/runtime/session_gate.py` — `ensure_case_scene`：已登录 → `session_prep=skip`；仅前置明文「退出再登录」才 `relogin`。
- `mino_nexus/services/resource_preflight.py` — `prep_resource_gate_issues` / `defer_device_session_gate`（仅 **登录宏进行中** 且 `session_prep=relogin` 时 defer）。
- `mino_nexus/loop/registry.py` — `_guard_require_session`：`logged_in` 且 block 为 empty/unknown 时查 **device_app**。
- `mino_nexus/loop/agent_loop.py` — prep `signal_done` 前 `refresh_session_block`（guest **与** logged_in）。
- `mino_nexus/loop/session_ensure.py` — `session_mismatch_reason`（显式 logged_out/guest 才拦；unknown 由 guard 补 device 维度）。

### 1.5 处理方向

1. 设备侧：确认 `device_app_sessions` 与真实登录态；必要时 prep 内 `inspect_session` / lease。
2. 代码侧：禁止再打开「unknown + logged_in 要求 → prep 收工」或「已登录前置 → relogin + defer 全跳过」。
3. 用例侧：若步骤本身测登录，前置勿写「已登录」；若写已登录，步骤 1 不应依赖未登录 Tab 行为。

### 1.6 链 B：3de fuse → 形象链路连坐（不可回退）

- **`device_run_continuity`**：`【熔断` / 登录态漂移 / 纯导航无进展 **不得** 因 `case-3de03811` 类失败而把 `avatar_profile_ready=False`（避免整包「已配置形象」开跑前拒跑）。
- **个人中心已就绪、步骤却在找 onboarding 多头像 picker**（摘要含「不存在多个头像/没有完成按钮」+「个人中心/3333…」）**不得**连坐链 B —— 属前置/用例车道与真机不符，不是「本批未跑通形象链路」。
- **`prep_avatar_setup_gate_issues`**：前置「未配置形象」且租约 `profile_data=filled`（或 Console 形象 facet=yes）时，**未** `prep_clear_done` 禁止 prep `signal_done`。
- **`block_fsm_logged_in_session_drift`**：前置 **已登录** + 本步验收 **个人页**，却在 **登录屏** 时禁止 `fsm_navigate` 目标「我的/个人页」（改走 recover / 确认租号与机态）。

锚点：`device_run_continuity._fail_clears_avatar_chain`、`nav_session_fork.fsm_blocked_logged_in_session_drift`、`registry._guard_block_fsm_logged_in_session_drift`。

## 2. 前台 / 遮罩 / LLM 截图（不可回退）

### 2.1 契约

- **被测 App 在前台**时，系统弹窗/协议 overlay 不得判成 **foreign_foreground** 从而 withhold 截图或误触发 recover。
- `app_foreground=unknown` **不得**等同 `no`  withhold LLM（仅明确 `no` 时 withhold）。
- DisplayGuard 异常时必须 **`finally` 释放 ready**，且 SLog 参数合法（避免 kwargs 崩溃拖死循环）。

### 2.2 锚点

- `mino_nexus/services/nav_capture_store.py` — overlay / on_target 判定顺序。
- `mino_nexus/loop/llm_screenshot_gate.py` — withhold 条件。
- `mino_nexus/loop/recovery.py` / `agent_loop.py` — `resolve_app_foreground_guard`。
- `mino_nexus/loop/device_display_guard.py` — ready / 日志。

## 3. 登录 scope 与协议同意（不可回退）

- **`accept_legal_consent`**：用户协议/隐私弹窗，**不受** `block_login_flow_unless_step_scope` 限制（与登录步骤 scope 无关）。
- **`block_login_flow_unless_step_scope`**：仅约束 **步骤未声明登录** 时的 `input_text` / `get_otp` / `request_sms_code` 等；勿扩大到 consent / recover。

锚点：`mino_nexus/loop/registry.py` — `_guard_block_login_flow_unless_step_scope`。

---

## 4. Do 阶段「已到目标仍空点」与 OTP（不可回退）

- **`require_do_work`**：`nav_tab` 等 intent 已满足时不得再拦 tap 族导致与 FSM 对抗；expected 可 defer 到 check 时 **`step_goal_met`** 须一致。
- **`action_fuse`**：`get_otp` 等 neutral cap 在无指纹变化时不应单独构成「有进展」；登录步应 **`try_auto_otp_fill`**（在 `request_sms_code` 之后）。

锚点：`registry._guard_require_do_work`、`action_fuse.py`、`agent_loop` OTP 自动填充、`nav_onboarding_open_loop` 模块级 import（避免 NameError 整步熔断）。

## 7. checkpoints_block 逐步解锁（不可回退）

do/check 阶段向 `agent-decide` 投喂的步骤列表须 **按当前步裁剪**，避免模型提前执行后面步骤（典型：`case-7bff9406` 在登录步误点「完成/返回」）。

| 阶段 | 可见内容 |
|------|----------|
| 操作步骤 k/N（`do_subphase=operation`） | 已完成步骤 1…k−1 的 **instruction + expected**；当前步仅 **instruction** +「达成信号待解锁」 |
| 当前步子动作达标（`do_subphase=achievement`） | 追加本步 **expected / 达成信号**（`do_achievement` 块） |
| 后续步骤 k+1…N | **整段不展示**（无「未到，禁止执行」泄漏文案） |

锚点：`mino_nexus/loop/step_pointer.py` — `StepCursor.prompt_block()`、`decide_success()` 与 `do_subphase` 一致。

回退症状：checkpoints 里出现未到达步骤的全文；do 阶段 success_criteria 提前写出下一步 expected。

## 8. 会话真源分层 + 登录中性进展（不可回退）

**并行/乱序跑批**时：

- 用例开跑：`begin_case_session_scope` → `session_dirty=1`，`session_fact=unknown`，**不继承**其它 case 的 inspect 结论。
- prep 收工：`prep_session_signal_done_block_reason` — 信任 **本任务 inspect 的 session_fact / session_block**；`dirty` 时 **不信**登记簿 alone。
- 登录微步：`get_otp` / `request_sms_code` / 验证码 `input_text` 在 `action_fuse` 中 **不触发无进展熔断**，同屏 pass 时写入合成指纹 `#neutral:…`。
- **里程碑切换**（prep→do、do 步进、enter check）：`reset_milestone` 须 **清空** `_coarse_actions` / `_post_states`，避免前置 `wait_ms` 等遗留序列在 do 第一步误触 **【熔断·动作模式】**（`case-d56a0422` 类）。

锚点：`session_scope.py`、`session_prep_trust.py`、`action_fuse.fp_neutral_cap`、`action_fuse.reset_milestone`。
