# 工作区消息与项目归属

- `collab_messages.body` 保留发送者正文；`collab_message_jobs.status/error` 是管家处理回执，不能拼进用户消息正文。失败解释由管家单独发送，新失败消息的 `origin=message:<message_id>` 指向原请求；历史消息不改写。
- options 返回 `project.id/name`，工作区事实同时携带该项目。当前对话归属固定，用户明确命中其他项目时只说明不一致并返回项目入口，不继续采用当前项目的渠道。所有项目/应用工具参数必须匹配工作区，应用目标不能落到另一项目。
- 用户明确指定应用时，渠道解析只在该应用内进行，不能回退到其他应用已保存的渠道。没有渠道和多个渠道是不同缺项，提示带当前项目名称。
- `@管家` 直接进入工作区管家循环，不再派到 conductor 角色的观察/编排聊天。开发绑定检查和 IDE 受管重启与用例执行分开，前者不要求测试渠道或用例范围；仍以 Scout 与 IDE 真实回执为准。
- 同轮重复工具调用不重发；补齐未执行工具的停止回执后，只给模型最后一次只读归纳机会，业务工具不再开放。对用户回复当前问题、已有事实和证据缺口，不把“查询已停止”或工具的“完成”当成用户任务已完成。

排查使用对应服务的只读消息、任务、开发操作和 session 记录。本地其他数据库中没有消息，不能据此推断线上没有执行；修改源码也不代表服务已经加载新代码。不得直接改业务库、通过 shell 杀进程或另起替代服务来验证。
