# 目录结构 —— 每个文件夹负责什么

> 2026-10-22 收口。`services/` 已拆完删除，`websocket/`、`semantic/` 已并入他处。
> 现在 **16 个代码包 + 1 个数据目录**，只允许**向下**依赖，由
> `python3 tools/arch_report.py --check` 强制（CI 也跑这条）。

## 0. 一眼看全

```
mino_nexus/
├── app.py  cli.py          13  装配根
├── api/                    12  HTTP / WS
├── loop/                   11  执行循环（含 execution/）
├── assistant/              10  助手与协作
├── casework/                9  用例工作台
├── action_space/  ai/       8  动作载荷 / 智能
├── navigation/              7  页面图 / 几何 / 登录链
├── runtime/                 6  RunContext
├── knowledge/               5  政策与知识
├── catalog/                 4  能力目录
├── resources/               3  资源
├── platform/                2  身份 / 设置 / 节点
├── records/                 1  事件账本
├── core/  contract/  models/ 0  地基
└── prompts/                 —  提示词数据（不是代码包）
```

层号就是依赖方向：**只能 import 层号更小的包**。同层之间也按上面顺序，不允许反向。

---

## 1. 地基（第 0 层）

### `core/` — 基础设施，不谈业务

`database.py`（engine / SessionLocal / `mino.db`）、`paths.py`（数据目录，**故意和 engine 分开**，
免得任何要拼路径的模块被迫 import ORM）、`log.py`、`protocol.py`、`schemas.py`、`http_util.py`、
`client_gate.py`、`mdns.py`、`build_info.py`、`capability_epoch.py`。

**放**：谁都需要的工具，且没有业务名词。
**不放**：任何"用例/设备/账号"相关的判断——那属于上层。

### `contract/` — 纯契约

只放类型、纯函数、端口协议：`ui_nodes.py`（页面节点读法）、`execution/`（`device.py` `ui.py`
跨层共享的不可变类型）、`case_preview.py`、`coords.py`、`errors.py`、`business_event_contract.py`。

**放**：能跨层传的结构、无副作用的算法（坐标换算、节点判定）。
**不放**：I/O、ORM、网络、数据库会话。这一条是硬约束——`contract/` 一旦碰库，所有包都会被拖进环。

### `models/` — ORM

一张表一个文件，51 个。类名就是 `mino.db` 里的表（`auth.py` → `auth` 表）。

**放**：SQLAlchemy 声明、表级约束。
**不放**：业务规则、跨表编排——那是 `resources/` `casework/` 的事。

> 注意 `models/settings.py` 是**设置表的 ORM**，`platform/settings.py` 是**读取设置的业务口**，
> 两者不是一回事。

---

## 2. 记录（第 1 层）

### `records/` — 事件账本

`eventlog/`（`atomic.py` 原子写、`writer.py` 写入口、`store.py` 读入口、`binding_store.py` 绑定）、
`verification.py`、`write_state.py`。

**放**：`session_events` 与运行台账的读写。
**不放**：判定逻辑。这一层只记事实，解释事实是上层的事。

任何层都可以**写**它（记录是横切关注点），但只有它自己能读表。

---

## 3. 平台（第 2 层）

### `platform/` — 身份、设置、节点

`identity.py`、`auth_store.py`、`session_auth.py`、`settings.py` + `settings_store.py`（唯二真源，见 AGENTS §8）、
`im_channels.py`、`model_sdk.py`、`llm_image.py`、`project_guard.py`、`runtime_mode.py`、`llm/`（客户端 / dispatch 记录 / 渲染 / 用量）。

**放**：与具体 App、具体用例无关的"平台级"能力：谁在跑、用什么模型、密钥从哪来。
**不放**：设备操作、业务 HTTP 调用。

---

## 4. 资源（第 3 层）

### `resources/` — 能被"占用"的东西

`accounts/`（租约 / 池模板 / 需求编译 / 会话匹配）、`session/`（会话前置、场景闸门）、
设备与节点（`device_*`、`node_*`、`resource_pool`、`access_scope`）、
项目环境（`project_env`）、文档库、设计稿（`figma_*`）、账号事实（`account_fact_*`）、
`runtime_tokens.py`（安装凭证）。

**放**：资源的登记、查询、租借、释放。
**不放**：资源上跑什么（`casework/` 决定），怎么驱动设备（Scout 决定）。

---

## 5. 目录与知识（第 4–5 层）

### `catalog/` — 能力目录

`loader.py` / `registry.py` 读 `catalog_entries`，`contracts.py` 是字段契约，`*_seed.py` 是启动时的系统能力种子，
`exec_classes.py` 定义 executor 分类。

**放**：能力声明、平台/caller/phases、`executor_order` 的算法。
**不放**："什么时候用哪个能力"——那是 `ai/` 与 `loop/` 的事。

### `knowledge/` — 判定依据

`check_observation_policy.py`、`checkpoint_text_policy.py`、`control_registry.py`、`desktop_catalog.py`、
`doc_*`（文档分片 / 匹配 / 归一）、`intent_surface.py`（整词对照）、`knowledge_*`（存储与作业）。

**放**：政策、口径、文档、匹配规则。**给判定提供依据，自己不做判定。**
**不放**：判定结果、执行动作。

---

## 6. 运行时与导航（第 6–7 层）

### `runtime/` — RunContext

`run_context.py`（把 Scout 上报的 manifest 翻译成 `RunContext`）、`menu.py`（可用能力菜单）、
`session_gate.py`、`platform_gate.py`、`cursor_state.py`、`env_names.py`。

**放**：本次运行的"当前状态"与"能做什么"。
**不放**：任何控件定位、页面几何——**这些在 `navigation/geometry/`**。
（`ui_consent` / `ui_dom` / `ui_sms_request` 曾经误放这里，2026-10-22 已搬走。）

### `navigation/` — 页面图 + 几何 + 登录链

| 子包 | 负责 |
|---|---|
| `atlas/` | 页面图：屏幕、状态、边、编译与合成、别名治理（30+ 模块，`nav_compiler` / `nav_fsm` / `nav_live_graph` …） |
| `geometry/` | 几何与控件定位：层级槽位、布局、**手机号框 / 发送钮 / 同意勾选框**（`hierarchy_slots` `nav_layout` `ui_sms_request` `ui_consent` `ui_dom`） |
| `login/` | 登录链：策略、证据口径、状态迁移、记账 |
| `overlay_evidence.py` | 浮层证据 |

**判据**：拿 node 列表算出"哪个控件"、算出"这一屏到那一屏怎么走"，都归这里。
它不认识 `RunContext`，不认识数据库会话——只吃 node 列表、吐结论。

---

## 7. 动作与智能（第 8 层）

### `action_space/` — 交给 Scout 的动作载荷

`scheme.py`（执行方案：dom / visual / dom_preferred）、`assemble.py`（参数装配、坐标缺失检测）、
`dom.py`、`visual.py`、`android.py`、`web.py`（平台差异）、`__init__.py` 里的 `assemble_execute_params()`。

**放**：把"要做的动作"变成 Scout 能执行的字段。
**不放**：连设备。这一层只产数据。

### `ai/` — 智能

`planner.py`（`decide_next_action`）、`job_store.py`、`skill_store.py`、`layer_stack.py`、
`roles_catalog.py`、`case_text.py`、`app_step_knowledge.py`、`llm_diagnostics.py`。

**放**：调用模型、组织提示词、解析决策。
**不放**：循环控制（`loop/` 决定是否采纳）、设备事实（`runtime/` 提供）。

---

## 8. 用例工作台（第 9 层）

### `casework/` — 用例从进口到结论

编译（`case_compilation`、`case_step_key_compiler`、`case_step_intent`）、
导入（`case_import*`）、评审（`case_review`）、预检（`case_preflight`）、
存储（`case_store`）、语义完整性（`case_semantic_integrity`）、
评审执行证据（`review_execution_evidence`）、
协作事件（`collab_events` / `collab_apply`）、平台迁移（`platform_migration*`）、
文档同步（`doc_sync` / `feishu_doc_service`）、任务记录（`task_store`）、
问题汇总（`app_issues`）、编译度量（`compile_metrics`）、
`qa/`（覆盖、脑图、草稿生成）。

**放**：一切以"用例"为单位的工作。
**不放**：跑用例（`loop/`）、存事件（`records/`）。

---

## 9. 助手（第 10 层）

### `assistant/` — 对话与协作

对话（`assistant_agent` / `assistant_conversation` / `assistant_gateway` / `assistant_media` /
`assistant_notify` / `assistant_cards` / `assistant_envelope` / `assistant_errors`）、
`workspace/`（成员 / 授权 / 触发 / 消息队列 / 报告 / 评审视图）、
`connectors/`（`plugins_store` 集成插件、`wechat_ilink`、`im_hold`）。

**放**：人怎么和系统说话、系统怎么找人（通知 / IM）。
**不放**：用例判定（`casework/`）、模型调用细节（`ai/`）。

---

## 10. 执行与入口（第 11–13 层）

### `loop/` — 执行循环

| 子包 | 负责 |
|---|---|
| （顶层） | `agent_loop.py` 编排、`case_runner.py` 跑批、`router_proxy.py` 网络边界、`local_executors.py` 四个本地执行器、`milestones.py` 里程碑、`step_pointer.py` 步骤游标、`guard_gate.py` 守卫 |
| `execution/` | 循环内 35 个"可命名阶段"（校验、登录导航、模型结束、守卫善后…），见 `ARCHITECTURE.md` §3.0 |
| `fuse/` | 执行期拦截：死循环、卡死、无进展、异常模型调用 |
| `observe/` | 会话轨迹、投影、步骤流——可观测数据 |
| `web/` `android/` | 渠道差异（网页 / 安卓环境与进展） |

**放**：一次跑批的决策与推进。
**不放**：设备操作（`RouterProxy` 之外一律不许）、HTTP（`api/`）。

### `api/` — HTTP 与实时通道

`r*.py` 路由、`deps.py`、`ws/`（`observers.py` 给 UI、`node.py` 接 Scout）、
`middleware.py`、`client_gate.py`、`replay.py`、`development.py`。

**放**：请求模型（**必须模块级**，见 AGENTS §7.1）、鉴权、序列化。
**不放**：业务规则——路由只做"转发 + 校验 + 包装错误"。

### `app.py` / `cli.py` — 装配根

`create_app()` 装配所有 router；CLI 入口。根上**只准**这两个文件。

---

## 11. `prompts/` — 数据，不是代码包

`prompts/{assistant,jobs,roles,skills,stack}/**` 是提示词与作业定义的**数据文件**，
启动时解析，格式错会拒绝启动（见 `docs/PROMPTS.md`）。它没有 `.py`，不参与 import 图。

---

## 12. 新东西放哪：一张判定表

| 你要加的东西 | 放哪 | 反例（别放这） |
|---|---|---|
| 新的表 | `models/` 一张表一个文件 | 别在 `resources/` 里建表 |
| 新的 HTTP 接口 | `api/r*.py` | 别在 `casework/` 里挂路由 |
| 新的能力声明 / 种子 | `catalog/` | 别写进 `loop/` 常量 |
| 新的判定口径 / 文档规则 | `knowledge/` | 别塞进 `ai/` 提示词里当硬编码 |
| "这一屏哪个是手机号框" | `navigation/geometry/` | 别放 `runtime/`（`ui_*` 的历史教训） |
| "这一屏到那一屏怎么走" | `navigation/atlas/` | 别在 `loop/` 里写死路径 |
| 新的动作字段 / 平台差异 | `action_space/` | 别在 `loop/` 里拼 payload |
| 新的循环阶段（>30 行且有名字） | `loop/execution/` | 别继续往 `_run_loop` 里堆 |
| 用例编译 / 评审 / QA | `casework/`（QA 进 `qa/`） | 别放 `loop/` |
| 对话 / 通知 / IM | `assistant/`（IM 进 `connectors/`） | 别放 `api/` |
| 设备租借 / 账号池 | `resources/`（账号进 `accounts/`） | 别放 `platform/` |
| 身份 / 密钥 / 模型配置 | `platform/` | 别放 `resources/` |
| 谁都要用的无业务工具 | `core/` | 别放 `contract/`（那里禁止 I/O） |
| 跨层共享的类型 / 纯函数 | `contract/` | 别放 `core/`（core 不认业务结构） |

## 13. 三条会被 CI 拦下的规则

0. **函数体内的 import 必须能解析**（`python3 tools/check_lazy_imports.py`）。
   全仓 72.9% 的 import 写在函数里，编译期看不见 —— 2026-10-22 的接口 500 就是从这来的。
1. **只许向下 import**（层号小的被层号大的用）。反向 = `[FAIL] 分层规则违规`，退出码 1。
2. **包级环必须为 0**。同层互引也会被抓——2026-10-22 就是因为这条才发现 7 条向上依赖。
3. **`loop/execution/*` 不许 import `agent_loop`**，否则环立刻回来。

自检方式见 `docs/架构/V8/代码分层方案-20261022.md` §11.6。
