# 9月17日 — 单步骤多意图识别和多意图达成后立即流转

> **维护说明**：现象与对照表保留本文；**结论与实施路线** 见 [`9月18日-意图识别与大模型注意力集中.md`](9月18日-意图识别与大模型注意力集中.md) §1–§2，并与 [`9月18日-fsm导航能力提升.md`](9月18日-fsm导航能力提升.md) 步骤导航计划联读。

**合并说明**：原「单步骤语义拆分（避免少下发事件）」与「单步骤达成预期立即流转（避免额外步骤开销）」是同一 **do 步合同** 的两面 —— **under-dispatch** 与 **over-dispatch**。实施与验收应 **成对检查**，避免只收紧收工导致早进 check，或只加 micro 计数却不阻止登录长链。

| 方向 | 问题 | 典型批跑 |
|------|------|----------|
| **少下发** | instruction 含多个动作/意图，未齐就 `signal_done` / enter_check | `cr-6461f827b22d::case-8b53a494` 操作 2/3；`cr-b883511e01ec::case-8b53a494` |
| **多下发/迟收工** | 屏上已达成仍继续无关 cap（登录链、重复滑动） | `cr-8e4116e8c715::case-c8cee4b9`；`cr-6461f827b22d::case-51fef028` 步 17 类 |

**优先级**：**P0（步骤合同 + 步进效率）**

## 0. 在执行架构中的位置

```text
用例 steps[n].instruction
        ↓
  step_intent（业务意图：同意/登录/退出/滑动…）     ← 主合同（少下发）
        ↓
  step_contract（动作族 + 分句 tap/swipe 次数）    ← 补充无意图步骤
        ↓
 require_do_work / skip_repeat_* / block_login_flow
        ↓
 step_effect probe → auto enter_check               ← 及时收工（多下发）
        ↓
 signal_done → enter_check
```

**互作检查项（每改一侧必测另一侧）**

1. **意图未齐** → 必须拒绝 `signal_done`，且 **不能** auto enter_check。  
2. **意图已齐 + 族/次数已齐 + 强 probe** → 应 **≤1 turn** 进入 check，**禁止** 再开登录/SMS 链（非登录步）。  
3. `require_do_work` 拒收文案须含 **已完成意图 / 未完成意图**（`format_intent_progress`）。  
4. 结构 cap（`accept_legal_consent`、`request_sms_code`）用 **意图 + skip_repeat_structural_cap**，不用「点击 1/1」误拦。

## 1. 少下发（多意图 / 多动作）

### 1.1 现象

- 「下滑 + 双点击」「上滑 + 点登录」：只做了 swipe + 1 tap 就进校验。  
- `require_do_work` 只写「未达成」而不列出 **缺哪条意图** → 模型反复 `signal_done`（`case-d84f1747` 操作 3/3）。

### 1.2 机制（已落地 / 进行中）

| 模块 | 作用 |
|------|------|
| `step_intent.py` | `instruction_required_intents`、`step_intents_satisfied`、`format_intent_progress`；`login_flow` 组合子意图 |
| `step_contract.py` | 分句统计 `点击` 次数 → `family_counts.tap >= n` |
| `registry.require_do_work` | 意图 + 族/次数双门闩；拒收带 progress |
| `agent_loop` | `correction_hint` 附带 progress |

### 1.3 目标（P1+）

- 分句 **target_hint** 对齐 tap summary（防点错按钮仍计数）。  
- `do_current` 展示 **子动作 1/n** 列表；与 **达成信号** 区分（见「预期文案影响」文档）。

---

## 2. 多下发 / 迟收工（意图已达成仍不收工）

### 2.1 现象

- 本步 expected 已在屏上，模型继续 SMS/登录/多余 swipe。  
- `do_tail`「登录弹窗先完成登录」与 **功能步** 冲突。  
- session `next=logout` 被当成当前步目标。

### 2.2 机制（已落地）

| 模块 | 作用 |
|------|------|
| `block_login_flow_unless_step_scope` | 非登录 instruction 拒绝 phone/sms/get_otp 链 |
| `skip_repeat_satisfied_step_action` | 意图已齐时限制重复同族 mutate |
| `skip_repeat_structural_cap` | 同一步不重复 accept_legal_consent 等 |
| `step_effect` + `agent_loop` | probe/loc + fam/intent 齐 → auto enter_check |
| `step_pointer.do_header` | 达成信号仅供 signal_done 判断，**不是**操作目标 |

### 2.3 目标（P1）

- login_module 与 default 两套 do_tail（Console Jobs）。  
- `step_goal_met` 锁 menu 为 signal_done / assert。  
- session hint 标注 `scope=step` vs `scope=task`。

## 4. 验收

1. 「下滑 + 双点击」：1 tap + swipe → `require_do_work` **拒绝**；progress 写 **未完成：第二点击**。  
2. 意图已齐 + 双 tap 完成 → **不应** 再拦 `skip_repeat` 于 **未完成其它意图** 的步骤。  
3. 功能步 expected 满足 → **≤1 turn** enter_check，history **无** 长 `get_otp` 链。  
4. `case-8b53a494` 操作 2/3 复跑：不漏发中间 tap/SMS cap。
