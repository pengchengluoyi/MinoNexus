## 2. 合并是怎么发生的（因果链）

架构图分桶在 `build_atlas` → `_atlas_cluster_doc` 中完成，单帧命中某一 `state_id` 需同时满足：

```
采集 turn
  → assign_turn_tabs（归属 Tab：灵感 / 我的）
  → skeleton_fp_from_turn（应用骨骼指纹）
  → bucket_key = (assigned_tab, skeleton_fp)
  → 同 bucket 内所有 turn 共用一个 state_id
```

真源代码：

- Tab：`mino_nexus/services/nav_synthesis.py` · `assign_turn_tabs`
- 骨骼：`mino_nexus/services/nav_app_skeleton.py` · `skeleton_fp_from_turn` / `chrome_cluster_discriminator`
- 分桶：`mino_nexus/services/nav_screen_registry.py` · `_atlas_cluster_doc`

索引写入 `doc.meta.atlas_turn_refs`（Studio 预览左侧列表的数据源）。

## 3. 为何这 9 条会进同一个「主面」桶

对上述 turn 在本机数据上复算，结果一致：

| 字段 | 9 条 turn 的共同值 |
|---|---|
| `chrome_cluster_discriminator`（`cd`） | 全部为 **`main`** |
| `framework.has_back` | 全部为 **假**（`detect_layout_framework` 未判出返回键） |
| `skeleton_fp` | 全部为 **`dadd785ac47b`**（v6 的 `main_surface` 体） |
| `semantic_page_role` | `profile` 或 `feed`，**不参与分桶** |

即：**在「灵感」Tab 内**，6 条 turn 共享同一 `(tab, skeleton_fp)` → 合并到 `page.tab_灵感.sk_dadd785ac47b`；**在「我的」Tab 内**，3 条同理 → `page.tab_我的.sk_dadd785ac47b`。

### 3.1 `main_surface` 策略（过度合并的直接原因）

当前 v6 骨骼在 `cd == "main"` 且 `has_back == false` 时，聚类体固定为：

```text
body = "main_surface"   → 哈希后即 dadd785ac47b
```

含义（见 `nav_app_skeleton.py`）：

- **不按** `profile_page` / `feed_grid` / `tab_shell` 再拆；
- **不按** 线框 region 坐标拆（避免列表滚动产生 30+ 节点）；
- **不按** 顶栏粉丝/订单等统计文案拆（视为 Feed 面噪声）。

因此：灵感 Tab 下的 **个人主页流、探索首帧 tab_shell、带「返回」但未判 detail 的帧**，只要 `cd=main`，都会进 **同一个** 灵感主面 state。

### 3.2 为何带「返回」的帧仍是 `cd=main`

`chrome_cluster_discriminator` 规则摘要：

1. 若 `kind == detail_page` 或 **`framework.has_back`** → 可走子页分支。  
   本批 turn 的 hierarchy **未稳定检出** `has_back`（`has_back=None/false`），即使用户看见返回按钮。

2. 若顶栏 chrome 含 **`返回`**（`chrome_has_back`）：
   - 需要再解析出 **非噪声标题**（`chrome_header_title`）才会 `cd = hash(标题)`；
   - 若只有 `['返回']`、无其它标题 → **`cd` 回落为 `main`**。

**实例**：

- `cr-0a2d207821d9case-99ab0675/4`、`cr-04b827be9cc5case-99ab0675/4`：chrome=`['返回']`，header 为空 → **主面桶**。
- `cr-ecfc1457ed56__explore__/4`：chrome 含 `G-ANI-3GD3-01` 与 `返回`；货号类文案走 `is_feed_surface_chrome` → 视为 Feed 噪声 → **`cd=main`**，且 `feed_grid` 与 `profile_page` 在 `main_surface` 下不再区分。

### 3.3 Tab 归属（为何 explore/1 在灵感、explore/4 在我的）

`assign_turn_tabs` 按时间序对每帧：

- 底栏可见时：选中 Tab、底栏 diff、结构签名缓存、**粘性上一帧 Tab**；
- 底栏不可见时：**继承 `shell_tab` / `prev_tab`**（二级页不强行改 Tab）。

因此：

- `cr-8982083156e0__explore__/1` 被判在 **灵感**（探索早期帧 + home/粘性 Tab）；
- `cr-ecfc1457ed56__explore__/4` 被判在 **我的**（当时底栏选中或继承 Tab 为「我的」）。

Tab 只决定 `(tab, sk)` 的 **第一维**；与「是否该算同一业务页」无人工语义校验。

### 3.4 与「误隐藏子页」的关系

此前 v4 曾把过多页面压成极少节点；v6 用 `main_surface` 收回重复节点时，**子页拆分完全依赖**：

- `has_back` / `detail_page`，或  
- `chrome_has_back` + **有效标题**。

本批采集中 **返回键未进入 framework、`返回` 单独出现不进子页**，导致 **本应独立的子页帧** 与 **灵感/我的主列表** 落在同一 `main_surface` 桶——这是 **规则缺口**，不是预览列表或 Studio 展示错误。

## 4. 对照：什么情况下不会并入该 state

| 条件 | 结果 |
|---|---|
| `cd` 为标题哈希（如「3D 预览」） | 独立 `subpage_title|…` 桶，例如 `page.tab_灵感.sk_9a2b744c400d` |
| `has_back=true` 且标题非噪声 | `subpage_detail|…` 或标题桶 |
| 不同 `assigned_tab` | 相同 `dadd785ac47b` 也会拆成 `page.tab_灵感.*` 与 `page.tab_我的.*` |

本问题列表中的 9 条 **均未满足** 子页拆分条件。

## 5. 结论（给产品 / 研发）

| 问题 | 结论 |
|---|---|
| 是否算「错绑 Tab」？ | 多数帧 Tab 来自 `assign_turn_tabs` 启发式；**无人工 Tab 真源** 时，探索/无底栏帧可能跟主流程不一致。 |
| 是否算「错合并页面」？ | **是（规则层面）**：在「灵感」「我的」各自 Tab 内，把 **主列表 + 仅含返回/货号的子帧 + tab_shell/feed_grid** 都收成 `main_surface` 一个 state。 |
| 根因 | `main_surface` 过粗 + **`has_back` 漏检** + **仅「返回」无标题不拆桶** + **货号类 chrome 不拆桶**。 |
| 与采集 ID 列表关系 | `atlas_turn_refs` 如实记录聚类结果；预览里多条 ID 指向同一 state 是 **分桶结果**，不是 ID 冲突。 |

## 6. 改进方向（v9）

1. **聚类**：`skeleton_fp` v9 = `kind/cols/scroll` + **`structural_cluster_token`（≥3 个结构 region 才共桶；稀疏帧单独 token，不单凭「返回」）**。  
2. **簇内再拆**：`split_indices_by_wireframe_similarity`（线框 Jaccard ≥ 0.40 才同页；采集增多、相似度不够则拆 `*-sN` 子桶）。  
3. **展示名**：侧栏有选中态 → 组合名；否则 **线框最靠上文案** → 编辑/文档/用例/LLM。  
4. **人工**：`atlas-pin-capture` / `atlas-split-capture`（`page.skcap*`）。

## 8. 骨骼聚类 vs 顶栏 chrome（未互相替代）

| 层 | 作用 | 典型入口 |
|---|---|---|
| **骨骼 `skeleton_fp`（v7）** | Tab 内**合并/拆分页面节点**：`main_surface\|kind`、子页 `detail`、标题桶 | `nav_app_skeleton.skeleton_fp_from_turn` |
| **顶栏 chrome** | 子页标题、展示名、部分 identify；**不**决定主列表是否合并滚动帧 | `nav_layout.stable_chrome_texts` |

v7 改掉的是「主面过粗 + 返回键拆桶」，**没有**用骨骼替代 chrome 采集；chrome 仍用于子页命名，但已限制在 **App 内容区顶栏**（`content_top_px` 以下），并过滤状态栏文案。

预览线框：`sanitize_wireframe` / `collapse_system_chrome_regions` **直接丢弃**状态栏带内 region，不再合并成带通知文字的块。
