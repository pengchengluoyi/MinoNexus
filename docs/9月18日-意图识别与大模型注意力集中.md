## 0. 目标（一句话）

**单步内**：程序判定「须达成哪些意图、是否连贯导航、操作子阶段 vs 预期子阶段」→ 动态收窄 LLM 上下文；**全局**：所有「重复下发 /  thought 与 action 矛盾 / 误用 BACK」走 **同一套 dispatch 门闩**，消灭分散的 skip/block 特例。

### 0.1 为何「改了很多次」仍像在用 tap 次数？（`cr-fe1bceba5900` 复盘）

| 现象 | 真因 | 不是 |
|------|------|------|
| `skip_repeat_satisfied_step_action`：tap 2/1 请 signal_done | 步骤 **无 regex 意图**（如「点击帖子卡片」）→ 走 **step_contract 族计数** 兜底 | 意图系统「失效」 |
| 拦了 tap 仍 fail | 拦错方向：叫 signal_done，但屏在相机页 **未进详情** | 单纯 repeat 没拦够 |
| 8b53 连发 6 次 `swipe up` | 用例 **向下滑**；模型反了；滚动时 **hierarchy 指纹在变** → action_fuse 无进展熔断未触发 | 9/17 清缓存类 skip_repeat 未覆盖 swipe |

**合同分层未统一时的规则**：

1. **`instruction_required_intents` 非空** → `require_do_work` 看意图；**跳过** `skip_repeat_satisfied_step_action`。  
2. **意图为空** → 仍用 **tap/swipe 族次数**（旧步骤兼容）。  
3. **结构 cap**（发码/同意）→ `skip_repeat_structural_cap` + 专用意图。

**2026-09-18 补**：`open_content` 意图；滑动 `swipe_direction_vs_instruction` + `skip_repeat_swipe_stuck`；族计数超额时 **勿再误导 signal_done**（未达成时改口「换目标/导航」）。

## 1. 多意图识别 + FSM 连贯性（问题一）

### 1.1 现象（摘要，详见 9/17 文档）

- **少下发**：多动作 instruction 未齐就 `signal_done` / enter_check。  
- **多下发**：屏上已达成仍跑登录/SMS/重复滑动。  
- **与 FSM 脱节**：导航步未按路线 hop 收工，或 Tab 步未走 `fsm_navigate`。

### 1.2 合同分层（保留并增强）

```text
instruction
  → instruction_required_intents（step_intent）
  → step_contract（族 + 分句 tap/swipe 次数）
  → step_nav_plan（连贯 / 非连贯 + hops）  ← 新增，见 FSM 文档 §2
  → require_do_work / dispatch_gate（§5）
  → step_effect probe → auto enter_check
```

| 模块 | 增强点 |
|------|--------|
| `step_intent.py` | 增加 **`nav_route` 意图**：从 instruction 解析 `to_state` 口语，与 `nav_tab` / 入口意图并列 |
| `step_contract.py` | 分句 **target_hint** 与 tap 摘要对齐（P1） |
| `step_pointer.py` | 展示 **子动作 1/n**（意图列表 + contract 计数），与 **达成信号** 分区（§3） |

### 1.3 连贯 vs 非连贯（程序判定）

| | 连贯 | 非连贯 |
|---|------|--------|
| **条件** | 所需意图可落在 **单条 nav 计划** 或 **同一 flow_block** 内；无「先主流程再弹窗再主流程」交叉 | 多段目标、挡屏 recovery、跨块 |
| **FSM** | `step_nav_plan.coherent=true`，hop 未走完 **禁止 signal_done**（`require_do_work` 增分支） | `segments[]`，段间可插 `fb.global.system_dialog` / login 宏 |
| **收工** | 意图 + hop + fam 齐 → auto enter_check | 每段分别收工；**全局意图齐** 才 signal_done |

**互作**（原 9/17 §0 检查项，仍有效）：意图未齐不得 auto check；意图已齐不得再开登录链（非登录步）。

### 1.4 稳定性：结构 cap 不交给 LLM 选路

登录步内 `request_sms_code` / `accept_legal_consent`：

- **P0**：纳入 `fb.global.login` 宏，**程序顺序**执行（FSM 文档 §4）。  
- **P0**：`session_gate` / menu **隐藏** 与宏重复的 recovery cap（或 guard 拒选「请走登录流宏」）。  
- 验收：同屏同态 **不依赖** LLM 在 `tap_element(发送)` vs `request_sms_code` 间随机（见 9/17 稳定性文档）。

## 3. 注意力集中（问题 2.1）

### 3.1 现象

do 阶段 thought 长段对比 **其它步 expected**，把 **achievement** 当操作目标（9/17 预期文案文档）。

### 3.2 子阶段模型 `do_subphase`

| 值 | 注入重点 | 隐藏/弱化 |
|----|----------|-----------|
| `operation` | **当前 instruction**、子动作 1/n、**本步导航 hop**（若有） | 完整 expected 改为 **一句 achievement 摘要** |
| `achievement` | **本步达成信号**、probe 提示、可否 signal_done | 其它步骤 expected、未来步骤列表 |

**切换规则（程序，P0）**：

```text
enter do step → operation
operation 子意图/contract 未齐 → 保持 operation
operation 齐（step_intent + step_contract）→ achievement
achievement + probe 强满足 → auto enter_check 或允许 signal_done
enter check → 完整 expected（已有 check_current）
```

与多意图关系：「操作 1/3 达成」后切 `achievement`，模型 **不再** 被允许去执行 instruction 里剩余句直到 check（剩余句若属操作，应仍在 operation 内用 micro 列表表达，而非跳到下一步 expected）。

### 3.3 上下文注入改动

| 位置 | 改动 |
|------|------|
| `step_pointer.prompt_block` | 拆 `do_current` → `do_operation` + `do_achievement` 两槽，按 `do_subphase` 选一 |
| `knowledge_hint.build_step_focus` | operation 只带 instruction；achievement 只带 expected 摘要 |
| agent-decide Jobs **v15** | 正文：「当前子阶段=operation|achievement」；**禁止** 在 operation 阶段用 expected 驱动 tap |
| `decide_success` / check | 完整 expected 仅 check 展开（保留） |

### 3.4 Studio（可选 P2）

Console trace：标记 `do_subphase` 切换点，高亮 thought 若含 **非当前阶段** 关键词（审计用，不参与 runtime）。

## 4. thought / action 一致（问题 2.3）

### 4.1 现象

thought 写 signal_done，action 仍 `press_key BACK`（9/17 思考与判定文档）。

### 4.2 已落地

`block_mutate_when_thought_done` + `decision_thought` 注入。

### 4.3 增强（P0 → P1）

| 层级 | 方案 |
|------|------|
| **Guard** | 扩展匹配：「本步操作已完成」「应收工」「进入校验」等 + **英文 signal_done** |
| **Planner 后处理（P1）** | thought 高置信收工 → **强制** `cap=signal_done`（仅 do 且 `do_subphase=achievement`） |
| **Schema** | agent-decide 增 **`decision_align`**：`{ "thought_conclusion": "continue|done|recover", "capability_id": "..." }`；解析时 **不一致则拒收重试一次** |
| **Prompt v15** | 硬约束：「最后一行 thought 结论与 action.capability_id 一致；收工必须 signal_done」 |

## 5. 统一重复下发与特殊拦截（问题 2.2）

### 5.1 问题

`dismiss_*`、`dismiss_ime`、`skip_repeat_*`、`action_fuse`、`limit_recovery_retry`、recover 重复文案等 **分散** 在 `registry.py`、`recovery.py`、`action_fuse.py`、`local_executors.py`，行为不一致，易出现 **guard 漏网 → 死循环** 或 **各管各的误拦**。

### 5.2 目标架构：`dispatch_gate`

**单模块** `mino_nexus/loop/dispatch_gate.py`（新）：

```text
evaluate_dispatch(cap, params, ctx) → Allow | Reject(reason, correction_hint, code)
```

**注册表**（数据驱动，P0 先代码内 list，P1 可部分进 catalog）：

| code | 原实现 | 条件摘要 |
|------|--------|----------|
| `skip_repeat_clear_app_cache` | registry | prep + history pass |
| `skip_repeat_structural_cap` | registry + step_intent | 同一步结构 cap + 意图已标记 |
| `skip_repeat_satisfied_step_action` | registry | 意图/族已齐 |
| `skip_repeat_tap` | registry | 同坐标/同 selector |
| `skip_repeat_launch_app` | registry | prep/do 各一次 |
| `action_fuse` | action_fuse.ProgressGate | 里程碑 / 无进展 / wait 熔断 |
| `block_mutate_when_thought_done` | registry | thought 收工 + mutate cap |
| `block_login_flow_unless_step_scope` | registry | 非登录步 SMS 链 |
| `block_back_without_nav_back_semantics` | **新** | 有 nav plan 且非 allow_back hop |
| `limit_recovery_retry` | recovery | recover_* 次数 + unified 系统弹窗 |
| `skip_repeat_recover_rule` | recovery 文案 | 同 rule 已拒 |
| `system_ui_dismiss_phase` | registry `_system_ui_dismiss_phase` | dismiss 阶段 tap 豁免策略 **集中定义** |

**`registry.py` 中 guard 函数改为薄包装**：只调 `dispatch_gate.evaluate_dispatch`。

**agent_loop**：拒收时 **统一** 写 `correction_hint` + `dispatch_gate_code` 进 session_log（Studio 可筛）。

### 5.3 与 action_fuse 的边界

- **里程碑 / 无进展 / wait**：仍在 `action_fuse.py` 实现，`dispatch_gate` **调用** 而非复制逻辑。  
- **同一 cap 重复**：以 **意图 + history pass** 为准，不以「点击 1/1」单计数误拦结构 cap（9/17 异常连续文档 §4）。

### 5.4 验收

1. prep：`clear_app_cache` ≤1 次 pass（112f10ef）。  
2. do：满 milestone **至多一条** 长熔断文案（9/17 §7）。  
3. `accept_legal_consent` 同一步重复 → 统一 code `skip_repeat_structural_cap`。  
4. thought 收工 + BACK → `block_mutate_when_thought_done`。  
5. 有 step_nav_plan 且无 allow_back → BACK **拒收**（与 FSM 文档联验）。
