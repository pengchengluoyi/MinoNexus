# 业务流逻辑块（flow_block）问题梳理

**背景**：§6 页面流转 + Studio A″ 架构图依赖 `meta.flow_blocks` 与 `studio_layout`。多轮迭代后，**壳层、布局、命名、数据** 四套语义不一致，成为比「连线样式」更严重的体验问题。

---

## 1. 设计意图（PRD / UI 图稿）

| 概念 | 含义 |
|------|------|
| **业务流 logic block** | 同一次 session 内、**≥2 步** 的有序页面链（如登录 手机号→验证码） |
| **展示块** | 画布上最多 **6 组** 壳层，bbox 随块内页数收缩 |
| **游离页** | Tab 根、枢纽、单步访问页：**无壳**，`flow_block_id: ""` |
| **壳层来源** | Studio 按 `studio_layout.states[].flow_block_id` **≥2 页** 才算 bbox；**不是** `flow_blocks` 全量列表 |

---

## 2. 当前实现链（真源分散）

```
采集 timeline + Atlas nav 边
    → build_flow_blocks_hybrid（前向跳转图组成块 > session 前向 spine）
    → order_states_in_flow_block（块内左右：返回 > 前向 > 时间轴）
    → enrich_atlas_doc（transition.driver + studio_layout）
    → Studio buildFlowBlockShellNodes + layoutPos.flow_block_id
```

**权重（2026-09-16 调整）**

| 用途 | 优先级（高 → 低） |
|------|-------------------|
| **是否同一块** | Atlas **凡可跳转边**（含返回/合成返回，不含 Tab）无向连通 + **贪心拼链**；**不要求** session 内连续前向点进 |
| **块内从左到右** | 返回边（A 返回到 B ⇒ B 在左）→ 前向跳转边 → session 首次出现序 |

**架构图 `studio_layout.x`**：布局末段全图按同一语义重排——返回/点返回 ⇒ 返回到的页在左；任意页间跳变（含无操作 auto、有操作 tap）⇒ 跳转前在左（时间轴相邻帧 + nav 边，Tab 除外）。

**问题**：用户理解的「登录流 / 下单流」与 **`fb.<sha256>` + 默认名「流程 · xxx…」** 无稳定映射；PRD §1.3 的文档/用例命名 **尚未接入**。

---

## 3. 已暴露的严重问题（按现象）

### 3.1 壳与布局两套坐标

- Nexus 写 `flow_block_regions` + `studio_layout.states`。
- Studio 壳 **只** 读 `layoutPos` 聚合 bbox，**不**再信 server regions 满屏宽。
- **旧 atlas** 未重编时：layout 是新算法、mental model 仍按旧 9 列竖条 → 「块不对、页不对」。

### 3.2 「块里有页 / 页不在块里」

| 来源 | 行为 |
|------|------|
| `flow_blocks[].state_ids` | 分段算法产出，**可含 atlas 中已 prune 的 state** |
| `_pick_display_blocks` | 只布局 **≥2 state 且在 atlas 内** 的块 |
| 单页块 | layout 清 `flow_block_id`；**meta.flow_blocks 仍可能保留 1 页段** |
| 节点 subhead「流 · xxx」 | 曾用 **全局** `flowBlockMap`，与 layout 壳 **不一致** → 无壳仍有「流 ·」文案 |

### 3.3 分段语义 ≠ 产品语义

- 按 **session + Tab 切换** 切路径，**不是** 用户标注的业务边界。
- 同一 App 多次探索 → **多段合并** 为一块，步序 = 时间序，**不是** 用例步骤序。
- `max_count=6` 截断 → 第 7+ 业务流 **只在 meta 存在、画布不展示**。

### 3.4 与连线的交叉污染

- 块内页被 **compact_layout** 拉近；游离页按 nav **贴源页右侧**。
- 若 `flow_block_id` 与 nav 图 **不一致**（弱关系跨 Tab），会出现：**壳在一处、线拉向远处游离页**。

---

## 4. 数据字段对照（Studio 该信谁）

| 字段 | 用途 | 勿用于 |
|------|------|--------|
| `studio_layout.states[sid].x/y` | 节点固定坐标 | — |
| `studio_layout.states[sid].flow_block_id` | subhead「流 ·」**仅 layout 有值时** | Studio 虚线壳（Atlas 已关） |
| `meta.flow_blocks` | 运行时 assist、transition.relation=intra | 画布分组真源 |
| `meta.flow_block_display_count` | 图例「N 组展示」 | 等于壳数量，不是 flow_blocks 总数 |

## 5. 短期收敛（已做 / 进行中）

- [x] **Atlas 架构图关闭虚线壳**（`__block__*`），避免空框/大框压页；块名仅 subhead。
- [x] 热点 **仅** 对有 nav 出边的 `nav_to` 点亮；`pruneWireframeNavTo` 去掉无边锚点。
- [x] 架构图 **不画** hierarchy / tab_scope / parent 补线。
- [ ] **人工块名**：Console/Studio 编辑 `display_name`（PRD §1.3，未做）。
- [ ] **块与 nav 弱关系** 分图层或灰显（未做）。
- [ ] **golden atlas** 固定 3 页 2 块 1 游离，回归壳+线+布局。

---

## 6. 中期方向（建议）

1. **双表**：`flow_blocks`（分析/assist）与 `studio_layout.flow_groups`（仅展示，人工可改 membership）。
2. **块来源可选**：session 自动 / 用例绑定 / 手工框选。
3. **壳默认关（Atlas 已关）**：后续若恢复，仅 ≥2 页且 bbox 不跨页时显示。
