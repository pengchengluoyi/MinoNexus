# 9月17日 — 大模型在操作步骤的思考被预期步骤文案影响导致判定异常

**问题类型**：**do 阶段** 模型在 thought 里反复纠结 **下一步/其它步的 expected（达成信号）**，把 **校验预期** 当成 **当前 instruction 的操作目标**，导致该 `signal_done` 时犹豫、该操作时去「凑预期页」。**样例**：`cr-6461f827b22d::case-51fef028` 第 17 步 — 已进拍摄页，thought 仍对比「选择你的形象配置页」是否出现。

**优先级**：**P1（判定稳定性）**

---

## 1. 现象（抽象）

Thought 链特征：

1. 「当前只做步骤 2，步骤 2 要求验证码登录…」  
2. 「达成信号说登录成功进入 **X 页**，当前是 **Y 页**？不对…」  
3. 在 X/Y 之间循环，最后可能 signal_done 或错误 mutate。

**本质**：**achievement / expected** 被注入 do 上下文且权重过高；模型 **注意力从 instruction 漂移到 expected 全文**。

---

## 2. 与相关问题的区别

| 问题 | 本文 | 思考与判定不一致 |
|------|------|------------------|
| 表现 | thought 逻辑绕 expected | thought 已结论 done，action 仍 BACK |
| 根因 | prompt 结构 / 字段混淆 | 输出未对齐 |
| 修复 | 纪律文案 + 字段 scope | `block_mutate_when_thought_done` |

---

## 3. 已落地 / 建议

| 项 | 说明 |
|----|------|
| `step_pointer.do_header` | 明确：**达成信号仅供 signal_done 判断，禁止当操作目标** |
| decide 模板 | do 块突出 **instruction**；expected 移到 check 专用块或缩短为「收工参考一句」 |
| `decide_success` / check | 完整 expected 只在 **check 阶段** 展开 |
| 程序收工 | 意图+probe 满足时 auto enter_check，减少模型自行「对照 expected 全文」 |

---

## 4. 验收

1. do turn 的 thought **不应** 长段复述其它步骤 expected。  
2. 登录步 instruction 完成、屏态与 **本步** achievement 不一致但 **instruction 意图已齐** → 允许 signal_done 进 check（由 assert 判 pass/fail）。  
3. `case-51fef028` step 17 类 trace：thought 聚焦「验证码/登录」instruction，不反复比对形象配置页。
