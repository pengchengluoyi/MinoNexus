## 0. 问题（一句话）

Today **步骤 expected 几乎只走 `assert_visual`（VLM）**；模型不懂业务、文案同义不同字、加载态/弹窗/页型时，**单次 VLM 判 pass/fail 不可审计、不可复现、可信度低**。需要把 expected **拆成可执行的校验点**，并在 **「求真」约束**下：**能确定则可通过、不必强制调工具**；**不能确定则禁止靠猜**；**判不成立时必须用 FSM / hierarchy 等能力复核后再 fail**。

## 2. 目标架构

### 2.1 总流程（意图分析 → 可选工具 → 校验；**调工具非必须**）

```text
enter check（步骤 n）
  │
  ├─ 1) 预期解析 expected_parse
  │      输出：CheckPlan { points[], ambiguities[], tool_hints[] }
  │      （hints 仅建议，不强制本 turn 全跑）
  │
  ├─ 2) 模型「求真」决策（check 专用 job / agent-decide check 阶段）
  │      输入：expected 摘要、CheckPlan、截图、hierarchy 摘要、nav_assist
  │      输出三选一（必须显式字段，禁止默猜）：
  │        A) check_pass_self     — 我确定 expected 已成立，无需调用 assert_*
  │        B) check_need_tools    — 我不确定 / 有歧义，请按 points 调用能力
  │        C) check_fail_claim    — 我认为 expected 不成立（尚未终裁，见 §2.3）
  │
  ├─ 3a) 快路径：A + 满足 §2.3 自证条件
  │      → 步骤 pass（证据来源=llm_self，带 confidence + 简短理由）
  │      → 不调用 FSM/VLM assert（省步数、省成本）
  │
  ├─ 3b) 工具路径：B，或 C，或 A 但未满足自证条件
  │      按 CheckPoint 调用 assert_page_state / assert_hierarchy / …（见 §3）
  │      输出：CheckEvidence[]
  │
  ├─ 4) 终裁 check_verdict（程序合成，§5）
  │      · 自证 pass：仅当 A 且无疑义点 / conf ≥ T_pass
  │      · 工具 pass：required 点 pass 且 conf ≥ T_tool
  │      · fail：**必须**有 ≥1 条非 LLM 证据 fail（或 inconclusive 升级人工），
  │              不接受「模型说 fail」单票否决（§2.3）
  │
  └─ 5) 写回循环
         pass → mark_checked → signal_done → advance
         fail → correction_hint（证据树）→ recovery 或 fail 本步
```

**原则**：

- **调用 assert_* / FSM 不是必须**；check 菜单始终保留 **`signal_done`（校验通过）** 与可选 **`assert_visual`**，由模型在「确定」时走快路径。
- **不确定 = 不许猜**：模型必须选 **B** 或明确 `confidence=low`，由程序拉工具；不许在 ambiguous 上直接 `check_pass_self`。
- **CheckPlan** 可由规则或轻量 LLM 生成；**终裁与 escalation 规则在 Nexus**，不靠模型自觉。

### 2.3 非对称校验规则（核心产品约束）

| 方向 | 规则 | 原因 |
|------|------|------|
| **Pass** | 允许 **仅 LLM 自证**（不调 FSM/VLM），当：CheckPlan **无** `ambiguous` 点、截图与 hierarchy **无矛盾**、模型输出 `confidence≥T_self` 且 `check_pass_self` | 简单预期（文案一眼可见）不必每步 localize；减延迟 |
| **Pass（禁止）** | 存在 §4.2 歧义类（页型/登录态/同义文案）或 `band=recover` 时 **不得** 自证 pass，必须先跑对应 `assert_*` | 批跑已证明纯 VLM pass 常假绿 |
| **Fail** | 模型 `check_fail_claim` **不能**直接 fail 步骤；必须进入 **工具路径**，至少跑 CheckPlan 里与争议相关的 **required** 点；**仅当工具 evidence 为 fail** 才终裁 fail | 防止「模型误判 fail」杀用例；fail 要可审计 |
| **Fail（快路径）** | 若某 `assert_*` 已 **program fail**（如 session=guest 但 expected 已登录），无需再问 LLM 是否同意 | 程序真值优先 |
| **Inconclusive** | 工具 inconclusive + 模型 low conf → `ask_human` 或本步 fail（可配置），**禁止**随机 pass/fail | 求真 |

**与旧表述的差异**：不是「FSM 一律优先于 VLM」，而是 **Pass 可 LLM-only（有条件）**、**Fail 必须工具背书**。

### 2.4 check 阶段模型输出合同（求真字段）

建议在 agent-decide（check phase）要求 JSON 字段（或 tool 等价物）：

```json
{
  "check_stance": "pass_self | need_tools | fail_claim",
  "confidence": 0.0,
  "uncertainty_reason": "",
  "covered_point_ids": ["cp1"],
  "skipped_tools_reason": "屏上文案与 expected 完全一致，无页型歧义"
}
```

| stance | Nexus 行为 |
|--------|------------|
| `pass_self` | 若 §2.3 允许 → 直接 pass；否则降级为 `need_tools` 并写 correction_hint |
| `need_tools` | 开放 assert_* menu；可建议先跑哪几个 point |
| `fail_claim` | **不**立即 fail；强制编排工具验证；工具全 pass 则 **推翻 fail_claim** 并记「模型误报」telemetry |

### 2.2 与 do 阶段的分工

| 阶段 | 问什么 | 主能力 |
|------|--------|--------|
| **do** | instruction 做完没有？ | `step_intent`、`step_contract`、`step_effect`（弱） |
| **check** | expected 成立没有？ | **求真 stance →（可选）CheckPlan + assert_* → 非对称终裁** |

do 阶段 **不得**用完整 expected 驱动 mutate（已有 `step_pointer` / `block_assert_in_do`）；check 阶段 **不得**为凑绿而 mutate（已有 `check_tail`）。

## 3. 校验点类型（细分能力目录）

每条 **CheckPoint** 建议统一形状：

```json
{
  "id": "cp1",
  "kind": "page_state | hierarchy | session | overlay | count_delta | nav_edge_effect | visual",
  "weight": 1.0,
  "required": true,
  "params": { }
}
```

### 3.1 `page_state` — 当前是什么页面（FSM）

| 项 | 说明 |
|----|------|
| **能力** | 新增 **`assert_page_state`**（本地 cap，不出 Scout） |
| **实现** | 读当前 turn 的 `nav_localized`（已有）；对比 `CheckPoint.params.state_id` 或 `display_name` / `meta.page_brief` |
| **数据真源** | NavFSM `states[].identify` + `meta.display_name` / `page_brief`（**禁止代码硬编码 App 文案**） |
| **输出** | `{ chosen, confidence, band, match_reason }` |
| **fail 语义** | 「期望屏 A，定位 B（conf x%）」 |

与「分析当前是什么页面」产品表述一致：**不是让 LLM 自由描述**，而是 **localize + 图上的 state 合同**。

### 3.2 `hierarchy` — 文案/控件是否存在或不存在

| 项 | 说明 |
|----|------|
| **能力** | **`assert_hierarchy`**（或复用 `evaluate_effect_assert` 子集） |
| **条件** | `text_contains` / `text_eq` / `content_desc` / `require_none`（弹窗文案消失） |
| **输出** | 命中节点 brief、matched_by |
| **典型** | 「出现生成中」「不应出现登录按钮」「底栏选中 Tab X」 |

### 3.3 `session` — 登录态 / 会话

| 项 | 说明 |
|----|------|
| **能力** | **`assert_session`**（包装 `relogin` / `inspect_session` + `session_gate.required_session`） |
| **典型** | 前置「未登录」、步骤「弹出登录页」、退出后「guest」 |

### 3.4 `overlay` — 系统弹窗 / 非目标前台

| 项 | 说明 |
|----|------|
| **能力** | **`assert_overlay_clear`** 或 **`assert_foreground_app`** |
| **实现** | 现有 overlay/fg 检测 + `permissioncontroller` 等（与 system_dialog_recovery 同源信号） |
| **典型** | 「无系统权限弹窗」「foreground 为目标 package」 |

### 3.5 `count_delta` — 数量是否变化

| 项 | 说明 |
|----|------|
| **能力** | **`assert_count`** |
| **实现** | hierarchy 上匹配 selector（如点赞数、列表项 resource_id 计数）与 **step 开始时快照** 或 **上一步 check 快照** 对比 |
| **存储** | `RunContext` 或 `StepCursor` 上 `check_baseline_snapshot`（仅计数/hash，不存图） |
| **典型** | 「点赞图标变为已点赞」「列表多一条」 |

### 3.6 `nav_edge_effect` — 导航边级强断言（复用）

| 项 | 说明 |
|----|------|
| **能力** | 直接调用 `evaluate_effect_assert(spec, nodes, chosen_state, …)` |
| **场景** | 步骤 expected 与 **某 state 或某边 effect** 对齐时（Atlas 已配置） |

### 3.7 `visual` — VLM 兜底

| 项 | 说明 |
|----|------|
| **能力** | 现有 **`assert_visual`** |
| **触发** | 仅当：① 无 FSM/hierarchy 判据；② 或 CheckPlan 标记 `ambiguous`；③ 或前序点 **split**（见 §4） |
| **输入** | **缩小后的子预期**（单条 CheckPoint 的 `natural_language`），非整段 expected |

## 4. 预期解析：从一句话到 CheckPlan

### 4.1 解析来源（优先级）

1. **Console 结构化字段（未来）** — `project_cases` JSON：`checkpoints: CheckPoint[]`（真源优先）。  
2. **规则 + 分句（P0）** — 按 `、；/` 拆分 expected；关键词映射到 kind（登录、弹窗、跳转、Tab、生成中…）。  
3. **LLM 分解（P1）** — `expected-decompose` job：输出 CheckPoint 列表 + `ambiguity_score`；**入库可审**后再跑。  
4. **NavFSM 反查（P1）** — expected 口语与 `state_id` / `page_brief` 模糊匹配，自动插入 `page_state` 点。

### 4.2 何时必须调用 FSM / 其他能力（与「可选工具」并存）

```text
模型 stance = pass_self 且无疑义
  → 可不调用工具，程序终裁 pass（§2.3）

模型 stance = pass_self 但有 ambiguous / 页型·登录态·同义文案
  → 拒绝自证；必须 need_tools

模型 stance = fail_claim 或 need_tools
  → 按 CheckPoint 编排工具（顺序由程序定，非 LLM 随意跳过）

expected 子句映射：
  单一 kind → 对应 assert_*
  歧义 → 标记 ambiguous → 至少 page_state + hierarchy；仍 unresolved → assert_visual（子句级）
```

**示例（造物相机类，仅说明类型，文案以 Console/FSM 为准）**：

| expected 片段 | 优先校验点 |
|---------------|------------|
| 进入帖子详情页 | `page_state` + hierarchy「详情页 landmarks」 |
| 弹出登录页面 | `session` + hierarchy「登录控件」+ `overlay` 无系统挡屏 |
| 登录成功 | `session=logged_in` + **非**单独 VLM |
| 3D空间 / 3D预览 | hierarchy **同义组** 或 FSM `aliases`；歧义时 **page_state** 定屏后再 VLM |
| 点赞已点赞 | `count_delta` 或 hierarchy 状态位 |

## 5. 校验结果可信度（Verdict + Confidence）

### 5.1 单点证据

每个 CheckPoint 产出：

```json
{
  "point_id": "cp1",
  "kind": "page_state",
  "status": "pass|fail|skip|inconclusive",
  "confidence": 0.0,
  "executor": "nav_localize|hierarchy|vlm|…",
  "summary": "人类可读一句",
  "raw": { }
}
```

**confidence 建议（程序侧，可调）**：

| executor | 典型 confidence |
|----------|-----------------|
| hierarchy exact + clickable | 0.95 |
| effect_assert pass | 0.9 |
| localize band=high | 0.85 |
| localize band=explore | 0.55 |
| localize band=recover | 0.35 → 触发 VLM 或 inconclusive |
| VLM only | 0.5–0.75（随 job 返回 calibrate） |
| llm_self（§2.3 允许） | 0.7–0.9（须显式 confidence；低于 T_self 强制 need_tools） |

### 5.2 步骤级合成（含自证 pass）

```text
llm_self pass（§2.3 允许 + confidence ≥ T_self）     → 步骤 pass（executor=llm_self）

工具路径：required 点全部 pass 且 weighted_conf ≥ T_tool → 步骤 pass

任一 required 工具 fail                              → 步骤 fail（摘要列出失败点）
模型 fail_claim 但工具 required 均 pass               → 步骤 pass（记录 model_false_fail）

required inconclusive 或 conf < T                    → inconclusive → ask_human 或 fail（配置）
optional 点 fail                                     → warning only
```

**Fail 终裁条件（硬）**：`∃ required CheckEvidence.status == fail` **或**（配置）全部 inconclusive；**不接受**仅 `check_fail_claim` 无工具证据。

**Studio 展示**：check 回合展示 **CheckEvidence 列表**（类似测试报告 assert 树），而不是只有 VLM 一段话。

### 5.3 与 assert_visual / signal_done 的关系

| 旧 | 新 |
|----|-----|
| check 回合 LLM 只调 `assert_visual` | 先 **stance**；确定则 **`signal_done` 等价校验通过**（自证）；不确定再 `assert_*` |
| 一次 VLM 判整段 expected | 多点 executor；VLM **`assert_visual` 仅在 need_tools 且子句级** |
| pass / fail 对称靠 VLM | **pass 可自证（有条件）；fail 必须工具背书**（§2.3） |

## 8. 验收标准（批跑 / 单用例）

1. **简单 expected**（无 ambiguous）：模型可 **`pass_self` + signal_done**，trace **无** assert_* 调用，且带 `confidence` 与理由。  
2. **歧义/页型/登录态类 expected**：`pass_self` 被 gate 拒绝，必须出现 **≥1** 次 FSM/hierarchy/session 类证据。  
3. **模型 fail_claim**：步骤 **不得** 直接 fail；须先工具验证；工具全 pass 时步骤 **pass** 并记 `model_false_fail`。  
4. **终裁 fail**：trace 中 **至少一条** `CheckEvidence.status=fail` 且 executor ≠ llm_self。  
5. Studio 可展开证据树（含自证 pass 与工具 pass 来源）。  
6. 造物相机专项：fail 摘要指向具体 checkpoint，而非笼统「预期未成立」。

## 9. 非目标（本方案不做）

- 不在 Nexus 内做图像算法 OCR/检测（仍 Scout + VLM）。  
- 不替代 Console 写用例；结构化 checkpoints 是 **增强**，长期仍兼容纯文本 expected。  
- 不在 check 阶段自动 mutate 设备（recovery 仍走明确 recovery cap + gate）。
