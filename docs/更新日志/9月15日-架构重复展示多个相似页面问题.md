# 9月15日 — 架构图重复展示多个相似页面

**范围**：造物相机等 App 的 Screen Atlas / 架构图（例：`app_id = 3d2b9799-0027-4c7d-bfe7-8c5b88f4087d`）。  
**现象**：屏面看起来像同一类页，图上却拆成多个节点（如 `page.tab_灵感.profile_profile_page_6` … `_10`）。

---

## 1. 结论（v8 已落地）

| 问题 | 说明 |
|---|---|
| 不是图画重了 | relation-graph 按 state 一节点渲染；重复来自 **`build_atlas` 分桶** |
| **v9 分桶** | `skeleton_fp` = kind/cols/scroll + **多组件结构 token**；簇内 **线框 Jaccard** 不足则拆桶；无 Tab、无标题哈希 |
| **state_id** | `page.sk{12位哈希}`（`sk` 后无下划线），例 `page.sk25977d48f26a` |
| **展示名** | `nav_atlas_naming`：四向侧栏选中态组合 → 否则内容顶栏 → 编辑名 / 文档 / 用例 / LLM；多帧投票可随采集更新 |
| 骨骼去噪 | 同 state 多访 → `merge_skeleton_wireframe` 剥低频 region |

代码真源：`nav_app_skeleton.skeleton_fp_from_turn`（v8）、`nav_screen_registry._atlas_cluster_doc`、`nav_atlas_naming.py`。

---

## 2. 现象

| 现象 | 说明 |
|---|---|
| 多个卡片线框很像 | 同 Tab 下多次探索，布局框架相近 |
| 标题都像 Tab 名 | 非 entry 曾用 Tab 短名作 `display_name`；顶栏文案未单独展示时更同质 |
| `state_id` 带 `_6`、`_7` | `layout_key` 冲突时 `_slug_atlas_page` 递增避重 |
| 合并后仍偏多 | `_merge_wireframe_duplicate_clusters` 只合并 **线框签名完全一致** 的桶 |

---

## 3. 根因（现状）

### 3.1 聚类键含 role、chrome、kind

`_atlas_layout_cluster_key` 要点：

| `role` | 键形态 | 后果 |
|---|---|---|
| feed / profile / main | `{role}:{kind}:{chrome_hash}` | 顶栏文案变或 role 误判 → 新桶 |
| detail | `{fp}\|{chrome_hash}` | chrome 变即分叉 |
| 其它 | 线框签名 / 框架 fp | 与「应用骨骼」不对齐 |

`chrome_hash` 来自 `stable_chrome_texts` → **目标：分桶完全移除**；采集结果只写 `meta`，Studio 编辑页展示（见 §4.4）。

### 3.2 其它

- `semantic_page_role` 启发式误判（profile vs detail）→ 不同桶。
- 探索修通后帧数增多，节点短期变多是副作用；**减重复**靠骨骼聚类 + 运行中去噪，不是刷新图。

---

## 4. 目标行为

### 4.1 流水线

```
采集 turn → 布局 framework + wireframe + 滚动语义
         → bucket_key = skeleton_fp（v8，与 Tab/顶栏标题无关）
         → 展示名 nav_atlas_naming（侧栏选中 / 顶栏内容 / 人工与弱信号）
         → 同一 state 多次访问 → merge_skeleton_wireframe 去噪
         → relation-graph 一 state 一节点（page.sk*）
```

### 4.2 应用骨骼 `skeleton_fp`

描述 **壳层与交互拓扑**（非 OCR 正文），从无障碍树 / wireframe / 导航遥测归纳：

| 维度 | 含义 | 示例 |
|---|---|---|
| 固定组件 | 多访中稳定存在的壳层控件 | 顶栏、返回、底栏 Tab、侧栏、FAB |
| 非固定 / 流式 | 随数据、滚动变化 | 列表 cell、feed 卡片内容 |
| 滚动语义 | 主内容区滚动方式 | `vertical_list`、`horizontal_pager`、`nested_scroll`、`none` |
| 内容槽位 | 结构模式（非文案） | 列数、卡片比例、WebView 区域 |
| 导航边（可进 fp） | 点击后产生 state 转移的控件签名 | 区分同壳不同出口的子页 |

`skeleton_fp` = 上述维度的归一化哈希（排除 volatile 文本；多次访问后再剥低频 region）。

**不采用固定「顶栏 / 内容 / 底栏」三层带** 作为唯一几何模型；该假设只覆盖部分 Tab App，无法统一描述 Web、抽屉、顶 Tab、分栏等。固定件与滚动语义替代 y 比例切带。

Web 与原生同一套抽象：节点 + 框 + 角色；底栏 Tab 仅是「固定底栏导航」一种固定件。

### 4.3 单次 vs 多次

| 场景 | 行为 |
|---|---|
| **首次 / 新 `skeleton_fp`** | 当帧算 fp；与已有 state 不同 → **新建 state**；不去噪 |
| **同 fp 多次采集** | 时间序 turns 上统计频次；高频 → 展示骨骼 wireframe；低频 → 不展示、不进 identify 必填 |

### 4.4 顶栏文案（chrome）

| 项 | 规则 |
|---|---|
| 分桶 | **不参与** `layout_key` / `bucket_key` |
| 采集 | 可用 `stable_chrome_texts` 等，与聚类解耦 |
| 存储 | `meta.chrome_texts` / `meta.header_title`；更新不新建 state |
| 编辑 | Studio 增加 **「顶栏文案」** 一行（见 `9月15日-编辑页面信息.md`） |
| identify | 仅弱提示，不作 localize 硬键 |

### 4.5 合并 vs 分拆（结构判定）

在同一 Tab 族内比较骨骼特征（固定件 + 滚动语义 + 槽位 + 可选导航边）：

| 情况 | 动作 |
|---|---|
| `skeleton_fp` 相同 | 同一 state；多次去噪更新线框 |
| 固定件重叠但主滚动语义不同 | 通常 **两个 state** |
| 固定件差大 | **新建 state** |
| 固定件共享多、主导航边不同 | 不合并内容区；修正 Tab 或并列 state |
| 仅流式区不同、壳与滚动一致 | 同一 state；去噪 |

## 5. 交付优先级（仅 P0 / P1）

> **实现状态（2026-09-15）**：P0 与 P1 主路径已落地（`nav_app_skeleton.py`、`build_atlas` 骨骼分桶、Studio 编辑/合并 API）。P1 可选「图上折叠」仍待办。

### P0 — 必须交付

**Nexus**

- 分桶键：**移除 `chrome_bit`、`role`**；以 `skeleton_fp` 为主（可先由加强线框/框架 fp 过渡，随即替换为骨骼模块输出）。
- 新模块（如 `nav_app_skeleton.py`）：固定/非固定、滚动语义、槽位 → `skeleton_fp`；`merge_skeleton_wireframe(turns[])` 供多次去噪。
- `build_atlas` / 采集落库：chrome 只写 **meta**；同 fp 多次命中时更新展示线框。
- `semantic_page_role` 只写 meta，**不进** `bucket_key`。

**Studio**

- 架构页编辑：**顶栏文案** 一行（读/展示 `meta.chrome_texts` 等）。

**效果验收**：由业务侧在真实 App / 任务上查看架构图节点数与合并是否符合预期（本文档不写自动化 fixture 要求）。

### P1 — 随后交付

**Nexus**

- 展示名策略：用户 **页面名称** > meta chrome 众数 > Tab 短名。
- 导航边纳入 `skeleton_fp`（依赖 nav 遥测与 state 对齐）。
- 运行中 capture 与 atlas 增量同步策略收紧（与探索/跑批共用同一去噪逻辑）。

**Studio**

- 只读 **采集次数** `meta.visit_count`。
- **合并到另一页 / 拆分为两页**（人工指定 canonical `state_id`）。
- 可选：图上折叠多 state，仅展示层。

### 明确不做

- 单 App「这些页算同一页」硬编码白名单。
- 三层带（`content_top` / `content_bottom`）作为骨骼唯一模型。
- LLM 判定是否同一页。
- 文档外的额外优先级标签（无 P2、P3 等；一律归入上表 P0 或 P1）。

## 6. 现状 vs 目标（对照）

| 取向 | 现状 | 目标 |
|---|---|---|
| 聚类真源 | Tab + role + chrome + kind | `skeleton_fp` |
| 顶栏文案 | `chrome_hash` 拆桶 | 仅 meta + 编辑行 |
| 单次新页 | 与多次同键，易误拆 | 新 fp → 新 state，不去噪 |
| 多次同页 | 无系统去噪 | 连续采集沉淀骨骼 |
| 语义角色 | 参与分桶 | 仅 meta |
