## 4. `cr-df6d22c19bd9` 专项（你提的 3 条）

### 4.1 `case-51fef028`：前置「新用户」 vs 租号「老用户」

**现象（Studio）**：前提「账号与数据：新用户」；上下文显示「已租测试账号 17633330010；环境 test；标签 老用户；环境匹配 · 标签「老用户」」。

**机制（代码，非「批内不重新租号」）**：

- `case_runner` 对每条用例调用 **`run_case` → 新建 `RunContext`**；用例结束 **`finally` → `release_ctx_lease(ctx)`** 清空 `picked_account`。
- 每条用例开跑 **`ensure_case_account`** 都会 **重新 `lease_for_context`**（除非本条 `need_account=false`）。

**真正根因**：

- 号池 **`pick_test_accounts`** 原先对「新用户/老用户」**无加减分**，仅 `env=test`（+6）即可选中 **老用户** 标签号。
- 前置整段 precondition 作 `tags_prompt`，**「新用户」与标签「老用户」未互斥**。

**已做（Nexus）**：

- `project_env.pick_test_accounts`：前置含 **新用户** → 老用户标签 **-24**；含 **老用户** → 新用户/未注册 **-12**。
- `session_ensure`：租号 reason 含标签冲突时打 **warn** 日志。

**建议（Console/号池）**：

- 新用户专项用例绑定 **仅「新用户/未注册」标签** 的号；或前置写 `session=guest` + 标签白名单。
- Studio 展示 **`score` / `reason`**，便于肉眼发现「环境匹配但标签反了」。

## 10. `cr-c8d98516acda`：再回归与防回归

### 10.1 `case-112f10ef` — expected 再次拖走 do

- **现象**：do 多轮 `wait_ms` + thought「生成中/加载」；check fail：expected「生成中」，屏上已生成完（如「杯边放空侠」）。

### 10.2 `case-8b53a494` — 同向 swipe 连发

- **现象**：方向已对（down），仍 5+ 次同向 swipe，`action_fuse` 偏晚。
- **对策**：同向计数不随 fp 清零；**≥3 同向即 guard**。

### 10.3 防回归清单（动 do/check/意图/swipe 必过）

1. 延后 expected 类：do prompt / 探针 / auto enter_check 是否一致。

3. `require_do_work`：`step_ops>0` 仍校验 intents。  
4. check：program pass 与 assert_visual 优先级符合非对称校验方案。  

**最小复跑集**：112、8b53、c8cee、guest 登录各 1。
