# 9月16日 — 增加页面流转识别功能（方案 v1）

**背景**：Screen Atlas 已能聚类出 `page.sk*` 与观测 nav 边（`nav_screen_registry`、v9 粗 lane + morph，见 [`9月16日-增加页面切换多态识别能力.md`](9月16日-增加页面切换多态识别能力.md)）。Studio「结构图」仍把节点 **按采集顺序填满三列网格**，边在节点间任意穿越，**看不出业务流程**；跑用例时 LLM 只有「当前一屏 + 稀疏 nav_assist」，**不知道自己在哪条业务流、流进行到哪一步**，导致误导航、重复操作、同用例多次跑结果不一致（见 [`9月16日-用例执行调用fsmnavigate能力异常.md`](9月16日-用例执行调用fsmnavigate能力异常.md) §0、`9月15日-fsm_navigate异常导致任务失败.md`）。

**关联**：多态 morph（进度条刷新、骨骼不变）→ **不拆页**；壳层变 / 新逻辑屏 → **拆页**（与 v2 §2 一致）。无底栏子流程孤点 → [`9月15日-导航架构页与探索循环问题核对.md`](9月15日-导航架构页与探索循环问题核对.md) P1-9。

**优先级**：**P0 数据模型 + 采集标注**（与 morph M2 共用证据）；**P1 Studio 布局 + assist 注入**；**P2 自动从用例/文档提议逻辑块名**（人工审）。

**状态**：Nexus **F1 + V0/V1 已落地**（`nav_flow_blocks`、Atlas `flow_blocks`/transition、assist【业务流】）；Studio 展示定稿见 [`9月16日 — 增加页面流转识别功能.md`](9月16日 — 增加页面流转识别功能.md)（A″ 图稿）；**Studio 渲染开发中**。

## 1. 概念模型

### 1.1 三层：逻辑块 / 逻辑页 / 流转

```
┌─────────────────────────────────────────────────────────┐
│  flow_block（业务流：登录、下单、下载）                      │
│  ┌──────────────┐   manual edge    ┌──────────────┐     │
│  │ page.skA     │ ───────────────► │ page.skB     │     │
│  │ 输入手机号    │                  │ 输入验证码    │     │
│  └──────────────┘                  └──────────────┘     │
│         │ auto edge (timeout/success)                     │
│         └──────────────────────────────────► page.skC     │
└─────────────────────────────────────────────────────────┘
         │ 块间边：Tab 切换、从首页进流入口（可标注 weak_relation）
         ▼
   其他 flow_block 或「全局导航」边
```

| 概念 | 定义 | 与现有 Atlas 关系 |
|------|------|-------------------|
| **逻辑页** | 用户心智一屏，`state_id = page.sk*` | 已有；morph 在 `meta.morphs[]` |
| **逻辑块 `flow_block`** | **有向子图**：若干逻辑页 + 块内 nav 边 + 可选入口/出口 | **新增**；引用已有 `state_id` / `edge_id`，不复制骨骼 |
| **流转 `transition`** | 块内或块间一条 nav 边 + **驱动类型** | 复用 `nav_fsm_edges` 或 atlas 观测边，增加 `meta.transition` |
| **全局跳转** | Tab、从商品进详情等 **跨流** 边 | 保留现有 atlas 边；UI 上 **块外** 绘制，尽量走块间「端口」 |

### 1.2 流转驱动类型（6.1 / 6.2 / 6.3）

| `driver` | 含义 | 采集信号（优先） | 示例 |
|----------|------|------------------|------|
| **`manual`** | 用户/模型显式操作触发 | turn 间有 `tap` / `press_key` / `input` 且 `effect_assert` 通过或边已编译 | 点「下一步」、填表提交 |
| **`auto`** | 无同 turn 操作但屏态/内容满足后继 | 骨骼不变 + **morph 计数** / 进度类 volatile 文案；或 `wait` 后 localize 变 chosen | 下载进度刷新 |
| **`system`** | 系统返回、权限弹窗、Deep link | `press_key BACK`、通知栏、包外拉回 | 返回键 |
| **`unknown`** | 仅知 A→B，尚未分类 | 探索首版默认；Studio 可改 |

**与 morph 的分工（6.3，对齐 v2）**：

- **同 `page.sk*`，仅进度数字/文案变** → `driver=auto`，记 `meta.morphs[]` / `observed_content_swaps++`，**不新建 state**。
- **下载成功列表、成功 Toast 关闭后新壳层** → 新 `page.sk*`，边 `driver=auto` 或 `manual`（若需点「完成」），**同属 `flow_block=download`**。

**与「首页 ↔ 我的」的区分（6.2）**：

- **块内**：相邻 turn 的 `turn_cluster_ids` 变化 + **同 session 无 Tab 根切换** + 连续 `manual` 边（或 orphan 时序链）→ 分段为一个 `flow_block` 候选。
- **块外 / 弱关系**：跨 Tab、visit_count 高但 session 内仅偶发一次 A→B → **不强行并入** 登录块；边上可标 `relation=weak`（UI 用浅色/虚线，不参与 flow_context 默认进度）。

### 1.3 逻辑块命名（6.1）

命名 **优先级**（均可覆盖，须 audit）：

1. Console / Studio **人工编辑** `flow_block.display_name`
2. **用例步骤**聚合：同一 `case_id` 连续 step 的「进入/填写/提交」动词 + 宾语（LLM job，输出 **候选**）
3. **需求 / UI 交互文档**（`knowledge_entries`）检索标题与章节锚点
4. 默认：`flow_block.fb{hash(ordered_state_ids)}` + 首屏 `display_name` 拼接

**禁止**：在 `nav_*` 合成代码里写死「登录」「下载」等 App 专用关键词做 **唯一** 分类器；可用 **结构信号**（输入框数量、stepper、全屏无 tab_bar）+ 人工审。

## 2. 架构图展示（6.0）

### 2.1 现状与问题

| 现象 | 根因 | 文档 |
|------|------|------|
| 三列满格换行 | `atlas_layout: skeleton_grid` / `orphan_grid` 前端按索引 `% 3` 或类似网格 | 用户截图 2026-09-16；P1-14 结构图/流程图未区分 |
| 边交叉严重 | 节点位置与 **业务无关** | — |
| 看不出登录/下载流 | Atlas 只有 **flat states + edges** | 本方案补 `flow_blocks` |

### 2.2 目标交互

1. **默认视图**：**按逻辑块分泳道/卡片**（块标题 + 块内节点 **自上而下或左到右** 按流序排列）。
2. **块外全局边**：从块 **出口端口** 连到另一块 **入口端口**；布局算法 **分层 DAG**（Sugiyama）或 ELK `layered`，约束 **同块内边优先竖直、块间边走通道**。
3. **线尽量不交互**：允许 **边 bundling** / 正交折线；块内边不穿出块框（或仅出口一条）。
4. **缩放与聚焦**：点击块 → 块内放大；hover 节点仍预览线框（已有 M3 morph badge 延续）。
5. **结构图 vs 流程图 Tab**（消 P1-14）：
   - **结构图**：块 + 页 + **全部** 观测边 + hierarchy/tab_scope 装饰（若仍需要）。
   - **流程图**：**仅块内主路径** + 标注 `manual/auto`；隐藏 weak 跨 Tab 边（可开关）。

### 2.3 业界可借鉴（6.0.3）

| 产品 / 领域 | 做法 | 本仓取舍 |
|-------------|------|----------|
| **Figma / FigJam User Flow** | 帧分组、Section、连接器从 **锚点** 出 | **flow_block 容器 + 端口** |
| **Miro Customer Journey** | 泳道按阶段 | 块 ≈ 泳道；块内 = 步骤屏 |
| **React Flow / ELK** | 自动布局、sub-flow | MinoStudio 已有 relation-graph → 加 **parentNode** 或分组层 |
| **Mobile app mapping（AppSee 类）** | 屏幕图 + 转移概率 | 我们：**观测边 + visit_count**，不编造未采集边 |
| **Harel 状态图子状态** | 复合状态 | **flow_block 不替代 state_id**；只是视图 + runtime 上下文 |
| **Page Object / 场景脚本** | 按场景组织 PO | **块名对齐场景**，但 state 仍 `page.sk*` 真源 |

**不做**：纯手动 Page Object 图（v2 §5 已否）；纯录制 GIF 流（无 localize 契约）。

## 3. 数据模型与存储

### 3.1 落盘位置（推荐）

与 [`NAVIGATION_ATLAS.md`](../基础框架/NAVIGATION_ATLAS.md) §0 一致：**运行时配置进 `mino.db`**，大证据进 `data_dir()`。

**方案 A（首期）**：写入 Screen Atlas 文档 JSON（`meta.flow_blocks` + 边上的 `transition`），与 `screen_atlas` 同步版本；Studio arch GET 已读 atlas。

**方案 B（正式 NavFSM 对齐）**：`nav_fsm.meta.flow_blocks` + 边 `execute` / 扩展 JSON；promote 时与 states/edges 一并校验。

```json
{
  "flow_block_id": "fb.a1b2c3",
  "display_name": "登录",
  "name_sources": [{"kind": "case", "ref": "case-xxx", "confidence": 0.7}],
  "state_ids": ["page.sk111", "page.sk222", "page.sk333"],
  "entry_state_id": "page.sk111",
  "terminal_state_ids": ["page.sk333"],
  "intra_block_edge_ids": ["edge.sk111_sk222", "edge.sk222_sk333"],
  "evidence_tier": "medium",
  "visit_sessions": 12
}
```

边扩展（atlas 或 fsm）：

```json
{
  "transition": {
    "driver": "manual",
    "flow_block_id": "fb.a1b2c3",
    "step_index": 1,
    "evidence_turns": [{"session_id": "...", "turn_id": 5}]
  }
}
```

### 3.2 与 `state_id` 铁律（避坑）

[`9月15日-架构聚类过并过拆复盘.md`](9月15日-架构聚类过并过拆复盘.md)：**不要把「是否同一屏」「Tab」「标题」绑在一个变量上反复改**。

- **`page.sk*` 仍只回答「物理/壳层逻辑页」**（lane + Jaccard + morph）。
- **`flow_block_id` 只回答「业务段归属」**；同一页可 **零个或一个** 主块（多归属仅 Studio 高级，默认禁止以免 assist 歧义）。
- **展示名** 仍走 display_name / aliases 治理，**不写回** bucket_key。

### 3.3 采集与合成 pipeline（P0）

在现有 `turn_cluster_ids` 连边逻辑（`nav_screen_registry` §时序 nav）之后增加 **离线/ run-end 阶段**：

1. **段切分 `segment_session_flows(session_id)`**
   - 输入：turn 序列、`nav_action_types`、tab_bar 变化、orphan 标记。
   - 输出：若干 `{ state_id[], edge_id[], drivers[] }`。
2. **聚段为块 `cluster_segments_to_blocks(app_id)`**
   - 跨 session：Jaccard 对 **有序 state_id 序列** 相似则合并块定义（同登录流）。
3. **driver 推断**
   - turn N 有 `last_event in (tap, input, press_key)` 且 N→N+1 变屏 → `manual`。
   - 同 cluster、morph++、无 tap → `auto`。
4. **写候选** → `nav_candidate_compiler` 新 kind：`flow_block_proposal` / `transition_driver`（**pending**，对齐 v2.5 §19）。

**硬约束**：[`9月15日-导航架构页与探索循环问题核对.md`](9月15日-导航架构页与探索循环问题核对.md) P1-4 **禁止 auto-accept 全部 pending**；块提议默认 **低置信 + 人工 accept**。

### 3.4 已知坑与对策

| 坑 | 后果 | 对策 |
|----|------|------|
| orphan_grid `edges: []` | 登录流在图上孤点 | P1-9：时序边 + **块内布局** 仍显示；本方案 **强制** orphan 参与段切分 |
| 跳转标签靠猜 | 错 driver / 错块 | P1-8：标签用 **实际 `selector_text`**；失败则 `unknown` |
| 百分比/时间 noise state | localize 100% 错流 | P0-6：noise **不进 FSM**；块提议过滤 `_fsm_state_is_atlas_noise` |
| 每帧 promote 图谱膨胀 | 块边界漂移 | P1-1：**run-end 合成** 块，不在每 turn 改块拓扑 |
| 结构图/流程图同图 | 用户以为已支持流程 | P1-14 + 本方案 **双 Tab 语义** |
| 探索当跑批约束 | assist 误导 | P0-7：explore 仅采集，**不注入 flow 进度为硬约束** |

## 4. 运行时：对用例执行的好处（6.4）

### 4.1 问题复述

| LLM 误判 | 根因（Nexus 侧） | 非 App bug |
|----------|------------------|------------|
| 已下载成功仍点「下载」 | 无 **流终态** 信号；步骤文案仍含「下载」 | ✅ |
| 已进验证码页仍 fsm 回首页 | localize 只看 **单屏**，不知 **块内 step** | ✅ |
| 同用例两次结果不同 | 随机 Tab 捷径 vs 返回链（见 fsm v2 §0.3–0.5） | ✅ |

### 4.2 `flow_context`（注入点）

在 **`nav_compiler.compile_assist`** 与 **agent-decide context**（`job_slots.nav_assist` 扩展）增加结构化块（非长 prose）：

```json
{
  "flow_block_id": "fb.a1b2c3",
  "flow_display_name": "登录",
  "step_index": 2,
  "step_total": 3,
  "current_state_id": "page.sk222",
  "terminal_states": ["page.sk333"],
  "driver_last": "manual",
  "progress_hint": "验证码页；成功后应进入首页，不应再点「获取验证码」"
}
```

**规则**：

1. `step_index` 由 **session 内** 最后一次 **manual** 边推进 + localize chosen 对齐；`auto` morph **不增 step_index**（6.3）。
2. 若 chosen 已是 `terminal_states` 之一 → assist 前缀 **「本流已完成」**；`fsm_navigate` 目标若与块无关，提示 **勿为完成用例而回到流入口**（软提示，不替代 declined 逻辑）。
3. `evidence_tier=low` 时块进度加 **「参考意见」**（与 v2 §3.3 一致）。
4. **与 `target_page` 规划正交**：块内优先 **沿 intra_block_edge** 提示下一步；跨块仍走 `plan_route`。

### 4.3 与 localize / morph 联动

- chosen ∈ 块内但 **morph 活跃**（下载中）→ `flow_context.phase = in_progress`，**不**新建 state。
- chosen 从 skA 跳到 skB 且边 `driver=auto` → 记录 telemetry `flow_auto_transition` 供校准报告。

## 7. 验收标准

1. **登录三屏**（手机号 → 验证码 → 首页）：架构图 **一个块、三块内竖排**，块外边到首页 Tab **≤1 条主出口**；assist 在验证码页给出 `step 2/3`。
2. **下载**：进度刷新 **单节点 + morph badge**；成功列表 **第二节点**；块内 `manual+auto` 边各至少 1 条观测。
3. **网格回归**：块内 5 页时 **不再** 出现「满三列换行与业务无关」的 **唯一** 布局（允许用户切回「平铺网格」旧视图）。
4. **用例稳定性**：同一「仅下载」用例，下载完成后 **下一轮 decide** 不再提议 `tap 下载`（抽样 10 次，≥8 次无重复下载操作）—— 在 **flow_context + 终态** 开启 A/B 可测。
5. **审核**：新块 **100% 经 pending accept** 才进 promote 路径（自动化测试钉死 P1-4 回归）。
