# MinoNexus：从「点击启动」到「单条用例结束」在做什么

> **用途**：对内汇报 / **飞书粘贴**。下图均为**纯文本流程图**（不要用「代码块-Mermaid」），整段复制到飞书正文或「代码块-Plain Text」即可直接阅读。  
> 若要用飞书自带「流程图」美化：按每节标题下的步骤节点，从左到右或从上到下拖拽即可。

---

## 一、一句话定位

**MinoNexus = 服务端大脑**（看图、组上下文、决策下一步）；**MinoScout = 手脚**（在真机/模拟器上执行点击、滑动等）。  
一次任务：选 App、设备、用例 → 启动 → **逐条用例** 在 **前置 → 操作 → 校验** 中跑完，汇总结果。

---

## 二、整体架构（谁和谁说话）

```
┌──────────────────── Studio / Console ────────────────────┐
│  选 App · 设备 · 用例  ──►  点击启动  ──►  看 trace/报告   │
└──────────────────────────────┬───────────────────────────┘
                               │ HTTP / WebSocket（任务、事件）
                               ▼
┌──────────────────── MinoNexus 服务端 ────────────────────┐
│  Case Runner（任务调度）                                    │
│       │                                                    │
│       ▼                                                    │
│  Agent 循环（prep → do → check）                           │
│       ├──► NavFSM · 知识库 · 项目文档（组上下文）           │
│       ├──► 大模型 agent-decide（选下一步）                  │
│       └──► Guards 门闩（下发前拦截）                        │
│                │                                           │
│         本地能力│                    设备能力               │
│    （问人/断言/等待）              EXECUTE 协议              │
└────────────────┼──────────────────────┬────────────────────┘
                 │                      │
                 │                      ▼
                 │         ┌──── MinoScout 节点 ────┐
                 │         │ WebSocket 在线          │
                 │         │ 截图 · UI hierarchy   │
                 │         │ 执行点/滑/输入          │
                 │         └──────────┬─────────────┘
                 │                    ▼
                 │              ┌ 被测设备 ┐
                 │              │ App 界面 │
                 │              └──────────┘
                 │                    │
                 └──── 截图/层级 ◄────┘（每 Turn 回传）
```

**数据方向小结**：UI 只连 Nexus；Nexus 决策后要么本机执行，要么经 Scout 动设备；每轮把新截图和 hierarchy 拉回 Nexus 再决策。

## 四、单条用例：三阶段怎么推进

**一条用例 = 多步**；每一步内部：**prep（若有前置）→ do → check**（无 expected 可跳过 check）。

### 4.1 单步内的阶段

```
   prep（前置）          do（操作）           check（校验）
 ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
 │清缓存/启动等 │ ─► │按 instruction│ ─► │按 expected  │
 │确认登录态等  │    │点滑输入导航等 │    │程序校验+VLM │
 └─────────────┘    └─────────────┘    └─────────────┘
       │                    │                    │
       └──── signal_done ───┴──── signal_done ───┘
                            （程序门闩可能拒绝提前结束）
```

### 4.2 多步用例串联

```
用例开始
   │
   ▼
┌────────┐    校验通过    ┌────────┐    校验通过    ┌────────┐
│ 步骤 1 │ ────────────► │ 步骤 2 │ ────────────► │ 步骤 3 │ ──► 用例 pass
└────────┘               └────────┘               └────────┘
   │                        │                        │
   └─ 任一步 fail/放弃/步数耗尽 ──────────────────────┴──► 用例 fail 或 blocked
```

### 4.3 阶段切换条件（文字版状态机）

| 从 | 到 | 条件 |
|----|-----|------|
| 用例开始 | prep | 用例配置了前置 |
| prep | do | 前置 signal_done 且 session 就绪 |
| do | check | 操作 signal_done 或程序自动进校验 |
| check | 下一步 do | 校验通过且 signal_done |
| check | 用例结束 pass | 最后一步校验通过 |
| do / check | 用例结束 fail | 放弃、校验失败或 turn 用尽 |

## 五、单条用例内：每一轮 Turn 在做什么

在 **max_steps** 上限内重复（默认约 24 轮，技能里可配）。

```
┌─────────────── 新 Turn 开始 ───────────────┐
│                                              │
│  ① Scout：截图 + UI hierarchy                │
│  ② 刷新 session（是否登录等）                 │
│  ③ NavFSM：逻辑页定位、路线辅助、挡屏预检      │
│  ④ Context Pack：导航辅助 + 知识 + 文档检索   │
│  ⑤ Step Pointer：当前步文案（do 弱化 expected）│
│                                              │
│  ⑥ 分支：当前处于 prep / do / check？         │
│       │                                      │
│       ├─ prep 或 do ──► ⑦ 大模型 agent-decide │
│       │                      │               │
│       └─ check ──► 程序校验计划 / assert_visual│
│                              │               │
│  ⑧ Guards 门闩（重复/方向/阶段/登录…）        │
│       ├─ 拦截 ──► 不下发，提示改动作，下一 Turn │
│       └─ 放行 ──► ⑨ 执行                     │
│              ├─ Nexus 本地（问人/断言/等待）    │
│              └─ Scout 设备（点/滑/输入/导航）   │
│                                              │
│  ⑩ 记录效果（意图、tap、swipe、屏指纹）       │
│  ⑪ 是否推进阶段（如 do→check）或结束本步      │
│                                              │
└──────────────────► 下一 Turn 或本用例结束 ───┘
```

## 六、决策与执行：门闩卡在哪里

```
  大模型输出（能力 id + 参数）
              │
              ▼
      ┌───────────────┐
      │ Guards 统一门闩 │
      └───────┬───────┘
              │
     ┌────────┴────────┐
     ▼                 ▼
  【拦截 skip】      【放行 ok】
  本 Turn 不执行      │
  写纠偏提示          ├──► Nexus 本机执行
                      │     （internal / vlm / hitl …）
                      │
                      └──► Scout 执行
                            （adb / uia … 点滑输入）

门闩常见项（prep/do/check 阶段组合不同）：
  · 防重复 tap / swipe / launch / 清缓存
  · require_do_work：操作或意图未做够不能结束
  · check 阶段 deny_mutate：禁止乱点屏
  · 滑动方向、同向滑动次数
  · guest 后误登录、无导航语义的 BACK
  · action_fuse：多轮无进展则熔断同类动作
```

## 七、信息如何进大模型（注意力怎么收窄）

```
  ┌───────────── 三渠道检索 ─────────────┐
  │ NavFSM        → nav_assist           │
  │ 知识库        → hint / 点名展开正文   │
  │ 项目文档      → doc_context          │
  │           （遇阻时可加文档，有次数上限）│
  └──────────────────┬───────────────────┘
                     ▼
            Context Pack（控字数）
                     │
  ┌───────────── 步骤指针 ───────────────┐
  │ 已完成步 / 当前步 / 待做步              │
  │ do：强调 instruction，延后 expected   │
  │ check：展示 expected + 校验计划摘要    │
  └──────────────────┬───────────────────┘
                     │
     截图 + hierarchy + session 登录块
                     │
                     ▼
            agent-decide Prompt
                     │
                     ▼
         下一步动作 或 signal_done
```

**程序侧意图**：用 instruction 拆意图/操作族，判断「做够了没有」；「生成中、登录成功、进入某页」等在 **do 不空等**，在 **check** 用程序校验 + 视觉断言。

## 八、校验（check）阶段怎么走

```
进入 check（本步）
        │
        ▼
按 expected 生成校验点（页态 / 屏上文案 / 会话 / 挡屏 …）
        │
        ▼
程序跑校验点
        │
        ├── 高置信且要点全过 ──► 标记 step_checked ──► signal_done ──► 下一步骤
        │
        └── 不确定或未过 ──► assert_visual（视觉断言）
                    │
                    ├── 通过 ──► step_checked ──► 下一步骤
                    └── 未过 ──► 继续 check 或判 fail
```

**原则**：pass 可工具 + 模型自证（无疑义点）；fail 需工具或视觉证据，避免无依据判失败。

## 九、三阶段能力对照（能干什么）

| 阶段 | 目标 | 模型常选能力 | 程序常做 |
|------|------|--------------|----------|
| prep | 环境与前态 | 清缓存、启动 App、读版本、recovery | 防重复 prep；require_session |
| do | 完成 instruction | tap、输入、滑动、fsm_navigate、登录 FlowBlock | 意图计数、导航计划、方向/重复滑动门闩 |
| check | 验证 expected | assert_visual、recovery | 校验计划、程序先判、禁止 mutate |

推进：prep/do 靠 **signal_done + 门闩**；check 必须 **出现过断言且 step_checked** 才能结束该步。

## 十、模块能力清单（汇报用）

| 模块 | 能干什么 | 怎么用 |
|------|----------|--------|
| NavFSM | 逻辑页定位、路线提示、fsm_navigate | Studio 配导航图，跑批自动加载 |
| 知识库 | 检索注入；模型可点名展开正文 | Console/Studio 维护条目 |
| 项目文档 | 向量检索；卡住时额外提示 | 文档入库后自动参与检索 |
| 大模型 | 每 Turn 决策；check 视觉断言 | 设置 Provider 并允许跑用例 |
| 能力目录 | 声明 cap 与 Scout 执行路径 | Console 维护目录条目 |
| FlowBlock / 登录宏 | 长登录流块执行、弹窗中断恢复 | 步骤 scope + 场景配置 |
| Check Plan | expected 拆点、程序校验 | check 阶段自动启用 |
| Guards | 统一下发前拦截 | 随 prep/do/check 阶段自动生效 |

## 十一、护栏一览（为何不会乱点乱滑）

| 类别 | 作用 |
|------|------|
| 重复下发 | 同一步不连点、不连滑、不重复 launch/清缓存 |
| action_fuse | 多轮无进展时熔断同类动作 |
| 阶段约束 | do 不能只做断言；check 不能乱操作屏 |
| require_do_work | 未做够操作/intent 不能 signal_done |
| 登录 / BACK | guest 后误登录、无导航语义 BACK |
| 滑动 / 等待 | 方向与用例一致；意图已齐禁止空等 wait |
| 效果探针 | do 不因 expected 弱关键词假达成 |

## 十二、怎么用（操作清单）

**测试 / Studio**

1. Scout 节点在线，设备未被其他任务占用。  
2. 配置 AI Provider，并开启「用于跑用例」。  
3. 维护用例（instruction + expected）；可选导航图、知识、文档。  
4. 选 App、用例、设备 → **启动** → 看任务详情 trace 与结果。

**管理员**

1. 调整 agent-decide 类 Jobs / Skills、能力目录。  
2. 维护导航图、FlowBlock、账号租号与环境。  
3. Nexus 与 Scout 协议变更需两侧同步，避免静默漂移。

---

## 十三、边界（汇报时建议说明）

- 无 Scout / 无在线设备 → 无法操作真机。  
- Nexus 不直连 adb；OCR/检测等不在 Nexus 本体，在 Scout 或 VLM 链路上。  
- 稳定性依赖 **Prompt + 步骤指针 + Guards + 校验** 四层一致；改一处需回归登录、滑动、延后 expected、FSM 跳转等典型用例。  
- 部分能力仍在持续迁移（如完整问人 UI、部分恢复路径），以当前 Studio 可见功能为准。
