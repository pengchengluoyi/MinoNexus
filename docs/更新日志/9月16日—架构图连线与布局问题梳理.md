# 架构图连线与布局 · 问题梳理（2026-09-16）

**范围**：Studio 架构 Tab（Screen Atlas + `navRelationGraph` + Nexus `nav_flow_blocks`）。  
**背景**：多轮迭代后仍反馈 **箭头不可见**、**游离页与主簇相距过远**、**读图规则与实现不一致**。

---

## 1. 当前现象（用户侧）

| 现象 | 典型表现 |
|------|----------|
| 箭头 | 图例有箭头示意，画布上贝塞尔线 **无端点三角**，方向只能靠标签/颜色猜 |
| 游离页 | 5 屏中 4 屏挤在上方，1 屏（如账户/用户中心）落在 **右下角大空白**，缩放约 40% 才全看见 |
| 连线层级 | 线有时被页节点盖住，或 spaghetti 叠线难以辨认 |
| 语义 | 虚线（auto/返回）仍从 **控件圆点** 出发，与「自动/返回从页底出」图例不一致（部分边已改 passive 锚点，取决于 `transition.driver`） |

---

## 2. 箭头为什么仍经常看不到

### 2.1 已确认过的实现问题

1. **`defaultLineMarker: 'arrow'`（字符串）**  
   relation-graph 3.x 需要 **marker 对象**（`viewBox/refX/data`）。错误类型会导致 SVG `<marker>` 无效，`marker-end` 为空。  
   **现状**：已改为 `RG_DEFAULT_LINE_MARKER` 对象。

2. **架构 nav 几乎全是 `fakeLines`（NodePoint → node）**  
   与普通 `lines` 不同路径渲染；需 **`showEndArrow` + `endMarkerId: {instanceId}-arrow-default`**，且在 **`addFakeLines` 之后** 才能拿到 `instanceId`。  
   **现状**：`enrichArchLineArrows()` 在 deferred fakeLines 上补 marker。

3. **虚线 + SVG marker**  
   部分浏览器对 **dash 路径的 `marker-end`** 支持差，箭头可能极弱或不可见（仍待 UI 验收）。

4. **终点被目标页节点盖住**  
   箭头在目标页顶边内侧时，曾被 **节点 peel z-index** 压住。  
   **现状**：提高 `rg-lines-container-el-lines` z-index，去掉压低 `rg-line-peel` 的规则。

### 2.2 仍未完全闭环

- 若 `instanceId` 在首帧拿不到，`endMarkerId` 仍可能缺一帧。  
- 未做 **自定义线层 / 手工箭头 path**（relation-graph 能力上限时的兜底）。

## 3. 游离页为什么离主簇那么远

这是 **布局 + 视口** 叠加，不是单一 bug。

### 3.1 产品定义

- **业务流块内页**：`flow_block` 内 ≥2 屏，横向排在块 bbox 里。  
- **游离页**：不在展示块内的 state（Tab 根、单页块被清壳、仅偶发访问等），`flow_block_id: ""`。

### 3.2 Nexus 布局链（`layout_states_for_flow_blocks`）

```text
块内排布 → _place_orphans_by_nav（贴入边/主分量右侧）
→  orphan 矩形写入 rects
→ _separate_rects（游离页 vs 块 bbox 碰撞推开）
→ 回写 orphan 坐标
→ min_x/min_y 归拢到 (48,48)
→ compact_layout_by_nav_edges（仅拉近有 nav 边的 dy）
→ _center_layout_on_canvas
```

### 3.3 根因 A：`_separate_rects` 纵向推开 **无上限**（已部分修复）

游离页矩形与 logic block 的 bbox **一旦重叠**，算法按 overlap 沿 **Y 向下推**。多轮迭代后，单页可被推到 **主簇下方数百～上千 px**。  
账户页等 **宽块 + 右侧 orphan** 时极易触发。

**修复方向**：Y 向单次推动 **封顶**（`_ORPHAN_MAX_BELOW_MAIN`）；推开后 **`_snap_orphans_beside_main`** 收回到主 nav 簇右侧窄列。

### 3.4 根因 B：居中与 `zoomToFit` 按 **全体 bbox**（已部分修复）

原先 `_center_layout_on_canvas` 对 **含离群 orphan 的全图** 算质心；Studio 再 `zoomToFit`，主簇被缩到左上角，orphan 占右下角，中间大片空白。  
**修复方向**：居中仅针对 **主 nav 连通分量 + 游离页列表**，不把「被误推远的 Y」算进焦点。

### 3.5 根因 C：数据与边

- 游离页 **长期无 nav 边**（仅 Tab 弱边未写入或未刷新 Atlas）→ 不参与 compact，只保留错误坐标。  
- **`edge.atlas.tab.*` 弱边** 依赖重启 Nexus + 刷新 Atlas；否则仍像「孤点」。

### 3.6 根因 D：与「viewport 正中心」预期差

设计文档写的是 **平移 + zoomToFit**，不是 force-directed 聚类。只要 bbox 里有一个远点，**fit 必然拉远**。

## 4. 颜色 / 线型（实现真源）

| 视觉 | 数据条件 |
|------|----------|
| 蓝 | 正向 `nav`，`meta.reverse` 假 |
| 橙 | `meta.reverse` 真（合成返回边） |
| 实线 | `transition.driver === manual`（或 unknown） |
| 虚线 | `driver === auto` 或 `system` |

**锚点**：

| driver | 架构图起点 |
|--------|------------|
| manual | 线框热点（fakeLine / NodePoint） |
| auto / system | 源页 **底边**（node border，非组件） |

---

## 5. 建议验收顺序

1. **重启 Nexus** → Studio 架构页 **刷新**（Atlas 每次 GET 重算 layout）。  
2. 看 **5 屏是否收拢** 到一簇（游离页在主簇 **右侧一列**，纵向偏移 ≤ ~128px + 行距）。  
3. 看 **manual 边** 终点是否有箭头；**虚线** 若仍无箭头，记录浏览器版本（Chrome/Safari）备 case。  
4. 账户页是否出现 **Tab 弱 nav** 蓝线（需采集里能识别多 Tab）。

## 7. Atlas 观测边过滤（2026-09-16）

**规则**：相邻采集帧 `i→i+1` 仅当 turn *i* 的 `cap_id` 属于真实设备操作时，才进入 `nav_transitions` / `edge.atlas.nav.*`。

| 允许 | 拒绝 |
|------|------|
| `tap_element` / `multi_tap` / `swipe_*` / `long_press_element` | 全部 `recover_*` |
| `press_key` 且 `action_key` 为 BACK 等 | `fsm_navigate` / `recover_fsm_navigate` |
| | 无 `cap_id` 的相邻跳变 |
| | `edge.atlas.seq.*` 补边（已移除） |
| | `edge.atlas.tab.*` Tab 全网弱边（已移除；Tab 切换需真实 tap 观测） |

实现：`nav_screen_registry._atlas_observed_nav_eligible`；`patch_turn_action` 回写 `action_key`（`press_key` 的 `params.key`）。

**注意**：旧采集若无 `cap_id`，刷新 Atlas 后边会变少——需重新跑用例采集或接受「仅展示有动作回写的帧」。
