# 9月17日 — 大模型思考和判定不一致问题

> **维护说明**：现象保留本文；**后续约束与 decision_align** 见 [`9月18日-意图识别与大模型注意力集中.md`](9月18日-意图识别与大模型注意力集中.md) §4。

**问题类型**：`agent-decide` 的 **thought** 与最终 **capability** 不一致 —— 思考里已写「本步完成，调用 signal_done」，实际下发 **press_key(BACK)**、tap 等 mutate。**样例**：`cr-6461f827b22d::case-51fef028`。

**优先级**：**P0（步进正确性）** — 比「想错」更严重：trace 显示模型 **自知应收工** 却仍改界面。

---

## 1. 现象

- Trace：`thought` 含 `signal_done` / 「本步操作完成」。  
- 同 turn dispatch：`press_key` / `tap_element` / `fsm_navigate`。  
- 后果：多余步数、误退页面、触发 action_fuse / require_do_work 循环。

---

## 2. 根因（分层）

| 层 | 说明 |
|----|------|
| 工具输出 | JSON 里 `capability` 与 prose thought 由同一采样生成，**无硬约束** 一致 |
| Prompt | thought 与 action 字段未要求「最后一行 capability 必须与 thought 结论一致」 |
| Guard 缺口 | 原先只拦 guard 列表内的 cap，不读 thought |

---

## 3. 已落地缓解

| 改动 | 说明 |
|------|------|
| `block_mutate_when_thought_done` | do 阶段：thought 匹配「signal_done / 本步…完成 / 应收工」且 cap 非 signal_* → **拒绝** mutate |
| `agent_loop` | `guard_ctx["decision_thought"] = thought` |
| `skill_defs` | do guards 增加 `block_mutate_when_thought_done`（`upgrade_run_case_sop_guards` 同步） |

拒收文案引导：`decision.status=done`，勿再发当前 cap。

---

## 4. 后续（可选）

- Planner 后处理：thought 含 signal_done 时 **强制** 改写为 `signal_done` cap（需防误触发）。  
- Console trace 高亮 thought/action **不一致** 行。  
- 统计 job 级不一致率，调 temperature / 结构化输出。

---

## 5. 验收

1. 单测：thought「调用 signal_done」+ cap `press_key` → guard **非空**。  
2. thought「继续点击发送」+ `request_sms_code` → **放行**。  
3. `case-51fef028` 复跑：同类 turn 不再 BACK 误退。
