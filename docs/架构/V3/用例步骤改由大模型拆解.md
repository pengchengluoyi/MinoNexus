# 用例步骤改由大模型拆解

> **状态**：已接入编译入口。步骤字段和导入分批见 [用例固化与控件身份](用例固化与控件身份.md)。  
> **关联**：[固化用例数据问题及页面逻辑优化](固化用例数据问题及页面逻辑优化.md) §2  
> **仓库**：后端 `MinoNexus`。提示词真源是 `llm_jobs` 里的 `case-step-compile`。  
> **要回答的事**：目录正则认不出新句式、又把认得出的句子配错事件时，拆步骤改由谁做；程序还守住哪些不能交给模型的边界。

上一份方案已经规定：编号步是作者划的边界，步内用跨度，不再按逗号切开。落地时跨度仍由目录里的 `compile_patterns` 正则产出（`compile_text_spans`）。正则就是固定字段。句式一对就过，对不上就整步不可执行；两个正则都能套上时，按优先级和长度取一条，语义错了也照样入库。

---

## 0. 拍板

| 题 | 决定 |
|---|---|
| 谁把编号步拆成事件 | `case-step-compile`。一次编号步一次调用。操作栏和预期栏都走它 |
| 模型能选什么 | 只能选本次提示词里给出的 `key_ref`，只能填该条目声明过的槽和枚举 |
| 下标谁算 | 模型交原文里的连续摘录。程序在这一段原文上定位 `[start, end)`。模型自报的下标不采用 |
| 正则还用不用 | 拆步骤不再走 `compile_text_spans`。校验失败也不退回正则 |
| 何时调用 | 保存 / 导入编译 `compile_case_step_program_keys` 时。跑批循环不调用 |
| 认不出或配错 | 整步 `coverable=false`，预览写明哪一步、哪一段、缺什么。不开跑，不改作者原文 |
| 前置栏 | 仍按「类别：要求」的结构化行解析。自由句若结构化解析盖不住，同一条编译任务处理，不另写一套词表 |

## 1. 固定字段现在的两种错

### 1.1 无法识别

正则是穷举句式。作者换一种说法，`finditer` 盖不住非空白字符，整步 `uncovered`。

例如操作写成「点一下右上方的登录入口，用邮箱验证码进去」，目录里没有这句的正则，步就不可执行。意思仍是登录块：入口、凭证、提交。

补正则解决的是这一句，下一句又落空。目录会变成句式表，而不是事件表。

### 1.2 语义配错

多个正则都能套上同一段时，选中的是优先级和长度，不是这句话在做什么。

已经碰过的配错：

| 原文 | 正则做成了什么 | 应当 |
|---|---|---|
| 预期里的「勾选…」 | 操作类句式命中，`layer_mismatch` | 留在预期层，按这条预期自己的 `key_ref` |
| 「输入手机号或邮箱验证码，完成登录」 | 曾被切成输入和另一个动作 | 一个 `operation.login_flow`，槽是凭证和提交 |
| 点击「其他」勾选框 | 角色枚举对不上就整步未识别 | `operation.tap`，`target.role=checkbox`，名称取原文 |

登录还有一段专门把兄弟命中吸进父跨度的代码。那是在正则配错之后再打补丁，新句式仍然进不去。

## 2. 模型只拆，程序只验

编号步内部仍是一整段话。标点留在原文里，不是事件边界。

一次调用的输入：

- 这一段原文
- 层：`operation` 或 `expected`（前置的自由句同样标成 `precondition`）
- 这一层目录的闭集：`key_ref`、人话名称、必填槽、槽类型、枚举、`platforms`、逻辑块 id 和槽列表

目录闭集由 `case_resource_key_catalog` 现算后塞进提示词。提示词正文不写被测 App 的按钮文案，也不写「看到某某两个字就选某事件」。

模型返回跨度，每条包含：

| 字段 | 含义 |
|---|---|
| `quote` | 原文里的连续摘录，逐字相同 |
| `key_ref` | 闭集中的一条 |
| `slots` | 逻辑块的槽。每槽有 `id` 和自己的 `quote` |
| `params` | 目录槽的值。点击是 `target.role` 与 `target.name`，刷新是可选的等待 |

登录仍是一个父跨度盖住整步，子摘录只作槽，不另起 `key_ref`。

```json
{
  "spans": [
    {
      "quote": "点击右上角登录,输入手机号或邮箱验证码, 完成登录",
      "key_ref": "operation.login_flow",
      "slots": [
        { "id": "entry", "quote": "点击右上角登录" },
        { "id": "credential", "quote": "输入手机号或邮箱验证码" },
        { "id": "submit", "quote": "完成登录" }
      ]
    }
  ]
}
```

点击：

```json
{
  "quote": "勾选「其他」",
  "key_ref": "operation.tap",
  "params": { "target": { "role": "checkbox", "name": "其他" } }
}
```

`role` 必须落在该 `key_ref` 的枚举里。名称从摘录里来，不从词表里来。

程序拿到摘录后，按出现顺序在原文里找第一处尚未占用的匹配，写成 `[start, end)`。同一摘录出现两次时，按模型给出的先后各占一处。找不到摘录，这条作废。

## 3. 校验

返回之后只做确定性校验，不再做第二次关键词匹配，也不调用 `compile_text_spans`。

1. `quote` 能在原文中定位；子摘录落在父摘录内。
2. `key_ref` 属于这一层。操作栏里选出预期事件，或预期栏里选出点击，记 `layer_mismatch`。
3. 必填槽有值，枚举合法。缺槽记 `missing_slot`，写明缺哪一个。
4. `platforms` 不含当前端，记 `platform_unsupported`。
5. 原文里除空白和 `，,。；;、` 之外，还有没有被任何跨度盖住的字，整步 `uncovered`，列出这几个字。

任一条失败：这一步 `blocked`，`coverable=false`。预览用现有 `user_message`，写明步骤号、栏、原文和原因。作者原文不动。

校验失败允许再调用一次。第二次的输入加上程序给出的原因（缺槽、层不对、摘录对不上、未覆盖的字）。第二次仍失败就停，不再重试。两次都失败时，不把模型的说明写进程序图，只留校验原因。

空返回、非法 JSON、`key_ref` 不在闭集里，都算这一次失败。

## 4. 何时调用，结果放哪

调用点是保存和导入已经在走的 `compile_case_step_program_keys`。每个编号步各调用一次。同一用例的多步可以并行，步与步之间不共享摘录。

结果仍写入现有的 `do_program_plan` / `check_program_plan` / 前置计划，`spans` 的形状与 [固化用例数据问题及页面逻辑优化](固化用例数据问题及页面逻辑优化.md) §2.2 相同。页面继续只画这份计划。

计划带上 `compiler: case-step-compile` 和当时的目录版本。原文和目录版本都没变时，保存直接复用计划，不再调用模型。

跑批只读已经落库的计划。执行循环里不拆步骤，也不因为这步认不出而临时改走正则。

Job 放在 `llm_jobs`，id 为 `case-step-compile`。启动时若没有这条 job 再种下。系统提示只写闭集、摘录、槽和「配不上就不要发明事件」。人话名称和枚举每次从目录填进用户消息。

## 5. 和现有代码的边界

| 现在 | 改成 |
|---|---|
| `compile_text_spans` 用目录正则产出跨度 | 操作栏、预期栏改由 `case-step-compile` 产出摘录，程序算下标 |
| 登录父跨度靠代码把兄弟命中吸进去 | 模型直接交一个 `operation.login_flow` 和它的槽 |
| 未覆盖或配错时没有第二来源 | 校验失败再问一次，附上原因。仍失败则整步不可执行 |
| 跑批中的看图执行 `agent-vision-exec` | 不动。那是在执行已经编译好的里程碑 |

不做的事：不恢复逗号切句；不在工作台用 `markClauses` 补事件；不把认不出的半句再拿去关键词碰；不在提示词里写某个 App 的按钮白名单；不在执行循环里补拆。

目录继续只声明「有哪些事件、每条有哪些槽」。句式正则不再作为拆步骤的依据。`compile_patterns` 可以留在目录里供对照，编译入口不读它。

已入库用例在这条 job 可用后按保存路径重编译。重编译期间页面仍认 `program_plan`，没有计划就显示未编译。
