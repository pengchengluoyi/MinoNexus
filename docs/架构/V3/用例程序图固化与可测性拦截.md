# 用例程序图固化与可测性拦截

> **状态**：方案。代码按本文改；导入预览可入库，执行前按可测性拦截。  
> **关联**：[用例密钥-操作与预期映射方案](../V2/用例密钥-操作与预期映射方案.md)、[用例执行-程序图专注与异常栈方案](../V2/用例执行-程序图专注与异常栈方案.md)、[里程碑-Plan-Exec-状态机](../V2/里程碑-Plan-Exec-状态机.md)、[步骤准出与登录态](../V2/步骤准出与登录态方案.md)、[扩展能力优化](../V2/扩展能力优化.md)、[开发手册](../../开发手册.md) §5  
> **要回答的事**：操作/预期如何像前置一样固化成可执行事件；导入要不要等人确认；哪些字段表示可测；知道测不了为什么还跑；异常时插打断还是改主路径；绑定缓存是什么。

固定场景里看图规划几乎写出同一条路，却每轮付一次模型和一次偏航。本文把用例从「一段说明文」改成「编译好的意图图」：导入时拆成可审的 `steps[]` 并直接落盘，执行时按图走看图执行（这时才出坐标），规划只在主路径被意外 UI 挡住时插打断。任意一步写不到当前能做的具体事件，整条用例在开跑前拦截，不烧时间和 token。

## 0. 拍板

| 题 | 决定 |
|---|---|
| 固化什么 | **意图图**（事件 / 逻辑块 / 检查点）。坐标、当次树、当次里程碑状态不进用例 |
| 坐标何时产生 | 仅看图执行（或 DOM 命中）当场出。生产环境里预存坐标不可靠 |
| 空间词（右上角、底部） | 点击事件的 **辅佐参数**，只给执行消歧，不是步骤身份 |
| 导入 | 预览拆分结果后 **直接入库**。不做人审闸门。拆分质量用后续跑批验证 |
| 拆不到具体事件 | 整条用例标成 **无法 UI 自动化**，写明哪一步哪一句。开跑前拦截，不「半自动看图规划」逞强 |
| 可做 / 不可做 | 以 **当前** 自动化能力为准。现在做不了就标不可做。不另开「能做但还没做」的产品债态 |
| 可测字段 | **不用** `lifecycle`。目录加 `ui_coverable`。`lifecycle` / `enabled` / `status` 各管各的，见 §5 |
| `enabled=false` / `deprecated` | 模型菜单和 **程序派发** 都拦。删掉启动时把 `relogin` 草稿改回启用的特例 |
| 前置死板 | 去掉编译器里的中文正则硬匹配。前置 / 操作 / 预期走同一条「目录编译 → 种子 → 执行」流水线，新事件只加目录 |
| 登录态 | 接口 > 当前屏已能证明 > 测试资源。 **禁止** 靠点击「我的」或任何元素来证明 |
| 异常 | 主路径不改。已知挡屏走目录 `kind=recovery` 规则；未知挡屏走 **interrupt 栈**。不把这条叫 recovery，避免和扩展包 kind 撞名 |
| 动态元素 | 位置、颜色、大小会变的，步骤标 `observe=visual_each_run`，执行时必须看图。不进绑定缓存 |

开发手册 §5.3 已按本节改：有程序图则程序种子，规划不得改业务边。

## 1. 目标与非目标

### 1.1 要对上的失败

| 现象 | 根因 |
|---|---|
| 同屏登录每次规划几乎一样，却又慢又会写歪 | 操作/预期没有像前置那样种子，每轮让规划当作者 |
| 前置加新事件要改 Python 正则 | `_LOGIN_FLOW_RE`、`classify_precondition_title` 把中文标题写进编译器 |
| 导入只存一大段 instruction | 编译产物没有成为跑批真源 |
| 执行中才发现某句测不了 | 可测性只在 telemetry 里，开跑没有闸 |
| `relogin` 标了草稿仍被程序跑通 | `enabled` / `lifecycle` 只过滤菜单，拦不住程序派发；启动脚本还会把草稿改回启用 |
| 规划在失败时「另找一条路」 | 把缺陷执行成另一条故事 |

### 1.2 做成什么样

1. 导入后每条用例带齐前置 / 操作 / 预期的程序图；原文只用于展示和打断时的窄上下文。
2. 开跑前就能回答：能否 100% UI 自动化覆盖；不能的话是哪一步哪一句、对应哪个事件。
3. 能覆盖的用例：有图则跳过看图规划，逐步看图执行；动态步每轮看图；坐标不当场不写进用例。
4. 不能覆盖的用例：任务里直接拒绝启动，Studio 标明原因。

### 1.3 明确不做

- 不在用例上存点击坐标、截图锚点、当次 hierarchy。
- 不把 fallback 原文当成「半自动还能跑」。
- 不在产品里维护「技术上能做、我们还没做」的第三态。
- 不用点击某个控件证明登录态。
- 不让看图规划重写已种子的业务顺序和 id。
- 不在编译器里加被测 App 文案或中文白名单（见仓库 `no-app-keywords`）。

## 2. 三层数据

用例不是一份大 JSON 什么都塞。三层职责不同，写错层就会把某一次跑批冻成「用例定义」。

```text
作者层     编号原文（前置 / 操作 / 预期）     给人看；打断时给规划看一句
编译层     *_program_plan（意图图）           跑批主路径真源
绑定层     上次成功的节点指纹（可选缓存）     加速执行，不是用例身份
```

| 层 | 存什么 | 存在哪 | 何时写 | 禁止 |
|---|---|---|---|---|
| 作者 | `precondition` / `instruction` / `expected` 原文 | 现有用例字段 | 导入、编辑 | 把程序图删掉只留原文当执行依据 |
| 编译 | `prep_program_plan`、`do_program_plan`、`check_program_plan` | `case.meta.resource_key`、`case.meta.step_program_keys` | 导入/保存时编译 | `x`/`y`、bounds、截图 |
| 绑定 | 意图 → 节点指纹 / `match` 表面形式 | **跑次或设备侧缓存**，不进 case 定义 | 某次 exec 成功之后 | 把缓存当断言真源；动态步写入 |

`do_program_plan.steps[]` 形态与现方案一致，只强调没有坐标：

```json
{
  "schema": "mino.do_program_plan.v1",
  "case_step": 1,
  "steps": [
    {
      "id": "do_s1_tap_login",
      "key_ref": "operation.tap_login_entry",
      "title": "点击登录入口",
      "kind": "visual_action",
      "hook_cap": "tap_element",
      "params": { "spatial_hint": "top_right" },
      "observe": "exec",
      "source_clause": "点击右上角登录"
    },
    {
      "id": "do_s1_login_block",
      "key_ref": "operation.login_flow",
      "title": "完成登录",
      "kind": "flow_block",
      "block_id": "fb.global.login",
      "observe": "exec",
      "source_clause": "输入手机号或邮箱验证码，完成登录"
    }
  ]
}
```

`observe`：

| 值 | 含义 |
|---|---|
| `exec` | 稳定入口。跳过规划，看图执行（或 DOM）当场出落点 |
| `visual_each_run` | 动态元素。每轮必须看图；不写绑定缓存 |
| `program` | 本地钩子（租号、取码、清缓存、登录态接口），不看图 |

空间提示只出现在 `params.spatial_hint`。同屏多个相似控件时，执行器用它选更近的那一个。布局变了提示失效，最多点错一次，不会把「右上角」冻成用例身份。

### 2.1 绑定缓存是什么

固化的是「要点登录入口」，不是「上次点在 (0.83, 0.12)」。

看图执行每次都要根据 **当前屏** 算出坐标或节点。这个落点只对这一帧屏幕成立：分辨率、状态栏、A/B、多语言都会让它失效，所以不能进 case。

绑定缓存是可选的加速层，记住的是 **指纹** 而不是像素：

- DOM：上次命中的稳定属性（resource-id、role、整词文案），外加语义层的 `match` / `exclude`
- 视觉：意图 id + 空间提示；坐标本身仍当场算

下次执行同一意图时：指纹在当前树上唯一命中，可以少一次看图；没命中或当前步是 `visual_each_run`，丢掉缓存，走看图执行。缓存写在跑次 / 设备侧，人在 Studio 改用例文案或程序图版本变化时作废。

这和 Midscene 的 plan/XPath cache、Mabl 的元素模型同一类：加速重复跑，不是测试定义。缓存命中失败必须回退到当场观察，禁止用旧坐标硬点。

## 3. 编译：目录驱动，去掉死板正则

前置、操作、预期 **对称的是流水线**，不是粒度。前置编译资源态和程序钩子；操作编译 UI 意图序列；预期编译检查点。三者都是：文案 → 目录条目 → `*_program_plan` → 跑批种子。

### 3.1 现在为什么死板

| 位置 | 问题 |
|---|---|
| `case_step_key_compiler._LOGIN_FLOW_RE` | 「完成登录 / 验证码登录」等中文写进编译器，命中才挂 `fb.global.login` |
| `loop/step_contract._LOGIN_FLOW_RE` | 更宽的「登录\|验证码\|短信」正则，后续扩展只能继续堆词 |
| `account_requirement_compile.classify_precondition_title` | 「设备登录态 / 账号与数据 / 环境与权限」标题白名单；新类别进不来 |
| `prep_program_plan` | 固定 `pick_account → pick_device → env_cleanup → 打开应用`，新前置事件要改 Python |

后果：只能识别写死的那几句；别的前置事件无法接收；每加一种说法就改代码，和导航铁律（不硬编码被测文案）同一类债。

### 3.2 改成目录扩展

编译器 **不再** 用中文正则猜业务。匹配顺序固定为：

1. 显式 `operation.*` / `expected.*` / 前置 `key_ref`
2. `【块:block_id】` / `【导航:screen_id】` / `【cap:capability_id】`
3. 目录 `write_examples`、`dsl`、`expands_to`（最长命中）
4. 导入 Job 输出的结构化 `steps[]`（id、key_ref、kind、hook_cap、params）
5. 仍匹配不上 → 该子句 **未映射**，见 §6，不写 `operation.generic` 去跑规划

新事件、新前置类别、新登录说法：Console 加目录条目或逻辑块，`write_examples` 带上作者会写的句子。编译器零改动。登录块仍由 `key_ref` / 块 id 挂上，不靠「完成登录」四个字。

导入 Job（拆分模型）的词表 = 当前 **可用且可覆盖** 的事件（§5.4）。模型只许在这张表里选。选不出来就对该子句打 `unmapped`，不要发明 cap，也不要输出坐标。

前置同样从编号行编成 `prep_program_plan.steps[]`，步骤来自目录，而不是代码里的四段模板。登录态那一行仍编成 `confirm_login_state` / `inspect_session` 这类 **程序钩子**，不编成「去点我的」。

### 3.3 登录态怎么证明

沿用 [步骤准出与登录态](../V2/步骤准出与登录态方案.md) 三级来源，本文再钉死一条：

**绝对不能通过点击某个元素来证明已登录或未登录。**

Web 读 Cookie / storageState；安卓有应用接口就走接口；没有接口时，只有 **当前屏已经能证明** 才写结论。当前屏证明不了，采用测试资源里的设备登录态，并在当步结论里记下「屏上未能证明」。禁止为了确认登录态去点「我的」、个人页或任何入口。

### 3.4 一行原文可以对应多条事件

「点击右上角登录，输入手机号或邮箱验证码，完成登录」是两条（点入口 + 登录块），不是把整段前置那样压成一步。拆分由 Job + `expands_to` / 逻辑块完成。块内步骤仍由 `nav_flow_block_catalog` 展开，编译器不把块内步再拆进用例行。

## 4. 导入：预览后直接入库

导入路径保持「解析 → 预览 → commit」，但 **commit 不再要求人确认每一步拆得对不对**，也不再用拆分质量拦住入库。

| 步骤 | 行为 |
|---|---|
| 预览 | Studio 展示每条用例拆出的 `steps[]` / `checkpoints[]`、未映射子句、`ui_coverable=false` 的命中。人可以看一眼 |
| 入库 | 选中的行直接写入。程序图、原文、§5.3 的 `ui_automation` 一并落盘 |
| 不入库闸 | 取消默认 `block_on_step_key_issues` 拦导入。拆坏了的用例先存下来，用后续执行效果看模型拆分质量 |
| 执行闸 | 见 §6。`ui_automation.coverable=false` 的用例不能进跑批 |

坐标字段在编译出口丢掉。Job 若误吐 `x`/`y`，Nexus 不落盘。

保存用例（人工编辑）走同一套编译，覆盖 `step_program_keys`。

## 5. 字段：可测、生命周期、开关分开

### 5.1 现在三个字段各自在做什么

目录行上你看到 `"enabled": false, "lifecycle": "deprecated", "status": "deprecated"` 是 **同一事实写了三遍**，不是三种业务含义。

| 字段 | 真源 | 含义 | 谁改 |
|---|---|---|---|
| `lifecycle` | `catalog_entries.lifecycle` | 资产生命周期：`draft` / `active` / `deprecated`。软删除写成 `deprecated` | 扩展包管理员 |
| `enabled` | `catalog_entries.enabled` | 运行开关。紧急关掉但仍未下线 | 管理员 |
| `status` | **不是表字段** | `rPacks._ui_status()` 派生给 Console：disabled 或 deprecated → `deprecated`；draft → `pending`；否则 `active`。写入时 `status` 再映射回 `lifecycle+enabled` | UI |

菜单过滤已经看 `enabled=false` 或 `lifecycle=deprecated`。程序派发没有完全遵守：`capability_enabled()` 只在逻辑块 runner 里用；启动时 `_stamp_dispatch_caller` 还会把 `relogin` 的草稿改回 `enabled+active`。所以管理员以为关了，程序仍能跑。

这三项 **都不回答**「这个事件能不能拿来做 UI 自动化覆盖」。`active` 的「好不好看」仍然不可测；`deprecated` 的 `tap_element` 仍然是可测动作，只是下线了。

### 5.2 新字段 `ui_coverable`

加在 `catalog_entries`（布尔，默认对现有真正能跑的 generic/check 为 `true`）。

问的是：**以当前产品能力，这条事件能否计入「UI 自动化 100% 覆盖」。**

| 值 | 含义 | 例子（说明用，不是白名单） |
|---|---|---|
| `true` | 现在就能派、就能判 | 点、输入、滑动、长按、按键、等待、导航、登录块、元素是否存在、文案、计数、当前屏 |
| `false` | 现在不能当作自动化覆盖 | 动画流畅度、性能体感、视觉审美，以及目录里尚未实现因而不能派的动作 |

没有第三态「能做但还没做」。现在派不出去的，就 `false`。以后做了，把实现补上并把该行改为 `true`。

预期侧若需要更细，可在 payload 里保留 `oracle_class`：`programmatic` / `vlm` / `human_only`。`human_only` 必须 `ui_coverable=false`。产品对外仍只展示可做 / 不可做。

不可用 **不单开字段**，由已有两个字段推导：

```text
不可用 = enabled==false 或 lifecycle==deprecated
不可做 = ui_coverable==false（且仍然可用，才会出现在「识别出来但测不了」里）
可做   = 可用 且 ui_coverable==true
```

| 对外三态 | 怎么来 | 进拆分词表 | 进模型菜单 | 程序派发 | 用例编译命中后 |
|---|---|---|---|---|---|
| 可做 | 可用 ∧ `ui_coverable` | 是 | 按 `caller` | 是 | 该子句可覆盖 |
| 不可做 | 可用 ∧ ¬`ui_coverable` | **否**（见下） | 否 | 否 | 整案不可覆盖，写明子句 |
| 不可用 | deprecated / disabled | 否 | 否 | 否 | 不该被命中；若旧图仍引用，整案不可覆盖，提示换新事件 |

「不可做」可以出现在预检报告里（好让人看懂「这句话我们认识，但当前不能测」），但 **不必传给拆分模型**。拆分模型只看见可做事件。模型若把审美句硬套到可做的 `assert_visual`，预检按原文规则仍可标不可做；优先靠目录 `write_examples` 把这类句子指到 `ui_coverable=false` 的检查点类型，编译直接判不可覆盖。

`status` 继续当 Console 投影，不必存第三列。可做/不可做用 `ui_coverable` 另画，不要塞进 `status`。

### 5.3 用例上的派生结果

`case.meta.ui_automation`（编译时写，开跑时只读）：

```json
{
  "schema": "mino.ui_automation.v1",
  "coverable": false,
  "blocked_by": [
    {
      "phase": "check",
      "case_step": 2,
      "source_clause": "动画过渡是否流畅",
      "reason": "uncoverable_event",
      "event_id": "assert_motion_smooth"
    }
  ]
}
```

| `reason` | 何时 |
|---|---|
| `unmapped` | 子句写不到任何具体事件 |
| `uncoverable_event` | 写到了 `ui_coverable=false` 的事件 |
| `unavailable_cap` | 程序图仍引用已下线/关闭的事件 |

一条 `blocked_by` 就够把整案 `coverable` 打成 `false`。不存在「部分步骤半自动」。

### 5.4 拆分词表

给导入 Job / 拆分模型的事件列表同时满足：

- `enabled=true`
- `lifecycle=active`
- `ui_coverable=true`
- 本阶段允许（`phases` 含 prep/do/check）

不可用、不可做的事件都不进词表，避免模型选到后还要事后作废。

### 5.5 `enabled` 必须拦住程序派发

落地时改三处，和 [扩展能力优化](../V2/扩展能力优化.md) §3.1 对齐：

1. 所有派发入口（看图执行、逻辑块钩子、本地执行器、`relogin` 内部再派）先 `capability_enabled()`。未启用或已废弃 → 不派，记 `guard/block`，原因 `capability_disabled`。目录没有该行时：逻辑块仍走自己的函数则保持现状并补目录行；其余视为未注册，不派。
2. 删除 `_stamp_dispatch_caller` 里「`relogin` 是草稿就改回启用」的特例。草稿就是不能跑。
3. 菜单过滤与程序派发读同一函数，不再只滤菜单。

## 6. 执行前拦截

已经知道某一步测不了，再开跑只浪费墙钟和 token。执行中标红没有产品意义。

| 时机 | 行为 |
|---|---|
| 导入 / 保存 | 写 `ui_automation`，Studio 按步展示。 **不拦入库** |
| 新建执行选用例 | `coverable=false` 的用例不可勾选，或勾选后提交被拒。文案带出 `blocked_by` 的步骤和原句 |
| `POST /case-runner/run` | 再次校验。整案拒绝启动，不创建成功跑批会话去空转。返回与 Studio 同一份原因 |
| 跑批过程中 | 不再用「这步 fallback、其余继续」；闸门在开跑前已经关掉 |

拦截文案固定为：无法 UI 自动化测试 + 第几步 + 那句话 + 原因（未映射 / 当前不能做的事件 / 事件已下线）。

人工在 Studio 改原文或补目录后重新编译，`coverable` 变 true 才能跑。

## 7. 跑批：有图则执行，规划只插打断

### 7.1 主路径

```text
读 case.meta.ui_automation → 不可覆盖则拒绝启动
进入 phase → 程序种子 *_program_plan 为 milestones
有 in_progress：
  observe=program      → 本地钩子，不看图
  observe=exec         → 跳过 vision-plan，vision-exec（或 DOM）当场出落点
  observe=visual_each_run → 本步看图执行；不写绑定缓存
工具 pass/fail 由程序写回焦点
最后一条终态且 exit_allowed → 阶段流转
```

有程序图时，看图规划 **不得** `milestones_append` 新业务边（已有 `plan_append/rejected`）。原文不进执行 Job 当任务作者，只在打断的窄上下文里出现。

动态步（信息流卡片、搜索结果、颜色尺寸会变的控件）在编译时标 `visual_each_run`。这不是「没固化」，是固化了「每轮必须观察」。

### 7.2 主路径被挡住：打断，不改路线

异常不是让规划另写一条用例。主图 step id 不变。

命名：扩展包 `kind=recovery` 仍专指目录里的 L0 规则和恢复原子（点亮屏幕、解锁、拉回前台）。主路径上的未知挡屏叫 **打断（interrupt）**，代码沿用已有 `interrupt_stack`，避免和 kind 撞名。

| 层 | 谁 | 做什么 |
|---|---|---|
| 已知挡屏 | `kind=recovery` 规则 | 命中即派 cap，不改 `do_program_plan` |
| 编译期可选 | `optional: true`、已在目标屏则 skip | 主图里早已声明 |
| 未知挡屏 | interrupt 栈 | 压入短序列（关掉挡层、返回、等待），做完 pop，回到原来的 `in_progress` |
| 仍过不去 | 本步失败 / HITL | 规划不得发明新的业务步骤 |

看图规划在这一节只允许 **窄范围**：给当前打断插恢复步，thought 必须「虽然…，但是…」。禁止重排、禁止删已有 id、禁止把登录改成另一条账号通道当「新路线」。

同一意图连续成功打断并稳定后，Studio 可提示「收进逻辑块或 optional 边」——人工确认才写回目录，默认不改用例。这是绑定缓存之外的 **晋升**，不是静默改主路径。

## 8. Studio / Console

| 面 | 做什么 |
|---|---|
| 导入预览 | 每步 events、未映射句、不可做事件。不强制人改完才能入库 |
| 用例详情 | 原文 + 程序图并列。不可覆盖的子句点亮，展示 `blocked_by` |
| 新建执行 | 不可覆盖的用例不能开跑，原因在选用例时就看见 |
| 扩展包 | 事件上分开展示：生命周期（`status` 投影）、启用开关、`ui_coverable`（可做/不可做）。不要合成一个下拉 |
| 跑批时间线 | 区分 `replay`（按图执行）、`interrupt`（打断）、`heal_skip`（本步动态看图）。规划次数应接近零（动态步和打断除外） |

## 9. 指标

以 `session_events` 为准，不写 pytest。

| 指标 | 用来证明 |
|---|---|
| `ui_automation` 拦截次数（未开跑） | 闸门在执行前，而不是跑到一半标红 |
| 单案 `agent-vision-plan` 次数 | 稳定步应降到接近 0；剩下的应能对上 `visual_each_run` 或 interrupt |
| 绑定缓存命中 / 未命中 / 禁止写入 | 缓存只加速，动态步为 0 写入 |
| `plan_append/rejected` | 规划没有改业务边 |
| `interrupt/push` / `pop`、打断后是否回到原焦点 | 主路径没被改写 |
| `guard/block` `capability_disabled` | 关闭的事件程序也派不出去 |
| 拆分后首次跑通率（按导入批次） | 评估 Job 拆分质量，而不是用导入闸门赌 |

## 10. 落地顺序

全仓仍只分 P1 / P2。

| 档 | 内容 | 验收 |
|---|---|---|
| **P1** | 目录加 `ui_coverable`；编译写 `case.meta.ui_automation`；开跑拦截；导入预览后直接入库 | 不可做/未映射的用例 `POST /case-runner/run` 被拒，session 不出现；可覆盖用例能入库 |
| **P1** | 有 `do_program_plan` / `check_program_plan` 则种子；规划禁止改业务边；稳定步只走 exec | 同登录主路径规划次数明显下降；`plan_append/rejected` 可查 |
| **P1** | 派发口统一 `capability_enabled`；删 `relogin` 草稿改启用 | 目录关掉后程序不再派该 cap |
| **P1** | 去掉编译器登录/前置标题硬匹配，改为目录 `write_examples` + Job `steps[]` | 新前置事件只加目录就能编进 `prep_program_plan` |
| **P2** | 绑定缓存（指纹，不含坐标）；`observe=visual_each_run`；打断晋升提示 | 动态步无缓存写入；打断 pop 后焦点不变 |
| **P2** | Studio 按步亮灯、扩展包三列字段、跑批 `replay/interrupt` 标记 | 选用例时就能看见不能跑的原因 |
