## 1. 任务详情

### 1.1 用例详情（三栏 / 轨迹 / 日志）

入口：`MinoWorkbench` `CaseRunView`。现在右上角只有「三栏 / 轨迹」。点三栏徽章时，截图要跟轨迹那一步走，这条已经按顺序对过；本节补状态颜色、用例 ID、日志。

#### 1.1.1 五种状态色

三栏里的每个徽章、轨迹表的每一行，用同一套底色。颜色只看这一步的执行状态。

| 状态 | 含义 | 视觉 |
|---|---|---|
| `pass` | 这一步已经做完且通过 | 淡绿底，字用通过色 |
| `skip` | 这一步明确跳过（无法执行、守卫跳过） | 灰色字，删除线。样子接近飞书文档里勾完的待办，不要再铺一块亮底 |
| `retry` | 这一步失败后重试过。重试后通过也保留黄色，方便看出曾经不稳 | 淡黄底 |
| `fail` | 失败且没有再跑过 | 淡红底 |
| `pending` | 还没执行到 | 深灰字，无彩底。和跳过分开：跳过是决定不做，未执行是还没轮到 |

前端用现有 token，不新写一套色值：通过 `--w-pass-bg`，失败 `--w-fail-bg`，重试 `--w-warn-bg`，跳过和未执行只用中性灰，靠删除线和字重区分。

后端给每个轨迹步、每个编译步一个闭集字段 `ui_status`，取值只允许上表五个。原始字符串（`give_up`、`declined`、`guard_skip`）留在 `status`，页面不再自己猜。重试的判定在执行器：同一 `step_id` 出现第二次及以后，该步 `ui_status=retry`，即使最后一次是通过。

没有 `ui_status` 的旧跑批，前端只把能确定的 `pass` / `fail` 画出来，其余当 `pending`，不把空状态画成通过。

#### 1.1.2 用例 ID

用例详情顶栏，标题右边放 `case_id`，等宽字体。旁边一个复制按钮，复制纯 id，不含标题。成功用现有 toast「已复制」。失败 toast 写明剪贴板不可用。

`case_id` 已经在任务用例行上，这一项前端就能做。

#### 1.1.3 日志

分段控件改为三项：`三栏`、`轨迹`、`日志`。日志不是第四套时间线。

- 有 `session_id`：内嵌现有 `SessionDetail`（回合、事件、LLM），和 Session Log 页同一组件。
- 没有 `session_id`：空态写「这次执行没有 session」，不要用任务 id 冒充 session 再打一串 404。

后端在任务用例结果上带回 `session_id`。现在前端用 `report_run_id` 或 `任务id::用例id` 去拉轨迹，这和 Session Log 的 session 不是同一个标识，日志页不能继续猜。

### 1.2 批次详情（任务详情，还没点进某一条用例）

入口：`TasksPanel` 点开一个批次之后的那一屏。

| 缺什么 | 放哪 | 谁提供 |
|---|---|---|
| 任务 ID | 标题下，等宽，可复制。复制的是 `task_id` / `run_id`，和列表里点进去的那个相同 | 已有。前端展示 |
| 任务总耗时 | 任务 ID 旁边。`finished_at - started_at`。还在跑则显示「已进行 Ns」并用 `started_at` 到现在 | 已有起止时间。跑中的「已进行」前端算 |
| 每条用例耗时 | 用例表增加一列「耗时」 | 后端每条用例结果加 `duration_ms`。没有起止时间时不要用 0 假装很快 |

总耗时是整批墙钟时间，不是各用例相加。并行时相加会大于总耗时，两列都保留，不互相换算。

## 2. 固化用例：识别必须重做

### 2.1 现在错在哪

两处都在用「先切开，再找词」。

后端 `case_step_key_compiler.split_clauses`：编号步内部再用 `_COMPOUND_SPLIT`（`；` `;` `。` `，` `,` `然后` `并`）切成短句，然后 `_match_catalog_clause` 用目录示例做子串最长命中。

前端 `markClauses`：按逗号切开，再用「点击 / 输入 / 文案检查」等前缀当事件。用例列表、用例预览、任务三栏在编译结果缺失时会走这条。所以页面上看到的「2 输入…、3 完成登录」是展示层自己拆的，不是程序图。

这解释三条例子：

| 用例 | 作者在说什么 | 现在 | 应当 |
|---|---|---|---|
| `case-65ddf812` | 同一登录步里的「输入手机号或邮箱验证码」和「完成登录」 | 被切成输入事件和又一个动作 | 一个 `operation.login_flow`。两句是这个逻辑块的槽：凭证、提交 |
| `case-1e1d4846` | 操作全是点击某类控件、输入某内容 | 词表对不上「元素 / 按钮 / 图片 / 勾选框 / 开关」，整步未识别 | 事件仍是点击或输入。缺的是参数：点谁、输入到哪 |
| `case-29179750` | 浏览器刷新，以及刷新要等多久 | 「刷新」没被当成页面重载，时间更没有进参数 | `operation.reload_page`，仅 Web。耗时或等到何种状态是该事件的参数 |

预期栏是同一套编译器，错法相同：该合成一个检查的两句被逗号切开；该带元素和规则的检查只剩一个动词。

### 2.2 步内跨度，而不是切句

作者层唯一允许的硬边界是**他自己写的编号**（`1.` `2.`）。编号步内部是一整段话。标点是句子的一部分，不是事件边界。

一段编号步交给一次编译，输入和输出都是结构，不是词表。

输入：

- 这一段的原文，带字符下标
- 这一栏的层：`precondition` / `operation` / `expected`
- 当前目录里这一层允许的 `key_ref`，以及每个 `key_ref` 的参数槽（必填、类型、枚举）
- 逻辑块定义：块 id、槽列表。登录块的槽是凭证和提交，不是「看到登录两个字」

输出：若干**跨度**。每个跨度是原文上的 `[start, end)`，加上 `key_ref` 和填好的槽。跨度可以嵌套。登录是一个父跨度盖住整句，两个子跨度分别盖住「输入手机号或邮箱验证码」和「完成登录」，子跨度的 `key_ref` 不是独立操作，而是 `slot=credential` 和 `slot=submit`。

```json
{
  "case_step": 1,
  "source": "输入手机号或邮箱验证码，完成登录",
  "spans": [
    {
      "start": 0,
      "end": 18,
      "key_ref": "operation.login_flow",
      "block_id": "fb.global.login",
      "slots": [
        { "id": "credential", "start": 0, "end": 13, "text": "输入手机号或邮箱验证码" },
        { "id": "submit", "start": 14, "end": 18, "text": "完成登录" }
      ]
    }
  ]
}
```

点击的目标同样是槽，不是把「按钮」写进事件名：

```json
{
  "key_ref": "operation.tap",
  "params": {
    "target": { "role": "button", "name": "登录" },
    "spatial_hint": "top_right"
  }
}
```

`role` 只能是该 `key_ref` 在目录里声明的枚举。点击至少要覆盖：元素、按钮、图片、勾选框、复选框、开关。输入至少要有输入目标（输入框或字段名）和输入内容来源（原文常量，或绑定上一步）。刷新至少要有 `platforms: ["web"]`，以及可选的等待参数（毫秒或直到某个稳定条件）。枚举加在目录，不写进编译器的中文正则。

没填上的必填槽：这一跨度 `blocked`，原因写明缺哪个槽。整段编号步有未覆盖的字符区间：这段 `blocked`，原因是「这几个字没有落进任何事件」。不要把未覆盖的半句再拿去关键词碰运气。

### 2.3 谁来产出跨度

一次编号步一次编译任务，任务只能从目录里选 `key_ref`，只能填目录声明过的槽。产出跨度的是 `case-step-compile`，不再用目录正则。摘录、校验和失败时不退回正则，见 [用例步骤改由大模型拆解](用例步骤改由大模型拆解.md)。

返回之后只有确定性校验，不再做第二次关键词匹配：

1. 下标落在原文内，子跨度落在父跨度内。
2. `key_ref` 属于这一层的目录。不属于则是 `layer_mismatch`（预期里写出了点击，或操作里写出了置灰）。
3. 必填槽都有值，枚举合法。
4. `platforms` 不含当前端（刷新写在非 Web）则这段不可执行。
5. 未覆盖区间非空则整步不可执行。

校验失败就保持原文，程序图标记 `coverable=false`，预览写明哪一步、哪一段原文、缺什么。不开跑。人不在预览里点采纳，程序不改作者原文。

工作台、导入预览、任务三栏：**只画这份跨度**。没有程序图就只显示原文，并标「未编译」。前端不再调用 `markClauses`。

### 2.4 和已有方案的关系

事件身份和参数分开、看图与 DOM 不互相改写、一句做不了整案不开跑，仍按 [指标和事件参数](指标和事件参数适配用例%20及%20纠正用例中错误调用.md)。本文替换的是它里面还默认「逗号可以切开复合句」的那一段，以及编译器里 `_COMPOUND_SPLIT` 的实现。

登录块、点击、刷新的槽位补进 `case_resource_key_catalog`。编译入口仍是 `compile_case_step_program_keys` / `case_clause_events`。`split_clauses` 删掉标点分支，只保留编号步切分。

已入库用例要重编译。重编译期间页面认 `program_plan`，没有计划就显示未编译，不用旧的逗号拆分顶上。

## 3. 新建执行：选用例

弹窗在 `CreateTaskDialog`。用例数据已经有 `title`、`module`、`case_id`，不新开接口。

- 每一行同时显示标题和 id。标题是主字，id 是次要等宽字。只有 id、没有标题时才单显示 id。
- 按 `module` 分组。组标题就是模块名，空模块归到「未分组」。组内按标题排序。
- 筛选框同时匹配标题、id、模块名。
- 勾选状态仍只提交 `case_ids`。分组不影响下发字段。

## 4. 管理后台

布局已经是 `AdminLayout`，颜色应走工作台 token。现在能力页大多是 `Planned` 占位，本期把占位换成能用的页。知识审核（`/knowledge`）保持占位。

### 4.1 用例密钥和转移规则：页面合，数据不合

两者现在难懂，是因为两个菜单各说各的，没有写明先后。

| | 用例密钥 | 转移规则 |
|---|---|---|
| 问题 | 这句话能编译成哪种事件，参数槽是什么 | 某个触发发生后，账号、设备、验证码这些资源要怎样变 |
| 何时用 | 导入编译、开跑前可测性 | 跑批过程中 |
| 存在哪 | 目录 `case_resource_key_catalog`，接口 `GET /settings/case-resource-key` | 表 `ResourceTransitionRule`，接口 `GET /settings/resource-transition-rules` |
| 能不能写成同一行 | 不能。一条点击定义和「登录成功后释放手机号」不是同一条记录 | |

页面合成一个路由 `/case-resource`（旧的 `/case-resource-key` 和 `/resource-transition-rules` 重定向过来）。

- 第一区「事件」：按层（前置 / 操作 / 预期）列 `key_ref`、人话名称、参数槽、支持的端、支持的看图或 DOM。点一条能看到它的槽是否必填。登录块在这里能看到两个槽，而不是两条事件。
- 第二区「跑起来之后」：转移规则。每条写触发、端、效果、是否启用。若效果引用了某个 `key_ref`，旁边能跳到第一区的那一条。没有引用就不要假装它属于某个事件。

存储仍是两套。本期规则只做启用、文案、看清效果。不在这个页上发明新的效果类型。

### 4.2 能力（知识审核除外）

沿用管理后台左侧「能力」分组，一项一页，不把 1600 行的旧技能页原样搬过来。

| 页 | 路由 | 这一版要能做的事 | 已有接口 |
|---|---|---|---|
| 技能 | `/skills` | 列表、看一条、新建、改基本信息和正文 | `GET/POST /settings/ai/skills`，`PUT /settings/ai/skills/{id}` |
| Jobs | `/jobs` | 列表、健康、看一条、改、预览 | `GET /settings/ai/jobs`，`GET .../health`，`PUT`，`POST .../preview` |
| 角色 | `/roles` | 列表、看提示词、改提示词 | `GET /settings/ai/roles`，`PUT .../prompt` |
| 编排 | `/stack` | 看当前栈、保存 | `GET/PUT /settings/ai/stack` |
| 扩展包 | `/packs` | 列表、启用或停用、看包里有哪些能力 | 缺列表契约时后端先补只读列表，前端不先画空表 |

聊天调试（`POST /settings/ai/roles/chat`）本期不做，避免角色页又变成一个对话框。

## 5. 两人怎么拆

接口先定，两边同时开工。下表「阻塞」是指没有该字段时前端如何降级，而不是停工。

### 5.1 后端（Nexus）

| 序号 | 做什么 | 落点 | 交出什么 | 前端没有它时 |
|---|---|---|---|---|
| B1 | 轨迹步和编译步增加 `ui_status` | 任务详情、轨迹投影 | `pass` `skip` `retry` `fail` `pending` | 只上色 pass/fail，其余当未执行 |
| B2 | 用例结果增加 `session_id`、`duration_ms` | 任务用例行 | 两个字段，毫秒整数或空 | 日志空态；耗时列显示「无」 |
| B3 | 删掉标点切句 | `split_clauses` | 只按编号步切开 | 前端不再依赖切句结果 |
| B4 | 步内跨度编译 + 确定性校验 | `case_step_key_compiler`、`case_clause_events` | `spans[]` 进 `do_program_plan` / `check_program_plan` / 前置计划 | 页面只显示原文和「未编译」 |
| B5 | 目录补槽 | `case_resource_key_catalog` | 点击的 `target.role` 枚举；登录块两槽；`operation.reload_page` 与等待参数；仅 Web | 编译任务无槽可填，相关句保持未编译 |
| B6 | 重编译已有用例 | 导入保存同一条路径 | `case-65ddf812`、`case-1e1d4846`、`case-29179750` 的计划与 §2.1 表一致 | 这三条在页面上仍是未编译 |
| B7 | 转移规则只读字段补全 | `GET /settings/resource-transition-rules` | 效果列表里若有 `key_ref` 就原样返回 | 规则页只能显示触发和开关 |
| B8 | 扩展包、逻辑块缺的只读列表 | 现有路由不够时补 GET | `{id, name, enabled}` 级别即可 | 对应页显示「接口未就绪」而不是假数据 |

B3、B4、B5、B6 是一条线，按这个顺序做。B1、B2、B7、B8 互不依赖，可与编译器并行。
