# 指标和事件参数适配用例 及 纠正用例中错误调用

> **状态**：方案。代码按本文改；先扩目录与编译参数，再改校验执行。不实现前不改 Job 词表以外的 prompt。  
> **关联**：[用例程序图固化与可测性拦截](用例程序图固化与可测性拦截.md)、[动作空间与语义转译方案](动作空间与语义转译方案.md)、[用例密钥-操作与预期映射方案](../V2/用例密钥-操作与预期映射方案.md)、[扩展能力优化](../V2/扩展能力优化.md)、[开发手册](../../开发手册.md) §5  
> **要回答的事**：导入用例大量「未映射」是目录缺事件还是编译器拆错；「不展示其他弹窗」为什么会去找文案「其他」；操作里写了预期、预期里写了点击该怎么办；校验怎么用上一步刚输入的内容；看图和 DOM 谁来做这些检查。

用例作者写的是产品指标（弹窗标题、按钮置灰、只留 100 字、引导在上传按钮右侧）。编译器现在几乎只认识「点击 / 输入 / 展示 / 不应出现」，于是大量预期落成未映射，少数误命中 `expected.ui_text`，执行时拿整句当画面文案去找。本文把事件身份和参数完全分开：目录只登记「检查什么种类」，具体标题、哪个弹窗、是否仅此一个只进 `params`。任一句子无法执行或无法验证，整条用例不开跑；提示写明是哪一步、哪一句、哪一种做不了。看图和 DOM 是两条互不改写的路线，同一步不得先树后图或先图后树。

## 0. 拍板

| 题 | 决定 |
|---|---|
| 事件身份 vs 参数 | **完全分开**。`key_ref` 只表示种类，不含任何产品句。标题、按钮字、场景名、长度、相对谁，全部只进 `params.element` / `params.rules` / `bind`。目录 `write_examples` 只写句式骨架 |
| 看图 vs DOM | **两条技术路线，互不改写。** 任务选定 `action_scheme=visual` 或 `dom`。同一步禁止「先读树再看图」「看图没把握再查 DOM」「能用 DOM 证伪就不看图」。当前路线做不了这一句 → 整案不开跑，提示写明「看图/DOM 未实现该检查」 |
| 有一句做不了 | **整条用例不执行。** 未映射、参数不全、错层、平台不支持、当前路线不支持，都是无法执行或无法验证。任一命中，`coverable=false`，开跑前拦截。不跳过该句继续跑其余步骤 |
| 提示写什么 | 每条拦截写明步骤、原文、原因种类、缺的是什么。禁止只写「此句无法执行」 |
| 未映射 | 当前目录没有对应种类 → 整条用例按 [固化方案](用例程序图固化与可测性拦截.md) §6 标不可 UI 自动化。本文先把缺口种类补进目录，再谈覆盖率 |
| 「展示」类短词 | 禁止用 1～2 字动词当唯一命中。否定、弹窗、样式、输入值、位置关系必须有独立 `key_ref`，且否定优先于肯定 |
| 「不展示其他弹窗」 | **不是** `expected.ui_text` 去找「其他」。与前半句「某弹窗弹出」合成一条弹窗检查：`which` + `exclusive=true` |
| 操作写进预期 / 预期写进操作 | 编译期诊断 `layer_mismatch`。提示写明「这句是操作/预期，写在了错误栏」。未挪正之前整案不开跑。不按写错的层派发 |
| 纠正谁来落盘 | 导入预览可一键采纳建议（把句子挪到正确层并重编译）。人不点就不改原文。程序默认不偷偷改作者层 |
| 跨步上下文 | 校验参数可以 `bind` 上一步操作产物（刚输入的文本、刚点的控件）。不把当次输入全文冻进用例定义 |
| 平台 | 「刷新页面」只登记 Web。安卓/iOS 写「刷新页面」且没有对应控件事件 → 未映射 |
| 被测文案 | 编译器、目录示例、导航代码都不写某个 App 的产品句。用例原文里的「」内容原样进 `params.rules` |

## 1. 要对上的失败

下面用导入用例里真实出现的句子说明缺口。斜体只是**作者层原文**，不是编译器要学的白名单。

### 1.1 预期步骤：缺种类，或拆错种类

| # | 作者原句（例） | 现在 | 应当 |
|---|---|---|---|
| 1.1.1 | *弹窗标题为「你主要用 … 来做什么？」* | 未映射 | 文案检查。元素=弹窗，规则=`{title: 「…」}` |
| 1.1.2 | *正文提示为「选择感兴趣的场景」* | 未映射 | 文案检查。元素=弹窗，规则=`{body: 「…」}` |
| 1.1.3 | *确认按钮默认置灰不可点击* | 未映射 | UI 样式检查。元素=按钮，规则=`{style: disabled}` |
| 1.1.4 | *场景选择弹窗自动弹出* | 未映射或糊成 `ui_text` | 弹窗检查。元素=弹窗，规则=`{which: 场景选择弹窗}` |
| 1.1.5 | *不展示其他弹窗* | 命中 `expected.ui_text`（句内有「展示」），执行去找文案「其他」 | **错误校验**。与 1.1.4 合成：弹窗检查，规则=`{which: 场景选择弹窗, exclusive: true}` |
| 1.1.6 | *仅保留前 100 字符* | 未映射 | 输入文案检查。元素=输入框，规则=`{max_length: 100}`，值绑定上一步输入 |
| 1.1.7 | *所有特殊字符、emoji 均可正常输入无报错* | 未映射 | 输入文案检查。规则=`{accepts_special: true}`；「无报错」是同一步的副作用观察，不是另找一个「报错」文案 |
| 1.1.8 | *在上传图片的元素右侧有一个新人引导弹窗* | 未映射 | 位置关系观察。元素=引导弹窗，规则=`{relative_to: 上传图片元素, relation: right, axis: horizontal}` |

1.1.5 是当前编译器最危险的假阳性：看起来「映射上了」，跑起来测的是另一件事。未映射至少拦得住；假阳性会把缺陷执行成通过或莫名失败。

### 1.2 操作步骤：缺种类

| # | 作者原句（例） | 现在 | 应当 |
|---|---|---|---|
| 1.2.1 | *勾选「其他」场景选项* | 未映射（「勾选」不在点击示例里，或整句进不了 tap） | 点击。元素=勾选框，规则=`{label: 「其他」}` |
| 1.2.2 | *刷新页面* | 未映射 | 刷新页面。仅 Web。`platforms=["web"]` |

### 1.3 写错层

导入用例常把「应当看到…」写进操作，把「点击 / 勾选 / 输入」写进预期。这是作者习惯，不是执行语义。

**禁止**：预期里出现点击事件就当真去点；操作里出现「按钮置灰」就当真当动作去「置灰」。也不许跳过这句、只跑其余步骤。

**要做**：识别错层 → 记入 `blocked_by`，原因 `layer_mismatch` → 预览写明这句是操作还是预期、写错了哪一栏、应挪到哪里。人采纳并重编译通过之前，整案不开跑。

### 1.4 跨步上下文

1.1.6 离开前一步「输入超长文案」没有意义。校验要比的是：**当前输入框里的值**，相对 **上一步实际提交的文本** 是否被截到 100 字，而不是在画面上找「100」两个字。

## 2. 程序现在错在哪

不是「模型笨」，是编译器和目录把指标压成了两三个粗事件。

### 2.1 目录种类不够

`case_resource_key_catalog` 预期层实际只有：

- `expected.ui_text`（文案包含 / 展示 / 显示 / 页面包含）
- `expected.ui_absent`（不应出现 / 不包含 / 没有 / 未展示）
- `expected.session_state` / `expected.screen_reached` / `expected.counter`

操作层有点击、输入、滑动、等待、关挡屏，**没有**勾选（带角色）、**没有**刷新页面。

作者写的是「标题 / 正文 / 置灰 / 弹窗 / 独占 / 字数 / 特殊字符 / 相对位置」，目录里没有这些种类，编译器只能未映射或硬塞进 `ui_text`。

### 2.2 短词最长命中 + 整句当 expectation

`_match_catalog_clause` 用 `write_examples` 子串、取最长命中。`expected.ui_text` 的示例含「展示」（2 字）。「不展示其他弹窗」含「展示」，而 `ui_absent` 示例是「未展示」不是「不展示」——于是命中文案检查。

命中之后 `_plan_step(..., layer=expected)` 几乎只写：

```json
{ "assert": { "mode": "vlm", "expectation": "<整句原文>" } }
```

没有 `element`，没有 `rules`。看图断言拿到整句，最容易抓住的实词是「其他」，就去找一个叫「其他」的弹窗文案。这是 1.1.5 的执行路径。

### 2.3 逗号切开破坏同一断言

`_COMPOUND_SPLIT` 含 `，` / `,`。这对「点击 A，输入 B」是对的。对「场景选择弹窗自动弹出，不展示其他弹窗」是错的：后半句是前半句的约束（独占），不是第二条独立校验。

切开以后，后半句丢失「哪个弹窗」，更容易掉进 `ui_text`。

### 2.4 没有参数抽取，只有 spatial_hint

编译器会从「右上角」抽出 `params.spatial_hint`，这是对的（身份仍是点击）。但「」内文案、元素角色（弹窗 / 按钮 / 输入框 / 勾选框）、样式词（置灰 / 不可点击）、数字（100 字符）、相对位置（右侧）都没有进 `params`。执行侧只能把整句丢给模型。

### 2.5 没有层极性

编译只在本层目录里匹配。预期句「勾选「其他」」在预期目录找不到点击，变成未映射；若某天有人把「勾选」写进预期示例，就会在 check 阶段派 tap——更糟。缺少「这句话的极性是 do 还是 check」。

### 2.6 校验 Job 吃的是散文

`vision_assert` 把 checkpoint 的 `expectation` 整句塞进 prompt。模型没有「元素 + 规则」结构，就会发明检查对象。约束用例写得再规范，执行仍可能跑偏。

### 2.7 导入 Job 词表与目录同瘦

固化方案已规定：拆分模型只能选当前可覆盖事件。词表瘦，模型不是漏拆，就是把 1.1.5 塞进「展示」。补事件必须 **目录、编译、Job 词表、执行** 同一天对齐，否则预览和跑批又分叉。

## 3. 事件模型：身份 + 元素 + 规则

一条编译产物固定四块：**身份、参数、路线、出处**。坐标、当次 bounds 仍然不准进用例（固化方案 §0）。身份和参数之间没有第三处塞产品句。

```json
{
  "key_ref": "expected.dialog",
  "kind": "checkpoint",
  "title": "场景选择弹窗自动弹出且仅此一个",
  "action_scheme": "visual",
  "assert": {
    "mode": "dialog",
    "element": { "role": "dialog", "name": "场景选择弹窗" },
    "rules": { "present": true, "exclusive": true }
  },
  "source_line": "场景选择弹窗自动弹出，不展示其他弹窗",
  "source_clauses": ["场景选择弹窗自动弹出", "不展示其他弹窗"]
}
```

`action_scheme` 来自**当前任务**选定的看图或 DOM，不是编译器按「这句用树更好证」临时改的。目录只声明该事件 **支持哪些路线**（`schemes: ["visual"]` / `["dom"]` / 两者都有）。任务路线不在支持列表里，整案不开跑，按 §5.2 写明当前路线和该事件实现了哪条路线，不改写 `action_scheme`。

| 字段 | 谁填 | 禁止 |
|---|---|---|
| `key_ref` | 目录种类，纯身份 | 把产品标题、场景名、数字规则写进 key_ref |
| `action_scheme` | 任务看图/DOM 卡片 | 同一步先 `dom` 失败再改 `visual` |
| `element.role` | 编译器按句式抽出的控件种类（dialog / button / input / checkbox / overlay / page） | 写死某个 App 的 className |
| `element.name` / `rules.*` 的引号内容 | **只用**用例原文「」或明确称呼 | 编译器用正则表去「认识」产品句；身份字段里再抄一遍 |
| `bind` | 指向本步之前的 do step id | 把当次输入的 200 字正文冻进 case |

操作同形，用 `params` 代替 `assert`：

```json
{
  "key_ref": "operation.tap",
  "kind": "hook",
  "hook_cap": "tap_element",
  "params": {
    "element": { "role": "checkbox" },
    "rules": { "label": "其他" }
  }
}
```

「勾选」不是新的 Scout 点击协议，是点击事件带 `role=checkbox`。刷新页面才是新能力。

## 4. 目录要加 / 要改的事件

`write_examples` 只写 **句式骨架**，用 `{title}` `{label}` `{n}` 占位，禁止写某个产品的完整标题。每条事件登记 `schemes`：它在看图路线、DOM 路线分别有没有实现。`ui_coverable` 按 **当前任务路线** 是否在 `schemes` 里计，不把「另一条路线能做」算进本路线覆盖率。

### 4.1 预期：文案检查 `expected.ui_copy`

替换「万能 `expected.ui_text`」作为默认。旧 `ui_text` 降为别名，仅在抽不出 `element.role` 时回退，且 **否定句不得回退到它**。

| | |
|---|---|
| kind | `check` |
| 元素 | `dialog` / `page` / `input` / `button` / 未指定则 `page` |
| 规则 | `title` / `body` / `value` / `label`（从「」抽取）；`match`: `equals` \| `contains` |
| 示例句式 | `弹窗标题为「{title}」`、`正文提示为「{body}」`、`输入框内容为「{value}」` |
| 路线 | 看图：截图 + 结构化看图断言（只吃 `element`+`rules`）。DOM：当前树上对应对话框节点的文本。任务路线不在 `schemes` 里 → 整案不开跑，提示「当前是看图/DOM，文案检查未实现该路线」 |
| 对应 | §1.1.1、§1.1.2 |

「所有特殊字符、emoji 均可正常输入」**不要**编成文案检查去找「特殊字符」四个字。见 §4.4。

### 4.2 预期：UI 样式检查 `expected.ui_style`

| | |
|---|---|
| kind | `check` |
| 元素 | 默认 `button`；可写 `input` / `tab` |
| 规则 | `style`: `disabled` \| `enabled` \| `selected` \| `unselected`；可选 `label` |
| 示例句式 | `确认按钮置灰不可点击`、`按钮不可点`、`{label} 可点击` |
| 路线 | 看图：断言「该按钮呈不可点/置灰」。DOM：读节点 `enabled` / `clickable` / `aria-disabled`。禁止看图路线去读树「帮忙确认」，禁止 DOM 路线看颜色截图 |
| 对应 | §1.1.3 |

### 4.3 预期：弹窗检查 `expected.dialog`

| | |
|---|---|
| kind | `check` |
| 元素 | `role=dialog`（含 sheet / modal / 引导层，执行侧按渠道角色映射，不写 App id） |
| 规则 | `which`: 弹窗称呼或标题；`present`: true\|false；`exclusive`: 当前是否只允许这一个 |
| 示例句式 | `{name}弹窗自动弹出`、`弹出{name}`、`不展示其他弹窗`、`仅显示当前弹窗` |
| 路线 | 看图：画面上是否出现该弹窗、是否同时还有别的弹窗。DOM：统计 dialog 角色节点 + 名称。同一任务只走其中一条 |
| 对应 | §1.1.4 + §1.1.5 |

**合并规则（编译器，不是模型）**：同一编号预期行内，一条 `present` 弹窗检查与一条「不展示其他弹窗 / 仅此弹窗」相邻（中间可被逗号切开），**必须合成一条** checkpoint，带 `exclusive=true`。禁止输出两条：一条找弹窗、一条 `ui_text`「其他」。

「不展示其他弹窗」单独出现、前文没有 `which`：仍编 `expected.dialog`，`exclusive` 无法落地则 `params_incomplete`，整案不可覆盖——不要降成 `ui_text`。

### 4.4 预期：输入文案检查 `expected.input_value`

| | |
|---|---|
| kind | `check` |
| 元素 | `input`（含 textarea / contenteditable） |
| 规则 | `max_length` / `min_length` / `equals_bound` / `prefix_of_bound` / `accepts_special` / `no_error_toast` |
| 示例句式 | `仅保留前{n}字符`、`最多{n}字`、`可输入特殊字符`、`emoji 可输入无报错` |
| bind | `from: prev_do.params.rules.text`（见 §6） |
| 路线 | 看图：断言框内可见文本长度/是否仍含特殊字符、是否有报错层。DOM：读 value 与 bind 比，看 error/alert 角色。禁止看图路线去读 `value` 属性凑长度 |
| 对应 | §1.1.6、§1.1.7 |

`accepts_special` 的含义是：上一步输入里的特殊字符/emoji **仍在 value 里，且没有错误挡层**。不是检查画面是否出现「特殊字符」文案。

### 4.5 预期：位置关系观察 `expected.spatial_relation`

| | |
|---|---|
| kind | `check` |
| 元素 | 主语控件（引导弹窗 / 气泡 / 角标） |
| 规则 | `relative_to`: 参照称呼；`relation`: `left`\|`right`\|`above`\|`below`\|`inside`；`axis`: `horizontal`\|`vertical`\|`any` |
| 示例句式 | `在{anchor}右侧有{subject}`、`位于{anchor}下方` |
| 路线 | 看图：画面上主语相对参照的方位。DOM：两边节点 bounds 比较。空间词是规则，不是步骤身份（与固化方案 `spatial_hint` 一致）。禁止 DOM 没命中再看图补一刀 |
| 对应 | §1.1.8 |

### 4.6 预期：收窄旧事件

| 旧 key_ref | 改后 |
|---|---|
| `expected.ui_text` | 别名 → `expected.ui_copy`。`write_examples` 去掉光秃的「展示」「显示」。否定词开头不得命中 |
| `expected.ui_absent` | 只用于「页面/列表不出现某文案或某控件」，**不**承担「没有别的弹窗」。弹窗独占走 `expected.dialog` |
| `expected.counter` / session / screen | 不动 |

匹配优先级（同句可多规则时）：

1. 层极性（§5）——先判断这句该不该在本层  
2. 否定 / 独占弹窗  
3. 样式（置灰、不可点击）  
4. 输入长度 / 特殊字符  
5. 位置关系  
6. 弹窗出现  
7. 文案 title/body  
8. 旧 `ui_absent` / `ui_copy`  
9. 未映射

### 4.7 操作：勾选仍是点击

不新增 Scout 协议。目录可加 `operation.check_box`，`expands_to` / 编译结果仍是 `hook_cap=tap_element` + `params.element.role=checkbox` + `rules.label`。

`write_examples`：`勾选「{label}」`、`勾选{label}`、`取消勾选「{label}」`（后者 `rules.checked=false`）。

不要靠「点击」两个字去碰「勾选「其他」」——「其他」必须进 `label`，角色必须是勾选框，避免点到旁边同文案的说明文字。

### 4.8 操作：刷新页面 `operation.reload_page`

| | |
|---|---|
| kind | `generic`（事件）+ 目录 `platforms=["web"]` |
| cap | 新建 `reload_page`（或复用 Scout 已有等价 id，两仓协议对齐后登记） |
| caller | `case`，`phases=["do"]` |
| 示例句式 | `刷新页面`、`刷新当前页`、`reload` |
| 非 Web | `platform_unsupported`。提示「刷新页面只在 Web 执行，当前平台无法执行」。不降级成下拉刷新。整案不开跑 |
| 执行 | Nexus 本地不碰浏览器。EXECUTE 载荷带齐 `executor_order`；Scout Web 渠道执行页刷新 |

协议：若现有 EXECUTE 没有这个 cap，按 [PROTOCOL](../../基础框架/PROTOCOL.md) 四步两仓同步。禁止 Nexus `subprocess` 开浏览器。

## 5. 纠正写错层，而不是执行写错的事件

### 5.1 极性

每个子句算两个分数：

- `do_score`：命中操作目录种类（点击、勾选、输入、滑动、刷新、关弹窗、导航、块）  
- `check_score`：命中预期目录种类（文案、样式、弹窗、输入值、位置、计数、登录态、到屏）

判定：

| 所在栏 | 分数 | 结论 |
|---|---|---|
| 操作 | `check_score > do_score` 且 check 能抽出完整规则 | `layer_mismatch`。提示「这句是预期（写出种类），写在了操作栏」。整案不开跑 |
| 预期 | `do_score > check_score` 且 do 能抽出 hook | `layer_mismatch`。提示「这句是操作（写出种类），写在了预期栏」。整案不开跑 |
| 任一层 | 本层命中但规则抽不全 | `params_incomplete`。提示缺哪一项（哪个弹窗、绑定的输入、长度）。整案不开跑 |
| 任一层 | 两层都不够 | `unmapped`。提示「当前目录没有对应事件」。整案不开跑 |

「确认按钮置灰不可点击」：`check_score` 高（样式），即使出现「点击」二字也不当操作。  
「勾选「其他」场景选项」：`do_score` 高；写在预期栏就是错层，**不要**编成 check 阶段的 tap。

### 5.2 拦截产物：整案不开跑，原因写具体

存在任一无法执行或无法验证的点，这条用例不进入跑批。不开跑就没有「跳过这句、后续句在错误屏幕上继续判」的问题；依赖该句的后续步骤也不会执行。

```json
{
  "code": "layer_mismatch",
  "step": 3,
  "layer": "expected",
  "clause": "勾选「其他」场景选项",
  "user_message": "步骤 3 预期「勾选「其他」场景选项」无法执行：这是操作（勾选框），写在了预期栏。挪到操作栏并重新编译后才能跑。",
  "suggested_layer": "operation",
  "suggested_step": {
    "key_ref": "operation.check_box",
    "hook_cap": "tap_element",
    "params": {
      "element": { "role": "checkbox" },
      "rules": { "label": "其他" }
    }
  }
}
```

| 谁 | 做什么 |
|---|---|
| 预览 | 步骤/预期列展示解析结果。每一条 `blocked_by` 用下面的句式写在该句旁边，不倒进备注。多条全部列出 |
| 采纳 | 按建议改栏或补参数后重编译。`coverable=true` 之后才能开跑 |
| 不采纳 | 原文不动。`coverable=false`。`POST /case-runner/run` 拒绝。没有跑次，没有 pass/fail |
| Studio 终态 | **未执行**。详情列出全部原因。不出现「部分步骤已跑、该句跳过」的时间线 |

提示句式固定四段，禁止只写「此句无法执行」：

| 原因 | 用户看到的句子 |
|---|---|
| `layer_mismatch` | 步骤 {n} {操作\|预期}「{原句}」无法执行：这是{操作\|预期}（{事件名}），写在了{预期\|操作}栏。 |
| `platform_unsupported` | 步骤 {n} 操作「{原句}」无法执行：{事件名}只在 {平台} 执行，当前平台是 {当前平台}。 |
| `scheme_unsupported` | 步骤 {n} {操作\|预期}「{原句}」无法执行：当前任务是{看图\|DOM}，{事件名}只实现了{另一路线}。 |
| `params_incomplete` | 步骤 {n} 预期「{原句}」无法验证：{事件名}缺少{哪一项}。 |
| `unmapped` | 步骤 {n} {操作\|预期}「{原句}」无法执行：当前目录没有对应事件。 |
| `capability_disabled` | 步骤 {n}「{原句}」无法执行：事件 {key_ref} 已停用。 |

不把纠正做成看图规划的自由发挥。规划仍然不得改业务边。未映射、错层、参数不全、平台不支持、路线不支持，开跑闸相同，差别只在上面这句原因。

### 5.3 约束作者与拆分模型

给导入 Job / 用例编写说明的硬约束（词表来自目录，不写产品句）：

1. 操作栏只写改变界面的动作（点、勾、输入、滑、刷新、导航、块）。  
2. 预期栏只写可观察结果（文案、样式、弹窗、值、位置、数量、登录态、当前屏）。  
3. 「看到 / 展示 / 置灰 / 不可点击 / 弹出 / 不展示」不得单独出现在操作栏。  
4. 「点击 / 勾选 / 输入 / 刷新」不得单独出现在预期栏。  
5. 一句里既有动作又有结果，拆成操作 + 预期两栏，不要写在同一栏用逗号糊过去。  
6. 模型不准为了「能映射」把预期改写成点击，也不准把操作改写成文案检查。

Studio 导入预览已能展示解析后的步骤/预期；错层建议走同一套 `steps_parsed` / `expected_parsed` / `flags`，不要再倒进备注。

## 6. 跨步 bind：校验读上一步产物

### 6.1 何时 bind

编译 `expected.input_value` 时，在**同一编号步骤**（同一 `case_step`）的 do 图里从后往前找最近一条 `operation.input_text`（或等价输入 hook）。找到则：

```json
{
  "bind": {
    "from_step_id": "do_s3_2_hook",
    "path": "params.rules.text"
  },
  "rules": {
    "max_length": 100,
    "prefix_of_bound": true
  }
}
```

`prefix_of_bound=true`：读回值应等于 bind 文本的前 `max_length` 字（或整段，若本来就不足 n 字）。  
找不到输入步：`params_incomplete`（「仅保留前 100 字符」离开输入动作没有对象）。

跨编号步骤的 bind 第一版不做（避免把上一条用例步骤的输入误绑过来），除非作者写显式 `【bind:step_id】`。

### 6.2 运行时填值，不写进用例定义

bind 的是 **路径**，不是那次跑批输入的正文。执行 do 成功后，把实际 `text` 记在跑次状态（session / 里程碑 params），check 再按 **本任务路线** 取框内结果比较：看图比画面可见文本，DOM 比节点 value。不要让看图 Job 重新发明一段 emoji；也不要让看图路线去读 DOM `value` 来「更准」。

### 6.3 1.1.6 的完整图

作者：

- 操作：在某输入框输入超过 100 字（含特殊字符）  
- 预期：仅保留前 100 字符；特殊字符/emoji 可输入无报错  

编译：

1. do：`input_text`，`element.role=input`，`text` 来自用例或资源  
2. check：`input_value` bind 上一步，`max_length=100`，`prefix_of_bound=true`  
3. check：同一 `input_value` 可合并 `accepts_special=true` + `no_error_toast=true`（同一元素，合并规则，不要拆成一次文案检查）

## 7. 参数怎么从句子里来（编译器，零 App 文案）

允许的抽取全是 **结构**，与 `no-app-keywords` 一致。

| 信号 | 用途 |
|---|---|
| 「…」或 “…” | `title` / `body` / `label` / `which` 的值。角色由句式前的词决定（标题 / 正文 / 勾选） |
| 元素种类词 | 弹窗、对话框、按钮、输入框、勾选、引导、页面 —— 这是控件角色词，不是某个 App 的 Tab 名 |
| 样式词 | 置灰、不可点击、禁用、可点击、选中 |
| 数字 + 字符/字 | `max_length` |
| 相对位置词 | 右侧、左侧、上方、下方、内部（复用并扩展现有 `_SPATIAL_HINTS`，用于关系检查而不仅是点击辅佐） |
| 否定 | 句首或谓语「不展示 / 没有 / 未出现 / 仅 / 只」——优先弹窗独占或 `present=false` |
| 平台词 | 「刷新页面」+ 当前 case 平台不是 web → 直接 `platform_unsupported` |

**不允许**：

- 编译器出现某个产品的完整标题、场景名、包名  
- 用「其他」当 `ui_absent` 的目标文案  
- 把「Hi3D」写进 `write_examples`

「」里的字原样进入 `params`，那是这条用例自己的数据。换一个 App，换一条用例，参数变，`key_ref` 不变。

句式骨架放在目录 `compile_patterns`（或现有 `dsl` 扩展），例如：

```text
弹窗标题为「{title}」     → expected.ui_copy  element.role=dialog  rules.title
正文提示为「{body}」     → expected.ui_copy  element.role=dialog  rules.body
{name}弹窗自动弹出       → expected.dialog   rules.which={name} present=true
不展示其他弹窗           → expected.dialog   rules.exclusive=true
勾选「{label}」          → operation.check_box  rules.label
刷新页面                 → operation.reload_page
仅保留前{n}字符          → expected.input_value rules.max_length={n}
在{anchor}右侧有{subject} → expected.spatial_relation
```

新增种类 = 加目录行 + pattern，不改 Python 里的中文正则表。否定优先、弹窗合并、层极性这三件事可以留在编译器，因为它们是结构，不是产品词。

## 8. 执行：看图一条路，DOM 一条路

沿用 [动作空间与语义转译](动作空间与语义转译方案.md)：任务 `action_scheme` 是 `visual` 或 `dom`。校验和点击遵守同一条铁律——**一条步骤只属于一种模式**。

禁止的混用（无论操作还是预期）：

- 看图出了坐标或判定，再用 DOM 树改点、改结论
- DOM 没命中，再偷偷看图补一刀仍算 pass
- 「置灰 / 弹窗个数 / 输入长度 / 相对位置适合用树证伪，所以看图任务也改走 DOM」
- 树空了就把 `observe` 升成 `visual_each_run`

Nexus 仍然不连设备。DOM 路线读的是 Scout 上报的当前树；看图路线用的是截图 + 看图 Job。两边都经 `EXECUTE` / 观察回执，只是载荷和成败标准不同。

| 路线 | 操作怎么做 | 预期怎么做 | 失败 |
|---|---|---|---|
| `visual` | 看图执行出坐标，`point_policy=coordinate`，不写 target、不吸附节点 | 看图断言只吃结构化 `element`+`rules`（禁止整句散文）。置灰、弹窗是否唯一、字数、相对位置都在画面上判 | 没坐标 / 画面不满足规则 → 本步失败。不查树 |
| `dom` | 当前树唯一命中节点，`point_policy=node` | 当前树读文本、enabled、dialog 计数、value、bounds | 无唯一命中 / 属性不满足 → 本步失败。不看图 |

目录 `schemes` 与任务路线的交集决定「这一句在本次跑批里能不能做」：

- 在交集里：按任务路线执行，参数仍是同一套 `element`+`rules`（身份/参数与路线正交）
- 不在交集里：该句 `scheme_unsupported`，整案不开跑。提示按 §5.2：「当前任务是看图，UI 样式检查只实现了 DOM」（或反过来）。不改道

`observe=program` 只留给本地钩子（租号、取码、等待、登录态接口），不是「DOM 校验的别名」。DOM 校验是 `action_scheme=dom` 的 checkpoint，不是 program 观察。

勾选：看图点勾选框位置；DOM 按 `role=checkbox` + `label` 命中节点。刷新页面不是看图动作，只挂 Web 页操作渠道。

看图断言 Job 的 user 槽只注入结构化 `checkpoints[]`。DOM 校验不调用该 Job。

## 9. 可测性与预览

沿用固化方案的 `ui_automation`。下面任一原因出现，整案 `coverable=false`，开跑前拒绝。终态是 **未执行**，不是跑批中的失败或通过。

| 原因 | 无法执行还是无法验证 | 用户看见什么 |
|---|---|---|
| `unmapped` | 无法执行 | 步骤、原句、当前目录没有对应事件 |
| `params_incomplete` | 无法验证 | 步骤、原句、事件名、缺的参数（哪个弹窗 / 绑定的输入 / 长度） |
| `platform_unsupported` | 无法执行 | 步骤、原句、事件名、只支持的平台、当前平台 |
| `capability_disabled` | 无法执行 | 步骤、原句、已停用的 `key_ref` |
| `scheme_unsupported` | 无法执行 | 步骤、原句、当前是看图还是 DOM、该事件实现了哪条路线 |
| `layer_mismatch` | 无法执行 | 步骤、原句、这句实际是操作还是预期、写错的栏、应挪到哪一栏 |

预览列：

- 步骤 / 预期：解析后的事件名 + 元素 + 规则（人能看懂「弹窗检查 · 场景选择 · 仅此一个」）
- 每条拦截：§5.2 的完整句子，多条都显示
- 备注：只放无法结构化的说明，不再倒 flags

`ui_automation.coverable`：`blocked_by` 为空才为 true。错层、路线不支持、非 Web 刷新都进 `blocked_by`，不另开「可开跑但跳过」的列表。

假阳性（1.1.5）修复后，原先「映射成功其实测错」的用例会变成正确覆盖或诚实的 `params_incomplete`，不允许继续绿。

## 10. 约束用例，减少模型胡编

三处同时约束，只约束一处会回流。

### 10.1 目录词表（导入 Job / 规划菜单）

只列出 §4 的种类和参数 schema。模型输出必须是：

```json
{ "layer": "expected", "key_ref": "expected.dialog", "element": {}, "rules": {} }
```

不准输出自由 `milestones[]`，不准输出坐标，不准发明 `expected.ui_text` 去消化「不展示其他」。

### 10.2 作者栏纪律（§5.3）

Studio 保存时跑同一编译。人在预期栏粘贴「点击提交」会看到「步骤 n 预期「点击提交」无法执行：这是操作（点击），写在了预期栏」，用例保持未执行，直到改栏后重编译通过。

### 10.3 执行输入纪律

看图执行只看到当前步的 `hook_cap` + `params`，不查树。DOM 执行只看到节点条件，不看图。看图断言只看到 `assert.element/rules`。原文只在打断时给一句（固化方案作者层）。模型看不到「其他弹窗」整句，就无法改去点「其他」。

## 11. 明确不做

- 不在编译器或目录示例写某个 App 的产品标题、场景名、包名。  
- 不把产品句写进 `key_ref` 或 `write_examples`；身份和参数完全分开。  
- 不把「其他」当 `ui_absent` 目标。  
- 不按错层原文派发（预期里的点击不去点）。错层、非 Web 刷新、当前路线不支持，都让整案不开跑，并按 §5.2 写明是哪一种无法执行。  
- 不跳过做不了的句子继续跑其余步骤。  
- 不把看图和 DOM 混在同一步：不先树后图、不先图后树、不用「更适合证伪」改道。  
- 不静默改作者原文；纠正必须经预览采纳或显式保存。  
- 不把当次输入正文、坐标、bounds 写进 case。  
- 不把弹窗独占做成两条散文断言。  
- 不用点击「我的」或任何入口证明登录态（固化方案已禁）。  
- 不为「刷新页面」在 Nexus 里起浏览器。  
- 不把 `lifecycle` 拿来表示「这种检查我们还没做」。本路线做不了就 `scheme_unsupported`，整案不开跑，提示写明当前路线和该事件实现了哪条路线。

| 步 | 做什么 | 完成的标志 |

| D | 执行：仅 `coverable=true` 的用例开跑。看图断言只吃结构化 JSON 且不查树；DOM 校验不调看图 Job；两路线失败不互改 | session 分得清 `exec/vision` 与树命中；不再出现「去找文案其他」 |
