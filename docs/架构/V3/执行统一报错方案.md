# 执行统一报错方案

> **状态**：方案。代码还没改。程序码四位，一套号码里带上通过、警示、报错。具体原因用工具码和 `session_events.id`，不再给每种场景单编三位。  
> **要回答的事**：网页 `timeout after 30.0s` 的程序码是什么；`-118` / `-130` 放在哪；一个工具同时能干网页和安卓时号码怎么编。

跑失败的用例现在把整段异常原文写进 `cases[].error` / `summary`。同一类问题每次措辞不一样，报告只能靠人读句子。`loop/observe` 负责把轨迹记下来，`loop/fuse` 负责把死循环拦住，两边都还没有「这个失败对外叫什么」。

排查一条失败只看三样：程序码、工具码、`session_events.id`。

---

## 1. 今天那句 30 秒超时是谁打出来的

报告里的 `timeout after 30.0s` 来自 Scout `core._timeout_result`：一次 `EXECUTE` 在 `timeout_sec` 内没有回来，Scout 用这句收口。Nexus 对 `launch_app` / `open_url` / `open_app` 把这个时限设成 30 秒（`router_proxy._timeout_for`）。

Playwright 自己的启动失败长这样：

```text
TimeoutError: browserType.launch: Timeout 30000ms exceeded.
```

它还有 call log。Chromium 连页面失败时用官方网络错误名，定义在 `net/base/net_error_list.h`，例如：

| 官方名 | 值 | 常见含义 |
|--------|----|----------|
| `net::ERR_NAME_NOT_RESOLVED` | -105 | DNS 没有解析到 |
| `net::ERR_INTERNET_DISCONNECTED` | -106 | 本机没有网络 |
| `net::ERR_TUNNEL_CONNECTION_FAILED` | -111 | 代理隧道没建成 |
| `net::ERR_CONNECTION_TIMED_OUT` | -118 | 连上对端超时 |
| `net::ERR_PROXY_CONNECTION_FAILED` | -130 | 代理本身连不上 |

Playwright 没有数字错误码。`-118`、`-130` 是 Chromium 的官方值。网页打开一条用例时，Scout 先 `chromium.launch`（Playwright 默认等 30 秒），再 `page.goto`。我们自己的 `goto` 默认等 60 秒（`playwright_hub.goto_options_from_params`）。外层 `EXECUTE` 在 30 秒先返回 `timeout after 30.0s` 时，Chromium 还没抛，工具码就是空的。这是允许的。

连上 VPN 之后内网站点能开、这句不再出现。人话里保留排查句：若这个环境的站点只在内网，先连接 VPN。工具码后来若带回 `-118`，同一句排查仍然适用；若带回 `-130` 或 `-111`，排查句改成代理或隧道。`-105` 和 `-130` 的修法不同，差在工具码上，不另编程序码。

## 2. 四位怎么切

程序码固定四位，字符串保存。从左到右：

```text
3 1 01
│ │ └── 工具，两位，全局一个号。01 永远是 Playwright，02 永远是 adb
│ └──── 侧，一位。这条失败归工具、模型、用例、资源还是过程
└────── 级别，一位。1 通过，2 警示，3 报错
```

级别留在同一套号码里，不拆成另一个字段。看到码就知道这次是通过、警示还是报错。后三位是故障归属：侧 + 工具。Playwright 上的工具侧问题，后三位都是 `101`；首位 `3` 是报错，首位 `2` 是只记一笔、流程还在走。

| 段 | 位数 | 取值 |
|----|------|------|
| 级别 | 1 | `1` 通过。`2` 警示，流程继续。`3` 报错，流程停住 |
| 侧 | 1 | `0` 没有具体侧（通过，以及「走完但有警示」的汇总）。`1` 工具，`2` 模型，`3` 用例预期，`4` 测试资源，`5` 执行过程，`9` 未归类 |
| 工具 | 2 | 见下表。`00` 表示这条不是某个驱动工具的错 |

工具号全局只有一套，不按安卓 / 网页各编一次。同一个驱动在网页上失败、在别的入口失败，工具位相同。一次失败记的是**当时把错误返回来的那个驱动**。页面操作记 Playwright，接口调用记 HTTP 客户端，手机记 adb。一个流程里既有页面又有接口时，号码跟这一下失败的驱动走，不另设「Web 还是 API」渠道位。

若以后有一个框架同时驱动网页和安卓，它底下仍是 Playwright 或 adb 在报错，程序码记那个驱动。只有失败发生在框架自己的编排、驱动还没返回时，才给这个框架单独一个工具号。这样工具身份不会被渠道切成两个号。

| 工具号 | 工具 |
|--------|------|
| `00` | 不是驱动工具 |
| `01` | Playwright |
| `02` | adb |
| `03` | Selenium |
| `04` | Browser Use |
| `05` | WDA |
| `06` | HTTP 客户端 |
| `07` | 桌面驱动，具体产品以后再定 |

两位一共 99 个驱动号。侧只有 10 个号，现在用 `0` `1` `2` `3` `4` `5` `9`。具体原因（DNS、代理、进程没起来、点偏一次）不占程序码，放在工具码里；没有工具码时，用 `session_events.id` 指到那一行原文。

通过也是四位。号码里不使用 `200`。界面标题写「用例正常」。

| 程序码 | 含义 |
|--------|------|
| `1000` | 用例走完，没有报错，也没有警示 |
| `2000` | 用例走完，没有报错，过程里至少有一条警示 |

用例上的汇总码：有报错，用把流程停住的那条（首位 `3`）；没有报错、有警示，用 `2000`，警示仍逐条保留；都没有，用 `1000`。

## 3. 三样一起看

| 栏 | 例子 | 作用 |
|----|------|------|
| `program_code` | `3101` | 报错、工具侧、Playwright |
| `tool_code` | 空、`-118`、`-130`、`TimeoutError` | 工具原文里的官方值或类名，允许空 |
| `session_event_id` | `session_events.id` | 打开这一行，看 trace、步骤、设备、渠道 |

`3101` 是：报错、工具、Playwright。它覆盖打开被我们的 30 秒围栏截断，也覆盖浏览器进程没起来。两者差在工具码和这一行 session 的原文里。

| 当时的原文 | program_code | tool_code |
|------------|--------------|-----------|
| 只有 `timeout after 30.0s` | `3101` | 空 |
| 已有 `net::ERR_NAME_NOT_RESOLVED` | `3101` | `-105` |
| 已有 `net::ERR_INTERNET_DISCONNECTED` | `3101` | `-106` |
| 已有 `net::ERR_CONNECTION_TIMED_OUT` | `3101` | `-118` |
| 已有 `net::ERR_TUNNEL_CONNECTION_FAILED` | `3101` | `-111` |
| 已有 `net::ERR_PROXY_CONNECTION_FAILED` | `3101` | `-130` |
| `browserType.launch: Timeout 30000ms exceeded` | `3101` | `TimeoutError` |

人话按工具码选句子，方便报告阅读。告警、重试若要区分 DNS 和代理，读 `tool_code`，再以 `session_event_id` 核对原文。程序码负责归到「哪个驱动上的哪一侧」，不负责把 Chromium 的每一种网络错误再编一遍。

安卓上同一句 `timeout after 30.0s` 是 `3102`（报错、工具、adb）。不套用网页的 VPN 排查句。Selenium 是 `3103`，Browser Use 是 `3104`。

点偏一次、重试又点中，是我们自己的过程，不是 Playwright 返回的错误：`2500`（警示、过程、工具号 `00`）。这一步发生在网页还是安卓，打开对应的 `session_events.id` 就能看到。它和 `3101` 的后三位不同，不会和打开超时混成同一类。

## 4. 第一批程序码

新码先加进 `codes.py`，再在 `classify.py` 写规则。对不上的用 `3900`，trace 留在该条 session 里。不把不认识的句子编进 `3101`。

| 程序码 | 级别 | 标题 | tool_code |
|--------|------|------|-----------|
| `1000` | 通过 | 用例正常 | 空 |
| `2000` | 警示 | 用例走完，过程中有警示 | 空 |
| `2500` | 警示 | 有一次没有点中，重试点中了 | 空 |
| `3101` | 报错 | Playwright 动作失败 | 空，或 `-105` `-106` `-111` `-118` `-130`，或 `TimeoutError` |
| `3102` | 报错 | adb 动作失败 | 空。设备不在线时工具码仍空，原文在 session |
| `3103` | 报错 | Selenium 动作失败 | 驱动返回的官方名，常为空 |
| `3105` | 报错 | WDA 动作失败 | 空 |
| `3106` | 报错 | HTTP 调用失败 | 空，或 HTTP 状态码字符串 |
| `3200` | 报错 | 模型没有给出可用结果 | 空。缺坐标还是空响应，看 session |
| `3300` | 报错 | 这一步没有达到用例预期 | 空 |
| `3400` | 报错 | 测试资源不满足 | 空。没设备、租约、预检，看 session |
| `3500` | 报错 | 执行过程停住 | 空。反复做还是没有进展，看 session |
| `3900` | 报错 | 未归类 | 空 |

`3101` 且工具码为空、`-118`、`-105`、`-106` 时，人话补一句：内网站点先连 VPN。`-130`、`-111` 时改成代理或隧道没有建成。`tool_code` 为 `TimeoutError` 且原文含 `browserType.launch` 时，人话写成：本机 Chromium 没有被拉起。

## 5. 目录和报告

`except` 是 Python 关键字，不能当包名。异常出口放在 `loop/exc/`，和 `observe`、`fuse` 并列。

```text
mino_nexus/loop/exc/
  __init__.py     对外只导出 classify、format_report
  codes.py        四位码表：码、标题；人话可以按 tool_code 选句子
  classify.py     用级别、侧、工具抽出程序码和 tool_code
```

`loop` 里失败收口、警示、用例正常结束，都经过这里。Nexus 继续不 import Playwright。`tool_code` 只从 Scout 已经返回的字符串里抽。

`observe` 照旧记轨迹。`fuse` 照旧决定停不停。停下来写报错；重试后继续走写警示。写入 session 之后，把这一行的 `id` 填回用例的 `fault.session_event_id`。

```json
{
  "scheme": 1,
  "program_code": "3101",
  "tool_code": "",
  "session_event_id": 0,
  "title": "Playwright 动作失败",
  "detail": "打开页面在 30 秒内没有返回。若这个环境的站点只在内网，先连接 VPN 再跑。",
  "trace": "timeout after 30.0s"
}
```

工具码已经回来时，程序码仍是 `3101`：

```json
{
  "scheme": 1,
  "program_code": "3101",
  "tool_code": "-118",
  "session_event_id": 0,
  "title": "Playwright 动作失败",
  "detail": "Chromium 报告 net::ERR_CONNECTION_TIMED_OUT（-118）。若这个环境的站点只在内网，先连接 VPN 再跑。",
  "trace": "page.goto: net::ERR_CONNECTION_TIMED_OUT at http://hitem3d-test.mathmagical.cn/ ..."
}
```

点偏后再点中、用例仍走完：汇总码 `2000`，警示条目是 `2500`，并带上那条警示自己的 `session_event_id`。没有任何报错和警示时，程序码为 `1000`。

`fault` 放在任务 JSON 里。session 记 `exc/case` 或 `exc/warn`，类型和原文都在 `session_events` 那一行。不给 `EXECUTE` 增加新的顶层字段，协议 golden fixture 不用改。Scout 以后把异常类名、message、`net::ERR_*` 放进现有 `raw_response`，供 `tool_code` 抽取。

## 6. 落地顺序

1. **Nexus 码表。** 按第 4 节写入 `loop/exc`。网页打开只有 `timeout after 30.0s` 时，程序码 `3101`，`tool_code` 为空。安卓同一句原文用 `3102`。用例正常结束写 `1000`。点偏后重试成功写 `2500`，汇总码 `2000`。每条都带 `session_event_id`。
2. **Scout 把官方错误带回 `raw_response`。** 有 `net::ERR_*` 时抽出负数填 `tool_code`，程序码仍是 `3101`。message 含 `browserType.launch` 时 `tool_code` 为 `TimeoutError`，程序码仍是 `3101`。
3. **围栏和 `goto` 时限对齐之后，官方错误才更常在围栏之前回来。** 这一步不改码表。对不齐之前，`tool_code` 为空是正常结果，用 `session_event_id` 看原文。

第 1 步重启 Nexus 后，新跑的用例才会带上 `fault`。已经落库的旧任务不回填。
