# 用例固化与控件身份

> **状态**：开发中。编译结果带 control_id，导入按每 5 条轮询。  
> **关联**：[用例步骤改由大模型拆解](用例步骤改由大模型拆解.md)、[固化用例数据问题及页面逻辑优化](固化用例数据问题及页面逻辑优化.md)、[NAVIGATION_ATLAS.md](../../基础框架/NAVIGATION_ATLAS.md)  
> **仓库**：后端 `MinoNexus`，前端 `MinoWorkbench`。  
> **要回答的事**：拆出来的步骤怎样指到同一个控件；看图创建的控件为什么不能假装已经有 DOM 定位；八十多条导入为什么不能一次解析完。

编号步仍由 `case-step-compile` 拆。本文替换的是拆完之后的步骤形状，以及导入预览的提交方式。目录正则继续不参与拆步骤。

## 0. 拍板

| 题 | 决定 |
|---|---|
| 控件身份 | `control_id`。执行时用它取出操作对象，不在步骤里再抄一份定位串 |
| 用哪一格定位 | 由执行渠道（看图 / DOM）和设备渠道（Web / Android）一起决定。选中的那一格没有值就补上，不改拿另一格 |
| 操作步骤 | `step_id`、`step_type=action`、`action_type`、`target_desc`、`control_id`、`step_params` |
| 预期步骤 | `assert_id`、关联的 `step_id`、`assert_type`、`target_desc`、`control_id`、`assert_params`（含 `rule`） |
| 没盖住的原文 | 预览和用例列表里置灰，标成未执行。行仍可导入，整条不开跑 |
| 导入解析 | 每 5 条一批。接口马上返回批次号，页面轮询，直到这张表解析完 |
| 标题、操作、预期任一为空 | 不解析、不固化。导入页整行置灰，不能勾选 |
| 看图能不能写出 Playwright / UI Automation 定位 | 不能。这两格留空，等采集或 DOM 方案补 |

## 1. 控件

### 1.1 一条控件

同一业务控件在 Web 和 Android 上是同一条 `control_id`，定位分通道存放。执行时按下表取一格。这一格是空的，就在这次执行里把它补上，不改用旁边那一格。

```json
{
  "control_id": "ctl_8f3a",
  "element_type": "button",
  "locator_value": {
    "playwright": "",
    "uiautomator": "",
    "vlm_text": "右上角登录"
  },
  "scope": "page"
}
```

| 字段 | 闭集 |
|---|---|
| `element_type` | `button` `input` `checkbox` `dialog` `text` `image` `switch` `page` |
| `scope` | `page` `iframe` `dialog` `new_window` `webview` `shadow` |
| `locator_value` 的键 | `playwright`、`uiautomator`、`vlm_text`。空字符串表示这条通道还没有 |

不设总的 `locator_type`。选哪一格只看当前任务的两个开关：

| 执行渠道 | 设备渠道 | 用哪一格 | 没有值时补什么 |
|---|---|---|---|
| 看图 | Web 或 Android | `vlm_text` | 补描述，用步骤上的 `target_desc`。不写坐标 |
| DOM | Web | `playwright` | 这次 DOM 命中该控件后，把定位串写回这一格 |
| DOM | Android | `uiautomator` | 这次 DOM 命中该控件后，把定位串写回这一格 |

看图任务即使 `playwright` 里已经有值，也不去读它。DOM 任务即使 `vlm_text` 有值，也不改走看图。选中的那一格补不上，这一步按未执行停住。

`control_id` 由程序生成，模型只交 `target_desc` 和它认为的类型、范围、看图描述。程序按「应用 + 端无关的业务描述」查找已有控件；对上了就复用 id，对不上就新建。两条用例写的是同一个按钮时，应得到同一个 id。对不上又很像时，先新建，并在控件上标「待合并」，不在导入时阻塞。

### 1.2 和现在导航图的关系

现在的边把 `resource_id`、`accessibility_id`、文案、千分比坐标写在边自己身上，数据来自采集。采集继续做，但写入控件的 `locator_value`，边和用例步骤只留 `control_id`。

从用例新建控件时，只填 `vlm_text`、`element_type`、`scope`。`vlm_text` 是描述：按钮文案、图标在说什么、相对哪个区域。看图每次执行都重新在当次画面上算坐标。版本一变、弹窗一变、页面一变，坐标都会变，所以坐标不进 `locator_value`，也不进导航图。

`playwright` 和 `uiautomator` 只在 DOM 渠道命中之后填写，内容是各自引擎的定位串。看图不写这两格，也不把当次坐标换算后塞进去。

## 2. 固化后的步骤

模型仍返回原文摘录。程序算下标，并写成下面两行。`key_ref` 留在程序图里供目录校验，页面主显示用这里的类型和 `target_desc`。

### 2.1 操作

```json
{
  "step_id": "st_1",
  "step_type": "action",
  "action_type": "click",
  "target_desc": "右上角登录入口",
  "control_id": "ctl_8f3a",
  "step_params": {}
}
```

`action_type` 能执行的是目录里已有能力的那些：`click`、`input`、`clear`、`check`、`scroll`、`swipe`、`wait`。`select`、`upload`、`hover` 可以出现在解析结果里，走现在的不可执行提示，文案是「无法执行，当前版本未实现」。这次不加这些执行器。

`step_params` 按 `action_type` 填：输入和清空要有写入内容或「清空」；等待要有 `wait_ms`；滑动要有方向。点击、勾选没有额外参数时是 `{}`。刷新页面的等待仍写在该步的 `step_params.wait_ms`，不另起一步。

登录块仍是一个父步骤。槽（入口、凭证、提交）各带自己的 `control_id`，父步骤的 `action_type` 为这条逻辑块，而不是拆成三个互不相关的点击。

### 2.2 预期

预期关联同一编号下的操作 `step_id`。一句预期对不上任何操作时，`step_id` 为空，预览仍显示，但不把它涂成某次操作的结果。

```json
{
  "assert_id": "as_1",
  "step_id": "st_1",
  "assert_type": "visible",
  "target_desc": "场景选择弹窗",
  "control_id": "ctl_22b1",
  "assert_params": {
    "rule": "visible"
  }
}
```

`assert_type` 闭集：`exists`、`visible`、`text`、`attribute`、`value`、`count`、`checked`、`enabled`。

`assert_params.rule` 用现在程序图里已经在用的规则，不另做一套前端规则引擎。对应关系：

| `assert_type` | `rule` 示例 | 还需要的参数 |
|---|---|---|
| `text` | `equals` / `contains` | `text` |
| `visible` / `exists` | `visible` | 无 |
| `enabled` | `enabled` / `disabled` | 无 |
| `checked` | `checked` / `unchecked` | 无 |
| `value` | `equals` / `max_length` | `text` 或 `max_length` |
| `count` | `equals` | `count` |
| `attribute` | `equals` | `name`、`value` |

点击写在预期栏，仍是层不匹配：程序图里不出现这条点击，预览写明写错了栏。

### 2.3 没盖住的字

摘录没有盖住的非空白、非标点，在预览和用例列表里保持原文位置，样式置灰，标成未执行。已识别的片段用现在的事件芯片。置灰的是这几个字，不是整行。

标题、操作、预期都有内容、只是有几个字没盖住：行可以勾选导入。导入后这几个字保持未执行，整条不开跑。这和下一节的「缺列」不是同一种灰。缺列是整行不能导入。

## 3. 导入

### 3.1 缺列

标题、操作、预期三列，任意一列去空白后为空：这行 `status=incomplete`。不调用 `case-step-compile`，不写程序图，不新建 `control_id`。导入表里整行置灰，勾选框不可用。

标题列兼容现在的 `name`。两列都空才算标题缺失。

### 3.2 每 5 条一批

现在 `POST .../cases/import/preview` 在一次请求里把每一行都解析完再返回。八十多行、每行又有多步模型调用，请求会拖到超时，页面一直转。

改成：

1. 同一次预览请求只做分列和缺列判断，马上返回 `preview_token` 和每一行的占位（缺列的已是 `incomplete`）。
2. 完整行按上传顺序每 5 条一组。服务端逐组解析。
3. 页面用 `preview_token` 轮询 `GET .../cases/import/preview/{token}`。响应里有 `parsed`、`total`、`done`，以及已经解析完的行。
4. 全部 `done` 后才能提交导入。未解析完的行不能勾选。
5. 轮询间隔由页面定，建议 1 秒。取消预览时丢弃这个 token 上还没跑的组。

5 是一组的大小，不是并行 5 个模型请求。组内仍逐条解析，避免把供应商限流打满。组大小放在导入设置里，默认 5。

同一张表里已经解析过、原文没变的行，复用程序图，不再调用模型。这是上一份方案里的缓存，导入也走它。

## 4. 不合理的地方

这些按字面做会和现有执行方式打架，本文不采用。

| 原文 | 问题 | 本文怎么定 |
|---|---|---|
| 一个 `locator_type`，同时又有三格 `locator_value` | 类型只能有一个，值却有三套 | 不设总的 `locator_type`。看图用 `vlm_text`，DOM + Web 用 `playwright`，DOM + Android 用 `uiautomator`。选中的格为空就补这一格 |
| 看图新建控件时写上 Playwright / UI Automation，或写入坐标 | 看图没有 DOM。坐标随版本、页面、弹窗变化 | 看图只存描述。坐标只在当次执行里使用。DOM 定位只在 DOM 命中后写入对应那一格 |
| `step_type` 固定写 `action`，又要求 `action_type` | 两个字段说的是一件事 | 保留两者：`step_type` 区分操作和预期，`action_type` 才是点击、输入、等待 |
| 预期里写了两次 `assert_type` | 第一个其实是步骤种类 | 步骤种类不重复占 `assert_type`。预期只保留一个 `assert_type` |
| `select` / `upload` / `hover` 直接当能执行 | 目录里没有这些能力 | 解析结果里保留。提示用现成的「无法执行，当前版本未实现」 |
| 缺列和「有几个字没盖住」用同一种灰 | 缺列是废行；没盖住的是还能看的原文 | 缺列整行不可选。没盖住的字置灰，标未执行。行可以导入，整条不开跑 |
| 八十行一次解析完再返回 | 模型调用次数乘上步骤数，必然超时 | 先返回占位，每 5 条解析一批，页面轮询 |
| 导入时就要求控件三条定位都齐 | 新用例还没采集过，永远导不进 | 导入只要求 `vlm_text`。DOM 定位后补 |

## 5. 先看效果，合并以后再定

这一期把数据留全，不做合并和拆分的操作界面。两条描述很像的控件先各存各的 `control_id`。等跑过一批、看清哪些其实是同一个，再定怎么并、怎么拆。

这一期要留在数据和日志里的：

- 每一格定位带 `source`：`case`（用例描述）、`capture`（采集）、`dom_hit`（DOM 执行时补上）。看图只标 `case`，并且只写描述。
- 导入轮询可以取消。关掉弹窗后，还没跑的组不再调用模型。
- 某一行超时，只重跑这一行，已经解析好的行保留。
- 一次执行在 session 里写下用了哪一格：`vlm_text`、`playwright` 或 `uiautomator`。看图同时记下当次坐标只出现在这次执行的参数里，不回写控件。

## 6. 怎样算做完

- 同一句「右上角登录」在两条用例里复用同一个 `control_id`。对象上 `vlm_text` 有值，`playwright` 和 `uiautomator` 为空。
- 操作步能看到 `action_type`、`target_desc`、`control_id`。预期步能看到 `assert_type`、`rule`，以及它关联的 `step_id`。
- 看图任务只读 `vlm_text`。DOM + Web 只读 `playwright`，DOM + Android 只读 `uiautomator`。空格在这次执行里补上；看图补的是描述，不是坐标。
- 预览里没被摘录盖住的字是灰的，标成未执行。识别到的字不是灰的。
- `select`、`upload`、`hover` 的预览文案是「无法执行，当前版本未实现」。
- 导入 80 行时，第一屏在分列之后就出现，随后每 5 行补上解析结果，直到 `done`。
- 标题、操作、预期缺任意一列的行是灰的，不能勾选，也没有模型调用。
- 预期栏写成「点击登录」时，仍然是层不匹配，不生成点击步骤。
