# Scout 插件下放到节点

> **状态**：已落地。飞书读文档、Meego 换票、飞书机器人 / 企业微信发消息、微信扫码都在 Scout 上调用。`user_plugin_secrets` 里的旧密钥已清空，不搬到节点。  
> **要回答的事**：CLI、邮箱、机器人这些插件的调用和密钥从 Nexus 挪到 Scout；网页只留 mino-workbench，插件参数按节点配置；CLI / MCP 不打进安装包，由 Scout 本机安装。  
> **关联**：[定位与系统边界](../../scout/01-定位与系统边界.md)、[安装与分层产物](../../scout/02-安装与分层产物.md)、[更新链路](../../scout/03-更新链路.md)、[协议与节点生命周期](../../scout/04-协议与节点生命周期.md)、[OTP / Gmail](../../基础框架/OTP_GMAIL.md)。

Nexus 继续决定什么时候做。真正拿密钥去连 Gmail、飞书、Meego、机器人的那一下，只在 Scout 那台电脑上发生。

## 1. 现在密钥和调用在哪

插件清单在 `plugins_store.INTEGRATION_PLUGIN_SPECS`。分类是文档 / IM / 缺陷 / 设计。密钥在表 `user_plugin_secrets`（按 Nexus 登录用户一整份 JSON）。策略开关在 `plugin_policies`，不含密钥。

| 插件 | Nexus 上实际在做的事 | 密钥 |
|------|----------------------|------|
| `gmail_otp` | `local_executors._fetch_gmail_otp` 在服务端用 `imaplib` 登录 | `app_password`、收件箱地址 |
| 飞书 | `feishu_doc_service` 用开放平台 HTTP 拉文档；长连接收消息尚未搬完 | `app_id` / `app_secret` 等，机器人行在同一份用户 JSON |
| 企业微信 / 钉钉 / Slack | 主要是把 webhook 存下来 | webhook、secret |
| 微信 | 扫码登录尚未搬完，条目还在 | 会话若写成功能，会落在服务端 |
| 禅道 / Figma | 连通和拉稿可以在 Nexus 上跑 | token |

另外两处和「账号之间不共用」直接冲突：

- `get_gmail_app_password(user_id)` 按**发起跑批的登录用户**取密码。密码在服务器上。
- `first_configured_gmail_inbox()` 会扫 `user_plugin_secrets` 里**任意一个**已配置用户，拿来做开号兜底。

`config.json` 里今天有节点自己的 `nexus_url` 和安装 token。插件密钥不在这份文件里，在 Nexus 的库里。

能力目录里的 `system_shell` 是 **adb 在设备上** 的抽象能力，不是在 Scout 这台电脑上跑命令。两边不要合成一个。

## 2. 拆到 Scout 的原因和范围

服务端若保存所有人的第三方 token，库文件、备份、日志、误导出都是泄漏面。插件密钥不再进 `mino.db`，也不进 Nexus 日志。

拆的是**插件的调用和参数**，不是跑批大脑：

| 留在 Nexus | 放到 Scout |
|------------|------------|
| 何时取验证码、过滤条件（发件人、主题、To、轮询时长） | IMAP 登录和读信 |
| 何时拉文档、何时发机器人消息 | 飞书 / Meego CLI、机器人 HTTP、微信会话 |
| 派给哪一台节点 | 本机安装 CLI / MCP、本机执行它们的命令 |
| 节点是否已安装、是否已配置（布尔） | 密钥本身 |

大模型供应商的 key 仍走 `settings` / `settings_store`，不在这次插件拆分里。

禅道、Figma、钉钉、Slack 同样停止在 Nexus 写密钥、停止在 Nexus 发起调用。本轮网页不给它们做入口。以后要做，按下面四类往节点上加，不恢复「文档 / IM / 缺陷 / 设计」。

已有 `user_plugin_secrets` **不自动搬**到节点上。自动搬等于再把全部密钥从库里读出来传一遍。各节点首次安装后是空的，由使用这台机器的人在网页上重填。旧表停止读写；清表由运维在备份之后做，不在排查或实现时对 `mino.db` 做删除。

## 3. 密钥放在节点上

一个 Scout 节点一份插件参数。节点 A 的密钥节点 B 读不到。跑批只用**当前执行节点**自己的密钥。这台机器没配，这一步失败，并说明去这个节点的对应分类里填写。不回退到别的登录用户，也不回退到别的节点。

`owner_user_id` 仍表示这台节点归谁。它只决定网页上谁能看见、谁能改，不表示密钥存在这个用户的 Nexus 记录里。另一个登录账号不能打开这台节点的明文参数。

### 3.1 操作系统安全存储

密钥优先进本机原生保险库，由 Scout 进程以安装它的那个用户身份写入。不写 `config.json`，不写插件目录里的明文文件。保险库不可用时保存失败并提示原因，不降级成明文。

| 系统 | 存储 | 写入方式 |
|------|------|----------|
| macOS | 钥匙串 Keychain | Scout 进程调用 Security 接口。条目服务名 `MinoScout`，账户名 `{node_id}:{分类}:{插件 id}:{字段}` |
| Windows | 凭据管理器 Credential Manager | 当前用户凭据。不提权 |
| Linux | Secret Service | libsecret。没有会话里的 Secret Service 时保存失败 |

非密钥参数（收件箱地址、飞书 `app_id`、Meego 项目标识、是否启用）写在节点数据目录的插件清单里，例如 `plugins/state.json`。清单可以随心跳报「已配置」，内容本身不上报。

macOS 上，未签名或每次打包签名都变的二进制，第一次写钥匙串可能弹出系统对话框，点一次允许即可。正式签名稳定之后不应每次都问。密钥不要出现在 `security` 命令的参数里，否则 `ps` 能看到。

不为此去申请辅助功能、完全磁盘访问或自动化权限。那些和插件密钥无关。

### 3.2 Nexus 上只留状态

`REGISTER` / `HEARTBEAT` 增加 `plugins`，只有状态：

```json
[
  {"class": "mail", "id": "gmail", "installed": true, "configured": true},
  {"class": "cli", "id": "feishu", "installed": false, "configured": false}
]
```

没有密钥，没有打码后的密钥。网页根据 `configured` 显示「未配置 / 已配置」。

网页提交参数时，请求经 Nexus 转到这台在线节点。Nexus 不落库、不写入 `session_events`、不打日志正文。转发只活在这一次连接的内存里。本轮不做网页到节点的端到端加密。节点离线时不能保存，提示先让这台 Scout 在线。

## 4. mino-workbench

之后网页只维护 **mino-workbench**。Studio 和 Console 不再各做一套。本文把插件从全局入口挪进节点；两套网页里其余页面怎么合成一个 workbench，另案，不在这里展开。插件页不再往 Studio 或 Console 上加。

### 4.1 去掉全局插件入口

workbench 没有「插件」菜单。`/settings/plugins` 这一类「给当前登录用户存一份密钥」的接口停止使用。

配置发生在 **Workbench 的 Scout 节点页 → 点进某一台节点**。每台节点各自填写，互不可见。Studio 和 Console 不再加插件界面。

### 4.2 节点内四类，而不是统一插件表单

分类按**怎么接**，不按业务（文档、IM、缺陷、设计），也不是所有插件共用一张表。

| 分类 | 本轮条目 | 形态 |
|------|----------|------|
| CLI | 飞书、Meego | 本机命令行。安装包不在 Scout 主 zip 里，装好后才出现参数 |
| MCP | 无 | 分类留着。列表为空，文案写「还没有 MCP」。以后每加一个是独立的安装和参数，不并进 CLI |
| Bot | 微信、飞书机器人、企业微信 | 这台机器上的会话或机器人凭据。纯 HTTP 的不另下安装包 |
| 邮箱 | Gmail | 这台机器上的 IMAP。代码随 Scout 的 app 层更新，不单独做安装包 |

点进某一类里的某一项，只看到这一项的安装状态、进度和它自己的字段。例如 Gmail 是收件箱地址 + 应用专用密码；飞书 CLI 是安装进度，装完才是 `app_id` 和 `app_secret`；企业微信是 webhook。不要合成「连接 / 能力 / 分类」那一套旧插件卡片。

原飞书插件拆开：文档和开放平台命令走 **CLI / 飞书**；群机器人走 **Bot / 飞书机器人**。两处密钥分开存，不共用。

## 5. CLI 和 MCP 的安装

Scout 主安装包仍然只有 runtime、app、browser 三层（见 [安装与分层产物](../../scout/02-安装与分层产物.md)）。CLI 和 MCP **不打进** zip，也不进 `heavy_deps` 里那种「首次 REGISTER 就后台拉 Chromium」。

装哪一个，由这台节点的页面上点「安装」触发。Scout 按发布清单下载该插件的归档，校验清单里的哈希，解到节点数据目录 `plugins/cli/<id>/` 或 `plugins/mcp/<id>/`。清单来源与现在的 Scout manifest 相同：固定的发布地址，不接受网页或模型临时填一个 URL。

一次只装一个插件。和节点自更新并行时，后点的一方等到前一方结束。失败时删掉这一次的半成品目录，不影响已装好的别的插件，也不回滚 Scout 自己的 `layers.txt`。

邮箱和纯 HTTP 机器人没有这一步。微信如果必须带本机组件，走和 CLI 相同的按需安装；只是协议、没有额外二进制时，不安装。

### 5.1 进度条和参数

进度沿用现在自更新的形状（`stage`、`label`、`percent`、字节数），单独一条事件，不写入节点自更新的 `update_job`，避免和「更新 Scout」的进度条混在一行。

| stage | 网页上 |
|-------|--------|
| `plan` | 对照清单 |
| `download` | 进度条按字节 |
| `verify` | 校验哈希 |
| `install` | 跑该插件自己的安装入口 |
| `done` | 进度条结束，展开这一项的参数表单 |

参数表单在 `done` 之后可填。未安装完成时表单不出现。保存走第 3 节：密钥进保险库，非密钥进 `plugins/state.json`，成功后心跳里的 `configured` 变为真。

网页轮询节点列表上的插件进度即可，间隔与现在远程更新进度同一量级。

## 6. 在 Scout 这台电脑上执行命令

今天 Scout 已经会在本机起进程，但都是固定用法：

| 现有 | 行为 | 和这次的关系 |
|------|------|----------------|
| `power.py` 的 `caffeinate` | 参数写死，子进程寿命跟着 Scout，以安装用户身份跑 | 说明用户级服务本身就能起子进程，不需要再申请一套系统权限 |
| 更新用的 `install.sh` / `install.ps1` | 只跑发布包里的脚本；远程更新时 `MINO_SCOUT_UPDATING=1`，避免脚本把当前进程杀掉 | 插件安装沿用「只跑包内固定入口」，不跑网页里粘贴的脚本 |
| adb、`system_shell` | 命令发到**手机** | 不复用这个能力 id，也不把手机 shell 的放行规则用到电脑上 |

新增的是：**只为已安装插件**在 Scout 所在电脑上执行它自己的入口。没有开放「在网页里填一条 shell」的输入框，模型也不能下发任意命令。

### 6.1 谁可以发起

| 发起方 | 允许的动作 |
|--------|------------|
| 节点页上的安装 / 卸载 | 跑该插件归档里的固定安装入口或卸载入口 |
| 跑批或文档同步 | 只发具名能力（例如「用这台节点的飞书 CLI 读某文档」）。Scout 把能力映射成该插件清单里写死的参数数组 |
| 其他 | 拒绝 |

具名能力仍走现有 `EXECUTE` → `RESULT`。循环代码不出现「有没有连上 Scout」。Gmail 取码从 `local_executors` 里的 IMAP 改为：Nexus 只带上 To、时间、发件人过滤和轮询预算，**不带密码**；Scout 从保险库读应用专用密码再去连 `imap.gmail.com`。

### 6.2 限制

- 参数是数组，不用 shell 字符串，这样网页或模型里的 `;`、管道不会被解释。
- 工作目录必须在该插件目录内。可执行文件必须是这个目录里的文件，拒绝 `..` 和目录外路径。
- 以 Scout 的安装用户运行。不 `sudo`，不提权。插件声明需要管理员时直接失败并写明。
- 安装类超时与现在 `node.update` 同一量级（等待应答约 10 分钟）。单次 CLI 调用另有更短超时，写在该插件清单里，上限 120 秒。
- 超时后杀掉整个进程组。
- 标准输出回传有大小上限。回传前去掉与保险库中密钥相同的子串。`RESULT` 和 `session_events` 里不出现密钥。
- 环境变量默认不继承调用方传来的字典。密钥由 Scout 从保险库注入进程环境，注入的值不回传。
- 插件进程不监听端口。MCP 若将来要本机端口，在那个插件的方案里单独立项，本轮没有 MCP，不预开端口。
- 本机日志记：节点、插件 id、入口文件名、退出码、耗时。不记参数里的密钥字段。

### 6.3 权限

不新做一套授权弹窗。Scout 已经是该用户的 launchd / systemd 用户服务 / 计划任务，起子进程和现在跑 `install.sh`、`caffeinate` 相同。

需要人点的只有第 3.1 节钥匙串（或另两个系统的等价保险库）第一次写入。安装插件、跑 CLI 不再额外要辅助功能或磁盘权限。

## 7. 协议（实现时同一轮改两仓）

按 [开发手册](../../开发手册.md) 和仓库协议规则：改 `docs/基础框架/PROTOCOL.md`、golden fixture、两仓 `protocol.py`，同一轮完成。

| 名称 | 方向 | 作用 |
|------|------|------|
| `Register` / `Heartbeat` 的 `plugins` | S→N | 仅安装与是否已配置 |
| `node.plugin_install` / `node.plugin_remove` | N→S | 按清单安装或移除一个 CLI / MCP |
| `node.plugin_progress` | S→N | 进度，字段对齐现有 `node.update_progress`，独立于自更新 |
| `node.plugin_config` | N→S | 写入参数。密钥只在 Scout 落入保险库 |
| 具名插件能力（如 Gmail 取码、飞书 CLI） | N→S | 普通 `EXECUTE`。参数里没有密钥 |

旧 Scout 不带 `plugins` 时，节点页显示「需更新后才能配置插件」，不把缺字段当成已配置。

## 8. 落地顺序

| 顺序 | 内容 |
|------|------|
| 1 | Scout 保险库读写；心跳带 `plugins` 状态；Nexus 停止读写 `user_plugin_secrets` |
| 2 | Gmail 取码改为向当前节点发 `EXECUTE`；失败文案指向该节点的邮箱分类 |
| 3 | workbench 节点页四类；Gmail 可配置；CLI / Bot 条目在，MCP 为空 |
| 4 | CLI 按需安装、进度条、装完后的参数表单；本机执行限制按第 6 节 |
| 5 | 飞书 CLI、Meego、三个 Bot。微信有额外组件时才走安装 |

第 1 步之后，服务端新写入的插件密钥应为零。旧行留在表里直到运维清理，代码路径不再读取。
