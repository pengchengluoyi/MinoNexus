# 看图方案准出优化

> **状态**：开发中。上一回合只判 `pass` 或 `fail`。DOM 方案仍在当回合读节点值。  
> **关联**：[动作空间与语义转译方案](动作空间与语义转译方案.md)  
> **仓库**：后端 `MinoNexus`。看图执行是 `agent-vision-exec`，入口 `loop/vision_exec.py`。  
> **要回答的事**：看图读不到输入框里的字时，登录准出为什么把「没读到」当成「没写上」；其他事件能不能同样改到下一回合看图；下一回合要带哪些位置和元素信息才能对准。

对照这次 Web 登录：`cr-6751c5d5f8c5::case-c6a41093`。模型以为点的是邮箱框，字进了验证码框。当回合 DOM 读回是空的，一条准出记 `field_value_unread`，另一条因为回执里有 `@` 又记 `email_field_input` 通过，接着去等验证码邮件。

## 0. 拍板

| 题 | 决定 |
|---|---|
| 谁在当回合读框里的字 | 只有 `action_scheme=dom`。节点值空就是没写上 |
| 看图方案当回合做什么 | 不靠 DOM 值关闭里程碑。设备回执只说明动作发出去了 |
| 看图方案何时算做完 | 下一回合 `agent-vision-exec` 看图，对照上一回合留下的检查单 |
| 上一回合是否达成 | 只有 `pass` 或 `fail`。没有第三种 |
| 检查单放哪 | 挂在当前里程碑上，并写进 session。下一回合提示词只读这一份，不重新猜 |
| 检查单里有什么 | 落点坐标、元素类型、字段种类、预期。不写被测 App 的文案白名单 |

DOM 方案不改这条。看图失败也不改走 DOM 读回。两条仍按 [动作空间](动作空间与语义转译方案.md) 互不改道。

## 1. 输入：登录不要把空读回当成没写上

### 1.1 现在错在哪

看图输入的落点是模型坐标（`point_policy=coordinate`）。Scout 只在这个点键入，不保证焦点在邮箱框。

当回合准出走 `attach_input_readback` → `device_input_text_exit`：

- 读到空字符串：`field_value_unread`，登录块当成没写上。
- 没带读回、回执里却有 `@` 或字段名 `email`：`email_field_input` 直接通过。回执格式是 `输入(email)@(x,y) …`，坐标里的 `@` 和字段名都会命中。

看图路径上，层级经常没有输入框的 `value`。空读回只说明 DOM 没给字，不说明画面上没有字，也不说明字进了哪一个框。上面那次就是字进了验证码框，邮箱框仍是空的。

### 1.2 看图输入改到下一回合

`action_scheme=visual` 时，`input_text` 当回合：

1. 设备回执是 pass 只表示键入动作已发出。里程碑保持进行中，记 `visual_check=pending`。
2. 不调用「节点值为空 ⇒ 没写上」。
3. 写下检查单（§3）。预期是：指定坐标上的输入框里看得到本次要填的内容。
4. 下一回合先给出 `prior_status`，再做新动作。未通过时，菜单里不给 `get_otp` 和发码点击。

下一回合只回答上一步做完了没有：

| `prior_status` | 含义 | 里程碑 |
|---|---|---|
| `pass` | 检查单上的位置、元素和预期都对上了 | 上一回合的里程碑改为通过 |
| `fail` | 没对上。框是空的、字在别的框、点错控件、画面没变化，都是失败 | 上一回合改回进行中，用这次的动作重做。连续两次失败则停止 |

不设「看不清」「可能」「跳过」。画面已经稳定时，模型必须二选一。没填 `prior_status` 时，程序按 `fail` 处理。

画面还在加载时，本回合只调用 `wait_screen_ready`，不要填 `prior_status`。这一下不是裁定：不记失败，检查单留着。等下一张稳定画面再给 `pass` 或 `fail`。明确的 `fail` 会把本回合带回的重做动作发出去；连续两次明确失败才停止。

`field_value_unread` 只留在 DOM 方案。看图方案不用它关闭登录。

## 2. 其他事件：同样用下一回合看图收口

点击、滑动、刷新、发码，当回合的设备 pass 只表示动作发出。完成与否由下一回合看图按检查单裁定，同样只有 `pass` 或 `fail`。

| 上一回合动作 | 下一回合看到这些才是 `pass`，否则 `fail` |
|---|---|
| `input_text` | 该坐标的输入框里有预期内容 |
| `tap_element` | 该里程碑标题已经完成。标题来自里程碑自己的 `title`，不另写 App 文案 |
| 滑动 | 列表或页面相对点击前发生了位移 |
| 刷新（仅 Web） | 页面已换成刷新后的画面 |
| 发码 | 验证码框已经可以填写 |

预期栏里的检查（弹窗是否出现、文案是否存在）本来就是看图断言，不占用这条「动作准出」。动作准出只回答「上一步做完了没有」，不代替用例预期。

未执行的预期保持未执行。设备在前置里点过、租过号，不能把预期涂成通过。

## 3. 下一回合看图要带的检查单

检查单在动作回执之后写入，在下一次 `run_vision_exec_turn` 之前放进 `success_criteria.prior_action`。模型必须先输出 `prior_status`（`pass` 或 `fail`），再输出本回合的新动作。没有待查单时不要填 `prior_status`。

一条检查单只描述上一回合的一个动作：

| 字段 | 含义 | 例子 |
|---|---|---|
| `milestone_id` | 被推迟裁定的里程碑 | `account_fill` |
| `capability_id` | 上一回合的动作 | `input_text` |
| `x`, `y` | 落点，千分比 0–1000，与 EXECUTE 同一套 | 模型给出的点，不是换算后的像素 |
| `role` | 元素类型，用目录枚举 | `input`、`button` |
| `field` | 输入框种类。非输入动作为空 | `email`、`sms_code` |
| `expected` | 这一处应看到的结果 | 本次要填的文字，或 `focused`、`screen_changed` |

`role` 和 `field` 来自动作参数和目录槽，不在提示词里写某个 App 的按钮文案。预期是这次要填的值或一种状态名，不是屏幕上的句子。

注入给看图的文本固定成一块，例如：

```text
上一回合待查
里程碑 account_fill
动作 input_text
位置 (630, 492)
元素 input
字段 email
预期 框内看得到本次填写的邮箱
画面还在加载时只调用 wait_screen_ready，不要填 prior_status
画面稳定后先给出 prior_status：pass 或 fail
```

坐标用动作当时的千分比。下一回合截图像素变了，也按同一千分比在画面上找，不把视口像素再换一次。日志里模型坐标和 Scout 落点像素可以并存，但检查单只保留千分比，避免把同一次点击记成两个位置。

session 记一条 `review/dispatched`。下一回合回答后记 `review/pass` 或 `review/fail`。没有 `pass`，不能把里程碑改成通过。

## 4. 和现有代码的边界

| 现在 | 看图方案改成 |
|---|---|
| `device_input_text_exit` 用节点值或回执里的 `@` 关闭邮箱步 | 看图输入不走这条关闭。DOM 方案仍走 |
| `milestones.py` 读回失败后，另一条路径不带读回又判通过 | 看图不走这条。只认下一回合的 `pass` / `fail` |
| `attach_input_readback` 空值即 `field_value_unread` | 看图当回合不调用它来收口 |
| `agent-vision-exec` 的 `prior_status` 为 done / pending | 改为 `pass` / `fail`。检查单带坐标、元素类型、字段和预期 |
| 点下去即成功（动作空间方案） | 设备 pass 仍表示点已发出。里程碑通过改到下一回合看图确认 |

不做的事：不把看图失败改成 DOM 补点；不在检查单里放 App 文案表；不让预期句子借用别的通过步骤来上色。
