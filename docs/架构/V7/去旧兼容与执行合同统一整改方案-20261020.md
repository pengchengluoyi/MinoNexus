# V7 去旧兼容与执行合同统一整改方案

日期：2026-10-20。

状态：部分源码已实施，继续整改中。第一批记录及下方接续记录说明实际范围；进程加载与真实链路尚未验收。

## 0. 决策、范围与既有计划的关系

用户决策：当前为测试版本，不再承担历史版本、历史数据格式和旧客户端的兼容。删除历史适配，统一当前合同；不再靠增加兜底分支修补差异。

本方案新增稳定性整改范围，使用 `V7-ST01`～`V7-ST08` 编号，不占用既有 V7-01～07、V7-R1～R9、V7-C* 编号。资源复位和真实跨端验收与 V7-R3/R4/R9 共用证据，不重复宣称完成。与 V7-C5 的关系是：本次仅要求去除历史迁移和补猜、保证当前空库初始化，不自动扩展为 verify_only、两阶段激活或零写启动整体重构。

参考：[旧版兼容与全局合同差异清单](minonexus-compatibility-contract-audit-20261020.md)。清单包含 C01～C32、D01～D21 的源代码位置与证据级别。本方案给出实施批次和验收要求。

范围包含 Nexus、相关 Scout 协议、Workbench 输入输出及当前文档。当前已审查的是 Nexus；Scout、Workbench 实施前必须核对各自规则及对应调用方，不能推定跨仓已兼容。

## 1. 目标与非目标

目标：

1. 一个事实只允许一种内部表达：身份、平台、渠道、模式、能力、阶段、资源和结果。
2. 当前合同缺失或不合法时明确拒绝，禁止转换成另一个平台、渠道、账号或执行方式。
3. 目录、菜单、绑定和派发基于同一份规范声明；必要的实时复查使用同一规则。
4. 任何拦截可说明在哪一阶段、哪条规则、基于哪些事实发生，以及如何恢复。
5. 全新测试库可以直接初始化并执行当前产品功能，不依赖历史数据库经历过若干次升级。

本轮方案不包含：删除用户现有数据库、自动搬迁数据、停掉用户 IDE 进程、移除普通 Agent 功能、扩大到零停机部署或所有历史设计需求。

保留账号与项目隔离、设备归属、未知写入隔离、幂等和事务准入。合法的当前运行降级（如结构不可用时按任务策略看图）不属于旧版本兼容。

## 2. 必须先统一的合同

| 概念 | 目标合同 | 禁止行为 |
|---|---|---|
| 目标平台 | `mac / win / android / web` | 接受 desktop/pc/ios/browser/adb 后在执行中猜测转换 |
| 宿主系统 | `mac / win / linux` | 将 Linux 宿主当作 Linux 原生被测平台 |
| 执行器 | 当前声明的 desktop/playwright/adb 等 | 用执行器名代替目标平台，或按 sn 前缀猜平台 |
| 平台覆盖 | 显式 scope；all 与 explicit 空集合不同 | 缺字段默认无限制；不同入口解释不同 |
| 渠道身份 | 原样稳定 ID + app_id + platform | 去点、截断、改变大小写后选别的渠道；首项跨平台回退 |
| 设备身份 | 经注册验证的 node_id/sn/platform | 未注册身份自动补全为 Android 或 adb |
| 普通执行模式 | 对外及内部统一为 `agent`（本方案目标） | 把 legacy 名称误认为必须整段删除的功能 |
| 严格执行模式 | 保留当前 v5 功能边界；合同版本另有字段 | 用 v5 替换所有平台、所有临时指令任务 |
| 能力 | 完整 event/caller/phases/lifecycle/implementation | 缺失时从名称、kind、visible_to 或白名单补猜 |
| 在线状态 | 边界规范化，统一状态判断 | UI、菜单和派发分别维护不一致白名单 |
| 网站归属 | 解析后的 origin，额外范围显式配置 | 用 URL 字符串包含或前缀证明同站 |
| 数据版本 | 当前 schema 与声明版本一致 | 读取时升级；DB 出错退回另一份 JSON 真源 |

`agent` 是拟实施的规范模式名，不表示现有代码已完成重命名。修改时须同步 API 默认、任务持久化、系统能力载荷、Scout 分派、Workbench 请求、幂等摘要及诊断字段。规范化必须发生在请求摘要计算之前。

空值原则：必须信息缺失 → needs_input；明确非法值 → invalid/rejected；明确不适用 → not_applicable。不能把这三种情况统一处理成默认平台或放行。

## 3. 实施批次

### V7-ST01：固定版本与依赖基线

状态：待实施。先完成本批，再并行安排互不冲突的改动。

- 记录 Nexus/Scout/Workbench 的源码版本、未提交改动、实际运行版本、进程启动时间、当前环境与数据根。

### V7-ST02：修正平台、渠道和站点身份

优先级：最高。覆盖 D01～D12、D14、D21，及 C01/C02/C07/C13/C15 中相关部分。

改动范围：`core/platform_contract.py`、AI 场景 schema、runtime 场景与平台判定、导航作用域、设备存储、控件定位、项目环境解析、Bot 作用域及对应 API。

- CaseScene、clamp、导入、筛选、导航和执行统一使用规范目标平台。
- 删除把未知/mac/win 自动改成 Android 或 adb 的逻辑。
- 四个平台统一检查平台覆盖；缺失、空集合和 all 不混用。
- 显式渠道不存在立即拒绝；平台不匹配立即拒绝；多候选需明确选择。
- 精确保存和匹配合法 channel ID，不使用 slug 作为身份转换。
- 先解析确定的渠道，再做执行环境白名单校验；有限白名单遇到空渠道不能直接通过。
- 原生桌面定位字段与 Web DOM 分开，不能因“不属于移动端”就选 Playwright 字段。
- 网页范围采用 URL 解析后的 origin；禁止 example.com 与 example.com.invalid 被视为同站。

验收：见第 5 节矩阵。函数级验证后，必须检查真实执行是否消费相同合同；不能只修校验器而让下游继续使用旧值。

### V7-ST03：去除旧数据真源与隐式迁移

覆盖 C01～C12、C21/C26/C28/C30 中历史数据部分，以及 D20/D21。

- 数据目录由一个入口决定；删除 macOS 旧 ~/.mino-nexus 自动回退，保留开发/正式完全隔离。
- 新库直接由当前 ORM 和当前声明初始化；旧版本不匹配应明确拒绝，不自动迁移。
- 把当前系统能力/恢复规则初始化与历史 upgrade 分开：删除旧升级链后，新库仍须有完整能力。
- 项目读取不补 admin、不补写时间；号池读取不迁入 env.test_accounts。
- 导航草稿只使用当前 DB 存储；保存异常返回失败，不另存旧 JSON 冒充成功。
- 删除旧知识、控件身份、旧议题、旧用例收养等运行时迁移路径及其无消费者入口。
- 删除不可达的共享密钥迁移代码，不运行它，不把旧共享凭据搬给任何用户。

验收：读请求没有迁移副作用；DB 故障不会切换真源；空库初始化完整；旧库不会被当前服务自动升级、清空或接管。清理旧数据库文件不属于本批实施动作。

### V7-ST04：统一能力目录、菜单与执行绑定

覆盖 C18/C19/C23、D13～D18，以及上一轮能力/导航阻断。

- 当前目录初始化写全 caller、phases、platforms、lifecycle、实现依赖和参数/结果合同。
- 删除运行时 derive/adapt 补猜；普通执行所需的本地能力通过正式声明注册，不丢失功能。
- 统一 lifecycle、阶段、平台、连通性和依赖求值；菜单仅是可调用能力的投影。
- 统一 params 与 parameters 的构建入口；核对普通目录和桌面动态能力两条路径。
- 导航意图与可执行事件分层；缺图按当前策略降级或在准入时明确阻断，不能先当作缺失事件再反复加例外。
- 将现有导航修复按实际工作树接续，不覆盖他人未提交修改；确认进程加载后使用新 session 验收。
- 拒绝原因逐层记录，不再统一写“平台或连通性过滤”。

验收：同一事实快照中菜单、绑定和派发对能力是否可调用结论一致；发生实时状态变化时有版本和明确原因；所需系统事件不会依靠历史库才存在。

## 4. 删除实施纪律

1. 先明确当前合同及消费者，再删除适配层；不在新合同外补第二套兜底。
2. 没有历史兼容不等于没有恢复能力；权限、幂等、隔离、重连及当前视觉降级仍保留。
3. 不删除“名称为 legacy 但承担当前功能”的实现；更名并同步声明/消费者。
4. 不执行旧迁移来给新方案准备数据。旧库和新测试库分离，旧库保留原样。
5. 当前工作树有未提交改动，实施前逐项核对，禁止重置或覆盖无关修改。
6. 源码改动、已加载、局部通过、真实验收四种状态分别记录，不混称“完成”。

## 5. 最小验收矩阵

| 场景 | 必须得到的结果 |
|---|---|
| mac/win 在场景、设备、导航、定位与派发间流转 | 身份不变，不出现 Android/adb/Web 兜底改写 |
| explicit=['web'] 配 Android | 不适用或明确拒绝，不进入 Android 执行 |
| explicit=[] / 缺 scope / 非法平台 | 分别按当前合同处理，不能一律不限平台 |
| 只存在 Android 渠道，请求 win | 明确无匹配，不返回 Android 首项 |
| 显式渠道不存在 | 拒绝，不改选其他渠道 |
| 渠道 ID 为 web.shop、大小写、较长合法 ID | 原样匹配，不截断去点 |
| 执行环境有限白名单，surface 缺失 | 先解析或 needs_input，不直接放行 |
| example.com 与 example.com.invalid | 不同站点；采集/恢复不误认目标 |
| 相同在线状态进入 UI/菜单/派发 | 判断一致；未知状态明确不可用 |
| 能力 phases 空、lifecycle 非 active、缺 implementation 合同 | 明确拒绝加载或准入；不前放后拒 |
| 普通目录与桌面动态能力 | 参数和依赖完整，菜单与绑定一致 |
| 全新数据库启动 | 当前能力齐全，不依赖历史 upgrade |
| DB 保存失败 | 显式失败，不生成旧 JSON 第二真源 |
| 旧目录存在 / 旧 schema / 旧 Scout | 不自动接管或迁移；版本不符明确说明 |
| 节点完整快照撤销一个执行器 | Nexus 不残留旧执行器能力 |
| 多 Web 槽、桌面独占、队列及隔离槽 | 容量解释与事务准入一致 |
| 写入结果未知、取消、断连及复跑 | 不盲目释放、不重复写入；恢复证据可追溯 |
| 缺 NavFSM 的普通执行 | 按当前策略降级或预检明确拒绝；新 session 证明结果 |
