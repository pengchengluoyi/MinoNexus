# V7-EX01 登录状态失效与诊断修复

日期：2026-10-20。承接 EX01 §10、§18、§23；保留工作树中已有首批缺陷与场景快照修复。本批只处理可确认的运行态问题，不把源码修复视为真实跑批验收。

## 本批变化

1. `mark_session_dirty` 统一将 `device_session`、`session_fact`、`task_session` 置为 unknown，撤销 `login_state_verified`，清除当前凭据提示与矛盾标记。原先仅置 dirty/清 evidence，读取 `device_session` 的里程碑逻辑仍可能拿到旧 logged_in；不传 reason 时也必须失效事实。保留 `login_form_visible` 对提交证明的既有处理。
2. `stamp_session_observation` 同步已校验的 session 至 `device_session` 及其 source，避免不同消费者读到新旧两份结果。继续遵守已有登录证据门禁，凭据不直接证明登录成功。
3. 新用例开始清理宏已完成集合、视觉让出记录、系统弹窗完成标记、自动提交次数和 OTP 失败计数；复位后 task_session 与 session_fact 对齐。业务步骤切换同时清理 `login_macro_yielded`，不能继承前一步的历史索引。
4. `web_auth_hint`、`session_contradiction` 每次观察先复位，并分别写入 `login/web_auth_hint`、`login/session_contradiction` 事件。只复用与 ctx.session_id 一致的 active writer；没有匹配 writer 时记录诊断未落盘警告，不串写其他会话。事件仅包含布尔提示、状态枚举与来源，不包含 Cookie、令牌、账号或截图正文。
5. 矛盾检测区分原始屏幕状态和经证据门禁后的 effective_session；原来屏幕同为 logged_in、但身份核验不足降为 unknown 时会被误记为状态矛盾。本批比较原始已知观察，事件另外记录有效状态，仍不放宽登录成功判定。
6. 删除无读取的内部 `_login_flow_step_n` 声明与写入，继续以 cursor.step_nav_plan_step_n 控制步骤切换。

## 核对结论

- `observation_fallback_reason` 已随公开上下文序列化，且观察策略本身已有 `observation/strategy` 与 `observation/fallback` 事件；不能仅因没有显式 getattr 就认定诊断完全未接。
- `task_session`、`env_fact` 属于公开上下文快照字段，本批不直接删除；task_session 先修复失效同步。未确认跨模块消费者前，不把“局部源码未读”当作删除公共字段的依据。
- 本批未删除特性开关，未合并 flow_block v1/v2，未改 v5 模式，未实现完整 CaseSession 单一写者或 TerminalReason 标注。
