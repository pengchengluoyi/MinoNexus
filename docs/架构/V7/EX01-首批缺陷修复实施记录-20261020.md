## 本批修复

| 问题 | 实施 |
|---|---|
| last_shot_width/height 无写者 | binding_cache 改读已由观测入口维护的 viewport_wh；没有尺寸或坐标不合法时不写坐标匹配缓存，文本/resource_id 指纹仍正常匹配。复用已有 milli_to_viewport_px 与执行侧换算语义，不改出站坐标协议。 |
| 旧帧尺寸残留 | 两处观测入口在采集前清空 viewport_wh，仅在宽高有效时更新。 |
| target_app_name 无写者 | 绑定项目时，从已经校验的 app_id 对应应用记录取 name，写入显式上下文字段；不从包名或用例文字猜应用名。 |
| 资源审计 session_id 缺失 | 用例入口在恢复租约前绑定真实 stream_id；审计与镜像统一读 ctx.session_id，移除 report_run_id 的隐式读法和 80 字符截断。 |
| 审计跨会话风险 | 只有 active_writer.session_id 与上下文一致时才复用 writer；否则按上下文 session_id 追加事件。缺 ID 记录诊断，不再静默丢失。 |
| 菜单 fail-open | 普通菜单（含 extra_ids 和各 audience）、恢复菜单均须有当前版本、已提交 binding 和菜单投影函数；缺任一项返回空菜单。仍调用绑定的实时校验函数，不仅检查字符串。 |
| 循环准入绕过 | 进入循环前要求已提交 binding；未绑定返回 blocked/binding_not_committed，并写 execution/blocked、execution_started=no。 |
| 两处默认 Android | RunContext.platform 默认 None；节点不存在时不再补 Android；from_node 只读设备声明，不由 SN 猜平台。无效设备平台在循环前 blocked/device_platform_invalid。 |
| 资源平台伪造 Android | resource_transition_engine 按统一四平台校验，Windows/macOS 不再被落成 Android；未知平台不能从租约补猜。 |

只声明本批实际用到的 case_id/session_id/target_app_name/viewport_wh/binding 字段。菜单回调不参与上下文序列化，避免复制绑定对象的锁。未宣称已完成 LoopState/CaseSession 状态所有权重构。

## 行为影响

当前探索入口没有建立 execution binding；本次收紧后明确 blocked/binding_not_committed，不再沿用无绑定的菜单/派发路径。探索恢复执行需要独立补齐动态探索的绑定合同，不属于已完成项。普通已绑定用例继续走现有执行循环；不合并 v5 循环。

无观测尺寸时放弃坐标缓存命中，不把 milli 数值当像素；不会替换执行器或放宽成功判定。

## 验证

未运行 pytest、未新增仓库测试或 mock、未操作真实设备、未写真实业务库。

在工作区独立临时库与纯函数检查中通过：
- 缺节点平台保持 None，显式 win 不被改写。
- 缺版本/缺 binding/缺投影函数均为空菜单；合法绑定只返回许可能力。
- 1280×800 下 (500,500) 命中像素中心 (640,400) 的节点，而非 (500,500) 节点；无尺寸、负数、越界、NaN/Infinity 不匹配。
- 应用名称来自实际应用记录。
- 无 active writer、同会话 writer、另一会话 writer 三种场景，审计与 session_events 均关联到同一真实 session_id；超过 80 字符的 ID 保持完整。
- 持有 RLock 的菜单回调不影响上下文序列化。
- 修改文件 Python 静态编译通过。

以上是本地隔离验证，不代表真实跑批、登录或设备执行已验收。需要在 PyCharm 重载 Nexus 后，以实际 run 的 session_events + session_meta 确认。
