# Mino Bots：Grok Bot、ChatGPT Dots、Muse 与 Manus 对照

日期：2026-10-19。补充产品级生命周期、交接和上下文比较。资料为官方公开文档，不是实际账号体验或源码实现验证。不能从产品描述反推其内部架构。

## 1. 先纠正此前调研范围

此前已深入调研 Grok Bot、Muse/OpenMuse，ChatGPT Dots 和 Cue 没有得到同等深度的比较，不能声称已经完整考虑。本轮补读 ChatGPT Dots 的创建、任务/记忆和控制官方说明，并重新核对 Grok Bot 管理与协作。

关于 Cue：用户在来源补充中填写了“mause”。该名称仍不足以唯一确定产品，不将它直接认定为 Muse 或 Manus。以下额外纳入 **Manus 作为候选对应与独立同类产品**，其资料来自 manus.im；Cue/mause 的准确归属仍待明确，不影响已完成的 Mino 设计。没有找到的产品功能不编造。

## 2. 这些产品分别解决什么问题

| 产品 | 公开定位与真实使用方式 | Mino 可借鉴 | 不应直接照搬 |
| --- | --- | --- | --- |
| Grok Bot | 一个 Bot 拥有名字、职责、独立对话和长期工作上下文；可创建多个角色并组群交接 | Bot 管理、明确职责、@与回复、一个阶段一个负责人 | 不能因 Bot 隔离就推断设备/登录态完全隔离；其个人 Bot 群不等于 Mino 项目多人授权 |
| ChatGPT Dots | 常驻个人代理，跨会话推进多个责任，委派后台代理/Work/Codex，用户持续插入要求 | 一个稳定负责人协调工作、可见子任务、任务环境绑定、上下文按需传递 | 没有依据把其个人 dot 直接描述为可无限创建的项目角色市场；后台 Agent 不等于持久 Bot 实例 |
| Muse | 个人代理持续推进目标，通过专用云 VM/浏览器执行并显示行动轨迹 | 用户只交目标，系统持续做事；成果与行动可查看，后续纠正保持连续 | 不复制其云电脑/安全基础设施；当前资料不足以证明有任意多 Bot 群、模板市场及其完整删除语义 |
| Manus（独立候选） | 任务执行与成果交付；Projects 共享任务指令/资料，Collab 让多人对同一任务继续输入 | 项目级上下文、多人围绕同一成果迭代、任务产物交付 | 不是已证明的 Grok 式 Bot 花名册；项目加入不自动共享所有任务；不能把“一个当前成果”当测试历史版本可删除 |

这四种体验可组合成 Mino 的产品方向：Grok 的职责入口＋Dots 的持续协调＋Muse 的目标推进＋Manus 的共同产物迭代。但实现仍用 Mino 现有角色/job/执行服务和少量开源组件，不部署四套代理平台。

## 3. Grok Bot：创建、复制、删除、群组与记忆

官方 bots 文档给出 New→Create new Bot、名字/描述/头像编辑；角色描述适合长期职责，消息适合具体任务。创建新 Bot 应因目标、工具范围或长期职责不同，而不是每次提问都建一个。

复制包含配置、技能等，**不复制对话历史、学习记忆或附件**。模板分享生成接收者自己的副本，不共享原电脑、登录或历史。隐藏只是移出列表，不暂停任务。删除会移除活跃 profile、对话和 routines，但共享电脑上的文件和登录可能保留，后台保留另按条款；不能简化为“删除 Bot 等于所有数据删除”。

官方群组示例为 2～6 个 Bot，支持 @、回复、执行中追加要求和异步交接；人数是对方当前产品行为，不作为 Mino 的硬编码上限。Bot→group 的交接当前有文本限制；不能因此默认附件和图片自动对所有接手 Bot 可见。

记忆保存稳定偏好、事实与工作摘要，但官方同样要求变化信息回源。Mino 应采用稳定职责＋版本化项目事实，不能靠 Bot 的长期记忆替代需求/用例数据库。

## 4. ChatGPT Dots：持续负责人、后台任务与选择性上下文

官方创建流程是打开 dots、设置名字/外观、连接所需插件；电脑连接可选。云任务可以在用户电脑离线时进行，本地任务需要原连接电脑在线。一个 dot 可以持续负责多件事，不需每次新开代理。

Tasks and memory 明确：dot 可以把任务交给并行后台代理，生成可见线程并继续指导；工作应留在其原始电脑/云环境，切换选中电脑不搬迁既有任务。任务结束不代表目标已经交付，需要看产物和错误。

**新任务只收到该工作的指令和上下文，不自动获得 dot 全部对话；连接电脑也不获得所有既有聊天。** dot 的持久笔记、ChatGPT memory 与当前窗口不是同一个东西。跨 ChatGPT/Slack/Teams 是同一个 dot，但消息可见历史分别存在；知道私聊信息不等于有权对群公开。

控制语义同样分层：暂停 dot 主任务不会自动停止所有委派任务或删除定时任务；删除 dot 不撤销已对外部系统产生的修改。自定义规则可允许指定范围内不再询问，但不能自动获得未连接应用的权限。

对 Mino 的直接启发：议题持续负责人＋有限后台工作项；显式子任务状态和取消范围；按工作包传上下文；Bot 实例删除与任务/成果保留分别定义。不要把每个后台子代理都注册成永久角色。

## 5. Muse：长期目标与可见产物

官方发布说明描述：用户提出目标，Muse 整理行动计划并持续执行，应用关闭后仍可继续；可通过 Muse/WhatsApp 交流，使用专用云 VM 和浏览器，展示行动审计，允许控制连接应用和遗忘某些记忆。

这些适合借鉴“用户不管理每一步”的交付体验。对 Mino 而言，需求、方案、用例、证据都应成为可定位成果，后台继续推进，用户回来能看到改变了什么，而不是只有一屏长对话。

但该来源并未充分描述“多个自定义 Muse Bot 的新增/删除/群组/模板版本”。相关格子必须写未核实，不能从 OpenMuse 的实现补成 Muse 官方能力。OpenMuse 仍只是独立开源应用，其 alpha/单 owner/外部服务依赖边界保持首版结论。

## 6. Manus：多人共同推进和项目上下文

Projects 官方说明：项目持有 master instruction 和资料，新任务继承项目配置。项目成员可以共享这些配置，但默认只看自己创建的任务；共享具体任务需要额外邀请。

Collab 官方说明：任务 owner 开启协作并邀请成员；成员可以看历史提示/产物并向同一任务继续输入。并发提示按顺序处理，不是所有指令同时改同一个成果。其文档明确由 owner 消耗 credits，成员不能继续邀请别人；这是对方产品规则，**Mino 不应因此把群主凭证自动共享给所有成员**。

该产品还说明配置传播差异：指令更新在当前任务下一次发消息生效，文件更新只影响之后新建的任务；因此“项目资料更新了”不等于全部运行任务都已看到新版。Mino 应明确 run 输入快照与新版本影响，不能让用户猜。

文档也提示 Collab 不适合严格版本历史追踪场景。Mino 面向测试，必须额外保留需求、用例与执行证据版本，不能照搬“一份当前产物”省略历史。协作接入时登录态的变化也不应被用户隐藏地承担。

## 7. 功能对照：哪些有依据，哪些仍未知

| 维度 | Grok Bot | ChatGPT Dots | Muse | Manus | Mino 方案 |
| --- | --- | --- | --- | --- | --- |
| 持久角色 | 多 Bot profile | 持续个人 dot，多项职责 | 个人代理 | 持久项目＋任务；非等价 Bot roster | 少量项目 Bot 模板实例 |
| 新增/复制 | 官方明确 | 创建个人 dot 明确；本轮未证实无限多实例/克隆 | 自定义多 Bot 创建未核实 | 创建项目/任务明确 | 创建/复制配置；不复制私密上下文 |
| 删除/停止 | 隐藏与删除区分 | 主任务/子任务/计划分别停止；有 delete | 细粒度删除合同未核实 | 本轮未核实完整删除合同 | 隐藏/暂停/移除/软删除区分 |
| 多人共同输入 | Bot 群与 Team Bot 要分别理解 | 跨渠道连续，不等于项目共享全部上下文 | 多人共编模式未核实 | Collab 明确支持 | 项目议题，多人输入有顺序和版本 |
| 工作交接 | Bot 间消息、群协作 | 委派后台任务与后续指导 | 目标持续执行；交接合同未核实 | 任务产物＋并行研究功能 | 持久工作项、输入版本、明确负责人 |
| 上下文 | 独立对话＋长期记忆，变化事实回源 | 选择性上下文、独立任务线程、持久笔记 | 长期偏好/任务记忆 | 项目配置继承与任务共享 | 分层上下文，版本真源在 Mino |
| 交付 | 文件/消息/行动 | Activity/Outputs、代码任务 | 行动与结果审计 | 明确任务成果导出 | 需求到证据的交付清单 |

## 8. 对应开源方案如何用

首版与第二版的广泛比较仍有效，本轮补充两个与 Manus 方向相关的项目：

- **OpenManus**：README 标 MIT，提供通用 Agent、工具与 flow；明确多 Agent 版本仍标 unstable。可研究任务规划与工具调用，不把它当完整 Manus Collab/Projects 的等价替代品。引入其浏览器/终端执行链会和 Scout 边界冲突，首期不整套引入。
- **CAMEL / OWL**：OWL README 标 Apache-2.0，是多 Agent 自动化框架，具备搜索、多模态、文件与工具协作方向；可与 Eigent 的底层生态一并研究。它不是即插即用的 Mino 项目权限与证据系统，不额外叠加在 LangGraph/AgentScope 之上。

这些是复用候选与研究来源，不是本轮安装清单。许可陈述来自公开 README，正式采用还需固定版本核对 LICENSE/依赖。优先级仍是现有 Mino 服务＋嵌入式 UI；确定缺口后选一个协作库；后续开发接 OpenHands 等适配。
