# V9 Workbench — 仓库可读

日期：2026-10-29。读完 [README](README.md) 再改。只改 `../MinoWorkbench`。界面遵守该仓开发手册：不加说明性标语；不新做一套执行或能力编辑。

Workbench 把项目仓库和用例脚本读出来。执行在 Scout，租约和日志在 Nexus。

## 1. 要做

### 1.1 项目仓库

项目设置里能看、能改脚本仓库地址和分支。数据仍是 Nexus 的 `project_script_repos`。地址保存后的检出由 Nexus 完成，页面只显示是否已配置、公开 URL、分支、最近一次失败原因。

不在页面里编辑脚本文本，不提供「把脚本提交到 Nexus」的保存。

### 1.2 用例与路径

用例上展示并允许维护 `script_path`（仓库内相对 `.py`）。

列表按模块分组。模块取 `script_path` 里 `tests/` 的下一级目录名。没有模块目录的文件归在 `tests` 组。不按需求 id 做目录。一个用例展示一条脚本路径，不按渠道列多份文件。

### 1.3 应用逻辑改为读 pages

现在的「应用逻辑」页改读仓库 `pages/<page_key>.yaml`：页面、状态锚点、控件、各渠道定位单元格、入口。数据形状见 [页面与脚本](页面与脚本.md)。

没有仓库或没有 `pages/` 时这一页为空。不读取、不写回 Nexus 里的导航表和控件表。页面上不编辑 YAML；要改定位就改仓库文件。

### 1.4 阅读

沿着检出只读三棵目录：

- `tests/`：模块和用例文件，一个 `case_id` 一个 `.py`
- `scripts/`：公共业务函数
- `pages/`：页面 YAML

点开文件显示源文本。没有检出时显示仓库未就绪，不造空编辑器。

执行日志继续用现有会话时间线（`tool/result`、截图）。不新做一种「脚本轨迹」页面。

### 1.5 DSH 入口

DSH 插件打开的就是现在的 Workbench。不新增第二个前端，不把 origin 改成运行时发现。插件文档若要写地址，写编译进去的 Nexus origin。

## 2. 不要做

- 不做能力目录或「自定义技能」编辑。业务函数在 `scripts/`，定位在 `pages/`。
- 不把应用逻辑写回数据库。
- 不按渠道展示或生成多份用例脚本。
- 不提供在页面上跑脚本、装 adb、装浏览器的按钮。
- 不改用例步骤原文的结构和需求字段。需求筛选取现有 `requirement_id`。
- 不改 Nexus 和 Scout。

## 3. 做完的样子

- 配好仓库的项目能看到 `tests/`、`scripts/`、`pages/`。
- 应用逻辑列出的页面和控件与 `pages/*.yaml` 一致，刷新后看不到只存在于旧库表里的页面。
- 用例列表上一条用例一条 `script_path`。
- 打开日志看到的仍是原来的会话事件。
