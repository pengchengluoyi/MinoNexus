## 1. 结论与边界

Workbench 当前最需要解决的，不是继续逐页增加卡片、徽章和按钮，而是让用户始终能回答五个问题：**我在看哪个应用的哪一版用例；系统具体理解了什么；为什么不能运行；这次实际执行了什么；下一步应该修哪里。** 当前页面已经具备不少基础能力，但这些答案分散在不同入口、不同字段和不同状态口径里，尚未形成稳定闭环。

主要问题集中在六处：

1. **原文、普通解析、严格发布和执行证据没有完整的版本解释链。** 列表与导入已共用原文标注组件，执行三栏却仍读旧的解析字符串；用户可能看见“预览有结果，执行页未编译”，或者无法判断展示的是哪一版。
2. **状态有时比事实更乐观。** 登录确认失败仍可能进入管理外壳；健康页请求尚未成功就显示“已连接”；部分启用字段缺失被解释为启用；缺失 token 用量被显示为零。
3. **执行入口与结果口径不统一。** 用例列表快速运行和任务弹窗的模式选择不一致；批次只用通过、失败、其他概括结果，缺少明确的未执行、未核验、取消、阻塞、未知写效果和清理结果。
4. **轨迹与日志的局部体验已经改善，但证据完整性仍有缺口。** 双接口重复投影已做保守去重；步骤与回合已有关联入口。剩余问题是请求失败被吞掉、运行详情缺少持续更新、分页搜索只检索已加载部分，以及截图补位与坐标标注可能错配。
5. **资源与配置页面存在“看得到，处理不了”的断点。** 账号页只有查看，空态却提示可以分配或登记；资源日志只请求默认第一页；配置草稿缺少一致的离开保护、刷新保护和版本冲突处理。
6. **管理导航仍保留大量占位入口，工程验收覆盖也不完整。** 切到管理后台首先进入占位工作台；能力目录之间没有形成解释链；操作记录没有实际写入调用；`verify` 不包含 lint 和构建，更不等于真实浏览器业务验收。

### 1.1 这次“全页面”的含义

覆盖路由表中的全部页面、应用内六个主视图、助手的全部标签页与主要子设置、节点接入/插件/日志、关键弹窗与抽屉，以及认证、权限、查询缓存、实时更新、分页、持久化偏好等跨页面逻辑。扫描范围为 `src` 下 156 个 TS/TSX/CSS 文件，共 16,696 行；对页面实现与主数据链路做重点阅读，对共性问题做全仓引用检索。

这不是“所有潜在 bug 已穷尽”的保证，也不是逐页真实业务验收。本轮没有查询业务数据库、连接设备、调用模型、提交运行任务或执行全产品浏览器验收。确定性结论依据当前源码；需要真实部署、权限数据、业务返回体或设备状态才能确认的内容单独标明。

源码基线 HEAD 为 `1100ad5`（2026-10-14，`Integrate V5 controls and execution views`），并包含当前七项工作树变更：`src/api/run.ts`、`RunBar.tsx`、`SessionDetail.tsx`、`sessions/queries.ts`、`CreateTaskDialog.tsx`、`tasks/trace.ts`、新增 `sessionRecords.ts`。本文按工作树现状审计，不能仅用 HEAD 复现全部结论；后续行号可能随开发变化，应同时按函数名核查。

### 1.2 不重复制造旧问题

以下能力在当前代码中已经存在，必须保留，不能再当作未解决问题重做：

- WorkShell 已合并应用导航，进入应用后不再增加第二条左侧导航。
- 截图布局已按平台固定；移动竖屏图占宽上限 35%；轨迹信息与列表采用 1:3；截图使用 `object-fit: contain`；切换截图保留旧图直至新图加载；首个无图步骤有截图补位。
- 点击箭头、拖拽动线已使用独立 SVG 覆盖层，不改写原始图片。
- 用例执行详情默认轨迹；日志已有回合、事件、模型调用视图；日志原始参数默认展开。
- 导入与用例维护预览已共用原文加彩色理解标注的组件；原文没有被折叠截断；列表三段内容合计占宽 84%。
- `mergeTraceSteps`、`mergeSessionEvents`、`uniqueSessionTurns`、`uniqueModelCalls` 已处理重复投影或重复快照，保留真实重试和不同事件序号。
- 请求层已有账号代际、取消旧请求、清查询缓存和断开旧 WebSocket 的保护；不能报告“完全没有账号隔离”。
- 模型配置按当前账号查询，Key 编辑默认空白；费用页已区分未知价格/用量，不把所有未知值当零。

近期部分改动有模拟接口浏览器验证记录；它们证明对应组件在该样本下正常，不能代替全部页面在真实数据上的验收。本文列出的剩余问题，也不意味着上述改动应整体回退。

### 2.1 占位、兼容与未接入实现逐项处理

当前占位：`/settings/apps/:appId/:section`、`/settings/projects/:projectId/env`、`/dashboard`、`/catalog`、`/catalog/:projectId`、`/catalog/:projectId/apps/:appId/*`、`/nodes`、`/account-pool-templates`、`/permissions`、`/knowledge`、`/network`，以及应用内导航架构。

- 环境/应用设置：映射到已有工作台配置，先核查能否唯一定位 app/project；不能唯一定位时给明确选择，不把旧链接默默导向无关应用。
- `/nodes`：管理入口可导向现有节点页，先说明管理员视角与账号视角是否相同，不能仅改路径后假称具备全组织库存。
- `/catalog` 家族：当前应用列表已是可用入口；组织级项目维护缺口与已取消知识/文档/信息基座分开决定。
- `/dashboard`：不作为默认管理落点；首版选择真实可用的运行状态或目录入口，不为替换空页先造复杂看板。
- 号池模板、权限配置：如果影响当前V5准入，先提供必要的现有配置/错误定位；完整管理界面按服务端合同另排，不用占位页暗示已交付。
- 知识审核、网络和导航图：V5非阻塞能力默认从主工作流隐藏或明确标“尚未提供”，不展示Vue迁移来源和阶段编号。

现有兼容跳转：`/settings`→节点；`/settings/dispatch`及子路径、`/dialogue`、`/agents`、`/report/*`、`/settings/schedule`→应用列表；插件列表/详情、`/timeline`→节点；`/case-resource-key`与`/resource-transition-rules`→对应目录zone；`/access`→权限；`/system`→健康；`/doc-library`、`/app-intel`→catalog；未知路径→应用列表。处理原则是：能保留对象身份就映射，不能就明确说明迁移/失效，避免用户以为进入了原报告。

`PluginsPage.tsx`、`BatchList.tsx`、`NumberedLines.tsx` 当前在src内没有被其他源文件引用。它们是未接入/历史实现，不是当前页面已有能力；是否删除需后续独立判断，本文不清理文件。

## 3. 问题登记与修复方向

标记：**S**＝源码确认；**D**＝产品/交互缺口或设计建议；**V**＝需要真实数据/部署确认。优先级：P1＝影响身份、事实、数据或主流程；P2＝影响理解、效率、恢复；P3＝治理/维护。未确认实际影响的风险不直接冒称已发生事故。

责任范围：**F**＝纯前端可修；**C**＝利用现有接口，但需核对合同/返回与前后端协同；**N**＝需要新增或补齐服务端记录/接口，另立实施范围；**J**＝需要Nexus/Scout真实执行证据。本轮都只提出方案，不授权执行后端改动。

### 3.1 全局、认证与导航

**G01｜登录确认失败仍可进入管理界面〔S，P1，F/C〕**  
`router/guards.tsx:58–60` 允许 `loggedIn=false` 且本地有token继续；`:68–74` 的 RequireAdmin 只在 `loggedIn=true` 时拒绝非admin。`lib/session.ts:55–59` 在探测失败后清身份但保留token，因此外层RequireAuth放行，内层RequireAdmin也放行。普通用户持有token、刷新时状态请求失败，即存在进入管理外壳的源码路径。**这证明前端门禁失效，不证明服务端权限被绕过。** 应区分身份未确认、会话失效和短暂离线；管理页必须有确认的admin身份才呈现。验收：三种账号、状态接口超时/401/403/5xx，全部检查页面和写按钮，不以“接口最终拒绝”替代前端门禁。

**G02｜会话形状缺失被当已登录，跨标签页状态未同步〔S/V，P1，F/C〕**  
`lib/session.ts:47–52` 使用 `data.logged_in !== false`，空对象也可得true；tokens读取是localStorage，但未发现storage监听来同步退出/换号。账号代际已经保护单页请求，应保留；补强明确字段校验、会话状态机和跨tab事件。跨tab实际污染需运行复现，不能宣称已发生泄漏。验收：200但缺data/身份字段不确认登录；A页退出/换号后B页及时停止敏感交互，旧响应不回填。

**G03｜管理入口首先落到不可用页面〔S，P2，F〕**  
`ui/UserMenu.tsx:65` 跳 `/dashboard`，该路由仍Planned；管理侧栏同时存在多个高权重占位入口。改为真实可用默认页，主导航显示可用状态。验收：管理员第一次进入即可完成查看状态或目录，不先经过迁移占位页。

**G04｜占位与失效链接缺产品化说明〔S/D，P2，F〕**  
`ui/Planned.tsx:24–43` 显示阶段、Vue来源和行数；`router/index.tsx:115` 未知地址默回应用列表；报告旧路由也丢对象上下文。将可用、只读、未提供、已下线区分；未知页保留原路径、错误和可用回链。导航图与已砍功能不要求在V5重新实现。验收：旧报告/未知路径不再假装正常打开应用列表。

**G05｜应用上下文仍有两种读取方式〔S/V，P1，F〕**  
`AppWorkbench.tsx` 从接口取得projectId并替换query；Cases/Tasks接收真实props，`AssetsPanel.tsx:19–21`、`EnvConfigPanel.tsx:32–33`、控件入口仍直接读query。首次渲染/错误链接时存在先按旧projectId查询的窗口。改为统一受确认的app上下文传递，不把query当权限或归属真源。验收：故意错配appId/projectId，只查询接口确认的项目；确认期间显示加载，不短暂展示其他项目内容。

**G06｜命令导航未过滤角色，模态键盘边界不完整〔S/D，P2，F〕**  
`layouts/CommandPalette.tsx:12–19,50` 向所有账号列出管理项；自建dialog没有完整焦点圈定、返回焦点和aria-modal，结果最多12条。统一导航权限；补焦点/键盘规范；明确结果截取与继续搜索。验收：普通账号无管理命令，Tab不进入遮罩下控件，Esc后焦点返回入口。

**G07｜URL能定位对象，却难以复现用户当前视图〔S/D，P2，F〕**  
`useUrlState.ts:30–36`、Cases/Tasks的setQuery普遍replace；日志视图/回合/搜索、助手列表筛选、配置控件选择多为局部state。Replace适合逐字搜索，不适合所有层级导航。详情进入与层级切换用push，搜索/临时输入用replace；必要上下文进入URL，敏感输入不进入URL。验收：应用→批次→用例→指定回合，可分享且浏览器返回逐层退，不退出整个工作台。

**G08｜页面错误边界不按路由/面板复位〔S，P2，F〕**  
`ui/ErrorBoundary.tsx` 只在手动重试清error；`AppWorkbench.tsx` 外层边界未按tab置key，`AdminLayout.tsx:148` 也未按页面置key。一个面板渲染失败后，切正常页面可能仍看到旧错误。为路由对象提供resetKey、保留错误诊断与用户重试。验收：使单面板故障，切另一tab恢复显示，无需整页刷新。

**G09｜状态字符串的语义压缩不一致〔S/V，P1，F/C〕**  
`ui/StatusPill.tsx:9–16` 和 `tasks/types.ts:47–52` 使用不同正则：exception分别为warn和fail，flaky在任务视图落other；done/complete用于流程结束又易被绿标业务通过。建显式、分领域枚举映射；流程终态、业务核验、写效果、清理状态分别显示，未知值保留原码和“待映射”。验收：blocked、cancelled、flaky、effect_unknown、unverified、done在各页含义一致，禁止未核验显示业务通过。

**G10｜写请求响应不确定与按钮失败混淆〔S/V，P1，F/N〕**  
创建、导入提交、运行派发均有请求超时，但前端没有统一受理查询/收据恢复；长插件操作也依赖请求完成。网络断开不证明服务端没创建或没执行。前端先明确“受理状态待确认”，保留输入与查询入口；持久request/receipt身份及幂等须由服务端保证，另排合同。验收：服务端受理后浏览器断线，用户恢复只能找回同次请求，不能盲点重试创建第二份任务。

### 3.2 登录、应用与创建

**A01｜登录错误全部挂在密码字段〔S，P2，F/C〕**  
`LoginPage.tsx:28–38` 将auth/status故障、连接失败等都写入password errors，误导用户改密码。区分字段错误、服务器不可达、凭证已受理但状态未确认；保留账号与回跳，确认失败不自动多次提交登录。验收：网络失败不标“密码错误”，恢复后继续确认身份。

**A02｜注册错误靠自然语言猜字段〔S/D，P2，C〕**  
`RegisterPage.tsx:22–25` 用“邮箱/密码”关键词决定错误归属。现有格式/长度/确认校验可保留；优先消费服务端字段错误/code，没有则页面级展示，不根据一句话产生错误定位。验收：英文错误、重复邮箱、业务限制、5xx均有准确位置，不臆造字段要求。

**A03｜应用执行角标的降级覆盖范围不透明〔S，P2，F/C〕**  
`apps/queries.ts:69–85` 退到最近40个runs后仍 `degraded:false`，用户看见0可能误以为无运行；空summary也触发额外runs请求。应区分完整汇总与有限窗口，显示“最近记录/计数待确认”，仅在明确不支持接口时兼容降级。验收：超过40个历史运行、summary返回空数组/形状错误，都不伪称完整计数。

**A04｜创建流程缺少提交边界与下一步〔S/D，P2，F/C〕**  
`CreateDialog.tsx:65–83` 在途未禁取消、遮罩、字段编辑；必填名称先通过required后再trim，纯空白边界需要统一；创建成功仅关闭。用统一提交快照与在途保护，显示受理状态；成功给“配置渠道/导入用例”的就地入口。验收：请求中改输入不改变成功提示归属；失败留草稿；创建后用户知道下一步。

### 3.3 用例导入、理解、版本与发布

**C01｜列表缺少“最新理解与可运行版本”状态〔S/D，P1，F/N〕**  
`CasesPanel.tsx:100–129` 主要展示用例身份、最近结果与三段内容；`CaseRow`没有显式的revision/job/artifact关系类型。用户不能区分原文已改、解析失败但旧产物仍存在、最新解析完成尚未发布、旧版回归。增加轻量状态摘要：最新原文r、最新解析任务状态、有效产物版本、发布版本及当前运行资格。前端不能从“有steps_parsed”推导当前可运行；版本字段由合同提供。验收：新原文+旧成功、新解析失败、旧版明确回归三种情况都可一眼辨认。

**C02｜模块、应用、需求分组与平台范围未解释清楚〔S/D，P2，F/C〕**  
列表按app请求用例，模块计数按project；导入又要求requirement并使用渠道id作为default_platform。应用级筛选、项目级资源、需求分组、平台/渠道不是一回事。要标明统计范围与筛选交集，检查平台字段是否期望平台族还是渠道标识；不能因名称相似自行转换。验收：一项目两应用、同名模块、多渠道，分组数/用例数/实际选中范围可解释且不串应用。

**C03｜跨页选择保留，但隐藏选择缺少复核〔S，P2，F〕**  
`DataTable.tsx:187`保留selectedRowKeys，CasesPanel在筛选/翻页后不清选择；RunBar只显示数量。保留跨页选择本身合理，缺口是看不到哪些已选项不在当前筛选。增加已选清单、当前页/当前筛选/全部所选的范围解释，删除/执行按真实清单确认。验收：选A页→搜索B→下发，不把隐藏A项伪装成当前筛选项。

**C04｜自动猜工作表，用户不能选择〔S，P1，F〕**  
`CaseImportDialog.tsx:127–132`选择第一个名称匹配“用例”的sheet，否则首sheet，没有工作表选择界面。多sheet可能读错表却正常进入映射。提供名称、行列数与小样本选择，原文件保持不变；默认推荐只是推荐。验收：目录sheet、多业务sheet、同名近似sheet均能明确选取，并记录来源sheet与行号。

**C05｜没有需求记录就不能导入，形成MVP前置死路〔S/D，P1，C/N〕**  
`:158–165`缺requirement直接拒绝，而工作台没有配套需求创建页。V5需求只是分组，不应要求先建设需求管理。建议使用已有合法未分组容器或最小分组接口，具体由服务端合同决定；前端不能虚构requirement_id。验收：新建项目可以导入第一批用例，不必借后台或数据库造需求，也不把分组升级为执行资格。

**C06｜文件处理缺少容量与完整性反馈〔S/V，P2，F〕**  
本地XLSX.read与sheet_to_json在主线程；无可见容量门槛、分阶段进度或被跳过数据摘要。大型表、合并单元格、CSV编码、公式显示、多行括号/否定/数量的完整性需验证。优先加限制与行数/空行/映射摘要，实际卡顿达到阈值再放Worker；不要为优化删内容或只取前N行不说明。验收：样本规模递增，解析时能反馈、失败保留输入，原文各关键字符不丢。

**C07｜映射与冲突决策对用户仍偏技术化〔S/D，P2，F/C〕**  
表头行显示0起；changeHeader将新建议skip与旧skip并集，改表头后早前被跳过的有效行可能仍被跳过；冲突目前只有skip/overwrite判断，稳定编号与目标revision没有可见解释。区分推荐跳过和用户手选，显示实际Excel行号/来源与内部索引映射；覆盖前展示旧/新原文和目标身份。无编号重新上传不能按标题猜覆盖；源身份支持另补合同。验收：来回改表头不悄悄减少数据行；同名不同case不误覆盖。

**C08｜预览任务只在弹窗内，刷新后难以恢复〔S，P1，F/N〕**  
token、rows、冲突选择均为组件state；关闭会尝试cancel；没有持久收据/job入口。后续应把“预览会过期”与“提交收据不可丢”分开，按项目与当前账号保存可恢复任务引用，后台job状态可查询。仅用localStorage保存token不能替代后端持久记录。验收：关浏览器/重启服务后，已提交行、待处理行和原case/revision身份仍能恢复。

**C09｜部分写入与未写入结果只打一条提示就关闭〔S，P1，F/N〕**  
`:258–262`用计数提示，包含blocked也reset并关闭；提交返回类型仅created/updated/skipped，未定义行级身份与错误收据。用户丢失“哪几条未写入、哪条成功落哪个版本”的上下文。提供提交结果清单，未写入留在问题队列；已提交项重试返回原收据。验收：10条中3条失败，只补失败项；成功项不再覆盖或重复创建；提示数量与实际case一致。

**C10｜导入取消、解析完成和可保存被绑得过紧〔S/D，P2，F/N〕**  
`:242–244`只有progress.done才可提交；三次轮询失败停止，关闭取消失败仍清界面且后台可能继续。当前已有可见取消警告，应保留；问题是任务入口随后消失。建议明确“停止前台查看/请求停止后台/已停止”的区别、恢复任务入口与逐行提交策略。是否允许已完成行先提交需事务/收据合同，不能仅解锁按钮。验收：解析部分失败不阻断其他case最终进库；取消结果未知可再次查询，不能提示全部已停止。

**C11｜有问题说明，没有就地修复闭环〔S/D，P1，F/N〕**  
`CasePreview.tsx`只有返回、原文理解和发布区；未接入原文编辑、新revision生成、根因复核与修复状态。仅让用户重新上传/重编不能覆盖所有问题。复用现页加原文编辑与最小问题侧栏，提供“修改原句/补渠道资源/补控件与核验/登记平台工具缺陷”的具体入口；由根因决定动作，不统一推给用户改文案。验收：选一条真实失败用例，不换成容易通过的样例，从原因修复到新版本实跑后关闭问题。

**C12｜普通解析与严格计划没有统一的版本对应解释〔S/V，P1，F/C/N〕**  
`caseUnderstanding.ts:42–47`读取 `meta.step_program_keys`/parsed/automation_details；严格发布另走 `getV5Preview`；字段集合中未直接统一 `v5_draft_step_program_keys` 与普通产物。维护页三段与发布区可能代表不同版本，需要核对实际API，不能先断言数据库丢解析。规范“原文revision→compile_job→artifact→publication→attempt”的引用；同页明确普通理解、严格草稿、冻结快照的归属。验收：所有徽章与发布动作均能定位来源版本；旧job晚返回不覆盖新原文。

**C13｜发布审阅与统计作用域欠明确〔S/D，P2，F/C〕**  
`V5Publication.tsx:46`统计按projectId，却入口在单case详情；`:58`发布成功invalidate全部queries；控制/基线变动后当前case原文预览不一定同步解释。保留现有expected_revision和服务端资格检查，补“项目统计/本案统计”标签、受影响依赖提示、按域精准刷新。审阅确认绑定所见draft_revision及完整依赖版本，在途禁止修改影响该提交的选项。验收：控件发布后相关case提示失效；项目统计不被读作单案数据；并发发布冲突保持草稿。

**C14｜前端解释与服务端识别仍容易被混为一谈〔S/V，P1，F/C/N〕**  
`caseUnderstanding.ts:88–114`按关键词推断登录方式，前置用conditionPair冒号拆分；`caseAnnotations.ts:4–8`仅唯一精确片段能定位。页面配色已比原先清晰，但没有可靠source_span时，重复短句、近义表达、多任务、摘要字段仍无法准确对应原文位置。应标出“服务端参数/解析摘要/展示推断/未定位”，建立参数别名与事件schema统一解释；偏移由服务端返回，前端不对模糊匹配装作精准。验收：重复词、否定登录、手机号/邮箱并列、嵌套参数，不错贴、不丢任务、不把推断当冻结参数。

**C15｜严格Web发布区未明确限定适用路线〔S/D，P2，F/C〕**  
`CasePreview.tsx:19–20`对每条用例都挂V5Publication；后者统一说明“运行使用已发布版本”“每案启动新浏览器”，并展示“允许执行效果未知时整案重试一次”的勾选项。它们是特定合同说明，不应让移动/PC或普通路线误以为拥有同样保证。显式标“严格Web计划审阅”和适用范围，普通路线展示其自身固化状态；把重试条件解释为合同核实的复位、停止、隔离和独立attempt约束，不能让单次勾选被读成任意未知写可重放。服务端已有的安全拒绝保留，新限制按已确认合同实施。验收：相同case切不同支持路线，各自实际保证准确；界面文案不替代服务端判定，也不把待验收修订当已部署能力。

### 3.4 执行入口、批次与结果

**R01｜两个运行入口的模式与保证等级不一致〔S，P1，F/C〕**  
RunBar只发action_scheme，没有execution_mode；CreateTaskDialog默认legacy，另用checkbox选择v5并限定Web。两个入口对同一组case可以形成不同解释。抽取统一的运行意图/预检/版本选择模型，复用现有入口；“观察方案”“执行合同”“产品版本”分别命名。验收：列表与任务页选同一目标、版本、case时，预检和最终载荷一致；没有严格能力时明确实际路线。

**R02｜运行前的目标与配置校验不完整一致〔S/V，P1，F/C〕**  
RunBar的blockReason主要看设备，env错误没有独立阻断，surface可以空；CreateTaskDialog的block也未明确env/cases读取失败，设备查询context未携带execution_mode（类型本身无该字段）与最终的headless选择。现已有服务端executable判定，应保留而非再造本地准入。需要明确渠道/环境是否允许服务端默认，以及预检是否覆盖最终模式。验收：配置读取失败、渠道被删、模式变化、设备忙、平台不符，提交前原因准确，最终服务器仍重新校验。

**R03｜取消与失败重试API存在，但任务页面没有入口〔S，P1/P2，F/C/J〕**  
`api/caseRunner.ts:35–39`已有cancel/retry，TasksPanel没有接入。建议展示当前可执行动作和影响范围。取消后显示请求取消/停止中/停止已确认；重试保留原请求和首次失败。**写效果未知、未确认停止或资源隔离时禁止普通“再跑一次”**，服务端拒绝与动作能力必须核对，不能前端直接放开。验收：取消不即刻标成功释放资源；真实安全重试有独立attempt与原案链接。

**R04｜批次历史检索与分页边界不足〔S/D，P2，F/C〕**  
TasksPanel列表只分页/刷新，没有状态、时间、任务/case搜索；不像CasesPanel，没有空的越界页归位。补最少任务ID/状态/时间筛选、总量与刷新时刻，以及统一分页规范；能否服务器过滤按接口确认。验收：旧任务可定位，删除/新增后停在非法页不显示“没有执行过”。

**R05｜“只看需关注”空集反而显示全部〔S，P2，F〕**  
`TasksPanel.tsx:44–50`返回 `attention.length ? attention : allCases`。当全通过时，按钮仍是“只看需关注”，列表却是全量，破坏筛选语义。严格保留空集，显示“当前没有需关注项/查看全部”；关注范围明确包括哪些终态。验收：全通过、全部运行中、混合阻塞三种批次，筛选与标题一致。

**R06｜批次统计难以说明每个原请求去了哪里〔S/D/V，P1，F/C/N/J〕**  
`TasksPanel.tsx:53–56,145–184`按pass/fail/running/other归类，fallback完成数只用pass+fail，主要卡片只显示通过/失败；缺requested_total、静态受阻、临时不可用、未执行/未核验与cleanup口径。不能直接断言后端丢分母，但当前UI不能完整解释。展示原请求N、已受理/已执行/已核验、未执行原因、隔离/停止状态；每执行单元使用身份，不只case_id。验收：混合资格/取消/未知写的批次每项有去向，不能把未执行从成功率分母删除。

**R07｜新任务选用例是项目全量，应用范围与错误态不清〔S/V，P1，F/C〕**  
`CreateTaskDialog.tsx:28,58–76`用getProjectCases(projectId)，无当前app过滤；`:180–181`失败后可能呈现“没有可选用例”。后端是否允许项目用例共享给该app需核对，不能先把共享当越权。按现有case-page合同呈现适用范围，显示不兼容原因、错误/重试；大项目不要每次拉全量。验收：同项目多应用，列表能说清哪些用例适用，错误不变空集，跨页选择身份稳定。

**R08｜执行三栏仍是旧字符串呈现，原文与理解分叉〔S，P1，F/C〕**  
`CaseRunView.tsx:48–54`使用steps优先于steps_raw；`columnEvents:260–286`只认数组/字符串序号，不支持统一结构，缺项直接写“未编译”；维护页已经使用fieldPresentation/ScriptField。优先复用统一展示模型，但运行页必须读**该次运行冻结快照**，不能拿当前case草稿替换历史。若快照缺失，完整展示当时原文并注明理解不可用，不再把取数缺口断言为未编译。验收：导入、保存预览、发布、历史执行四处同版同义；修改当前原文不会改写历史图文。

**R09｜批次详情与用例身份对多设备/重试不充分〔S/V，P1，C/N/J〕**  
详情选择与rowKey主要用caseId，runId兼容拼接 `${taskId}::${caseId}`；现有关系多靠session_id/report_run_id。多设备同case、多attempt或session代际时，caseId不是执行单元唯一身份。显示并使用服务端稳定execution/attempt/session引用；旧记录保留兼容入口。验收：同case两设备同时执行、整案重试、历史SN变更，不串选中行、截图、终态。

### 3.5 轨迹、回合、事件、模型与截图

**S01｜轨迹两个来源失败被吞成成功空数据〔S，P1，F〕**  
`CaseRunView.tsx:36–37`两个接口都 `.catch(() => ({data:{}}))`。一方失败时另一方数据有价值，但当前既不显示局部失败，也不能区别“没有轨迹”。用独立来源状态/部分可用提示，保留已有数据与针对性重试；全部失败进入错误态。验收：任一403/500/超时都可见来源问题，另一来源正常展示，不伪称本次没有事件。

**S02｜运行中的轨迹、日志详情缺持续更新〔S，P1，F/C〕**  
task详情每5s轮询，但CaseRunView trace query和useSessionDetail/List没有interval；`useAppRealtime.ts`只更新任务/用例结果，没有刷新轨迹、session事件/回合/模型。驻留详情可能一直停在打开时。按running状态增量拉取或现有消息精准失效，终态停止；重连执行补偿同步。验收：停留同页即可看到新回合、截图、终态，不靠切页；断WS时有查询兜底，终态不无限轮询。

**S03｜首张补位截图可能承载当前事件的错误标注〔S/V，P1，F/C〕**  
`CaseRunView.tsx:84–89`currentTrace无thumb时使用firstScreenshot，但interaction仍取currentTrace；`:243`覆盖层只检查src加载一致，不检查截图是否属于当前事件。结果可能把第二个事件坐标画在第一张补位图上。补位可以保留，但标“参考截图，非当前事件”；只有capture/event引用一致才画标注。新图失败保留旧图时也维持证据来源标签。验收：无图点击/拖拽步骤能看参考图，不能出现假的当前落点。

**S04｜坐标空间与PC前后证据仍靠启发式〔S/V，P1，F/C/N/J〕**  
`interaction.ts:48–58`未知坐标单位默认1000；`DesktopEvidence.tsx:32–35`后图取同/下一回合的首个observe，而非完整action_ref/attempt/capture匹配。ResizeObserver和contain缩放已经实现，应保留；需要规范坐标单位、原始尺寸、捕获身份、窗口/屏幕作用域和前后关系。只有有依据才绘制，缺失标“坐标空间未确认”。验收：像素/比例/百分比/1000制、截图缩放/留白/窗口变化、同回合多动作与重试图都不误关联。

**S05｜已有关联层级，但关系身份不足以覆盖所有情况〔S/V，P1，F/C/N〕**  
`executionLinks.ts`读取step_ref、turn等，`knownTurns`主要按turn数；phase、attempt、稳定call/event来源引用未组成完整关系键。当前“未关联”保留是正确的，不能用相邻时间猜匹配。需要显式关系路径“原句→任务→执行单元/attempt→回合/阶段→事件→模型请求/返回→图/事实”；缺字段归入未关联并说明原因。验收：同一步多回合、同回合多阶段、工具重试、未关联前置，都可追溯而不硬凑层级。

**S06｜日志筛选和选择不可完整分享，层级范围容易误读〔S/D，P2，F〕**  
view、turnScope、typeFilter、search和picked为局部state；SessionLog只有session URL；进入模型/事件后仍须清楚说明“当前步骤/当前回合/全部”。将非敏感范围与选中身份入URL，返回保留上层选择和滚动；总数、当前范围数、未关联数并列。验收：复制URL打开同一回合/事件，返回三栏仍在原步骤，筛选后详情不残留已排除对象。

**S07｜日志搜索是已加载摘要搜索，全量程度说明不足〔S，P2，F/C〕**  
session事件首批100条，loadMore按seq追加；`SessionDetail.tsx:119–123`仅搜seq/type/label/turn/phase和截到240字的eventSummary，不检索完整payload/未加载后页。页面已有“已加载异常”标签，可扩展到所有计数与搜索结果；必要时现有接口支持服务器搜索，否则提供明确“仅已加载N/M”。验收：关键词在第241字或第101事件，不错误声称整次会话无匹配；翻页不丢当前引用。

**S08｜日志束的失败隔离、数据身份与脱敏边界需补〔S/V，P1，F/C/N/J〕**  
`api/sessions.ts:104–113`Promise.all将events/llm/metrics/turns绑成整体，单项故障会使全部不可看；默认数组/对象又缺逐字段合同校验。保守去重已实施，但缺seq/call_id时不能证明两条相同文字就是重复。原始参数默认展开、复制、图片、MinoCard和严格证据JSON出口需要同一脱敏规则。已有局部字段隐藏不是全面安全证明；本文未采集到真实秘密泄漏。验收：模型统计接口坏仍能读事件；真实重试保留；敏感值在正文/数组/嵌套/复制/截图/诊断均不泄露，缺身份保留记录并标来源。

### 3.6 测试资源与环境/控件配置

**E01｜资源“账号管理”实际上只能看，下一步入口缺失〔S/D，P1/P2，F/C/N〕**  
Accounts组件只有query和DataTable，空态却说“从号池模板分配，或手工登记”，对应号池模板路由仍占位。明确“账号查看”边界，并提供当前MVP实际可用的登记/分配/配置链接；服务端未提供则作为接口缺口，不设计前端假保存。验收：缺测试账号能找到真实补齐动作，不在两个空页之间来回。

**E02｜未占用被当“可用”，未登记/缺状态仍可能绿标〔S，P1，F/C〕**  
`AssetsPanel.tsx:75–76`locked为false/undefined都绿标可用，registered=false又同时显示未登记。未锁定不等于具备资格/环境/授权/资源身份。分别显示占用、登记、事实新鲜度与当前任务准入；未返回字段显示未知。验收：未登记、环境不符、状态缺失、资源隔离时不会用“可用”概括。

**E03｜资源页本地分页掩盖后端固定窗口〔S，P1/P2，F/C〕**  
资源日志API默认page=1/page_size=50，调用无分页参数；机态API默认limit=200；DataTable只对已取数据本地分页。页面共50/200不是项目总数。按现有API接服务端分页和总量；无总量就写“已加载/最近N条”，增加查询窗口与继续读能力需合同确认。验收：第51条日志/第201条机态可定位，绝不把窗口总数写成全量。

**E04｜机态观察与当前事实、账号身份混用〔S/V，P2，F/C〕**  
机态页“绑定账号”用session_display/session_id兜底，行内容含created_at，但没有清楚的当前/历史/过期状态与对应执行链接。区分设备上当时观察到的登录身份、平台绑定账号、执行session；无法解析身份不要显示会话ID冒充账号。验收：历史观察与当前资源明确分开，能回到来源session，过期观察不影响当前准入判断。

**F01｜环境刷新可覆盖未保存草稿，离开无保护〔S，P1，F〕**  
`EnvConfigPanel.tsx:54–59`query.data变化就setDoc并重设active/saved；dirty虽显示，未发现路由离开或beforeunload保护。保护基线和draft，后台新版本到达显示冲突/待刷新，不覆盖用户输入；离开给保存/放弃/留在当前的操作。敏感字段仅内存保留，不写URL/通用本地草稿。验收：正在输入时其他面板触发env失效、切页面、刷新网页都不会静默丢改动。

**F02｜配置与发布的在途编辑、审阅失效规则不一致〔S/V，P1，F/C〕**  
控件的reviewed只在control对象变化时清空，修改定位值/敏感属性不会立即撤回勾选；环境保存成功回调读取当时最新doc，若请求中继续编辑可能将未提交版本标已保存。发布按钮loading并不能代替冻结输入。提交捕获完整快照/expected_revision；所有影响审阅字段变化使审阅失效；在途禁相关编辑或明确保留后续草稿。验收：勾选核对后改selector不能直接继承审阅；请求发出后修改内容，成功仅确认实际提交快照。

**F03｜“上线顺序”与“默认运行环境”被强绑定〔S/D，P1/P2，F/C〕**  
`EnvConfigPanel.tsx:75`、`envModel.ts:263,302`把default_profile设为列表首项。用户调整上线顺序就改变默认跑批环境，尤其移动正式环境到首位时影响大。拆成独立设置与显式变更反馈；兼容旧配置时说明迁移规则。验收：仅排序不改变default_profile；从运行入口能看见真实默认环境与来源。

**F04｜环境全量序列化可能丢未建模字段/独立默认值〔S/V，P1，C〕**

**F05｜控件变更影响只是文案提示，未形成待办闭环〔S/D，P2，F/C/N〕**

**Q03｜搜索、数据密度与渲染成本缺统一预算〔S/D/V，P2，F/C〕**  
Cases每次输入更新query并请求；SavedScriptField在列表缺理解时逐可见case取详情（Query会合并同case三列请求，不能算成三倍）；AppList全量项目扁平展示，CreateTask全量用例。长文本、200行模式与虚拟滚动需真实测量。采用搜索debounce/中止旧请求、列表带轻量理解摘要或批量详情、按需要分页；减少内边距和重复标签，**完整展示原文与任务，不恢复折叠/截断**。验收：请求数、首次可操作时间、切步骤时间、列表滚动与长行高度均有实测，不能只比较组件行数。

**Q04｜技术文案、字体密度和窄屏行为仍不一致〔S/D/V，P2，F〕**  
Session列表直接running/pass、session；V5Evidence直接wire/lane/attempt、JSON；部分参数label未知原码，辅助信息大量11px；管理双栏使用固定min-width，外壳固定导航。现有主题、密度与reduced-motion已有实现，不能说全无适配。统一“中文解释优先、技术码次级可复制”，关键事实不缩到脚注；按容器宽度分配，截图布局不随每张图改变。验收：常用桌面、窄窗口与200%缩放可读；长参数不按字拆坏；深浅主题主次与焦点一致。

**Q05｜类型与组件治理仍不足，文档存在迁移残留〔S，P3，F〕**  
`tsconfig.app.json`strict=false；核心row多unknown索引/any，unwrapOne只脱信封不验字段；部分页再用默认空对象/数组掩盖形状漂移。NodePlugins706行、Nodes510、Import490、RunView445超过手册400行需要说明；无引用组件与旧Studio/Console术语仍在注释/手册。按域补DTO与适配器/必要运行时校验，重点拆多职责页，不一次翻全库strict。验收：关键错形状数据变可诊断错误；唯一前端术语统一；拆分不重复功能、不改变接口字段。

**Q06｜“verify通过”不等于可交付页面与真实闭环〔S/D，P1/P2，F/J〕**  
package.json的verify只含typecheck、banned、no-electron，不含lint/build；仓内未发现.github CI配置；无证据可证明全部路由的缓存清空后加载/懒加载、深链接、角色矩阵和真实session链路都验收过。补最小发布检查与证据记录，沿用现有契约，不往Nexus提交tests/mock、不跑pytest。验收：构建产物经真实HTTP与无缓存浏览器检查所有当前交付路径/按需资源，真实业务依据session_events+session_meta，不用模拟成功证明设备执行成功。

## 4. “字段从哪来、为什么重复、识别为何不准”的专项解释

### 4.1 当前数据与前端加工必须分层

| 内容 | 当前来源/处理 | 可以相信到什么程度 |
| --- | --- | --- |
| 名称、模块、平台、前置、steps_raw/expected_raw、steps/expected | 导入/用例接口字段；fieldSource做多形状兜底 | 有内容不代表已编译；要绑定原文revision，兜底不能遮掉错形状 |
| meta.step_program_keys、do_program_plan/check_program_plan、步骤/检查点/slots | 普通固化或预览返回的结构，前端改显示名称 | 是服务端返回结构，但必须确认产物版本、字段含义与当前适用性 |
| steps_parsed、expected_parsed、automation_details | 服务端解析摘要/覆盖说明；summaryTasks再组织 | 摘要不一定等于完整执行计划，不应作为任务身份或准确参数真源 |
| 登录逻辑标题、手机号/邮箱/验证码/密码识别 | planTask结合服务端参数、slots和前端loginMethods关键词 | 一部分是前端展示推断；“原文”标签不能暗示服务端已确认该登录策略 |
| 前置条件名称/值 | conditionPair文本拆分＋服务端resource_key摘要 | 文本冒号拆分是展示，不是账号资格编译；后者以服务端资源合同为准 |
| 彩色徽章、任务数、中文参数名、参数去重 | ScriptField、caseAnnotations、labels/value词表 | 展示加工；去重只能减少同义显示，不能删除真实任务或改变冻结产物 |
| 黑色原文上的事件位置 | source_clause/source_line＋唯一精确字符串匹配 | 当前缺span时无法定位重复短句；已经采用不猜位置是正确边界 |
| 严格发布资格、draft_revision、actions/checks、baseline | 独立V5预览/发布接口 | 不能仅因同case_id就与普通理解视为同版，需引用一致 |
| 运行状态、轨迹、回合、事件、模型调用 | task/session接口及两来源投影合并 | 汇总、投影和事实不同；最终事实以真实session持久记录为准 |

因此第六类疑问的答案是：**不是全部可见文字都原样来自服务端。** 数据字段多数来自服务端，中文标题、部分登录方式、条件拆分、布局位置、徽章、计数与显示去重由前端生成。识别精度必须从服务端原句定位、事件schema、产物版本与前端解释边界共同治理，单纯换一轮颜色不能解决。

### 4.2 重复的不同类型不能混用同一种“去重”

- **同一事实被多个接口投影返回**：按稳定event identity合并来源；保留更完整的回合、坐标与图引用。当前已做保守兼容，但缺身份时有上限。
- **同一响应/回合快照被多次加载**：按seq/call/turn身份和内容合并；真实重试、call/result不同阶段保留。
- **同一参数的别名/摘要重复**：schema决定规范名，展示别名可省略；来源可展开查，不改保存数据。
- **多个真实任务参数刚好一样**：必须全部显示，保留任务数与各自原句位置，不能按文字删成一项。
- **原文、理解摘要、发布快照、运行回执重复叙述同一动作**：这是层级重复，改展示顺序与“当前版本/历史版本”标签，而非删数据库记录。

### 4.3 最小理解显示模型（拟议展示合同，不是现有API承诺）

原句：`case_revision + section + source_line_id + 原文`。  
任务：`artifact_id + task_id + source_span + event/schema_ref + 参数 + 参数来源 + 状态/阻断原因`。  
执行：`execution_unit_id + attempt + session_id + step/task_ref + turn/phase + event_seq/call_id + capture/action_ref`。

优先复用现有字段：有稳定ID就使用，不为了字段名重造框架；缺少关系时前端明确标“未关联/未确认”，必要补字段作为C/N项。span必须定义字符索引/多行/Unicode约定，并验证start/end对应原句；模型建议参数与已确认冻结参数分开。

## 5. 页面与UI改造方案

### 5.1 保留现有结构，统一主工作流

```mermaid
flowchart LR
    A[应用上下文] --> B[用例列表：原文与版本状态]
    B --> C[理解与问题：原句、任务、原因]
    C --> D[按根因修改原文或配置]
    D --> E[新修订与编译产物]
    E --> F[核对与冻结兼容路线]
    F --> G[只读预检：资格与临时资源]
    G --> H[按固定版本执行]
    H --> I[原请求结果与未执行原因]
    I --> J[步骤与任务]
    J --> K[执行回合与阶段]
    K --> L[事件、模型、截图与事实]
    L --> C
```

一个工作台承载这条路径，不增加独立需求平台、来源平台或另一套事实仓库。结果链接回到该次执行，编辑链接回到当前草稿；两者不能混为同一详情。

### 5.2 用例列表与导入预览：原文是主阅读线

1. 用例身份列保留名称/编号/分组/端；三段仍以原文完整展示为主，当前16/22/31/31可作为桌面默认，不先恢复低内容占比。
2. 原句下划线/编号表示原文位置；徽章紧贴有可靠span的词句，颜色只表达准备/动作/逻辑/校验/待处理；同时给中文类型，不能只靠颜色。
3. 每条原句显示实际拆分任务数，摘要单独标“解析摘要”；任务参数只显示当前事件有意义的字段：点击的目标、输入的值来源、登录方式及环节、拖拽起终点、等待窗口、断言的数量/范围/否定与必需性。原文含敏感值时按出口规则处理，但不能为了脱敏删掉业务要求。
4. 任务与参数在同一阅读流内自然换行，不用每参数独占一张卡；普通中文按词句换行，长ID/URL允许局部断行；减少重复title/source/parameter，保持真实任务全部展开。
5. 重复短句且无span时，标“未定位原文片段”并给同一步任务集合，禁止强行贴第一次出现的位置。服务端参数、展示推断、未确认参数用文字标识来源。
6. 不规定所有case都相同行高；长用例天然占更多高度。通过更宽内容列、紧凑间距、去装饰与重复字段提高同屏数量，不以省略号、默认折叠或裁切原文换取“多显示几条”。支持筛选到当前关注的问题，而非压缩所有内容到不可读。
7. 导入右侧/顶部提供来源sheet/有效行/跳过行/冲突/未写入摘要，原表小样本仅用于映射；审阅采用与保存后列表相同的数据解释模型。

### 5.3 理解与最小问题侧栏

复用CasePreview，组成“原文／当前理解／未解决项”三层，发布仍在当前页。每个问题只需：阶段、六类根因、复核状态、对应原句/任务、原因、责任位置、具体修复动作、证据链接、所属revision。

六类根因沿用V5基线：原文/预期缺信息、编译理解错误、应用识别/核验能力缺口、环境/账号资源问题、执行工具链问题、真实应用问题。模型只建议，不能替人工改判定；不确定先待复核。修复后必须标“待实跑”，只有真实验证可标已解决；复发重开。

修复按钮按原因出现：改原文、补启动渠道、补资源、配置控件/业务范围、登记平台缺陷、查看真实应用失败。临时资源忙不是修改原文的理由。无权限则给真实只读解释/请求维护入口，不显示假可保存表单。

### 5.4 运行入口与批次

RunBar与CreateTaskDialog复用同一“运行意图”模型，保持两个产品入口。共同显示应用/渠道、平台与目标系统、环境、设备/节点、用例范围、原文/产物/发布版本、实际合同/保障等级、观察方案。

预检结果分为可执行、静态受阻、临时不可用、待补充；先解释再下发，保留原requested_total。用户明确选旧版回归才允许旧产物；最新原文未固化不能默默跑旧版。严格Web与普通移动/PC的能力差异采用服务端事实展示，不能以一个checkbox覆盖整个产品版本。

批次显示完整去向摘要：请求N、执行X、核验Y、通过/失败/未核验/未执行；阻塞原因可筛选到具体case；首次失败和后续attempt并列。取消、清理、释放分别确认；没有停止证据不提供“已安全停止”或解除隔离的UI暗示。

### 5.5 截图与执行详情

- 继续按选定执行目标平台固定布局。Android/iOS竖屏参考采用左图右详情、图最大35%；Web/PC宽屏按既有结构，图栏与详情按容器分配。混合平台app依据**这次执行目标**选择一次布局，不因每张截图宽高或点击步骤变化重排。
- 轨迹区域信息/列表1:3作为默认；短窗口允许信息区内部滚动或压缩次级字段，关键状态/关联/原句保持可见，不机械挤到按钮无法点击。
- 图片contain，加载交接保留旧图；旧图/补位图明确来源，当前事件缺capture关联时不画动作标注。加载错误给重试和原引用，不留无限loading。
- 原图与标注分层，坐标单位/图像引用/viewport确认后绘制。点击、长按箭头和拖拽动线是事件请求或执行回执的可视化，标清“请求落点/回执”，不能暗示请求坐标就证明动作成功。
- 当前行使用稳定主色背景、左侧细边、明确文字与焦点，视觉弱于失败警示；选中、失败、批量勾选分开。键盘上下可选、Enter进入回合，能返回原步骤。

### 5.6 日志：逐层看，不横向迷路

首层“步骤/任务”回答业务哪里出问题；第二层“执行回合/阶段”回答系统如何尝试；第三层“事件/模型”回答具体输入、事实和回执。保留现有三个日志视图，统一面包屑与范围提示，不再要求用户独立拼三份平行列表。

每层显示本范围/已加载/全量数与未关联项；保留原始参数默认展开，但上方先给精简结构化摘要。技术码、JSON、复制和来源放在事实层，不把重要结果埋进长JSON。搜索范围明示，增加从模型调用回事件、从事件回task/turn与capture的定位。

真实重试应可见且属于原attempt/新attempt；来源重叠只合并投影。未知关系不能猜，解释为什么未关联即可。运行中更新与断线恢复统一调度，用户查看历史时不反复跳选中项或滚动位置。

### 5.7 资源、配置、节点与模型

资源页首先回答“现在这个任务缺什么资源、谁占用、何时观察、在哪里补齐”，而不是仅展示ID。配置页首先显示生效版本与待保存草稿；探测、保存、发布、影响用例和新任务准入形成可追溯链。

节点页继续用单列表与目标详情，主要概览展示节点连接、设备当前状态、任务可执行性和阻断；接入插件与安装任务独立组件；日志给窗口与新鲜度。设备页保留精确node回链。模型页按provider独立保存；当前使用方/生效用途、已验证状态与预算/费用链接就地可见。

### 5.8 助手与管理页

助手保持个人入口；请求/任务、绑定、会话、设置、订阅、MCP各自边界不变，但统一查询范围和状态文案。首次接入有连续下一步，已接入用户直接处理当前请求；群策略仍由绑定身份与项目权限约束，报告域名不被私网IPv4正则误拒。

管理页只展示当前真实交付能力，目录按事件→逻辑块/能力→角色/技能/模板→实际引用建立只读解释链。已只读的页不强行增加编辑按钮；错误、未知、未提供与零项分别呈现。运行状态和本地操作记录明确证据范围，不把它们当全产品健康/服务器审计证明。

## 6. 实施分层、依赖与交付包

### 6.1 纯前端能解决什么，不能替代什么

| 工作 | 纯前端可交付 | 前端不能单独保证的部分 |
| --- | --- | --- |
| 导航/权限/错误态 | 门禁收紧、角色过滤、真实落点、404、按面板复位 | 服务端项目/操作权限校验、账号身份真实性 |
| 原文与理解UI | 同版适配器、完整展示、参数来源、保守锚定/去重 | source_span、不可变revision、产物与原文引用准确性 |
| 导入体验 | 工作表选择、映射、跳过解释、冲突清单、提交结果保留 | 持久收据、行级事务、job恢复、幂等和覆盖版本校验 |
| 运行入口 | 相同模型/载荷、预检状态消费、实际保障等级说明 | 统一服务端执行绑定、资源版本、准入、未知写与隔离保护 |
| 层级关联 | 消费已有step/turn/seq/call/capture、显示未关联、URL范围 | 缺失身份/关系由服务端补写，不能用时间邻近补成事实 |
| 轨迹/日志刷新 | 分来源错误、运行轮询/增量、终态停、重连补拉 | 服务端事实写入及时性、顺序与分页/快照一致性 |
| 截图/坐标 | 保持比例、固定布局、加载交接、补位来源、合法坐标渲染 | 捕获与动作引用、坐标空间、执行效果、事实完整性 |
| 配置/模型表单 | dirty与提交快照、逐项保存、审阅失效、错误恢复 | expected_revision冲突、依赖失效关系、敏感数据服务端隔离 |
| 资源/目录 | 当前窗口/未知显示、稳定key、回链、筛选、合理只读说明 | 资源实际状态与可执行性、目录真源和全量查询能力 |
| 费用与指标 | unknown/partial/zero、统计范围、分页、下钻 | 服务端账本/原请求分母/准确价格与token事实 |

现有API已足够的项先修前端；需要合同的项提供最小字段与缺口说明。不能把“前端能把三张表连起来”误认为已经具备完整执行关系，也不能把所有问题都推给后端。

- 页面覆盖：第2节矩阵中每个实际交付页面都有加载、空、失败、只读/无权限、成功和恢复检查；占位页不计成功交付。

## 10. 测试工作台视觉与交互专项设计方案

### 10.1 设计依据、目标与实施边界

本节把本轮反馈转为可以交给前端实施的页面方案。观察依据包括用户对五个页面的具体描述，以及模型密钥、任务列表、环境配置三张截图。截图能证明布局和文案问题，不能证明请求失败原因、接口字段完整度或安装器内部行为；Scout与助手的问题按用户报告列为必须覆盖的交互场景，实施前用当前实际返回值核对。

| 页面 | 当前可见或用户报告的问题 | 用户应获得的体验 |
| --- | --- | --- |
| 模型密钥 | 模型、凭证、费用和压缩参数横向平铺；大量小字和相同输入框争夺注意力 | 先看清接入状态，再完成连接、选模型、调整行为；每组字段都有明确用途 |

| 我的助手 | 未绑定的IM渠道占据主界面；少量真实渠道也占用整行大区域 | 日常只看已绑定渠道和真实待办，需要扩展时再进入渠道管理 |
| 任务 | 批次编号成为主体；用例、目标、进度和事件信息不足；结果含义含糊 | 扫一行就知道做了什么、在哪执行、执行到哪、结果是什么、该从哪里排查 |
| 环境配置 | 环境设置、顺序和操作堆在顶部；渠道列表与详情上下堆积，右侧大片空白 | 左侧选择环境，中间选择渠道，右侧完整配置；保存范围和运行默认值清晰 |

本节的设计目标是**结构清楚、事实可信、操作稳定、长时间使用舒服**。精致感通过字体层级、对齐、边界、语义颜色和恰当留白建立；数据密集页面保留表格效率，表单按业务分组，避免所有内容都做成同样大小的卡片。

范围约定：

1. 本轮只写方案，不安装技能、不修改前端或后端代码，不执行安装、升级、模型验证或真实任务。
2. 后续落地仍以Workbench前端为改造范围。Nexus与Scout的执行、版本发布、数据持久化与协议规则保持现有职责。
3. 前端可以调整布局、状态呈现、草稿、排序、路由参数传递以及已有字段的组合展示；不能补造版本、设备、事件、能力、费用或核验结论。
4. 需要服务端事实而现有契约缺失的内容，明确标记「当前未提供」，登记依赖；不能为了做满界面而默认修改后端。
5. 第1–9节仍负责全页面问题目录。本节优先深化用户点名的五个页面，不将其他页面的历史问题改写为已解决。

#### 三个设计技能的使用安排

用户提到的`motionsites`、`impeccable`、`taste-skill`作为后续设计参考方向保留。本轮没有完成这三个技能的来源、安装状态和具体能力核对，也没有调用它们；下面是本项目拟分配的设计工作，不是对这些技能能力的事实声明。

| 参考方向 | 本项目拟安排的工作 | 使用限制 |
| --- | --- | --- |
| motionsites | 评估标签切换、保存反馈、抽屉和状态变化的动效节奏 | 不引入滚动劫持、持续装饰动画或阻碍排查的内容位移 |
| impeccable | 检查可读性、布局、焦点、状态辨识和操作一致性 | 结论必须对应实际页面与可执行验收，不能只留下审美形容词 |
| taste-skill | 校准文字层级、内容密度、对齐与页面间的整体视觉语言 | 不改变业务含义，不用装饰掩盖未知、失败和缺字段 |

后续若采用这些技能，应先核对准确来源、阅读其适用约束，再按下述页面规则产出设计。技能不能替代数据契约、业务状态和用户已经明确的布局要求。

### 10.2 统一视觉、密度与交互规则

#### 10.2.1 页面骨架

各页统一为「标题与主操作 → 选择/筛选 → 主内容 → 就地反馈」。主操作放在标题右侧或表单底部固定动作区，同一操作不同时在多个位置反复出现。全局导航沿用现有Workbench应用结构，页面内部不增加另一套全局菜单。

| 层级 | 内容 | 设计规则 |
| --- | --- | --- |
| 页面标题 | 模型密钥、Scout节点、我的助手、任务、环境配置 | 标题22–24px；说明14px，优先一行说明当前工作对象 |
| 区块标题 | 连接与凭证、启动配置、运行设备等 | 16px，允许一行简短说明；不把每个字段包装成区块 |
| 主体 | 表单、表格、日志说明 | 正文14px，字段标签13px；长时间阅读内容不依赖11px小字 |
| 辅助 | ID、更新时间、字段来源 | 12–13px，次级文本色；完整值可复制，不能只靠悬浮才能理解 |
| 控件 | 输入、按钮、标签切换 | 桌面按钮和输入建议36px高，触屏交互目标至少44px |
| 留白 | 页边、区块、字段 | 页边24px；区块间24px；组内12–16px；密集表格另设紧凑间距 |

这些尺寸是设计初值，不是所有屏幕的固定像素合同。以实际内容容器宽度、字体缩放和文本长度校准；保留现有品牌主色，不在每个页面发明不同的强调色。

颜色按含义使用：主色表示选择和主要操作；绿色表示有证据的成功或在线；橙色表示需要关注或配置不完整；红色表示失败或破坏性操作；灰色表示中性、未知和未发生。状态同时写出文字和必要图标，不能只靠颜色判断。

选中行采用浅主色底、细边界或左侧标记，并提供清晰焦点轮廓；避免整行深色遮住内容。`hover`、选中、键盘焦点、禁用是不同状态，不共用同一套浅灰样式。

#### 10.2.2 响应式与稳定布局

以下宽度均指**扣除Workbench全局侧栏后的内容容器宽度**。不能按当前截图比例或当前步骤内容动态改变整个页面结构。

| 容器宽度 | 表单类页面 | 列表与详情类页面 |
| --- | --- | --- |
| ≥1280px | 选择导航220–256px，详情占剩余宽度；相关字段可两列 | 主列表保留核心信息；节点详情可将主信息与设备概览并排 |
| 960–1279px | 导航200–220px，详情至少保留可读宽度；组内由两列转一列 | 节点列表约220px；任务减少次要列，核心内容不隐藏 |
| 720–959px | 环境或服务商选择进入顶部选择器；详情铺满 | 节点列表与详情通过明确返回入口切换；任务保留可滚动表格或切紧凑摘要 |
| <720px | 单列，操作区可换行；不横向挤压多个表单分组 | 优先保留身份、状态、结果和详情入口；次要信息进入详情 |

长名称优先换行或在详情显示，短操作不换行。不得让「对话」「日志」「概览」逐字竖排；为按钮预留最小宽度，文本区允许收缩，长ID使用独立复制入口。单次数据刷新不改变用户正在阅读的列表顺序或滚动位置。

#### 10.2.3 反馈和动效

首次读取使用与最终内容近似的静态骨架或局部加载说明；需要真实数据才能判断的按钮先禁用。后台刷新保留旧内容，并标记「正在更新」或「上次读取于……」，不把整页内容清空。

短过渡建议120–220ms，用于标签高亮、抽屉进入、保存完成和按钮状态；读取、安装与升级的实际进度由真实状态驱动。遵循系统减少动效偏好，提供无位移的即时状态切换。屏幕截图切换继续沿用「旧图保留至新图可用」的既定原则。

错误在发生位置说明影响范围和恢复操作。Toast仅作为辅助反馈；表单保存失败、版本检查失败、渠道读取失败应保留可见结果，不能短暂弹出后消失。

#### 10.3.2 字段组织与解释

| 分组 | 包含内容 | 可读性规则 |
| --- | --- | --- |
| 连接与凭证 | Key状态、Key修改、Base URL、接入类型 | Key保持脱敏；「留空不修改」写成字段帮助，清除Key单独放次级危险操作 |
| 模型选择 | SDK候选、模型ID/接入点、自定义模型、向量模型 | 先选预设或自定义模式，再展示适用输入；不把候选选择与自定义ID设计成两个互相竞争的必填项 |
| 能力说明 | 图片、工具、结构化输出等实际已知能力 | 显式区分「支持」「不支持」「未知」；手填模型ID不能自动推断为支持或不支持 |
| 生成参数 | Temperature、最大输出token、Thinking等 | 展示适用条件、单位和留空含义；不支持的参数不让用户误以为会生效 |
| 运行用途 | 接入启用状态、是否允许用于用例执行 | 接入启用与跑用例权限是两件事，分别标注；全局运行开关留在页面级并解释作用范围 |
| 费用 | 输入/输出/向量单价及来源 | 标明币种、每百万token等单位；手填价格标记为自定义，估算与实计区分 |
| 压缩策略 | Plan、Web、Android、PC等已有平台参数 | 保留当前配置语义；字段旁解释实际单位/倍率，未核实之前不将数值强行解释成百分比 |

对话模型和向量模型的留空含义按现有契约明确显示，例如「留空使用现有默认策略」；若历史文字提到FTS等技术名词，用业务说明解释其效果，并在辅助说明中保留准确术语，避免用户将全文检索误认为向量模型。

#### 10.3.3 保存、验证与切换

保存状态与验证状态分别显示。例如「已保存 · 尚未验证」「有未保存修改 · 上次验证针对旧配置」。验证成功只代表该次请求覆盖的能力成立，不能顺带标记所有模型能力都可用。

| 场景 | 界面行为 |
| --- | --- |
| 首次读取 | 保留分组骨架；保存、验证、清除操作均不可误触 |
| 未编辑 | 保存禁用；有已保存配置时允许验证，说明验证可能产生少量用量 |
| 有草稿 | 保存可用；验证按钮明确只验证已保存版本，不能将验证结果贴给草稿 |
| 保存中 | 当前提交防重复；保留输入及提交对象，不允许响应串到其他服务商 |
| 保存失败 | 草稿保留，显示失败原因与重试入口 |
| 验证中/失败 | 分别呈现进行中、认证失败、连接失败、模型不可用等实际返回结果；不自行编造细分原因 |
| 切换服务商 | 有草稿时支持保存、放弃或继续编辑；无草稿直接切换 |

验收重点：1440px及更宽屏幕不再出现一排等权字段；用户能在一次扫视中找到当前接入、Key状态、模型、保存状态；编辑后旧验证结果不会被误认为覆盖新配置。

节点列表建议240–280px，详情占剩余宽度；窄档按10.2.2退化。每项固定分成名称、系统与设备、最近联系三行，名称最多两行，完整值在详情展示并可复制。聊天操作移到选中节点详情标题栏，避免与列表名称抢宽；若保留列表快捷入口，必须为图标设置可读标签和固定点击目标。

排序默认稳定采用「可在线执行 → 状态需关注 → 离线 → 稳定名称/ID次序」。在一次浏览周期内冻结已有行位置，心跳变化只更新状态；用户点击排序/刷新后重排，新发现节点先提示再纳入。状态类别必须由实际连接与可用事实决定，不把「在线」直接等同于「可执行」。

概览、设备、接入、日志采用完整尺寸的文字Tab，目标高度至少36px，选中态与焦点清晰。各Tab保留节点上下文和自己的滚动位置，不能让用户切到日志后不知道在看哪台节点。

#### 10.4.2 版本信息与升级状态

版本区同时展示当前节点实际上报版本、适用于当前系统/架构的可安装候选、最近检查时间。未知版本显示「未上报」，不能显示为`0.0.0`或「最新」。发布标签、可安装包和当前运行版本是三个不同事实。

「有新版本」必须满足：候选发布符合当前渠道/发布规则，版本可按既定策略比较，且存在适配当前系统与架构、符合既有安装契约的实际安装产物。若项目采用manifest，应按已有契约校验适用项，不能仅依据Release标签或一个下载URL判断。存在多个Release时，按既定版本与渠道规则查找最新适用候选，不能因最高标签无包就忽略其他可安装的新候选。

| 状态 | 主文案 | 操作与限制 |
| --- | --- | --- |
| 首次读取/检查中 | 正在读取节点版本 / 正在检查可安装版本 | 展示固定宽度占位；升级、下载、重新下载均不出现为可用主操作 |
| 检查失败 | 暂未能确认更新 | 「重试检查」；保留上次结果及时间但标为旧结果，不写「没有新版本」 |
| 已确认无适用新包 | 没有适用于此节点的新版本 | 可「检查更新」；若确有较高发布标签但无包，辅助说明「已发布版本暂无此系统/架构安装包」 |
| 有适用新包 | 可升级至具体版本 | 展示系统、架构、版本差异；满足权限及既有升级条件时启用「升级」 |
| 当前版本未知/无法比较 | 当前版本未上报 / 暂无法比较版本 | 可继续检查信息，不自动认定可升级；按现有契约决定是否提供独立安装入口 |
| 升级中 | 正在升级至具体版本 | 禁止重复提交；仅在真实进度可得时展示百分比，否则展示实际阶段 |
| 等待重连 | 安装已触发，等待节点重连 | 保留目标版本和已知状态；不能提前显示升级成功 |
| 结果待确认 | 尚未确认节点运行版本 | 提供重新读取状态与排查入口；不能把超时等同于确定失败后盲目重装 |
| 已确认成功 | 已运行具体版本 | 以节点重新上报的运行版本确认，更新最近检查/确认时间 |
| 已确认失败 | 升级失败，显示实际可得原因 | 保留任务上下文；只有既有契约确认可安全重试时才提供重试操作 |

「重新下载」仅属于已有安装包下载的恢复操作，不能充当首次加载、版本未知、无适用包时的默认按钮。需要同版本重新安装时另设明确的维护操作入口，说明对象和影响，不与日常升级混用。

**前端边界：**如果现有接口只返回一个最新标签，而不返回可安装产物及系统/架构信息，前端无法可靠作出「可升级」判断。此时降级显示「发布版本已知，可安装状态未确认」，登记契约缺口；本方案不要求改后端，不在浏览器擅自拼接GitHub地址或引入新的第三方鉴权。

#### 10.4.3 节点与设备信息

| 区块 | 优先展示的事实 | 缺失时的呈现 |
| --- | --- | --- |
| 节点身份 | 名称、规范节点ID、系统/架构、运行版本、连接状态、最后心跳 | 未上报；保留复制节点ID，不推断主机信息 |
| 运行概况 | 设备总数、可用数、忙碌数、执行能力、当前任务等已有事实 | 未提供；不能把未知当空闲，能力不以插件数量代替 |
| 主机与插件 | 主机名、启动/连接时间、插件版本与状态等已上报信息 | 按权限和已有返回展示；不为补全界面新增机器采集逻辑 |
| 设备列表 | 设备名称、平台/系统版本、可用/占用/离线状态、所属节点、设备身份 | 空态与读取失败分开；状态时间不新鲜时说明「上次上报」 |
| 任务联系 | 关联任务名称/ID与跳转 | 仅有准确关联时展示；不存在关联时不自动猜测 |

概览先展示关键事实，再给出「查看设备」「查看日志」等就地入口。设备不做只有图标和名称的小卡片，默认使用可扫描的紧凑列表；长设备身份放次行，可复制。

设备跳转必须使用契约规定的完整、规范身份；是否需要节点ID、平台或序列号共同定位，以现有API为准。名称、短ID和UI截断值都不能参与路由定位。路由编码/解码保留完整值，处理空格、冒号、斜杠及其他特殊字符，避免把合法ID截断。

设备详情的状态按读取过程区分：

1. 正在读取：保留节点与设备上下文，不提前显示「没有这台设备」。
2. 请求失败或权限不足：显示实际失败和返回节点入口，不伪装成404。
3. 节点列表已报告设备、详情源暂未同步：显示「节点已上报，详情暂未同步」及重读入口；只有能够确认来源关系时才用此文案。
4. 已离线但仍有记录：展示最后已知信息与时间，不作为不存在处理。
5. 权威详情明确不存在，且排除读取中和身份传递错误：才显示「设备不存在或已移除」。

实施时先追踪「列表规范身份 → 路由 → 详情请求」三段，确认问题是否纯前端造成；若是两种数据源不同步，前端只能解释和重读，不能制造设备记录。

#### 10.4.4 添加节点

添加节点采用宽度约760–880px的引导弹窗，窄屏退化为全屏面板；顶部明确当前进度，步骤依次为「选择平台 → 获取安装方式 → 等待节点接入」。选择系统与架构后，只展示适用安装方式和包可用状态。

安装区将「终端命令」「下载安装包」「操作说明」按实际支持能力展示；命令用等宽字体、合理换行和独立复制按钮，不要求用户识别一长串无说明字符串。复制成功就地反馈；复制不等于安装成功，获取安装包不等于节点已接入。

| 场景 | 内容与操作 |
| --- | --- |
| 安装资料读取中 | 保留步骤、平台选择与骨架；不可复制不完整命令 |
| 尚无适用安装包 | 明确说明当前系统/架构不可安装，允许返回更改平台；不提示升级成功或无限重试 |
| 资料获取失败 | 展示影响范围与一个「重试获取」操作；不同时出现含义相同的重试和重新生成 |
| 接入凭据确需重建 | 单独解释为何要重新生成、旧凭据是否失效；仅在既有契约支持且用户明确触发时执行 |
| 等待接入 | 显示等待对象与最近状态读取时间；仅凭可靠关联识别新节点，不把任意新上线节点当作本次结果 |
| 接入确认 | 显示已接入节点名称、版本、设备概况及「查看节点」 |
| 关闭弹窗 | 不把关闭解释为取消机器端安装；有正在进行的远端操作时说明后续查看入口 |

用户报告的安装失败在本节不定因；网络、发布包、manifest、权限或命令问题均需实际错误证据后才能确认。

### 10.5 我的助手：已绑定渠道成为轻量状态区

#### 10.5.1 页面布局

```text
我的助手                                   [渠道管理] [设置]
已绑定渠道：[企业微信 · 在线] [Telegram · 离线]   最近更新 …

[对话] [请求与待办] [执行记录] [订阅] … 保留现有真实功能入口
┌──────────────────────────┬────────────────────────────┐
│ 当前主内容               │ 当前上下文/待处理请求      │
│ 对话、记录或待办         │ 有实际内容时出现           │
└──────────────────────────┴────────────────────────────┘
```

渠道名是示例，不代表当前账号已绑定这些渠道。一个或两个渠道以紧凑状态项展示，可自然换行；不为每个渠道分配等宽大卡片或整行高度。主内容获得主要宽高，辅助栏只在确有内容且宽度足够时出现。

#### 10.5.2 显示规则与渠道管理

主界面只显示**当前账号已绑定**的IM渠道；在线、离线、认证异常都是绑定后的运行状态，离线不能导致渠道消失。未安装、已安装未绑定、可接入但未配置的渠道都放入「渠道管理」，不常驻日常视图。

| 数据状态 | 主界面表现 | 下一步 |
| --- | --- | --- |
| 初次读取身份和绑定 | 渠道状态读取中 | 不提前写「尚未绑定」 |
| 已绑定并在线 | 渠道名、在线、必要账号简称 | 点击查看绑定信息与管理 |
| 已绑定但离线/异常 | 保留渠道，显示状态与实际原因摘要 | 进入对应恢复流程；不引导重复绑定 |
| 读取成功且零绑定 | 一条紧凑空态说明 | 「绑定渠道」进入管理，不展示所有渠道占位卡 |
| 读取失败 | 绑定状态暂不可用 | 就地重试；有缓存时标明旧数据，不将失败当零绑定 |

渠道管理中区分「已绑定」「可添加」，安装状态、绑定状态、在线状态各自呈现，不能合成一个含义不明的圆点。绑定、解绑与渠道级设置使用现有接口能力；解绑保留明确对象与影响说明，管理入口不自动执行安装或绑定。

保持请求、对话和执行记录的已有业务层级。前端不能因某个渠道未绑定而隐藏来自其他有效渠道的待办，也不能将全局在线连接数量冒充当前用户的已绑定渠道数。

### 10.6 任务：让任务意图和执行事实取代批次编号

#### 10.6.1 列表结构

任务页保留高密度表格。主列展示「任务做什么」，批次ID降为可复制辅助信息；筛选不再只围绕完整编号输入。

```text
任务                                           [新建任务]
[任务名/编号搜索] [执行状态] [结果] [时间]   [刷新]
最近更新 … · 当前筛选 … · 数量按服务端实际口径显示

任务 / 用例范围     目标 / 环境     执行进度与结果   最近事件   时间 / 详情
登录回归           Android · 测试  已结束           登录断言…  开始时间…
3条用例 · cr-…     设备名称…       执行3/3；失败2    事件时间…  [查看]
```

以上为设计示例。任务名称、设备、环境和事件仅在已有事实可得时展示；缺失项用清楚的缺省文案。旧批次无名称时显示「用例执行批次」，使用已知用例范围作副标题，不能将猜测标题写成服务端事实。

| 栏目 | 默认占比初值 | 展示规则 |
| --- | --- | --- |
| 任务与用例范围 | 28% | 名称首行；用例数量与短ID次行，数量口径明确 |
| 目标与环境 | 18% | 平台、目标设备/节点、环境；只有平台时不伪造设备 |
| 执行进度与结果 | 22% | 生命周期、已执行/总数、核验结果分别表达 |
| 最近真实事件 | 18% | 可理解的事件摘要、所属用例/步骤及发生时间；无事件接口时明确未提供 |
| 时间 | 10% | 本地化时间、耗时或进行中时长；完整时区与时间可在详情查看 |
| 详情入口 | 4% | 固定不换行的查看操作，提供键盘可达的入口 |

比例按真实内容调整，不让操作列被4%的初值挤碎。普通任务行建议72–88px，常用信息最多两行；异常文本在详情看完整，不把所有原始日志塞入列表。默认不折叠用例原文的既定要求仍适用于用例页，不能误用任务摘要设计去截断用例原文。

任务名/编号搜索应说明检索范围；如果现有接口只能查完整编号，就明确区分「按完整编号定位」与「筛选已加载任务」，不能宣称已支持全量模糊搜索。

#### 10.6.2 状态、结果与统计口径

任务展示三个不同维度：生命周期回答「运行到哪里」，执行统计回答「实际执行多少」，核验结果回答「有什么证据证明结果」。不再用一个「其他」掩盖排队、取消、阻塞、未知等不同状态。

| 维度 | 允许呈现的含义 | 禁止推断 |
| --- | --- | --- |
| 生命周期 | 排队、运行、结束、取消、阻塞、状态未知，按实际可得字段映射 | HTTP成功不等于运行成功；没有结束时间不必然还在运行 |
| 执行统计 | 已执行、总用例、未执行等有明确口径的数量 | 总用例数不能当事件数，已结束不能当全部执行 |
| 结果 | 通过、失败、未核验等现有事实及核验证据 | 返回完成不等于断言通过；缺字段不等于零失败 |
| 最近事件 | 最新实际事件、所属对象与原始发生时间 | 列表刷新时间不能冒充事件时间，不能凭任务状态合成一条已发生事件 |
| 用量/耗时 | 实际记录、估算或未知，分别标注 | 缺token或费用不显示0；估算不显示成账单 |

只有明确映射到现有契约的状态才使用确定文案。旧数据不能可靠区分时显示「已结束 · 结果未完整提供」等事实组合，并在详情说明，避免为了填满状态图而补造历史记录。

首屏不逐行加载所有Session日志。若列表或已有批量汇总中没有最近事件，先交付其余事实列，事件列显示「详情中查看」或「当前未提供」，按实际能力选择；不发起N条额外日志请求造成瀑布加载。

#### 10.6.3 详情和日志的渐进关系

详情保留「任务 → 用例 → 步骤 → 回合 → 事件/模型调用/原始参数」的深入路径。回合里的事件和模型调用是并列证据视角，不把一个事件硬归给某次模型调用。

| 深度 | 默认回答 | 展示与跳转 |
| --- | --- | --- |
| 任务摘要 | 本次意图、目标、环境、范围、总进度 | 用例结果列表；保留原筛选和返回位置 |
| 用例详情 | 这条用例执行到哪里，原文是什么 | 默认进入轨迹；原文/理解/执行证据保持可核对关系 |
| 步骤 | 当前步骤做了什么，关联哪些执行回合 | 明确关联回合数、事件摘要和截图来源 |
| 回合 | 本轮如何决策和尝试 | 展示该回合实际关联的事件与模型调用 |
| 底层记录 | 具体输入、参数、返回与错误 | 原始参数默认展开；长记录可分区滚动，不能再显示重复摘要 |

关联以已有显式标识优先，保留原文与时间等辅助信息供核对；没有可靠绑定的记录进入「未关联记录」，说明原因，不按数组索引、相同文案或时间接近强行归属。跳转携带任务、用例、步骤和回合中实际存在的身份，返回后恢复选择与滚动。

列表摘要与详情存在必要复述，但在同一详情区域不连续渲染同一记录两次。去重依据已有稳定事件/调用标识或确认的重复投影规则；真实重试、不同回合的相同动作和更新快照不能因文案相同被删掉。

### 10.7 环境配置：环境、渠道、详情形成可用的横向工作区

#### 10.7.1 布局与操作范围

截图中的问题不仅是表单宽度不足，还包括渠道列表在上、当前渠道表单在下，导致用户需要跨越很长距离才能看到编辑对象。宽屏改为三块连续工作区：左侧环境导航、中间渠道选择、右侧配置详情。

```text
环境配置                              当前环境有修改 [保存当前环境]
[项目环境] [控件定位]

┌ 环境 200–220px ─┬ 渠道 220–240px ─┬ 详情：剩余宽度 ───────────┐
│ 默认运行环境   │ Android         │ 测试 / Android            │
│ [测试  ▼]      │ 包名/完整度摘要 │ 配置状态 · 已保存/有修改   │
│                │ iOS             │                           │
│ 环境顺序       │ Web             │ 启动配置                  │
│ 1 测试 [默认]  │ Windows / macOS │ 启动标识 / 地址 / 适用字段 │
│ 2 预发         │ 其他已有渠道    │                           │
│ 3 正式         │                 │ 登录策略                  │
│ [新增环境]     │ [添加渠道]      │ 登录方式 / 账号来源       │
│                │                 │                           │
│ 排序操作       │                 │ 验证码策略                │
│ 独立于默认值   │                 │ 来源 / 固定值 / 适用条件  │
│                │                 │                           │
│                │                 │ [检查当前渠道配置]        │
│                │                 │ [危险操作：移除渠道]      │
└────────────────┴─────────────────┴───────────────────────────┘
```

宽屏条件建议内容容器≥1280px，三个区域之间16–24px间距；详情至少能容纳完整的一列表单。960–1279px将渠道选择放到详情顶部，保留环境导航；更窄时环境和渠道均采用顶部选择器，详情单列。响应式按容器宽度切换，不因渠道内容多少临时改变布局。

右侧详情容器填满剩余宽度，不设置把整页锁在左侧的固定窄宽。字段本身可按内容设合理上限：短枚举不拉成超长输入框，URL、包名和说明优先占整行；相关且独立的字段才使用两列。正常留白留在分组之间，不留下半屏无法使用的空区。

默认运行环境、环境顺序、当前编辑环境名称、保存、删除分别在明确层级出现。环境列表选中某项只切换编辑对象，不偷偷改变默认运行环境；排序只改变顺序，不改变默认值。

#### 10.7.2 配置分组与条件字段

| 分组 | 主体内容 | 条件呈现 |
| --- | --- | --- |
| 启动配置 | 当前渠道/平台、启动标识、地址与现有可配置项 | Android包名、iOS标识、Web地址、PC相关字段按已有渠道契约展示 |
| 登录策略 | 自动/指定等已有模式、账号类型、账号来源 | 仅对适用模式显示手机号起始值、账号字段等；提示真实影响范围 |
| 验证码策略 | 自动、固定值、邮箱或人工等现有方式 | 固定值、发件人、主题等只在相应策略适用时显示 |
| 参数引用 | 可供用例引用的现有变量及语义 | 显示人类可读名称，复制准确变量；不将技术变量当作主标题 |
| 校验结果 | 当前渠道字段问题、环境完整性问题 | 字段级就地提示，跨渠道问题给出定位；未配置但未使用渠道不默认当失败 |

条件字段隐藏时保留还是清空原值，必须沿用现有契约，并在切换产生实际数据影响时说明；不能通过纯视觉重排静默丢弃用户配置。设计不能擅自统一Windows、macOS与PC的业务定义，应保留当前已有渠道标识，只统一用户可读文案。

#### 10.7.3 保存和校验

本方案以「保存当前环境」表达整环境草稿提交。实施前核对现有写接口粒度：如果实际只支持单渠道保存，按钮和脏状态必须改为「保存当前渠道」，不能用一条成功提示暗示整环境保存成功，也不能为统一文案新增后端事务。

环境内切换渠道时保留各渠道草稿，并让列表显示修改标记。切换环境、离开页面或刷新时提供一致的草稿保护，不能只保护某个按钮入口；离开提示提供保存、放弃、继续编辑，保存失败留在当前环境。

「检查当前渠道配置」默认做已有能力支持的非执行校验。若某种检查会启动设备、登录、获取账号或提交执行，必须使用准确操作名并解释作用，不能伪装成普通表单检查。

只有已有版本号/更新时间契约支持可靠并发检测时，才能给出确定的版本冲突判断；冲突后保留本地草稿并展示差异/重新加载选择。没有版本契约则登记限制，不假设最近保存一定不会覆盖他人修改。

### 10.8 与既有用例、三栏和日志设计保持一致

此次重排不得破坏此前已经确认的工作台规则。这些是兼容约束，不代表本轮重新实施或验收。

| 既有区域 | 必须保留的规则 | 与本节的连接 |
| --- | --- | --- |
| 用例原文与理解 | 前置、操作、预期正常完整展示；不恢复折叠；彩色标注解释文字来源、参数和任务拆分 | 任务详情提供返回原文入口，不让模型摘要取代原文 |
| 同一内容的重复展示 | 先确定原文、理解、投影各自职责，再按准确身份处理重复 | 任务、回合、事件、模型调用共用事实与关联口径，不多份独立拼装 |
| 截图布局 | Android/iOS固定竖屏；Web、PC/macOS/Windows固定横屏；已确定平台后不随步骤切换 | 窄容器响应式可以调整，截图方向或事件类型不触发整页重排 |
| 截图尺寸 | 等比`contain`，宽或高至少一边达到可用边界；竖屏图区域最多35%宽度 | 空间分配优先确保步骤和回合信息可读 |
| 无图补位 | 首步无图时使用首张可用截图，并明确来源步骤；当前图与补位图区分 | 不能在来源不匹配的补位图上画当前事件坐标 |
| 交互覆盖层 | 点击箭头与拖拽动线位于独立覆盖层，不写入原始图片；坐标映射依实际图框 | 无可靠截图/尺寸/坐标关联时说明未标注，避免假证据 |
| 轨迹分区 | 事件信息约25%、列表约75%；内容溢出在各区滚动 | 概要高度有上限，不因一条长事件挤没列表；小屏保证可读最小高度 |
| 默认视图 | 用例详情默认轨迹；回合、事件、模型调用均可进入；原始参数默认展开 | 逐层深入同时保留当前选中上下文 |

参数解释使用「来源文字 → 识别出的任务 → 参数/能力 → 实际执行证据」链路。来源未提供、解析不精确和字段重复分别列为数据契约核对项；前端能整理展示和标明来源，不能假装重新识别后的参数就是服务端已固化结果。

### 10.9 纯前端可解决项与事实依赖清单

这份清单用于约束后续开发范围。标记为依赖核对的项目仍可先完成诚实的加载、未知、失败状态，不必等接口补全才能改善页面。

| 项目 | 前端可独立完成 | 需要已有契约提供/实施前核对 | 缺失时的界面 |
| --- | --- | --- | --- |
| 模型密钥分组 | 布局、字段解释、草稿和保存/验证区分 | 凭证状态、模型候选、能力与验证范围 | 能力未知、未验证；不显示推断成功 |
| Scout加载误操作 | 加载/失败/更新中禁用策略，操作入口隔离 | 请求的明确完成/失败结果 | 检查中或暂未能确认更新 |
| 可安装版本判断 | 按既有规则组合展示与过滤已返回候选 | 发布渠道、系统、架构、安装产物与版本信息 | 可安装状态未确认，不误报升级 |
| 节点资料丰富度 | 重排已有事实、显示更新时间和未上报 | 节点心跳及插件/设备上报实际字段 | 未上报/当前未提供 |
| 设备跳转 | 完整身份传递、路由编码、读取状态与返回路径 | 详情规范身份、数据源与权限语义 | 读取中/详情未同步/实际请求错误 |
| 已绑定IM渠道 | 依据当前账号有效绑定过滤、紧凑布局 | 绑定身份、安装状态、在线状态的可靠区别 | 读取失败不当零绑定 |
| 任务列表信息 | 使用已有汇总字段重排名称、目标、进度和结果 | 名称、用例范围、目标、环境、事件摘要实际可得性 | 有什么显示什么，缺失项不填0 |
| 任务深层关联 | 使用显式关系筛选、跳转和保留上下文 | 步骤、回合、事件、调用的可靠身份与关系 | 未关联记录，不靠时间猜归属 |
| 环境配置布局 | 环境/渠道/详情结构、条件字段、草稿保护 | 写入粒度、默认/排序语义、版本冲突合同 | 按实际保存范围命名并说明限制 |

后续开发中如发现必须新增后端事实才能达到某项完整体验，将其列为独立契约缺口，保持后端不动；不能把「前端优化」扩展成后端逻辑调整。

### 10.10 交付顺序与页面验收

#### 10.10.1 建议实施顺序

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| A：先修状态可信度 | Scout首次加载、版本判断、设备身份和读取状态；助手绑定过滤；任务未知值口径 | 读取中不可误操作，失败不显示无更新/零绑定，设备跳转不丢身份，缺字段不填0 |
| B：完成主要工作区 | 模型分组表单、节点列表/详情、环境三块工作区 | 五个页面的内容区域与主操作层级一致，长文案和宽屏不再挤压或空置 |
| C：贯通执行层级 | 任务语义列表、用例步骤到回合/事件/调用、上下文返回 | 用户能逐层下钻和返回，未关联记录有解释，真实重试不被去重 |
| D：统一视觉细节 | 渠道轻量状态、表格密度、焦点、错误、保存反馈及克制动效 | 各页键盘可用、状态可读，布局稳定，减少动效设置有效 |

以上是后续实施安排，不是本轮开发完成记录。实现时先复用当前基础组件与已有查询策略，避免为这五个页面创建五套按钮、Tab、状态徽章和错误面板。

#### 10.10.2 逐页验收场景

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| KEY-01 | 已配置/未配置服务商、长模型ID、宽屏 | 凭证、模型、参数、费用分组清楚，无七八个等权字段挤在一行 |
| KEY-02 | 修改后未保存、保存失败、切换服务商 | 草稿保留，验证结果指向准确版本，离开保护有效 |
| KEY-03 | 自定义模型能力未知 | 未知不显示为不支持或通过，验证结果不越权覆盖其他能力 |
| NODE-01 | 首次加载、慢请求、后台刷新 | 无可点击的升级/重新下载误操作；刷新保留旧内容并说明时效 |
| NODE-02 | 新Release无本机安装包、较旧候选有适用新包 | 按实际可安装候选判断；没有适用新包显示没有新版本 |
| NODE-03 | 版本检查失败、运行版本未知、非标准版本 | 分别显示未确认/未上报/无法比较，不伪装成无更新或最新 |
| NODE-04 | 升级触发后断连、重连未确认版本 | 不重复提交、不提前报成功；最终以实际运行版本确认 |
| NODE-05 | 长节点名、长ID、心跳变化、窄窗口 | 排序稳定，名称可读，操作不竖排，概览/接入/日志入口清晰 |
| NODE-06 | 设备ID含特殊字符、离线设备、详情读取失败 | 路由身份完整；读取、失败、离线、未同步、不存在分开 |
| NODE-07 | 添加节点慢加载、缺包、获取失败、关闭后继续安装 | 步骤清楚，无重复恢复按钮，无假接入确认，关闭不误报取消 |
| AST-01 | 0/1/2个绑定及多个未绑定渠道 | 常驻只显示绑定渠道；0绑定是紧凑空态；可添加渠道留在管理 |
| AST-02 | 已绑定离线、认证异常、绑定接口失败 | 离线仍可见；异常和读取失败不变成零绑定 |
| TASK-01 | 新任务、历史无名称、缺环境/事件字段 | 行内优先语义信息，ID可复制；缺字段诚实说明，不补造事实 |
| TASK-02 | 运行、结束未核验、失败、取消、阻塞 | 生命周期、执行统计与结果可分别理解，不用「其他」掩盖差别 |
| TASK-03 | 多步骤/回合、重复快照、真实重试、缺关联 | 关系准确；未关联单独解释；同一区域不连显两份，真实尝试保留 |
| CFG-01 | 1440/1920px视口与不同全局侧栏状态 | 详情使用剩余内容宽度，环境/渠道/详情相邻，不再窄表单堆左侧 |
| CFG-02 | 切换环境、渠道、登录与验证码策略 | 默认值与顺序独立；草稿不丢；条件字段符合已有语义 |
| CFG-03 | 校验、保存失败、版本冲突或合同缺失 | 操作范围准确，失败有恢复入口；不声称具备不存在的并发保护 |
| COMMON-01 | 内容容器1280/960/720px附近及200%字体缩放 | 长文案不盖住按钮，主要操作可达，表格/日志必要滚动有明确边界 |
| COMMON-02 | Tab/Shift+Tab/Enter与减少动效偏好 | 焦点明确、对话框可退出、错误可读；无必须依赖动画才能理解的状态 |

实施验收应在实际Workbench页面中检查，优先使用脱敏样例或已有安全读取场景覆盖这些状态。首次加载、跳转与布局不应靠触发真实升级、解绑或模型付费调用才能验证；远端写操作与真实费用沿用既有业务授权流程。

本节的文档交付标准是五个页面都有可实施的布局、状态规则、数据边界和验收场景。后续开发应逐项更新实际完成情况与未解决契约缺口，不能把方案中的预期表现直接改写成完成结论。
