## 1. 输入、先决条件与最小闭环

输入沿用现有文字三列用例的导入方式，不建设手写计划格式。V5 增加的是编译后的审阅与冻结：预览映射、资格检查、控件补定位和冻结发布。模型只在编译期参与，运行期只读冻结版本；不重新引入需求理解与用例生成。

```text
文字用例（三列）
  → 现有导入解析/编译（编译期可调模型；记录 dispatch_log 与版本）
  → 编译预览 + V5 资格检查
  → 缺定位的控件 → Workbench 补 typed locator → 人工核对后发布
  → 人工确认预期强度 → 冻结发布（统一来源守卫）
  → v5 模式 / 节点固定 / lane 租用 / 每案新 context / 未登录基线
  → 严格目标动作和独立 wire 回执
  → 动作后的定向原始事实与新截图
  → Nexus 原子谓词 + required 消费
  → Evidence/verdict 原子提交 → 状态机终结（unknown 且可复位 → 整案重试）
```

首批三条文字用例：有效登录、错误密码被拒、空账号被拒；另保留“错误密码但预期仍写登录成功”的裁判反例（同样是文字用例，发布审阅时固定预期）。预期要写成能映射到原子谓词的说法（例如“页面出现登录标记”）；“页面显示正常”这类含糊预期会被资格检查拦下，这是预期行为，也借此暴露不可验证的写法。

wrong-password 用例预期错误提示，正确拒绝就应 pass；裁判反例保持成功预期，必须 fail。expected 强度由维护者发布审阅，校验器不能证明需求语义充分。登录成功可用业务认可的强标记，SPA 不要求路由变化。

开工核实项：Scout 在目标机器上报 Web 槽且 headless；Nexus 可固定到该节点（同机若同时有打包版与开发脚本两个 Scout，确认各自 sn/node_id，V5 只指向配置节点）；demo 可复位；资源元数据能实际供给；受控 demo 秘密来源可用。业务账号尚未就绪先用 demo，不查询/索取真实密码，不假设账号池租约已经支持 Web。

## 2. 第 0 阶段拆分

### 0A：热修复与现存编排缺陷

分开发布：**HF-1 秘密止漏**独立于 V5，可先单独上线，demo 验收不依赖它，接真实凭据才以 0B 哨兵验收为门槛；**PR-A 编排止血**是 V5 的第一批改动。

| 项目 | 修改落点 | 验证出口 |
| --- | --- | --- |
| 采集与输入绑定止漏（HF-1） | dom_collect password 的 text/value；hydrate_bound_text/typed_by_step | 节点和规则绑定不含秘密原值，原字段类型不变 |
| 回执/模型/日志出口止漏（HF-1） | summary/error/plan_event/raw_response 与实际序列化 | 不靠仅 UI 遮罩；实际必要设备输入仍正确 |
| Web IME 整改（PR-A） | 同意框、通用 dismiss_ime；核对已排除 Web 的发送验证码分支 | Web 收起动作不调用 go_back，真正浏览器后退能力不变 |
| 新设备请求独立编号（PR-A） | RouterProxy 共享分配；local 编排、logout/recovery/flow | 不同设备动作不同 wire；逻辑 seq 保留 |
| 控件回写守卫（PR-A） | control_registry 写入口及 locator_stop_reason/note_execution_locator/nav_route | V5 runtime 不学习；发布 typed 控件不被旧路径改写 |

HF-1 范围小：采集端一处、绑定一处、摘要/日志副本脱敏，不含新协议字段，工作量主要在逐出口验证。秘密 nonempty/length 和新远程来源元数据留给协议批次。控制回写保护所需模式标记先在 Nexus 本地生效，Scout 准入字段随后升级。

0A 可惠及旧模式，但旧输入 fallback、视觉定位与执行安全仍未整体通过 V5 验收。不要把“止血完成”标为“V4 已全面可信”。

### 0B：场地、核实与基线

| 项目 | 交付 | 注意 |
| --- | --- | --- |
| 秘密哨兵会话 | 受控输入，覆盖成功/失败/超时，检查实际节点/回执/日志/模型出口 | 接真实凭据的准入条件；demo P0 不需要；报告仅出口与计数 |
| 小型本地 login demo | 主 page、SPA 强标记、错误/必填、checkbox、真实提交计数、有限延迟、复位 | 服务端每次真实提交累加，不以客户端请求键去重掩盖重复 |
| 真实 BACK 路径场景 | 前一页历史 + 当前登录页 + 输入框聚焦 + 同意框 | 修复后仍在当前页、同意框实际改变，不更换非导航键避开缺陷 |
| 文字用例导入样本 | 三条 demo 文字用例走现有导入；检查预览映射、自动产生的 draft 控件；Workbench 补 typed locator 后冻结发布 | 只建一份真源；旧 dom_hit 不自动转发布配置；同一文字重复编译的差异可见 |
| unknown 规模 | 从现有 session 统计各写类能力的超时/缺回执率，按能力与站点 | 决定 retry_policy 默认；无数据时不预设 |
| 节点与 lane 现状核实 | 目标机器实际注册的 Scout 节点（打包版/开发脚本）及各自 sn/node_id；是否 headless；Playwright 能否取得并结束 lane 的浏览器进程 | 取不到时 lane 隔离降级为节点隔离，写入风险 |
| 幂等历史归因 | 脱敏统计合法同请求重取、可证实不同动作复键、信息不足 | 原始命中数不等于假通过数 |
| append 写入基线 | eligible attempts、store errors、返回0各类，按入口 | SessionWriter 锁存在不等于 DB 跨入口原子 |
| capability 耗时基线 | 成功/失败/超时、缓存命中、样本数与 profile | 无实测时明确 demo 初值；不编造 P95 |

demo 只含登录相关页面与只读计数/复位/有限延迟，不建通用代理或环境变异平台。计数仅证明请求接收数，还需真实 checkbox/输入值等状态观测；不能用“客户端两条日志”代替“动作都发生”。业务环境迁移另核对数据、复位、权限和控件。

## 4. 会话验收记录

每条记录保存：预标定 should_pass/should_not_pass/expected_rejection，冻结发布版本与编译期版本/dispatch_log 引用，控制与目录选定快照，Nexus/Scout build，模式/sn/node/context，retry_of/attempt，逻辑→wire 映射，execution阶段，事实/截图与 Evidence，验证状态和主原因，站点实际计数，复位结果。

受控异常限定在受控节点/lane；丢回执/超时注入位置记录清楚，不能在真实支付/业务账号上试。事件存储故障时需要外部调用结果与独立计数辅助证明，不能仅查询一个已经写失败的日志通道。

遵循两仓 CLAUDE.md：不新增/修改 tests/test_*.py，不运行 pytest。协议样例管理先解决 AGENTS.md/CLAUDE.md 的真源及提交规则冲突，见主方案 §13；其余验收以可重复的受控会话和 session_events/session_meta 为依据。会话回放不是读取旧 pass 后再宣布通过：必须实际跑新构建并读取 demo 状态。上述均是后续开发验收，本轮未执行。

## 6. lane 租用与并行发布条件

lane 租用落地前，P0 只能把“每节点 1 个活跃 run、明确选择 v5、对应 build”的结果称为 V5 受控执行已验收，结果不外推并行。串行同样要验收两个不同任务竞争准入，不只是一次任务内部并发 1。

放开并行（每节点最多 4 个活跃 v5 run）只需三项，对应 E24–E26：

1. 4 个 run 同时到达，各租到独立 lane，无排队，提交计数与证据链正确；容量满时第 5 个排队，不超额接单。
2. 4 个中 1 个故意卡死：其余正常结束，卡死 lane 被隔离并可恢复；若 Playwright 取不到 lane 的浏览器进程，如实降级为节点隔离并记录对其余 lane 的影响。
3. 容量由 Scout 上报，Nexus 按上报值准入；lane quarantined 时可用容量下降。

不要求证明“同一线程上多个 run 互不影响”，因为 v5 不允许多个 run 共线程。headed 模式共享桌面，仍限 1 个 run。灰度开关只影响新任务，旧任务沿选定模式；无法证明 lane 隔离范围时按节点隔离。

移动与 PC 还需各自写安全及视觉准出，后续独立排期；离线 VLM 标定报告不等于已经解决端级执行风险。

## 7. 指标和门槛

| 指标 | 定义与分母 | 首期要求 |
| --- | --- | --- |
| 静默跳过 | 不同写意图共键，后者未做却拿前者成功 | E00固定场景0；历史可证实计数另列 |
| 重复写 | 一个固定写意图的真实动作/站点提交次数，含换新键重做 | 正常意图至多一次；写前拒绝为0；仅键级计数不够 |
| 标定反例假通过 | should_not_pass被判verified_pass /标定反例数 | 全部已标定反例拦下；只是回归保护，不是总体准确率证明 |
| 证据链完整率 | verified_pass可回链到固定check/action/来源/事实/版本/终结 | 受控通过100% |
| 正例未核验 | should_pass中unverified/总数 | 受控正例0；灰度至少20条且>5%告警，少样本只报计数 |
| 正例总误拒 | should_pass中verified_fail+unverified/总数 | 同时报告，不把困难样本移出分母 |
| 秘密外泄 | 哨兵原值出现在实际非必要执行出口次数 | 0；未过不能接真实凭据 |
| 存储故障 | eligible store_errors/eligible append attempts，按入口 | 关键故障不得绿；有前后基线 |
| 延迟/窗口拒绝 | 实际耗时、超时、timeout_before_dispatch/正例数 | 无隐藏续时；profile与样本随数据固定 |
| 配置污染 | 未授权运行写入已发布typed控件次数 | 0；不能仅核对当时session副本 |
| case 重试 | flaky 通过数/总 case；effect_unknown 发生数/写动作数；重试后仍失败数 | 单列，不计干净通过；受控场景在未注入时 unknown 应为 0；灰度同样 >5% 告警 |
| 并行吞吐 | 排队等待时间、lane 利用率、lane quarantined 次数 | 只记录，无统计门槛 |
| 可映射比例 | 首批文字用例中预期可映射到原子谓词的比例、资格检查拦下原因分布 | 只记录，用于判断文字用例的可验证性，不作质量结论 |

20条/5%为可用性告警初值；0/N不构成统计可信度证明。旧日志缺载荷时不把幂等命中归因为假通过。超时样本按截尾/失败类别展示，不只取成功快样本。

unverified为终态、标准CI非成功，不等人工。结束资源释放和执行器真正停止分开：没有停止证据的实例隔离不叫设备队列死锁，也不能假装副作用已撤销。

## 8. Workbench与维护工作台

会话详情先支持结论→check→wire动作→控件事实→脱敏读数/截图；展示当时配置与当前注册表、手工来源/Schema、expander、谓词/build、模式/sn/node/profile、reason/legacy reason。过期artifact明确expired。

轻量配置UI只编辑既有注册表，并列出导入产生的 draft 控件待办；用例页显示发布状态、未发布修改与差异预览、资格检查结果。其目的不是造新的用例编辑器，而是让文本入口不会悄悄改变执行真源。

周表可先服务端聚合导出：reason_code、计数与分母、关联会话、下个修复、本周结果。维护者本人每周检查，优先处理泄漏/静默跳过/重复写/存储故障，其次未核验和目标配置；不引入虚构多人owner流程。

compatible fix受控反例回归；breaking合同只重校受影响计划。普通配置更新后下个run选定revision，历史结果仍用当时session快照解释。

## 9. 三端VLM离线校准

并行整理现有合法Web、Android/iOS、PC素材和P0新截图，每条固定expected、来源与人工pass/fail/信息不足；分歧保留，不为凑数重复操作真实账号。复用vision_assert独立推理，不调设备，不接在线恢复。

按端、输入框、动态控件、错误提示分层报告混淆计数、假通过/假失败、信息不足、可判覆盖，保留模型/视觉prompt/verifier版本。这里的prompt记录服务视觉裁判复核，与取消的用例生成无关。小样本只报计数；未标定视觉不能升为主门禁。

## 10. 开工清单与未验证项

已定：控件唯一真源、Web IME平台分支、严格目标能力、文字用例导入+资格检查+冻结发布、check v2、同步与资源守卫、节点固定、lane 租用、协议字段/fixture清单、分批PR、case 级重试与并行三项验收。

待实施验证：秘密止漏完整性、历史复键规模、unknown 实际规模、append错误率、真实驱动耗时、lane 浏览器进程可取性、打包/开发节点核实、文字编译的可映射比例（首批用例中有多少预期能映射到原子谓词）、计划消费兼容、视觉误判率。它们有明确交付位置，仍无实测结果；开工不能据文档将其标为完成。

## 8. 路线 B 本版补充验收（已确认范围）

下列 B 编号补充而不替代 E00–E26 与 D08，N0–N5 均属本版；平台切换不是 V6 待办。四值平台不自动扩展严格 Web 合同的支持范围。
