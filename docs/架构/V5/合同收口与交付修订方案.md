## 2. R01：注册事实、调用规则、执行绑定分开

注册只回答实际实现能力；不能单凭事件 ID 已注册就向模型开放，也不能把旧目录中所有字段一并降为展示字段。

| 层 | 权威来源及维护方式 | 必须表达的内容 |
| --- | --- | --- |
| 能力事实 | Scout 执行器注册；Nexus 本地执行器注册 | event_id、implementation_id、executor、runs_on、支持平台、参数合同版本、所需观察/设备能力、当前可用原因 |
| 调用规则 | Nexus 程序合同及现有授权/策略入口；不由 Scout 或模型授权 | caller、允许阶段、enabled/lifecycle、项目/账号/目标作用域、执行合同限制 |
| 执行绑定 | Nexus 装配层按选定任务生成并固化 | 选定实现及版本、node/device、executor_order、selected_impl、low_level、device_hint、适用目标与观察路线 |

字段名称可复用既有模型，不要求新建三套存储。程序事件的调用规则由代码注册；业务流程与现有配置仍经 Workbench 维护。事件展示页只读，不等于删除停用与权限能力；现有停用状态、deprecated 和 caller 限制不能在注册或升级时自动解除。

执行装配的权威由 Nexus 已知版本的事件适配合同提供；Scout 注册声明实现及参数版本，Nexus 只能选择自己理解的合同。未知版本先拒绝绑定，禁止缺字段后依赖 Scout 默认值。原 implementations 中仍承担 low_level/参数映射的内容，在替代合同完成前不得停止读取；完成后才将旧描述降为展示元数据。

菜单 = 已注册且依赖满足的实现 ∩ 当前用户/项目允许 ∩ 当前 caller/phase/合同允许。程序专用事件只供程序调用，不因模型能拼出 ID 而放行。Scout 执行前保留实际实现、参数与目标校验。

**验收 R01**：注册但停用、program-only、错误阶段、错误项目的事件均不能获得不合法调用；合法事件的完整 EXECUTE 装配可追溯；未知参数版本写前拒绝，实际写入数为 0；多实现绑定确定且运行不临时换实现重放。

## 3. R02：编译不依赖节点在线，执行绑定固定快照

| 阶段 | 输入与判断 | 持久结果 |
| --- | --- | --- |
| 文字编译 | 原文 revision、编译合同、语义事件及参数合同；不要求已经选择节点 | 所需事件、参数、断言、资源和依赖；保留 unresolved，不伪造实现 |
| 预检 | 选定设备、实时注册及健康状态、权限和资源情况 | runnable_now、检查时间、阻断类别；静态不支持和暂时离线分开 |
| 开跑绑定 | 复核预检依赖，选定本次实现与策略 | attempt/run 的脱敏执行快照 |
| 运行 | 按绑定快照执行；检查节点代际、合同、撤销/停止信号和实际能力 | 新证据和状态；不修改冻结语义或静默换合同 |

语义事件合同由已安装的版本化代码/编译目录提供；它不宣称任何节点当前可执行。注册视图仍是当前可执行实现的依据，两者不是重复的运行能力真源。

运行快照至少保存原文/计划版本、事件及参数/结果合同、实现选择、调用规则版本、节点与进程代际、目标、观察策略、执行合同、必要资源引用、预算和证据策略。复用现有 runtime_context/session，不新增第二套运行事实库；不保存秘密原值。

实时视图可以不落库，但**本次消费的绑定及判定依据必须落库**。排队期间能力变化须在开跑时重检；运行中不满足绑定时停止相关动作并记录原因，已可能执行的写不重放。不同节点得到不同预检结论，不应改写同一原文的语义编译结果。

**验收 R02**：无在线节点仍可导入/解析并查看结果；节点离线显示资源不可用而非用例语义错误；预检后节点换版本不能偷偷执行新合同；旧会话仍按当时绑定解释；缺快照不能宣称可复核。

## 4. R03：区分条件必需与真正可选

optional 不能同时表示“可能不适用”和“缺实现也可以不做”。复用现有步骤结构表达适用条件与完成要求，编译/发布时固定，不允许运行模型删除必选项。

| 要求及适用性 | 实现情况 | 结果 |
| --- | --- | --- |
| 始终必需 | 有实现 / 无实现 | 执行并核验 / 阻断 |
| 条件必需，已证实适用 | 有实现 / 无实现 | 执行并核验 / 阻断 |
| 条件必需，已证实不适用 | 任意 | not_applicable，记录证明，不计通过证据 |
| 条件必需，适用性未知 | 任意 | 有界观察；仍未知则未核验/阻断，不跳过 |
| 真正可选且不承担作者要求 | 无实现 | 允许 unavailable_optional，但报告明确未做且不计证据 |

登录协议是条件必需：已有勾选状态可作为满足证据；未勾必须处理；空树/截断不能证明不适用。不存在唯一“所有必填都 native”的块平台公式，需同时验证条件分支、适用性探测和必要依赖。运行前无法决定的条件保留有界观察节点，不能假装静态预检已完成判定。

**验收 R03**：无协议、已勾、未勾、结构缺失、需要勾选但无实现五类分别处理；后两类不得 skipped→登录准出；真正可选缺实现单列，不补造通过。

## 5. R04：本地工具依赖与登录完成证据

Nexus 注册本地函数只证明函数存在。解析工具是否可用还需检查其依赖：assert_visual 的截图与账号模型配置、confirm_login_state 的目标观察、get_otp 的租约/插件/发送时间窗等。首期依赖使用 §14.4 的固定扁平检查，不新增通用递归依赖引擎；候选实现只按已声明组合选择。

预检区分三件事：实现存在、依赖已配置、运行时事实有效。未知设备/模型结果不能在预检阶段假定成功；错误归资源/能力/执行，不改写为用例定义错误。截图、OTP 和模型结果仍在运行时验新鲜度与归属。

登录结论分开记录：是否登录、是否满足要求身份、是否回到原业务上下文。Web Cookie/localStorage 只作辅助线索；凭据存在、HTTP 200、离开表单均不单独证明登录成功。以用例/环境确认的登录标记、所需身份及业务上下文证据核验；无充分证据为未核验，不因为有 Cookie 转绿。

**验收 R04**：过期 Cookie、错误身份、仍停登录页、正确登录但回错帖子均不冒充完整成功；有本地工具但缺截图/模型配置/OTP 来源时明确指出依赖缺口。

## 6. R05：登录态复用不免除必要租约

将“复用，不额外租号或重登”改为：无需重复登录或重新选择账号，但需要账号/数据隔离的任务仍须获得或验证对应资源租约。

| 场景 | 处理 |
| --- | --- |
| 本任务已有匹配且有效租约 | 沿用句柄，观察身份与目标，不重复租号 |
| 已登录但本任务无租约，操作需要隔离 | 确认身份并领取相应租约；被占用则等待/受阻，不能无锁使用 |
| 只读且合同明确无需身份或账号隔离 | 可免账号租约，仍须设备/上下文准入 |
| 登录身份未知，操作依赖身份 | 有界核验；不能把本次租约账号猜成设备当前账号 |

清理、退出和释放租约分别记事实。租约到期、窗口关闭或 force-stop 都不证明副作用结束；未知写继续隔离。

**验收 R05**：两台设备已登录同一个受隔离账号时不能并行取得同一独占资源；复用同一任务租约不重复分配；免租约只读路线有明确合同依据。

## 7. R06：首批单次否定检查与必要完整性取证

D10 中首批 8 条用例实际依赖的单次检查和范围完整性子集提升为 P0；连续监测、闪现捕捉、延迟复现及长期不再出现的业务逻辑不纳入本版 N3。通用跨 frame、大页面扩展和 SDK 优化仍可后续安排。

本期“刷新后不再弹窗”的执行语义已确认：刷新完成并达到明确页面就绪检查点后，针对指定弹窗做一次有效观察；检查时未发现则该检查通过，发现则失败。不额外等待 5 秒、不循环采样、不建设 DOM 持续监测。报告写“检查时未发现弹窗”，不把它扩大为持续或永久未出现。

- 单次指一个业务检查点，不是一旦 DOM 空结果就判通过；证据须来自刷新后的当前页面，能够观察指定区域。采集失败、页面未就绪、作用域不可观察时未核验或受阻，不把失败当作没有弹窗。
- DOM 不可观察时仍可按现有观察策略在同一检查点用截图补证；这不是新增时间窗口或连续取证。
- “全部/数量”仍需集合边界与采集完整性；单次检查不解除空间范围要求，不改其他原文的量词。
- check 取证动作须被合同允许，不能为取证执行未经声明的业务写动作。

**验收 R06**：同一检查点弹窗存在/不存在分别正确判定；刷新前旧证据、采集失败、未就绪不能判不存在；截断列表或视口外目标不能冒充全量证据。本期不以闪现、稍后出现或缺持续监测能力阻塞该单次检查的交付。

## 8. R07：实施依赖单向，影子阶段不删除旧路径

本次文档整理不触发任何等待中的实施任务。本轮取消文件名状态标记，设计/代码/业务验收分别按 §20 状态表维护；不依据文件名自动开始任务。

建议验收后按以下次序实施：

1. **当前 DOM 切片收口**：依托已有程序注册与保护补齐 D01–D07、R03/R05/R06 必要部分，完成 D08。允许有限重复注册代码暂存，不依赖整套事件迁移才修当前故障。
2. **事件合同准备**：完成 R01/R02/R04 与 C01/C02，明确事件实现及调用合同，列出消费者和数据引用清单。
3. **只读影子比对**：新 resolver 对现有快照并行计算，记录差异；保留旧执行行为，不删除归一化、不改平台值/SN、不移除旧事件、不解除停用。
4. **原子业务切片替换**：词表、协议、消费者、必要数据迁移和事件引用迁移作为完整合同切片验收。迁移歧义则中止并列清单；数据迁移是新合同 N4 必交项，具体清单与保护见 §18；本轮不执行迁移或设备升级。
5. **强制新解析**：有依据的差异逐条确认后启用；保留原写安全、阶段、权限和证据守卫。

删去事件方案“D05 必须依赖事件整体迁移”的硬依赖，以及“E02＋E09 是不改变行为的最小影子切片”的说法。已有必填不跳过保护不能在影子阶段退回旧缺陷。影子结论不覆写实际 verdict。

**验收 R07**：任务依赖无环；每个切片有完整输入/消费者/退出条件；影子运行不会改变实际选路、写次数或准出结论；新合同未验收时不提前停读旧装配信息。

## 9. R08：V5 总交付与两类验收

8 条有效业务用例 + 2 条占位是 2026-10-14 的固定审计基线，不是实时数据库总数。后续新增用例另列，不替换或偷偷缩小原分母；占位按正常流程补定义或归档，不计通过。

| 交付包 | 必交内容 | 完成依据 | 当前状态口径 |
| --- | --- | --- | --- |
| P-A 执行闭环 | D01–D08；首批必要的完整性、身份、隔离、写安全、真实检查 | 8 条逐项去向及真实 session；支持范围内已确认工具阻塞为 0 | 已有源码/局部检查，D08 未证明完成 |
| P-B 导入与版本 | XLSX、持久收据、revision/job、幂等补交、旧 job 不覆盖、冻结兼容计划 | 真实输入与 provider 编译；中断/改文/重编/版本选择证据 | 待实现核对和端到端验收，不由 P-A 代替 |
| P-C 用户处理问题 | 理解侧栏、原句/线索/断言、六类根因、复核、修复入口 | Workbench 问题→原句→修改/配置→重编→实跑关闭 | 待实现核对和端到端验收 |
| P-D 结果与使用边界 | 原请求分母、未执行/未核验、复跑并列、证据、平台保证等级 | Workbench 真实接口/浏览器操作；反例、秘密出口及异常矩阵 | 复用已有合格证据，补缺项 |
| 后续扩展 | 严格 Android/PC 合同、通用复杂树、飞书持续同步等 | 独立范围与验收 | 不扩大当前 MVP 门槛 |

P-A 单独通过只能称“首批执行场景已验收”。V5 面向首批用户的产品完成需要 P-A 至 P-D 均满足选定范围。事件平台重构不是 P-A 的循环前置；本版已确定采用路线 B，必须满足 R01/R02/R04/C01/C02，并完成 N0–N5 及 §19.2 的切换复验；§21 的词表统一和 SN 迁移均属本版范围。新合同验收前保留现合同只是过渡顺序，不是路线 A。

总体不要求全绿：有效产品反例应 fail；资源不足可列 blocked；未知执行必须未核验。支持范围内语义明确的用例不能因已确认工具缺陷仍无法执行/判定，不得靠改分类或删分母达标。

## 10. C01–C03：三个一致性修订

### C01 协议变更类型

provides 从字符串数组变为对象数组、移除旧平台字段和改设备身份属于破坏性合同变更，不能写成 additive。新增可选字段本身可以 additive，但不能掩盖整个变更的破坏性。明确协议/参数/结果版本、双方校验、历史证据读取和不兼容拒绝；不以同版本 fixture 自洽代替旧请求拒绝验证。

### C02 tier 与 runs_on 正交

### C03 页面识别线索与业务断言

“进入拍摄页（底部有几个圆形按钮）即可”默认解析为到达拍摄页的业务断言，加有来源的识别线索；不编造精确数量。只有作者明确要求或审阅确认后，线索才成为独立 required 断言。“必须显示 3 个按钮”必须保留精确要求。括号/或/否定原文保存；AND/ANY 及分支充分性在编译审阅固定，运行不能挑弱分支。

**验收 C01–C03**：不兼容消息明确拒绝；Scout 工具分类正确且依赖不丢；同一句原文在 MVP、DOM、编译、展示和核验中的强度一致，相似页面不能仅靠圆按钮通过。

## 14. 唯一执行绑定入口与最小数据结构（新增工程）

### 14.1 单一生成函数

拟放在 Nexus `services/execution_binding.py`，复用现有 catalog、scope、input_contract、device_targets 与 runtime_context。这个模块当前尚不存在，不能把它写成“复用已有解析器”。

```python
resolve_execution_binding(
    requirements,       # 固定原文/计划的语义与依赖，不是自由文本
    target,             # 已验证项目/应用/环境/节点/设备
    capability_snapshot,# 一致的当前注册快照
    policy_snapshot,   # 当前调用规则与授权范围
    execution_contract # legacy 现合同或新绑定合同版本
) -> BindingResolution
```

这是纯解析/校验入口：不调模型、不操作设备、不租号、不写库、不自动选择其他项目或节点。调用者先通过既有入口取得一致输入；预检和开跑均调用同一个函数，开跑使用新鲜输入重新生成，不能直接复用过期预检结果。

compile 只产出 requirements，不调用这个面向具体目标的绑定函数。菜单、准入解释、dispatch 参数装配读取 BindingResolution 的投影；阶段推进/资源领取/日志提交仍在原模块，不能塞进解析器。Scout 保留副作用前校验，这属于安全复核，不是再实现一份业务解析。

BindingResolution = status(ready/needs_input/blocked/not_applicable) + binding(仅 ready 完整) + diagnostics[]。diagnostics 至少含 reason_code、责任类别、case/step/clause、缺失字段、恢复入口和是否可重检。离线、争用、真实不支持分别编码；needs_input 是开跑前资格状态，不新增长时间占设备的运行终态。

### 14.2 ExecutionBinding v1（拟议内部合同，不直接新增同名 wire 消息）

| 字段组 | 必需字段与来源 | 规则 |
| --- | --- | --- |
| 身份 | schema_version、binding_id、binding_revision、plan_ref、project_id、app_id、owner_scope_ref | 服务端认证/固化计划提供；模型不写 owner；binding_id 不含秘密 |
| 目标 | node_id、sn、platform、env_profile、env_surface、target_ref | 目标为单个平台；宿主系统另属 host，不参与用例平台枚举 |
| 代际 | node_connection_generation、scout_process_generation、capability_revision | 前者可由 Nexus 连接生成；后两者新协议需 Scout 提供；不能用桌面/session_generation 或包版本冒充进程代际 |
| 路线 | execution_mode、execution_contract_version、action_scheme | dom_preferred 是观察策略，不代表严格合同；actual observation route 单独逐动作记录 |
| 事件绑定 | 每项 operation_ref、event_id、implementation_id、executor、runs_on、params_contract、result_contract、target_mode/write_mode 等必要组合 | 仅计划实际用到的事件，去重存实现；复杂逻辑块用已编译子步骤引用 |
| 派发装配 | executor_order、selected_impl、low_level、device_hint_template | 由现有装配信息或新版本适配器生成，不能为空后让 Scout 猜；每个候选实现都有自己的装配，禁止给后备执行器复用首项 low_level |
| 限制 | policy_ref、caller、allowed_phases、enabled/lifecycle、target_scope、effect_class(read/write/cleanup) | 是程序约束，不由注册覆盖；临时禁用/取消仍可实时否决 |
| 依赖/资源 | requirements_ref、dependency_checks、lease_requirements | 保存检查结论及引用，不保存密码、OTP、令牌；现有租约句柄在领取后单独记关联 |
| 预算/证据 | timeout_profile_ref、evidence_policy_ref、source_revision、created_at | 固定策略与取证强度；设备/context 生成后追加实际来源关联，不改已冻结业务要求 |

动态 params、wire step_idx、真实 focus_ref、node_ref、截图内容不写成永久绑定。每次派发基于 binding_id、operation_ref 和当前受检观察装配 Execute；唯一 wire 分配仍由现有 RouterProxy 负责。

字段复用优先：现有 Execute 的 executor_order/selected_impl/low_level/device_hint/timeout_sec 保持运输职责。新合同如需 binding_id/代际在 wire 上验证，须明确两仓协议版本，不能先只写 Nexus JSON 然后声称 Scout 已校验。

### 14.3 写入边界与结果适配

新合同用 execution={started:no|yes|unknown, phase, reason_code} 的领域形状；明确 wire 映射为已有严格字段 execution_started，不同时维护两个写边界真源。普通布尔回执由入口适配：true→yes；false 只有执行器能证明写前失败才→no；缺失/异常→unknown。既有历史回执只按其原合同读，不回填新保证。

effect_class=write 且 yes/unknown 时，禁止换坐标、换实现或换键重放。确认 no 才能在固定预算内恢复尚未执行的同一意图；只读失败可按声明重取。EventStatus、业务 verdict、写效果、停止/清理结果分开，blocked 不统一解释为“等待人工”。

当前普通 route 返回多个执行器但 selected_impl 只有首项；首期新绑定对写动作选一个实现，后备路径只允许重新绑定尚未开始的动作，且必须有已批准候选和完整装配。严格路径保持已有更严格限制。

### 14.4 依赖解析范围收敛

第一期不做通用递归依赖图、通用动态插件流程或多层调度引擎。Gmail 动态取码采用 get_otp 的固定、程序专用子合同，纳入本版。事件适配器返回固定的扁平 requirement 列表，复用现有检查器：账号模型配置、观察能力、精确输入组合、目标环境、资源引用、预算/证据策略。

初始实现限制建议：每个事件最多 32 个已声明依赖；只允许合约内固定 all/any 选择；依赖不再引用其他事件来自动展开。若作者声明嵌套或自引用，按 dependency_contract_unsupported 拒绝并列开发项。复杂逻辑块仍由既有编译阶段展开，不在绑定时造新业务步骤。

这比“有界展开、拒绝循环”的 R1 描述更窄，覆盖 R04 首批实际需要。后续若证明需要通用依赖图，再单独立项，不能借 R2 实施无限扩展。

## 15. 快照存储：已核实基础与新增保障

### 15.1 实际代码情况

- `models/session_event.py::SessionMeta` 已有 runtime_context/verdict JSON、finalization_id；`session_store.open_meta` 创建会话但没有绑定参数。
- `session_store._meta_dict` 返回 `dict(row.runtime_context or {})`；可以读取空对象，但没有新 binding schema 的版本分派。
- `session_atomic.append_batch` 可在一个 SQLite 事务中写 events 和 runtime_context；meta_patch 是整体赋值，不是深度合并，也不校验 binding 不可变。
- `loop/v5_case_exec._attempt` 先建 meta，在 probe/open_web_v5 前提交 context，后续补 baseline、lane 及最终 verdict。context 已包含 publication/controls，不应再完整复制一份相同发布内容。
- 普通 `observe/session_log.open_session` 写 session/start；open_meta 异常会返回 writer，不能宣称普通路线已做到“绑定持久成功才派发”。普通 force_close 的 event/meta 不是同次事务。

结论：复用现有表可行，但写入守卫、合并规则、体积和旧记录展示属于新增实现与验收，不能只加一个 JSON 字段就算完成。

### 15.2 写入时机与更新规则

1. 预检只返回 BindingResolution 预览，不占资源，不创建执行 session；人审内容保存为草稿 revision，不能写成已运行快照。
2. 任务受理保留 requested_total、目标选择和编译版本；真正 attempt 开始时重新解析并取得既有准入/租约。
3. open_meta 后，使用 append_batch 在同一事务写 `execution/bound` 与 runtime_context.execution_binding。**该事务成功前不派发任何 UI 写动作，包括 open_web_v5。** 失败立即释放尚未使用的准入；若此前已有副作用则按实际停止/隔离处理。
4. binding 的语义、实现和调用规则冻结；实际 context generation、lane、租约领取、动作观察另以事件关联，必要状态仅投影到 runtime_context.runtime_state。不整体覆盖其他调用者写入的 context。
5. 新增 binding 写服务执行 schema 校验和 binding_id/版本比较；同 ID 同内容重复提交幂等，不同内容拒绝。复用已有事务，不另建事实库。
6. 首期对开启新绑定保障的路径用原子终结记录 verdict、关键证据和 meta；普通历史路径保持其保证等级，不能统一标严格通过。

### 15.3 体积、秘密与旧记录

新增 execution_binding 子对象按 UTF-8 JSON 字节计量，**256 KiB 仅为初始告警线，不是拒绝开跑阈值**。超线记录 `binding_size_warning`、实际字节数、合同/计划版本及去重情况；结构合法且真实持久化成功时允许继续，不静默截断。先采集首批及代表性大型计划的大小分布、事务耗时与失败原因，再由存储和执行负责人审阅硬限值、依据及版本；硬限值未批准前不得返回 binding_too_large 阻断。真实存储失败、schema 错误仍按写前守卫阻断，与大小告警无关。整个历史 runtime_context 不套此新限制；发布原文/controls 引用已有快照，事件绑定去重，不复制整份注册表、历史图片或 DOM。

必需数据不得仅存 hash 后丢正文；hash 仅用于一致性，对版本内容的引用必须能够回读当时快照。敏感字面值不进 binding，调用参数中秘密仍按现有安全通道即时解析，不能为了可追溯把明文放入低层装配。

旧会话缺 execution_binding 时展示“旧合同记录，未记录统一绑定”，仍按原 session_id 打开证据；不根据现在的目录补造历史绑定。未知新 schema 显示不支持该详情版本并保留原始脱敏记录，不误判为空或通过。此处是历史读取，不是 R4 禁止的运行平台别名兼容。
