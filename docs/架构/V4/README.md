## 统一交付顺序

阶段是依赖关系，不要求重复开发已完成项；每项先确认构建和已有证据，再补缺口。

| 顺序 | 范围 | 开放门禁 |
| --- | --- | --- |
| 1 · 归属与契约 | 账号隔离、模型执行 owner、文件真源、能力协商与可信验收 | 双账号越权及重启恢复通过；未知结果不补 pass |
| 2 · Mac 最小闭环 | Desktop 准入、纯视觉窗口 / 输入、证据链与停止 | 授权宿主新 Session 通过；故障时旧代不能继续操作 |
| 3 · 社交写入口 | 私聊绑定、write receipt、持久补发 | 无重复创建、解绑停发、崩溃未知结果可核查；只读 MCP 可提前并行验证 |
| 4 · 扩面与性能 | Windows、Linux、B/C 路径、更多渠道及远程性能 | 分平台 / 渠道 / 场景验收后逐项开放，不能复用 Mac 或本地结果宣称全支持 |

每条状态只用“方案待实现 / 工作树已有代码 / 隔离验证通过 / 部署后已验收”，记录构建、协议 / 模板 / 用例版本、场景、Session 或测量记录及剩余限制。本轮只是文档修订，不新增任何运行通过证据，也不自动提交或发布。
