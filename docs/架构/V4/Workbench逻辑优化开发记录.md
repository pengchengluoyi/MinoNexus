# Workbench 逻辑优化开发记录

日期：2026-10-11。依据同目录《Workbench逻辑优化开发方案.md》，本轮涉及 MinoWorkbench、MinoNexus、MinoScout。

## 本轮实现

- 注册只需要邮箱、密码、确认密码；字段旁校验，不发验证码、不提供忘记密码。注册后回填规范化邮箱并保留登录目标。普通注册固定 `role=user`、`email_verified=false`，未验证邮箱可以登录。新增数据库邮箱唯一约束，注册插入和会话写入分别使用独立事务。
- 退出、会话失效及切账号时取消查询、清理旧缓存并断开旧实时连接；刷新已有会话成功后恢复当前账号 WebSocket。
- 移除助手默认应用、默认设备及其候选查询、提示词注入和隐式补参。旧字段输入忽略，数据库旧列保留。启用开关移至状态区。工具缺参追问，候选按用户节点权限过滤，执行前检查设备在线和权限。
- 统一节点页与助手页的 IM 渠道状态。LangBot 按平台拆分，安装、进程、连接、持有及当前用户绑定独立展示；离线、待确认、状态未上报、待绑定互相区分。助手状态只聚合当前账号可访问节点；MCP 独立显示。
- 应用详情恢复并纠正 `projectId`。用例和任务默认每页 50 条，分页及筛选保存在 URL；查询缓存按账号、应用、项目及参数区分。导航悬停/聚焦预取，详情和轨迹按需加载，关闭的新建任务弹窗不请求全量候选。
- 新增用例分页摘要、模块计数、当前页结果批量查询及任务摘要接口。主列表与模块、设备、上次结果分别加载，辅助失败提供重试。旧客户端无分页/无摘要路径保留。
- 根据实际查询计划新增分页复合索引。后台停止轮询，当前应用的实时事件更新详情或失效相关查询，保留轮询兜底。
- 新增 `mino:list-performance` 事件及 `window.minoListPerformance()` 读取入口，分别记录导航、JS、API、渲染、失败及面板挂载时的数据可用性。

## 验证结果

使用独立临时数据库，包含 10,000 条用例、1,000 个任务，每任务 50 条含较重轨迹的用例。未操作共享 `mino.db`、未驱动真实设备；未新增/修改 `tests/test_*.py`，未运行 pytest。

- `npm run verify` 通过：类型检查、禁用词、Electron 依赖检查。
- 最终 `npm run build` 通过。生产构建通过本地 HTTP 在 Chromium 验证；40 个打包资源可加载，修改涉及的页面、详情和轨迹懒加载无非预期 HTTP 或运行错误。
- 真实 HTTP / UI 验证注册、字段错误、邮箱回填、目标恢复、重复邮箱规范化、并发重复邮箱唯一约束、普通注册不能指定管理员、未验证邮箱登录。
- 用例分页、搜索、失败/未跑过的全历史筛选、详情按需请求；任务分页、详情及轨迹懒加载通过。
- 缺失/错误 `projectId` 恢复、切应用空态、模块/结果查询失败不阻塞主列表、用例详情错误返回列表通过。
- 模拟节点验证连接、待绑定、节点离线、待确认、状态未上报；助手开关、MCP 分离、切账号缓存清理通过。模拟客户端实时事件验证仅当前应用刷新及用例状态更新；刷新页面后认证 WebSocket 恢复通过。
- 使用模拟设备只验证参数与权限门禁：旧默认值不补参；即使只有一台在线设备也追问；其他账号设备不进入候选；离线设备不能执行。未进行真实 LLM → Scout 设备执行验收。
- 两仓 20 份 golden fixtures 字节一致并通过双方交叉 round-trip。现有 HEARTBEAT fixture 已覆盖 `connection_verified/connection_source`。哈希见双方协议文档；协议版本仍为 2。
- 修改及新增 Python 文件通过 AST 解析，三个仓库 `git diff --check` 通过。

## 列表性能

机器与网络：本机生产构建 + 回环 HTTP。每页 50 条。冷进入使用新浏览器上下文并禁用 HTTP 缓存，先初始化应用配置面板和应用上下文，再点击左导航；保留方案中的悬停预取。缓存切回在同账号同应用中复用查询缓存。

计时从导航点击开始，到正确列表真实绘制后的两帧结束，同时确认 50 条实际列表行及导航可交互；骨架屏不计成功。真实空态另做功能验证。

| 页面 | 冷进入样本 / 成功 | 冷进入 P95 | 缓存切回样本 / 成功 | 缓存切回 P95 |
| --- | --- | --- | --- | --- |
| 用例 | 30 / 30 | 123.2 ms | 30 / 30 | 91.0 ms |
| 任务 | 30 / 30 | 81.2 ms | 30 / 30 | 48.0 ms |

本地导航点击口径达到方案的 1.5 秒 / 300 毫秒目标。该口径不包含点击之前的整站首次文档、基础依赖和应用上下文初始化，不代表远程部署性能。采样里的 `cached` 表示面板挂载时已有数据，悬停预取也可能使其为 true；冷进入与缓存切回按独立浏览器上下文及测量场景划分。

隔离 HTTP/ASGI 单次接口观察：用例摘要 16.1 ms / 11,329 bytes，任务摘要 43.0 ms / 15,086 bytes，当前页结果 1,489.3 ms / 4,191 bytes。这些接口数字不是 P95。上次结果独立加载，不阻塞默认主列表。

## 后续事项

1. LangBot 4.10.11 当前可用接口没有持续连接确认字段。本轮保留兼容的 `connected`，仅在本次进程启动后 120 秒内收到真实渠道消息时令 `connection_verified=true`；超期显示待确认。持续适配器连接/认证事件尚待接入，不能把本轮当作持续在线保证。
2. 全历史结果的 SQLite JSON 查询仍约 1.49 秒。失败/未跑过筛选功能已验证，但没有单独采集其 P95；后续可按真实数据压力评估结果索引或物化存储。
3. 当前构建仍有 vendor 大包体积提示；导航预取达到本地点击指标，整站首次加载与远程网络表现应另外测量。
4. 上线前用实际 Scout 节点快照及真实消息复核，按仓库规范以 `session_events/session_meta` 验收实际执行链路。

本轮未创建分支或提交；保留既有及并行产生的项目修改。

## 2026-10-12：最新需求 P0 账号隔离补齐

本次依据更新后的方案第 5 节继续开发，覆盖 MinoNexus、MinoScout、MinoWorkbench，保留前轮注册、默认值清理与分页优化。没有修改需求原文、共享数据库或 MiniOrangeServer，没有创建分支/提交。

### 已实现

1. 三页及全部关联节点/设备/插件/日志/接入/远程操作按会话 owner 隔离，管理员无跨账号默认查看或使用权限；越权统一 404。跨账号上报同一设备 SN 被忽略，不能继承已有设备配置。
2. 模型配置、Key、base URL、模型、默认项和用途开关持久化到 ai-user:<uid>；保存/删除/连接验证及实际 LLM/embedding 都校验执行账号，无全局、管理员或环境 Key 回退。Workbench 增加本人已保存配置的连接验证按钮。
3. 执行身份用局部上下文贯穿 HTTP、线程、助手与后台任务；任务/QA/预览创建时固化 owner，恢复从持久 owner 取得身份，缺归属拒绝。任务、session_events/session_meta、模型诊断与文档资料读写/检索按 owner 过滤；无归属文档不自动同步。
4. 社交路由使用 node owner 与实际机器人 instance/tenant/sender；一次性绑定码原子消费，回调执行前去重，群成员独立授权。恢复绑定后的同 sender 上下文，旧绑定或未分域消息不参与。模型、工具、回复、正文读取及跑批通知复核 binding_key；解绑再绑定也不会复活旧执行。
5. Scout 初次连接在确认 owner 前不启动渠道，不发送旧插件快照。插件密钥与本地历史按 owner/服务/实例分域，拒绝跨账号或跨服务继承；未归属旧配置保留并停用。双方注册能力门禁阻止旧客户端继承配置，要求成对升级。
6. WebSocket 必须认证，快照/事件按 owner 推送；发送及操作时复核 token，旧凭证吊销后关闭连接。前端账号 epoch 丢弃迟到结果，三页缓存包含 uid，退出/切账号取消请求、清缓存和明文临时态、断开旧连接。
7. 迁移前做不覆盖的一致性备份；仅可信旧任务归属回填。全局 Key、旧社交映射、无归属节点及本地插件不自动分配，业务状态仍在 SQLite。

### 交付边界

- 可信历史 owner 保留；全局 Key、旧未确认社交映射/节点/本地配置保持停用或待确认。本轮没有维护认领、共享节点或转移 UI，不能通过新账号登录隐式继承。
- Nexus/Scout 协议版本仍为 2，但账号隔离能力门禁要求 Scout 与 Nexus 成对升级。
- LangBot 仍用本进程最近 120 秒的真实消息确认连接，不能保证持续适配器在线；本次来源/实例校验不等于持续连接状态证明。
- 已开始的模型请求或已提交的后台任务不因解绑撤销既有执行；后续模型/工具步骤、回复/通知均复核旧绑定。真实渠道和设备执行需部署后继续用 session_events/session_meta 联调。
- vendor 大包提示仍存在，整站首次加载/远程网络及全历史结果筛选性能保持前轮注明的测量边界。
