# V6：持续维护与执行可靠性方案

状态：第二版演进设计，未开发、未承诺全部功能同时上线。前置为[V5 MVP验收](../V5/方案/用例维护解析与执行闭环统一方案.md)；V6吸收此前完整方案中超出MVP的内容，不反向增加V5交付门槛。

2026-10-18 实施补充：来源维护、组合资源准入、请求收据、截止时间与报告对比已有本轮源码增量，详细状态以[本轮合并记录](实施/V6-源码合并记录-20261018.md)为准。本文正文保留设计目标，不能再将首段“未开发”理解为所有模块均未实现。用户已取消升级与回退功能，相关旧实施文档仅保留历史证据。

本次版本决策：**V5先消除工具卡点、指出用例问题并跑通真实闭环；V6再让维护自动化、解释可复用、执行更可靠。** 产品V5/V6与运行时execution_mode分别命名，不能把产品升级理解为所有平台都切成严格Web执行。

## 1. 版本边界与启动条件

| 能力 | V5已应具备 | V6增加什么 |
| --- | --- | --- |
| 输入 | XLSX一次性导入、收据/revision/job | 真实Sheets接入、文件绑定、来源变更持续触发 |
| 分组 | 用例列表分组字段与筛选；不影响执行 | 有实际需要再补分组详情，非核心依赖 |
| 理解 | 原句/理解/线索/断言/问题侧栏 | 经复核的应用识别资料、受影响用例定向重验 |
| 问题分析 | 阶段×六类根因×复核状态 | 修复/复发趋势、版本影响、批量维护 |
| 执行 | 固定版本与证据，开始/清理底线 | 节点合同细化、资源组合准入、故障接管 |
| 作业 | 持久编译job，失败/中断可见 | 后台周期任务、预算、并发/乱序/重启协调 |

V6启动前，V5需在选定真实应用/目标平台的全量验收范围上报告各case去向，支持范围内已确认的工具阻塞为0，并完成至少一条原失败用例从修复到证据的闭环。不得用V6功能尚未完成解释V5工具缺陷。

飞书spike可以在V5期间独立进行，只提交读取样本、实际接口/权限条件、失败模式和下一步工作量；不以spike通过宣称已经支持持续同步，也不阻塞V5上线。

## 2. V6按三项收益交付

| 增量 | 用户收益 | 准出条件 |
| --- | --- | --- |
| V6-A 来源维护 | 修改表格后无需重复手工搬运、能看到最新解析任务 | 实际Sheets与绑定文件分别完成读取→diff→revision→job→审阅→新run |
| V6-B 解释与诊断 | 同类问题少重复解释，工具误判更容易定位 | 复核资料能减少同类误判；旧版本不污染新版本；原句/证据可追溯 |
| V6-C 持续执行 | 节点异常/进程重启后不丢剩余项、不重复未知写 | 正式安装进程通过中断/停止/隔离/资源争用验收 |

A/B/C共享V5的用例/产物身份，可按实际痛点独立推进。持续来源更新与执行自动接管是两个能力；只交付A时不宣称长期无人值守执行已经完成。每个增量先验收一个真实工作流，再扩大范围，不重新做一个总平台。

## 3. 后端：真实来源和持续更新

### 3.1 来源限定与单主规则

仅飞书Sheets与本地XLSX/CSV，不扩展Bitable、docx、Git或通用连接器。复用Scout现有连接与节点身份，Nexus不直接操作用户电脑，也不import Scout。

| 方式 | 实际保证 |
| --- | --- |
| 飞书Sheets | 显式工作表/范围/映射；先验证真实Sheets读取，不能走read_doc冒充 |
| 文件重新上传 | 在原source_id下提交新快照；无持续读取能力 |
| Scout绑定文件 | 显式节点与准确路径，周期读取；节点在线时不依赖Workbench打开 |

持续更新要求稳定、非空、不重复的编号，唯一键(source_id,external_case_no)，保留前导零。编号/路径/工作表变化先确认重绑定；不用名称或行号猜身份。不清楚来源的旧case仍按平台维护，不影响原有执行。

源维护字段（正文、已映射业务平台/前置）在平台只读；改为平台维护须解除条目绑定、增加generation，在途旧job不能写入。V5上传副本不是天然源绑定；升级时逐批预览确认，不把所有历史文件自动接成双主。

需求分组仍是组织元数据，不进入编译或执行身份。平台分组与来源映射的分组有明确字段归属，改变分组不触发语义重编。

### 3.2 完整读取、差异与删除

结果包含source_id/read_id/generation、映射版本、complete、content_digest、带源位置的结构化行和错误。分页/分块不全、截断、重复编号、文件读取中变化时快照不生效，不能部分覆盖旧有效来源。

有远端revision时核对读前读后版本；没有一致性快照时变化后复读确认，仅作为保守检测，不宣称事务一致性。Excel锁文件不当新来源，取保存值不执行宏，缺公式结果不能当正常正文。

行重排/相同内容不重编；一条业务变化只排受影响case。源中消失只产生退役候选，空表/断网/文件暂缺不自动删除。源删除与账号/权限异常分别记录。

建议初始Sheets每15min、本地每60s检查，同一来源一个活跃读取任务，失败有界退避；实际间隔依限流、规模、运行成本验证后配置，不承诺任意大表吞吐。

### 3.3 作业、预算与最新指针

沿用V5收据/revision/job，按需求增补source_binding、逐行映射与generation，不新建通用消息队列。事务内登记来源变更、新revision、收据和queued作业；模型/网络工作在事务外。

更新后自动解析通过明确开关启用，绑定现有执行账号/模型配置、并发/每日构建/调用或token上限。预算耗尽waiting_budget，配置缺失blocked_config，不偷偷借其他账号或无限重试。

每case保留latest_source_revision、latest_compile_job_id、latest_valid_artifact_id、active_publication_id；最新失败必须可见，旧发布只供明确选择旧版回归。

旧job完成先比较revision/generation/当前job指针，不覆盖新状态；A→B→A保留三次来源历史，可复用A产物但保留本次revision引用。相同输入强制重编保留新候选与实际成本，不自动发布。

构建键包含原文语义、应用/平台、prompt/编译合同及实际依赖，不含需求ID。模型切换不自动重编全库；依赖/业务前置变化使受影响计划和resource_key重验，不能拼新原文+旧计划。运行中模型调用结果未知时保留interrupted，不盲目重复付费。

### 3.4 数据位置、保留和写回

原文在选定单主来源，平台保留不可变副本；派生计划/发布/执行证据只在平台。source/job/revision/artifact/publication/issue均复用SQLite和现有服务目录，不拆独立服务。

不默认写回表格或文件。可导出编号、解析问题、版本、最近结果与平台链接；脱敏且防公式注入。未来若确有需求，只评估独立状态列/独立报告文件的条件写与回环排除，不修改源正文或把计划塞回表格。

待审阅、当前有效及被运行引用的版本不能随临时preview清理。可清理未引用临时快照/轮询记录但要有显式策略。秘密继续资源引用，不写入原文、构建计划或额外日志。

## 4. 后端：应用理解和问题改进

V5六类根因保持：用例定义、语义/应用识别、动作/核验缺口、配置/环境、执行工具链、纯UI证据边界/人工前置。V6只在其下增加必要reason_code，不重新换一套相互冲突的大类。

### 4.1 经复核的页面资料

复用已有导航/控件资料，保存经确认的页面别名、识别特征、正反例证据、适用app/平台/build与revision；不建第二套页面真源。原句中的提示作为有来源的候选，不自动视为可靠事实。

拍摄页目标与“底部圆按钮”线索分开；相似页面反例与证据不全样本继续保留。历史通过可建议新识别资料，但不能拿模型自评通过自动训练或自动入库为真值。减少提示需有无提示对照证据，显式业务断言不自动删除。

训练/微调不是V6默认任务，样本积累也不等于模型已训练。只有资料检索仍解决不了且有独立标注/验证集时，再单独评估。

### 4.2 问题闭环和度量

每个issue关联app/platform、case语义revision、source_ref、诊断与复核证据。重复日志不膨胀case数。根因变更留记录，编译修复只是“待实跑”，目标平台证据满足后才“已验证解决”，复发重开。

看板扩展最近更新到解析完成时延、复用/失败率、受影响case、确认误判/真实边界、待复核和复发趋势。比例标分母与样本范围；多根因可重叠但总case去重；未知数据不显示0。verified_fail是运行结论，不直接当用例问题。

修复优先级按实际阻塞case数与频率，不按图表多少。维护者可以确认分类，不能更改历史verdict；人工复核另记manual_review。模型不能删必选项、改预算或释放隔离。

## 5. 后端：执行可靠性扩展

这些是V6增量目标，不能用来放宽V5已有的停止、清理、未知写保护。按实际节点/平台分别验收，不把一台Web成功外推三端。

### 5.1 节点与资源准入

复用REGISTER/HEARTBEAT的runtime_capabilities，明确contract/version/features、platform/os、build、process_generation、capacity/readiness。派单看最新快照，超过两次协商心跳周期不可准入；合同默认精确匹配，只有显式兼容矩阵才放行其他版本。

EXECUTE带期望合同与代次，Scout在副作用前复核。实际不符返回contract_mismatch，Nexus停派受影响能力；旧节点缺声明严格路径拒绝，不能自动转探索。build用于追溯和已知坏版本规则，不简单要求所有节点最新版。

组合资源租约归Nexus，Scout不自行换账号。账号与共享数据域由资源配置声明，不以“不同账号”推断隔离。准备阶段在短事务内领取资源集合，不能全部成功则回滚排队；不拿住账号无限等设备。

租约包含attempt/resource/epoch/expiry；续租间隔不超过TTL的1/3，并覆盖合法在途与停止窗口。TTL到期不证明安全：未开始且无副作用才可回排；已派发先隔离和对账。模型不能猜共享域或续期。

### 5.2 attempt状态、期限与停止确认

lifecycle与verification、effect_state、resource_state分开保存。effect_unknown可以与interrupted共存，不应互相覆盖；终结未核验不是资源已恢复。

建议基准配置（待平台实测校准，不是硬编码跨平台SLA）：资源等待120s/单元；attempt_wall沿用明确用例预算；停止清理10s/attempt；异常对账自检测起最多30s（包含停止阶段）；人工等待15min且受批次截止限制。批次预算按所选工作量与允许attempt保守计算，重启/复跑不重置预算。更严格现有合同优先。

Nexus在任务创建时固定版本化策略，worker和模型不能自行续期；持久绝对deadline，进程内用单调剩余时间。到期自动终结为对应blocked/timed_out/interrupted等结果，未知资源继续隔离，不永久挂批次。

停止证据必须绑定node/process_generation、attempt和执行器实例；新进程启动或心跳消失不能证明旧动作停止。自动解隔离要求停止证据+资源复位核验+旧租约失效/新epoch。人工只能登记处置并发起复查，无证据的强制释放不作为正常操作。

迟到回执追加reconciliation，更新当前资源状态，不改写原attempt未知效果或结论。“已停止”不能推出“从未写入”或“业务通过”。

### 5.3 清理、依赖与重启接管

默认用例独立初始化；复用setup模板需要明确依赖并校验无环，不以执行顺序猜登录态。依赖失败记prerequisite_unmet，清理失败只阻塞相关资源域。关闭页面/App不等于后端数据回滚。

重启分页扫描全部未终结执行单元，先重建租约/隔离；未开始项重新准入，在途项先对账，已终结项保留。安全复跑必须先停机/清理成功、发布策略允许、仍有预算，并使用新attempt与新wire空间；不从未知写中途续跑。

批次无活动项才关闭，关闭类别区分完整核验/不完整/取消；资源安全独立显示。清理失败保留检查点事实，但最终verified仍遵循该模式合同，不能为显示好看放宽严格V5要求。

### 5.4 固定报告与复跑

执行单元身份包括case_revision、计划、平台/目标、环境/数据基线与被测build；按execution_unit_id更新，避免多设备同case命中第一条。请求选择和受理收据幂等，原分母不可变，改变选择另建关联run。

报告关闭后冻结；复跑新attempt或新关联run，保留retry_of/derived_from。失败→通过、通过→失败都显示不一致，不能最后一次覆盖；旧有效核验存在但最新未核验时两者并列。跨版本/环境/build不能拼凑通过，无法证明可比时分开。

未核验、旧版未知、静态受阻、缺资源、取消继续留在原范围分母；创建前明确不适用单列，运行中建议不适用不能删分母。“批次关闭”“已核验完成”“全部通过”“环境安全收尾”是不同结论。

## 6. 前端：只补有收益的维护能力

| 视图 | V6新增内容 | 不做什么 |
| --- | --- | --- |
| 来源与更新 | 真实绑定/映射/刷新、周期开关、预算、读/编译状态、历史收据 | 不把上传称监听，不假造来源已支持 |

## 7. 准入与验收

### 7.1 V6-A：自动维护

真实Sheets和节点文件分别验收：完整读取、编号/多行/工作表、无变化零模型调用、单行变更局部构建、A→B→A复用、旧job乱序不覆盖、文件锁/原子替换/节点离线、重启后队列/预算保持、关闭前端仍更新。缺一来源验收则只声明已完成的来源。

### 7.2 V6-B：迭代收益

同一应用/平台/样本版本比较原句映射与实际核验，报告确认误判数量和分母；仅编译通过不算业务修复。页面正反例、防自评污染、资料变更影响范围、错误分类纠正和复发可追溯。没有基线不声称提升百分比。

### 7.3 V6-C：无人值守能力

正式安装进程下验证断线/取消/人工到期/未知写回执/迟到停止/租约过期/进程重启/一资源污染其他继续/多设备同case。检查未开始项不丢、已完成项不重做、未知写不重放、资源不误放、报告可解释。

测试使用隔离环境和授权测试资源，按仓库以真实接口/session证据验收，不跑pytest，不灌业务库。只声明实际验证的Android/iOS及PC OS，不默认三端全支持。

## 8. 延后且不自动进入V6的事项

写回源正文、通用连接器、自动训练、需求多对多/审批、全量历史迁移、独立消息中间件、大规模服务拆分、自动发布语义变化、跨应用共享未经验证的识别资料。只有明确收益、责任和验证条件时再立项。

原完整方案中的细节不再整体当作V5清单；V6也不是把所有设想一次性做完。来源维护、应用解释和持续执行分别用真实工作流证明收益，再决定下一项。
