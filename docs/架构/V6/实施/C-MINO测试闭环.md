# C：MINO 测试闭环

通过正式 Scout 浏览器操作测试 Workbench，测试 Nexus 分发真实用例到测试 Scout。复用普通项目测试链，不新建泛化 Nexus 代理、协议预暂存或归档平台。

工作项：

- 三测试应用有独立连接、端口、数据根、凭据和实际 build。
- 页面能定位测试 node_id/build、任务结果和 session；证据不足明确未完成。
- 测试 Scout 的 PyCharm 模块只操作专用样例项目，不停止自身或正式控制链。
- 正式链的浏览器与测试侧设备分配明确，避免两套任务同时控制相同资源。
- 提交引用、包摘要和 session 可关联；测试库删除后引用不可读，不伪造已归档。

验收至少包含测试 Scout 新代码真实执行，以及错误凭据、目标、旧 build 的失败情况。页面通过不声明测试 MCP 全工具回归通过。C 与 D1 可并行，不阻塞先做 Scout 更新。

### 本轮修复

- 空闲 Web 的容量心跳不再被当成执行占用；同一 SN 的容量记录不能覆盖真实在途步骤。实际步骤、持久任务、隔离槽位和异常容量仍阻止 IDE 操作。
- Scout 停止逻辑同时保护 IDE、正式服务和当前控制端口。源码测试 Scout 继续保护开发控制链；正式 Scout 的源码规则允许准备开发端口，但保留用户、源码目录、IDE 父进程和 PID 创建时间复核。该正式 Scout 端口规则尚未发布到已安装版本。
- 首次编译新增的控件身份作为该 job 的派生产物记录，避免新增控件导致编译自我失效。仅排除本 job 插入的完整一致行；并发修改、删除或无关新增仍使结果失效。
- 编译器合同升级为 13，步骤拆解提示升级为 11。精确 Web 文本检查保留明确目标、字面值和相等强度，不将 contains 提升为 equals；不同目标的并列检查分别保留。不可见检查在 V5 发布时保留否定含义。控件身份优先使用检查目标，不使用泛化的“文案检查”事件名。
- 启动迁移为 `tap_target`、`input_target`、`read_web_target_facts` 保留程序调用身份和准确阶段，解决重启后目录合同被清空导致 `event_call_not_allowed`。开发库通过正常管理 API 配置了这三项能力及样例控件，没有直接写业务数据库。

2. 错误开发登录凭据返回 401；错误实例和旧 build 分别被拒绝，随后恢复原绑定配置。
