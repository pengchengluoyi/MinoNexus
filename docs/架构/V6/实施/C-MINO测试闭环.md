# C：MINO 测试闭环

通过正式 Scout 浏览器操作测试 Workbench，测试 Nexus 分发真实用例到测试 Scout。复用普通项目测试链，不新建泛化 Nexus 代理、协议预暂存或归档平台。

工作项：

- 三测试应用有独立连接、端口、数据根、凭据和实际 build。
- 页面能定位测试 node_id/build、任务结果和 session；证据不足明确未完成。
- 测试 Scout 的 PyCharm 模块只操作专用样例项目，不停止自身或正式控制链。
- 正式链的浏览器与测试侧设备分配明确，避免两套任务同时控制相同资源。
- 提交引用、包摘要和 session 可关联；测试库删除后引用不可读，不伪造已归档。

验收至少包含测试 Scout 新代码真实执行，以及错误凭据、目标、旧 build 的失败情况。页面通过不声明测试 MCP 全工具回归通过。C 与 D1 可并行，不阻塞先做 Scout 更新。
