# D2：Nexus 安装升级

## 首期不做的工作

不实施 verify_only、业务激活接口、零 SQL 写入启动模式，不整体重构 ensure_db，不自动编排协议预暂存。主线是：空闲→停服备份→离线迁移→正常启动→基础探测→成功或兼容代码回退。

## 安装与执行

硬前置：先完成正式基线安装与可验证的服务登记；当前源码目录运行的 Nexus 不直接进入自更新。A 阶段迁移异常传播、seed 只升不降两项修复与隔离验收完成后，才能开放离线升级和自动兼容回退。

应用和助手分别登记 LaunchAgent；助手稳定位于 launcher，不用 current 中的解释器运行自身。plist 不随更新改写，bootout 应用后助手继续执行，bootstrap 原 plist 拉起目标版。验证 macOS 登录会话、服务组停止、助手重复启动和崩溃恢复行为。

current 使用同目录临时链接加原子 replace；进程启动解析固定 release 根，避免运行中混读两版。维护阶段和 OS 锁分开，锁释放不代表上次事务完成。遗留维护状态由助手/CLI 按实际阶段恢复，不能删除锁文件后直接正常启动。

现有数据库优先登记原路径。日志有界轮转；权限、服务路径、工作目录和环境固定，不依赖用户终端。

## 数据兼容准入

新 release 提供离线 migrate/schema 校验 CLI，复用实际迁移实现，不维护两份迁移逻辑。前置审计包含 create_all、run_auto_migration、bootstrap、旧版启动初始化及外部副作用。

离线迁移后正常启动会再次调用 ensure_db，只有重复执行验证安全才可放行。旧版在新 schema/代表性新数据上的启动及业务读写也需验收。新增列并不证明这些条件成立。遇到问题只局部修复或将该版本转人工，不恢复全量模式重构。

使用受控数据库副本演练，不外发真实消息。备份覆盖 SQLite 一致性及迁移触及的受管文件；涉及不可恢复外部副作用的迁移排除自动更新。新服务开始启动前记录 writes_reopened，之后失败默认只回代码；无法兼容保留现场人工恢复。

## 探测实现依据

现有信息端点是 /sys/server_info；补实例/build/health_contract_version。health 200、实例/build匹配、probe initialize/ping/tools/list 为稳定基础合同，不是全业务回归。

probe kind 必须贯穿鉴权结果，不能解析成用户后丢失限制。方法检查在 RPC 分发前，批量请求逐项验证，拒绝 tools/call；普通 HTTP API 不接受 probe。认证不更新 last_used_at、不建立助手凭据/交互记录。正常启动的其他写入仍可发生，不要求验证全应用只读。

验收记录离线失败恢复、启动失败回退、probe拒绝/越权、包/实例错配、助手每阶段中断与 MCP 重连续接。自动回退失败应报告 needs_operator，保留本地独立恢复入口。
