# Workbench：应用开发环境交互合同

入口为项目→应用→配置→开发环境；本文件定义交互合同；实现及真实验收范围见 [开发与验收记录](hi3d-B-开发与验收记录.md)，不将未实测平台视为通过。

## 配置与摘要

默认关闭“开发联动”，关闭时展示“未配置开发环境，可直接运行普通测试”。启用后选择正式 Scout 节点，填写本机 PyCharm MCP URL（当前实测 HTTP 流地址为 http://127.0.0.1:64342/stream）、IDE 项目路径，再读取并选择运行配置。

三个 MINO 应用分别保存 IDE 项目路径、应用源码目录与运行配置；允许共享连接，但禁止用浏览器所在电脑推断 Scout 节点。URL 下提示：“此地址由所选 Scout 所在电脑访问；127.0.0.1 指该电脑，不是 Nexus 服务器。”不自动配置其他 Agent 客户端。

保存配置只表示已保存，不表示连接成功。按钮顺序为“保存”“检查连接并读取配置”“重新检查”；检查走正式 Nexus→指定 Scout→PyCharm，读结果不启动应用。重连/刷新不得自动执行配置。

连接摘要显示节点、IDE 版本、项目路径、配置名称、最后检查时间、配置 revision。手工确认测试参数单独显示，不与系统连接检查混为一个绿色状态。

## 复制配置导入与 Scout 本机存储

默认流程：在 PyCharm 手动开启 MCP → 点击“复制 HTTP 流配置” → Workbench 选择 Scout 后粘贴 → 本地解析预览 → 保存到 Scout → 检查连接 → 选择 IDE 项目与运行配置。手动编辑 URL 保留为高级方式，已有连接可被多个应用引用。

JSON 支持明确的单服务器对象/已知 MCP 配置包装；包含多个服务器时让用户明确选择。解析器只接受预期 URL/传输/header 字段，未知格式报错不猜；JSON 本身不执行。首期 HTTP Streamable 支持以真实导出样例验收，不能只凭截图声称所有客户端配置格式通用。拒绝导入 Stdio 的 command/args 启动命令；SSE 不与 HTTP 流混为同一已验收能力。

保存前显示节点、端点、传输与敏感字段遮罩，说明“保存在这台 Scout，其他电脑不会自动继承”。本机端点限制、权限检查和项目映射仍生效。Scout 离线显示“未保存到节点”，不能仅在 Nexus 缓存就显示成功；保存失败保留旧版，草稿不进日志或浏览器持久存储。

Scout 复用 config.py 的 JSON 配置，在 ide_connections 保存 connection_id、url、transport、可选非秘密 headers、revision、最近检查结果；沿用配置读写入口，保存时保留 nexus_url/token 等其他字段。Nexus 保存节点/连接引用及应用绑定、脱敏状态。配置更新失败保留旧版，原始粘贴内容成功后从页面清除；秘密字段不进入日志。

不扩展 im_store.py、不新增 SQLite 用途或迁移。当前本机 PyCharm MCP 无需 Authorization，首期按无鉴权连接实现；带 token/认证 header 的导入提示“当前版本暂不支持此认证配置”，不静默忽略也不明文保存。秘密存储方案留待真实需求出现时处理。

配置导入成功≠连接成功≠可执行/可重启。前端分别显示“已保存到节点”“检查通过”“能力部分可用”；HTTP 超时没有回执时保留操作 ID，不建议重新导入作为修复，不重复启动。Workbench dev 的成功启动和端口冲突均已拿到回执，不能继续显示为未验证。

## 人工开启与连接判定

首次提示：“请在 PyCharm → 设置 → 工具 → MCP 服务器中启用并点击应用，将 HTTP 流地址填到这里。”提供“已开启，重新检查”按钮；它只触发 Nexus→Scout 连接检查，不构成已成功状态，也不替代应用执行授权。无需自动配置其他 Agent 客户端。

连接拒绝/超时/404 均显示“请确认 MCP 已开启并应用，同时核对端口、路径及节点电脑”；附真实错误码和检查时间。404 不是授权失败的证据，更不能据此要求开启 Brave。401/403 表示当前访问被拒，提示检查 IDE 访问设置，不能自动断言一定需要 token。200 也不能单独通过：必须返回合法 initialize、tools/list 和匹配项目结果。

人工确认、最近连接结果、执行权限分别保存和展示。用户点击“已开启”后仍失败，保留真实错误；项目不匹配不重新要求用户开启 MCP。当前审计中先前访问的是 63342/mcp，后来是 64342/stream，不把不同地址的结果渲染成开关状态检测。

## 默认与自定义项目映射

默认推荐一个应用对应一个 IDE 项目窗口，便于管理；不强制拆窗口，也不把窗口数量等同 MCP 端口数量。表单提供可编辑的三个字段：

- **IDE 项目路径**：传给 MCP 的 projectPath，应从 IDE 实际识别的项目中选择或手工填写后校验。
- **应用源码目录**：该应用实际仓库目录，可与 IDE 项目路径不同；不自动拿它覆盖 projectPath。
- **运行配置**：在选定 IDE 项目下读取并选择；同项目多个应用分别绑定正确配置，名称不足以证明用途。

当前用户布局的映射示例：

| 应用 | IDE 项目路径 | 应用源码目录 | 运行配置 |
| --- | --- | --- | --- |
| Nexus | /Users/changpengcheng/code/MinoNexus | /Users/changpengcheng/code/MinoNexus | 待确认对应配置 |
| Scout | /Users/changpengcheng/code/MinoNexus | /Users/changpengcheng/code/MinoScout | 待确认对应配置 |
| Workbench | /Users/changpengcheng/code/MinoNexus | /Users/changpengcheng/code/MinoWorkbench | dev（已核对为 npm run dev） |

界面提供“使用另一应用的 IDE 连接/项目”以减少重复填写，但应用源码和运行配置仍独立保存。修改任意映射使之前检查失效。提示：“多个应用可共享一个 PyCharm 项目；IDE 项目路径用于定位窗口中的项目，不要求等于应用仓库目录。”

源码路径不被 MCP 识别时，优先提示检查 IDE 项目映射，不要求用户重新打开仓库。只有实际项目入口匹配失败才进入“项目未打开或路径不匹配”。不根据附加目录名称自动执行配置；截图中的历史 MinoStudio 不因此加入本方案应用范围。

## 状态与具体提示

| 状态 | 页面提示 | 操作 |
| --- | --- | --- |
| 未检查 | 配置已保存，尚未检查连接 | 检查连接 |
| 检查中 | 正在通过所选 Scout 连接 PyCharm | 禁止重复检查，同一 operation 查询 |
| 节点离线 | 开发电脑的 Scout 离线 | 查看节点；不提示改服务器 localhost |
| 连接拒绝/超时 | 无法连接该电脑上的 PyCharm，请确认已启用 MCP 服务器并应用设置 | 修改端点/重试检查 |
| 404/协议错误 | 地址未提供对应 MCP 服务，请复制 PyCharm 的 HTTP 流配置 | 重新配置；不自动改为任意端口 |
| 401/403 | IDE 拒绝访问，请检查本机连接权限 | 提供设置指引；不在普通表单索取或展示密钥 |
| 项目未打开 | 已连接 PyCharm，但目标项目未打开或路径不匹配 | 展示服务返回且权限允许的项目列表，用户明确选择/打开；不自动换项目 |
| 无运行配置 | 项目已连接，未找到可用运行配置 | 提示在 PyCharm 创建，再刷新 |
| 能力部分可用 | 已连接：可读取、执行配置；自动重启需找到当前应用的运行进程 | 未实现前仅人工引导；实现后按现有应用配置显示“重启测试应用” |
| 详情不可核验 | IDE 未返回命令/环境详情，请在 PyCharm 确认测试参数 | 手工确认，不标数据隔离已自动验证 |
| 配置已变更/过期 | 上次检查不适用于当前配置，请重新检查 | 阻止用旧清单执行 |

本机只读测试已显示 MinoNexus 有五个配置；MinoScout/Workbench 源码路径未被识别为独立项目入口，截图确认它们在同一窗口加载。应共用正确 IDE 项目入口，而不是强制新开窗口。界面不得把“连接成功”渲染成“三应用全部就绪”。

## Brave 模式及执行授权

显示“IDE 执行确认：由 PyCharm 设置控制”。若没有可信查询接口，标记“未自动检测”，可另显示用户手工确认的模式及确认时间，不能从工具存在/一次读取成功推断 Brave 开启。

简短说明：“若 PyCharm 已启用无需确认执行，IDE 可能不再弹窗。Mino 仍仅执行本应用已配置且获授权的运行配置。”不要求用户为了普通测试打开 Brave，也不强行关闭已开启设置。

Brave 不能替代 Mino 权限。Scout 优先复用 MCP 开发能力；execute_terminal_command 仅用于已核对的本应用固定停止动作，不向 Agent 开放任意 shell。写文件和重构不因连接成功而自动开放。Agent 已有授权可复用，不要求每步重复弹窗；用户从页面执行时展示节点、项目、配置及动作。

只有接口明确返回待确认时才显示“请到 PyCharm 确认”；单纯超时显示“执行结果尚未确认”，不得假装知道 IDE 正在等待弹窗。

## 执行与结果

- “执行配置”需已通过当前 revision 的连接/项目检查，获得应用执行权限，且已确认测试参数。该动作只能表述为执行，不能承诺会重启。
- 按钮与结果区分：请求已接受、IDE 已返回、目标就绪、测试通过。读到配置并不表示程序正在运行。
- 已有目标可访问时，纯测试可显示“复用当前运行实例”；需要加载新代码时仍按 HMR 或明确重启处理，不能凭 HTTP 200 判本轮改动已生效。
- 有回执且 timedOut=true 时显示“已返回运行输出，正在检查服务是否就绪；程序可能继续运行”，通过应用就绪探测后显示“服务就绪”，不自动重发。它与 HTTP 无回执的超时不同。
- HTTP 超时且没有回执时显示“执行结果尚未确认，请查看 IDE 或检查目标；不会自动重试”，回显 operation_id。无状态接口时不能展示虚构的实时运行状态。
- 非零 exitCode 必须显示执行失败，即使 MCP isError=false；端口冲突提示“测试地址已被占用：请核对是否为当前应用”，保留错误输出。错误本身不触发重试或强杀；重启须先确认占用的进程来自当前应用，再停止旧进程。
- 启用自动重启后展示“找到当前应用→等待任务空闲→停止旧进程→IDE 启动→就绪/版本探测”；占用进程的目录不符、存在多个候选或权限不足时直接说明具体原因，提示在 IDE 中处理。不得向 Agent 暴露通用 kill 或 shell 输入。
- 需要重启且当前应用进程可定位时自动执行，不要求人反复点 IDE。定位不到旧进程时提示具体情况，以及“请在 PyCharm 选中本应用运行标签，点击‘重新运行’（Rerun，不是‘自动重新运行’）”。用户确认已人工重启后仅探测就绪及可读取的版本；人工确认和 HTTP 200 均不直接代表新代码生效或用例通过。
- 本机执行接口仅提供单次返回输出；结果区显示来源、截断、timedOut/exitCode。未实现独立续读时不画持续滚动日志或无限加载。
- 升级等待沿用 queued/blocked_by_update 和截止时间，避免 Agent/用户以为执行卡死。

## 验收

覆盖无配置正常测试、节点离线、端点错误、项目未打开、部分能力、配置修改、详情缺失、Brave 未知、IDE确认/超时区分、重复点击和升级阻塞。补充覆盖长驻 timedOut=true 但就绪、isError=false 但 exitCode=1、受控停止前后的身份/任务检查及人工 Rerun 后版本检查。Workbench 的启动、端口冲突、人工 Rerun 和受控 SIGTERM→MCP 启动已通过；Scout 安全门禁和页面提示待产品链实现后验收。
