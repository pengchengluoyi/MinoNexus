# V6 安全复跑守卫（2026-10-18）

本批为执行可靠性缺口修复，不代表 V6 整体完成。Android Studio、PyCharm 相关 APK 打包按本轮用户要求后置；已取消的组件升级、回退功能不恢复。

## 发现与改动

- 后端旧 `retry_failed` 仍按 case_id 去重后调用新任务入口。这会重置批次预算、读取当前草稿，并在 per_device 模式下扩大复跑范围。现在 HTTP 与助手调用共用拒绝准入，不再通过该路径创建任务。
- 严格执行器的历史发布可允许 `effect_unknown` 重试；旧实现只要求 `executor_stopped`。停止不证明业务复位。现在每次调用仅执行一次，保留原 verdict 和 attempt；历史策略不能触发未知写重放。
- 新发布仅接受关闭重试的策略 `{on: [], max: 0}`。非零策略返回 `retry_reset_verification_required`；作者声明 reversible 不能代替复位证据。历史发布内容不修改。
- 新增 `GET /case-runner/tasks/{task_id}/retry-eligibility`，返回原预算剩余时间、失败执行单元及阻塞原因。相同 case_id 在不同设备上的失败项独立返回，通过项不纳入；缺执行单元身份明确记录。
- `POST /case-runner/tasks/{task_id}/retry-failed` 返回结构化 409，包含 `message`、`reason_code`、`eligibility`。当前不会返回可复跑；诊断中固定保留 `retry_admission_not_ready`，避免将“未发现隔离”当成授权。
- 诊断检查持久组合租约，held/isolated 均阻塞，不仅检查 run 的 write_safety。缺失、无穷、NaN、布尔型截止时间不作为有效预算。

## 验证

在独立工作区源码副本和全新临时数据根上启动本地 HTTP，使用实际注册/鉴权及生产路由检查，未运行 pytest、未连接设备或模型服务、未写真实业务库：

1. 无认证返回 401，另一个账号查询同一任务返回 404。
2. 同用例三设备的 fail/pass/blocked 只返回两个失败执行单元。
3. 持久资源隔离返回 resource_not_released；指定其他设备不能绕过。
4. 拒绝复跑后任务数量、原任务完整 payload 和租约隔离状态不变。
5. 纯策略检查覆盖失效预算和“已停止但仍隔离”的未知写。

Python 修改文件通过语法解析。上述仅证明源码守卫和隔离 HTTP 行为，不是正式进程加载、真实设备停止/复位或业务通过证据。未提交 Git、发布或重启正式服务。

## 后续开发

安全复跑重新开放前还需：可追溯的资源复位证明及旧 epoch 失效、发布策略准入、继承原绝对预算、按 execution_unit_id 固定失败范围、保留原版本/环境身份、请求幂等和新 attempt/wire 空间。不得仅删掉本批守卫或用新任务预算替代。
