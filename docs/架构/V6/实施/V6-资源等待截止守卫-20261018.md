# V6 资源等待截止守卫

## 问题与复现

资源组合准入在等待循环顶部只检查批次状态，没有在领取前拒绝已过期的 `resource_wait_deadline_at`；账号分配器等待、SQLite 写锁等待期间也可能越过截止时间。复跑继承的 `attempt_deadline_at` 未用于裁剪资源等待。

在全新临时 SQLite 中，直接通过原 `claim_without_account` 调用链，给任务提供已过期的持久等待截止，仍成功创建了资源租约。该复现没有连接设备，不读取或写入正式业务数据库。

## 实现

- 首次等待期限写入任务；再次等待从持久任务读取，不信任调用方旧快照。`run_store` 合并时保护已建立的等待截止，不能由旧快照延长。
- 进入账号领取前检查批次、单元和资源等待截止；账号等待时长与循环休眠均裁剪到最早截止时间。
- 在账号/资源领取的同一 SQLite 写事务内，再次核对任务、执行单元状态及已持久化截止。即使锁等待后才进入事务，也不能越期领取。
- 拒绝时不创建组合资源，也不写入账号租约；不解除既有隔离，不修改原预算或历史结论。

## 验证

本地真实资源分配、账号分配与 SQLite 路径完成 7 组检查：已过期等待；批次/单元过期；过期不调用账号分配器；账号和无账号迟到领取；单元预算裁剪；陈旧快照与缓存丢失后截止不变；预算内领取与正常释放。
