# E：循环验收

前置：所使用组件的更新与恢复已分别验收。Agent 始终通过正式 Nexus MCP 操作，不因升级异常自动切到测试 Nexus。

1. 修改测试代码，经正式链准备并测试，读取失败步骤及真实执行 build。
2. Agent 自行提交/推送，CI 发布安装包；Mino 不监听或审批提交。
3. 请求固定版本升级。有活动批次时保留其后续执行，新请求明确返回更新阻塞 ID；空闲后安装。
4. 断线重连查询原 operation，核对目标 build；重复请求不再次安装。
5. 演练目标版启动失败→兼容旧版恢复，以及不能兼容时正确进入人工维护。
6. 继续原开发循环或其他项目任务，验证排队恢复和目标未漂移。

协议变化首期走管理员维护窗口，使用固定版本 CLI/安装器，不测试自动预暂存或注册拒绝追 latest。

遵守仓库测试约束，使用真实 session、构建及隔离安装演练留结果。不新增/提交 tests/mock，不跑 pytest。代码依据随实现更新，主文档只保持稳定合同。
