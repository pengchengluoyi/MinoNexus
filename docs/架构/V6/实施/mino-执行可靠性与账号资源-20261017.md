# V6 执行可靠性与账号资源：第一批实现

日期：2026-10-17。范围：持续执行可靠性、账号与测试资源维护。状态：已修复当前代码中确认的基础缺口，完成隔离 SQLite 并发与冷启动验收；不宣称两项 V6 方案已整体完成，也不宣称 Android 原失败用例已通过。

## 已定位并修复

| 问题 | 实现 |
| --- | --- |
| 未登记账号状态被当作未配置/未注册 | unknown 不再满足 no、unregistered、ne 等硬约束；显式要求 unknown 仍可匹配。未登记资料/地址默认为 unknown，不补造“没有” |
| 锁定/隔离账号可能因匹配分高仍入选 | 筛选直接排除 locked、dirty、quarantine、bad；占号事务再次检查 |
| 模板分配忽略占号失败 | 只有 SQLite 原子占号成功才返回凭证，保留 run/case/device 身份，失败尝试下一候选或明确拒绝 |
| 筛选与抢占之间账号状态发生变化 | 同一写事务重新核对环境、最新 facets、锁定及租约；不使用筛选时旧快照放行 |
| 过期自动回收账号/设备租约 | TTL 只表示待核对，不作为停止证明；保留占用，由已有任务终结/停止证据恢复路径释放。代价是无充分停止依据的旧租约继续阻塞，不自动兜底释放 |
| 旧释放请求清除新租约 | 每次领取/续租生成 lease_id，释放比较完整旧租约；账号表单更新保留现有租约，删除/整池替换拒绝未释放账号 |
| 续租失败仍返回成功 | 原样返回抢占结果；恢复失败清空上下文凭证，不继续使用旧账号 |
| 失败用例将预期后置状态写成账号事实 | 失败时不再把作者 facet_effects 直接作为已达成状态写回；结束写回前核对租约仍属于本 run/case/device。既有轨迹推断机制仍存在，未宣称完成证据化状态管理 |
| 多设备同 case 更新第一项 | 新任务每执行单元生成 execution_unit_id；执行器按 case+设备更新，歧义/缺项拒绝 |
| 已关闭报告被旧后台快照覆盖 | 落库事务保留已结束报告，仅允许独立 write_safety 对账推进；迟到 patch 不改变原结果 |
| 重启只扫描 80 条 running | 分页耗尽 running/queued；原范围与已完成结果保留，未执行项记 blocked/no，在途记 blocked/unknown；不自动重放 |
| 一台设备未知动作阻断其他设备 | 用例执行与结束清理的隔离判断按 sn 收敛；账号/最终批次释放仍遵守现有保守写安全门禁 |
| 内存任务列表混入其他账号 | 缓存合并与数据库查询采用相同 owner 过滤 |

## 第一批交接工作及顺序

1. 账号事实与证据：把当前 LLM 推断和作者提示进一步拆成候选/确认事实；补充同账号、应用、环境、版本与 session 证据引用、条件写回和 Workbench 审阅。既有形象字段作为项目配置使用，不硬编码应用页面。
2. 组合资源准入：当前设备、账号、共享数据域尚非一个原子领取集合；需设计 attempt/resource/epoch/expiry 的共同持有合同、续租与全失败回滚，并复用现有 device_reservations 与账号真源。
3. 持续执行接管：当前重启只保证全量记录去向和不重放未知动作；安全重排未执行项、持久总预算、依赖初始化及停止/复位联合证明仍需补齐。
4. 节点合同：已有执行 binding、节点代次与能力校验可复用；统一协商心跳的新鲜度、组合资源期望代次与跨平台副作用前复核尚需联动 Scout 合同。
5. 报告与复跑：已冻结原报告并修复单元定位；跨 run 的 retry_of/derived_from、版本/环境/build 可比性、双向结果不一致展示尚需开发。历史无身份报告不能补造可比结论。
6. 真实验收：授权测试环境下验证原 Android 资源问题、账号初始条件、同 case 多设备、并发取消/续租、重启恢复及 Workbench 展示；生产历史结果保持原 verdict。
