# Workbench D3 安装升级合同

## 范围

macOS 已完成独立原生安装包、独立更新助手、固定版本升级、静态热切换、运行时停启、回退和中断恢复的本地验收。旧版本和配置保留，不处理 Nexus 数据库。Linux/Windows 的服务更新尚未验收。

新基线安装生成 installation_id；历史基线缺少该身份或更新合同会被拒绝，需先在新目录安装新基线并明确迁移服务登记，不能覆盖旧安装目录。

## 构建

完整包：

```sh
python3 scripts/build_release.py --output /absolute/output --tested-nexus-build <已实测的Nexus-build>
```

静态包复用一个真实原生包的精确运行时：

```sh
python3 scripts/build_release.py --static-from /absolute/native.zip --output /absolute/static-output --tested-nexus-build <已实测的Nexus-build>
```

`--tested-nexus-build` 可重复提供，只能填写已实际验证的组合。缺少声明的版本不能自动准入；构建成功不等于业务兼容。`--allow-dirty` 仅产出带 dirty 标记的本地验收包，发布清单生成器继续拒绝它。

正式清单沿用 schema 1、固定 GitHub Release tag 和 SHA256/字节大小。`scripts/write_manifest.py` 输出 Workbench 更新合同及已验证的 build 组合。原有 CI 默认生成完整原生包；静态包由上述显式构建命令生成，再使用同一发布清单合同。不要为同一个 build_id 发布内容不同的包。

## 安装与服务

沿用 `mino-maintain install --package ... --sha256 ... --root ... --port ... --nexus-url ...`。首次安装要求新目录和完整原生包，不接受只有网页的静态包。

`register --root ... --service-file ...` 同时登记应用定义和独立 `.updater` 助手定义。`start/stop/status --root ...` 管理应用。助手位于稳定 launcher，不属于被停应用进程组，RunAtLoad/KeepAlive 为 false。服务仅保证当前登录会话内运行。

## 固定版本操作

以下均使用安装目录中 `launcher/mino-maintain`：

```sh
mino-maintain check-update --root /absolute/install --manifest /absolute/manifest.json
mino-maintain update --root /absolute/install --manifest /absolute/manifest.json --package /absolute/package.zip --operation update-001
mino-maintain operation --root /absolute/install --operation update-001
mino-maintain recover --root /absolute/install --operation update-001
mino-maintain rollback --root /absolute/install --build <保留的build-id> --operation rollback-001
```

清单和安装包由操作者从固定发布版本取得，当前 CLI 不提供任意 URL 下载代理。每个意图使用稳定 operation；同参数重复请求返回原记录，参数冲突拒绝。未完成事务阻止新事务，不能靠删除锁文件清除维护状态。

`--defer` 只登记请求；随后 `recover` 启动同一操作的独立助手。`cancel-update --operation ...` 仅能取消尚未安装的 requested 请求。开始安装后只允许查询/恢复，不做不确定的强行取消。

脏构建在默认升级/回退中被拒绝。隔离验收时可显式加 `--local-verification`；该选项只适用于 dirty 包，记录明确写明没有验证业务兼容。正式更新会读取配置 Nexus 的 `/sys/server_info`，要求其 build_id 在包声明的已验证列表中，并在切换前复核。

## 生命周期及失败处理

requested → installing → prepared → stopping（运行时变化时）→ switching → restarting（运行时变化时）→ verifying → succeeded。

- 纯静态包的 runtime_id 必须与现有运行时一致；网页和 runtime 分离，current 原子切换后服务按请求读取新网页。旧页面继续按 `/releases/<build>/...` 加载原资源。
- 原生包按实际运行时摘要判断是否需要停启。停服核对服务登记并等待端口可重新绑定；不以 TCP TIME_WAIT 误判仍有监听，不做强制 kill。
- 每个关键动作前持久化状态。助手崩溃后从原状态继续，复用包、release 和操作记录；已经完成的操作不再次安装。
- 验证 installation_id、当前网页 build、实际 runtime_id 和 health。失败后恢复旧指针，必要时重启旧服务，成功恢复记 rolled_back；无法恢复记 needs_operator 并保留诊断。
- needs_operator 需要操作者修复登记、权限或资源问题。不要删除记录或将失败伪装为成功；本地 start/stop/status 和原始记录仍可用。

## HTTP / WebSocket 部署来源

Nexus 启动环境通过 `MINO_WORKBENCH_ORIGINS` 配置逗号分隔的准确 HTTP(S) origin；服务部署应写入服务登记的环境，而非依赖终端临时变量。

未配置时允许 localhost、127.0.0.1、mino.local 的 5273/5274。跨主机或 HTTPS 部署必须明确增加实际来源。CORS 与 UI WebSocket 使用同一规则；无 Origin 的非浏览器客户端仍按原鉴权处理，来源检查不代替认证。

## 本轮验收结果

- 真实原生包及独立 LaunchAgent 应用/助手启动。
- 安装阶段真实终止助手，恢复同一 operation 成功。
- 静态在线切换、旧版懒加载资源、幂等、参数冲突、取消及回退通过。
- 运行时升级/降级经过真实服务停启；注入新版启动失败后成功自动恢复旧版。
- 最终原生助手默认拒绝脏包；显式本地更新/回退通过；未声明已验证 Nexus 组合时拒绝。
- Chromium 禁缓存验证实际升级恢复后的页面：82 个资源加载/解析通过，0 脚本错误、0 加载失败。
- 独立数据目录的真实 Nexus：允许来源通过 CORS/WS 来源检查；拒绝来源 WS 返回 403；允许或无 Origin 的匿名 WS 仍按原鉴权拒绝。

正式发布、真实跨主机/跨登录会话验证、真实业务 build 组合验收以及 Nexus MCP 统一更新入口集成不在本轮已验证结论内。未更改正式运行服务，未发布 Release。
