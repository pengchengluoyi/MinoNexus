## 清缓存缺陷与已完成修复

旧正式任务 `cr-6d50d0c5b50e` 执行“清应用缓存”时，seq58 实际记录 `pm clear com.mathmagic.magicam`，曾清除应用本地数据。此事已向用户告知，不能改写为未发生。

源码修复包括：

- Scout 原生 cache-only 能力先检查系统支持，只允许带 `--cache-only` 的清缓存；不支持、失败或超时均不回退清除数据。失败状态 BLOCKED，阻止后备执行器重放。
- Nexus 程序能力自动升级旧目录记录；缓存清理不再充当退出登录、形象复位或已租账号的证明。
- 缓存清理只使当前设备登录观察失效；保持账号业务事实、历史绑定及其他设备观察。
- 账号写回提示词版本 2 已由实际加载器解析通过，明确缓存不能证明登出或业务复位。

## 本轮新增：复用账号池的新号机制

用户已明确允许从账号池申请新账号，并确认新账号用于建立未配置初态。沿现有 `phone_pool_lease.py` 的顺序开号路径发现两处缺口：新号只初始化少量核心字段，无法满足原用例的 `field_7065t5=no`；“未配置形象”未进入新号优先分支，仍选择了标注不准的旧号。

已修复：

1. 按现有 fresh_user 合同初始化新号；对已定义且支持 no 的既有形象字段填入新用户初始值。其他业务字段不从需求凭空复制；不满足新用户状态的需求在补号前拒绝。
2. 未配置形象且与新用户状态相容时优先新号；原用例、预期和编译条件保持原样。新号初态改变或领取失败后不回退到旧号。
3. 同一 owner、应用、任务、用例、设备、渠道和环境使用稳定补池 ID。重复申请与进程恢复复用同一账号；不同设备使用不同账号。
4. 在同一 SQLite 写事务中递增号码、写入账号、初始字段与补池审计。跳过同项目同环境已有手机号，避免将导入旧号再次当作新号；保留其他环境配置。
5. 明确指定手机号时尊重精确身份，不静默申请替代账号。修复 need_facets 已有前置但 params 未重复填写时遗漏身份提示的问题。跨环境请求不补号。
6. 补池审计明确 `source=phone_seq_provision.v2`、`business_state_verified=false`。初始值属于补池合同，登录后的形象选择页和完成后的取景页仍必须取得原用例独立断言；并不把补池记录伪装成 UI 观察。
