# V6 第二批：应用理解、诊断闭环与账号事实复核

日期：2026-10-17。代码范围：MinoNexus、MinoWorkbench。此批为源码实现与隔离验收，不是正式部署，也不代表 V6 全部准出。

## 已实现

### 应用理解与诊断

- 复用 NavFSM 页面，记录别名、正向特征、排除特征、正反例会话事件、平台与构建范围。候选经维护者批准才可生效；不进行训练或修改业务断言。
- 知识和私有证据按执行账号隔离。写入受项目维护权限、页面修订号、请求幂等键约束；页面识别基础变化后旧知识失效。正反例必须来自本应用、本账号已结束会话的观察事件。
- 运行时从数据库取已批准记录，仅匹配当前账号、平台、精确构建版本和页面基础摘要后覆盖运行副本；未知构建不应用。定位候选携带知识 review ID，命中排除特征、缺少正向特征或缺少层级时不能选中该页面。
- 导航图整份保存保留审阅记录、过滤客户端伪造的审批元数据；公共导航导出不包含私有证据。有审阅历史的页面或图不能直接删除，需另行设计归档流程。
- 影响预览区分结构中的页面 ID 引用与文字候选，并纳入适用平台已批准别名。文字匹配不是完整语义影响证明；无命中不等于无影响。
- 所选用例复用既有复检或编译队列；检查影响令牌与源码修订，逐条返回结果，部分失败不掩盖。编译不自动实跑，也不直接把问题设为已解决。
- 趋势按用例去重展示复核、曾实跑验证解决和复发，延续既有诊断及审批历史。无对照基线时改善率为空；不把执行失败直接认定为用例问题。

Workbench 入口：应用 → 问题清单 → 应用理解与诊断。

### 账号事实

- 用例结束的模型推断、作者后置提示和通过推断改为候选，未确认前不改变分配使用的账号事实。
- 新增 SQLite `account_fact_candidates` 表，按 owner/session/account 幂等；记录原事实、候选变更、应用、环境、可用的平台/build、session/finalization 和租约来源。未知来源字段保留未知，不补造。
- 候选生成事务校验当前租约、账号事实基线、已结束会话、账号/应用/项目范围以及隔离状态，拒绝失去持有权或旧快照产生的写回。
- 确认事务校验维护权限、记录归属、空闲租约、原事实摘要、环境与观察事件，确认后才更新真实 facet；拒绝只更新审阅状态。重复决定可幂等返回，冲突决定被拒绝。
- 人工确认独立记录为 `human_confirmed`，不等同于自动业务核验，也不会修改历史 verdict。当前界面显示本账号最近 200 条候选/决定。

Workbench 入口：应用 → 配置 → 账号事实。

## 接口与数据

- `/project/{project_id}/apps/{app_id}/understanding/pages`、`/trends`。
- `/understanding/pages/{state_id}/reviews`、`/reviews/{review_id}`、`/impact`、`/revalidate`。
- `/project/{project_id}/account-facts`、`/account-facts/{candidate_id}`。
- 页面知识仍保存在既有 NavFSM 状态元数据中，没有第二个页面目录；诊断复用 `case_review_records`，编译复用既有 job/revision。
- 新表由现有 SQLAlchemy 启动建表机制创建，不对已有业务数据做重写。旧会话不会自动变成候选；旧误标字段不批量猜测修复。
