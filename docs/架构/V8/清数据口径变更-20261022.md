# 清数据口径变更：`clear_app_cache` = `pm clear`（2026-10-22）

## 决定

按用户明确指示：

1. 去掉 仅缓存选项（已废弃） 与「仅清缓存」承诺；
2. 去掉 `旧清数据别名` 全部逻辑（它不是一条独立能力，是 `clear_app_cache` 的旧别名）；
3. 只保留 `clear_app_cache` 一个名字，实现直接调用 `pm clear`。

## 为什么改

- **用户口径**：对用例前置来说，「清缓存」和「清全部」没有差别——两者都要求重新登录。
- **技术事实**：安卓非 root 没有跨应用的登录态 API（`docs/架构/V2/步骤准出与登录态方案.md`），
  `pm clear` 是唯一确定性的未登录重置；只清缓存不会让任何 App 退出登录
  （2026-09-18 复盘已记录：前置 guest，清缓存后 session 仍为 `logged_in`）。
- **命名与实现原本不符**：改名前的 `旧清数据别名` 在 Scout 里被路由到同一个 仅清缓存函数，
  Scout 文档却标它「清数据、需 device_owner」。两条名字一条实现，是纠纷来源。

## 与 2026-10-19 事故的关系

2026-10-19 正式任务 `cr-6d50d0c5b50e` 声称「清应用缓存」，seq58 实际下发 `pm clear`，
清掉了应用本地数据（见 `docs/架构/V6/实施/Android-清缓存与新账号补池-20261019.md`）。
当时的应对是收窄成仅清缓存，避免「名字说清缓存、实际清数据」。

本次变更是把**名字改成与副作用一致**，而不是把副作用藏起来：

- 能力名仍是 `clear_app_cache`（协议 id 不变，避免两仓同时改动 breaking change）；
- 结果里 `cleanup_scope = "app_data_and_cache"`、`source = "adb.pm_clear.v1"`；
- 目录描述、prep 里程碑标题都写「清除应用数据与缓存」。

## 副作用边界（必须在证据里说清）

| 会丢 | 不会丢 |
|---|---|
| 本地登录凭据（token / cookie / 本地 session） | 服务端业务事实：作品、订单、形象配置（若存服务端） |
| 本地缓存、草稿、未上传素材 | 账号池中的账号本身 |
| 运行时权限授予状态（可能需重新授权） | 其他设备的观察与历史绑定 |

**已知建模缺口**：账号/业务字段目前没有「存客户端还是存服务端」的标记，
因此无法自动判断某个字段在 `pm clear` 后是否复位。这属于后续数据模型工作，
不能用「清缓存不证明复位」这类模糊话掩盖。

## 代码落点

- `MinoScout/mino_scout/executors/app_cache.py`：`pm clear --user current <pkg>`；
  失败/未知一律 `error`，不回退任何其他清理方式。
- `MinoScout/mino_scout/executors/adb_executor.py`：`provides` / `supports` / 执行分支去掉 `旧清数据别名`。
- `mino_nexus/catalog/skill_channel.py`：能力描述与 `requires_caps` 更新，抽象能力名去掉 `旧清数据别名`。
- `mino_nexus/casework/execution_requirements.py`：不再把 `clear_app_cache` 映射到 `旧清数据别名`。
- `mino_nexus/catalog/{tool_schema,recovery_seed,resource_transition_seed}.py`：别名行与规则删除。
- `mino_nexus/casework/prep_plan.py`：安卓 + 前置要求未登录时，自动安排 `prep_clear_cache`。
- `mino_nexus/casework/resource_transition.py`：清数据成功后机态按构造记为 `logged_out`（本地凭据已删）。
- `mino_nexus/resources/resource_preflight.py`：安卓不再因「登记簿 logged_in + 用例要未登录」拒跑。

## 验收

- 静态门禁：`arch_report --check`、`check_globals`、`check_calls`、`check_returns` 全绿。
- 业务验收：`api-1-218`（前置「用户未登录」）应在 prep 中执行 `clear_app_cache` 后
  进入 do，且不再出现「找不到登录入口」。
