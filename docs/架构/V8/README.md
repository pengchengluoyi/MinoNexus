# V8 说明（已并入 Mino Bots）

2026-10-19 起，原 V8 后置能力与 V7 协作首期 **合并为一套 Mino Bots 方案**，不再分两期交付。

真源文档：[Mino Bots 方案](../V7/MinoBots-方案.md)（第五版，测试工作区）。

## 与 V8 原设想的对应关系

V8 原先按「交付流水线 / 多角色评审 / 用例草稿落库」组织，第四版已判定这些与测试执行无关，退出主线。下表只保留**仍然有效的对接点**，并标注它们现在归谁。

| 原 V8 能力 | 现状 | 第四版归属 |
| --- | --- | --- |
| 交付流水线（LangGraph） | `collab_langgraph.py` 已存在，服务于「生成需求/用例」流水线 | **冻结**，不进测试工作区 |
| 多角色评审（`req-qa-bm`、`knowledge-reviewer`） | 现有 job | **冻结**；测试工作区不发起评审 |
| IM 群同步（飞书/微信入站镜像） | 经 `assistant_gateway` 镜像到绑定议题 | 改为**仅出站通知**，入站默认关（工作区「资源」页签的通知渠道） |
| 议题记忆（LLM 摘要） | 写 `collab_topics.memory` | **移除**；由代码生成的 `digest` 与主动播报替代 |
| Bot 市场（`collab_marketplace.yaml`） | 安装只插 `project_bots` 一行 | **冻结**；一个项目只有一个管家身份，不需要市场 |
| 开发代理（OpenHands） | `OPENHANDS_API_URL` | **保持下架** |
| 用例草稿落库（`apply_drafts` → `upsert_cases`） | LLM 生成草稿的落库通道 | **移出主线**；用例只来自导入 |

## 仍然有效的外围约束

- 写入门禁不变：正式用例发布、设备执行仍走现有合同与 preflight。
- 用例来源仍是项目导入（飞书表格、用例 API、手动导入），平台不生成。
- 工作区、任务、工作项的结构见第五版 §2、§3、§5。

## 当前状态

第五版只是方案。已有代码里第四版新增的任务表、派发器、线程表与 `run_store` 全项目闸门按方案 §7 处理；其中闸门会影响手动执行，建议优先移除。
