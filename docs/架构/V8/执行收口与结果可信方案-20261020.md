## 1. V8-A 执行收成一条路径

目标：准入结束时生成一份不可变合同；循环内的登录状态和导航状态各自只有一个写者；准备失败不进入操作。主循环大分支本批不整体搬迁。

### A1 准入合同 `ResolvedCase`

在 `loop/case_runner.py` 的 `run_cases` 准入末尾构造，传入 `_run_loop`。循环只读它，不再读原始 case dict，不再改平台。

必填字段：

| 字段 | 来源 |
|---|---|
| `run_id` / `case_id` / `sn` / `session_id` | 本次任务 |
| `platform` | 设备声明，只允许 `android`。空值沿用现有 `blocked/device_platform_invalid`，不补默认 |
| `app_id` / `target_package` / `target_app_name` | 已校验的应用与任务；`expected_build` 仅在任务显式指定时校验 |
| `account_lease_id` | 已租到的账号；无租约则本字段为空，并由 A3 决定能否进入 Do |
| `execution_mode` | 内部固定 `agent`，公开请求不再提供版本选择 |
| `execution_binding` | 已提交绑定。缺绑定沿用现有 `blocked/binding_not_committed` |
| `max_steps` / `wall_budget_sec` | 现有预算，循环内不得延长 |
| `capability_snapshot` | 本次菜单允许的能力及其 `executor_order` / `low_level` / `selected_impl` |

`session_meta` 写入合同摘要：平台、包名、`expected_build`、账号租约、绑定版本、预算。缺必填项在准入 `blocked`，不进入循环。

### A2 两个状态组改为单一写者

`LoopState` 保留。本批只收所有权最乱的两组，其余字段仍按现有写入，但新增写入必须落在声明过的字段上。

| 状态组 | 字段 | 唯一写者 | 现在的交叉写入 |
|---|---|---|---|
| Auth | `login_evidence`、`session_fact`、`task_session`、`device_session`、`device_session_source`、`login_flow_macro_active`、`login_flow_macro_done`、`login_auto_submit_attempts` | `loop/login_transition.py` 暴露的一组函数 | `login_state_probe`、`session_persist`、`flow_block_runner`、`agent_loop`、`login_submit` |
| Nav | `nav_hierarchy_nodes`、`nav_vlm_hierarchy`、`nav_localized`、`nav_localized_state`、`nav_localized_confidence` | `loop/nav_runtime.py` | `agent_loop`、`channel_observation`、`check_box`、`conditional_steps`、`email_login_auto`、`login_block_steps`、`login_submit` |

其他模块改为调用这两组函数。直接给这些字段赋值视为缺陷。每次变更追加现有 `session_events`，事件名沿用，不另建事实表。

`flow_block_runner.py` 仍被 `agent_loop.py` 调用，并写登录宏字段。本批先把这两处调用和它写的宏字段交给 Auth 写者，确认事件序列不变后删除 v1 文件。`flow_block_runner_v2.py` 保留。

### A3 阶段门

出口仍是现有 `_leave`、`_leave_case`、`_leave_execution_blocked`。资源释放只发生在这三个函数里。

- Prepare：租约、清缓存、启动、登录提交确认。失败调用 `_leave_execution_blocked` 或 `_leave(status=fail)`，不进入 Do。
- Do：只消费 `ResolvedCase.capability_snapshot` 里阶段为 `do` 的能力。
- Check：派发前拒绝 `kind` 不是 `check` 的能力。提示词里的「禁止点击」保留为说明，不再是唯一约束。
- 三个出口统一释放账号和设备租约。

### A4 本批不做

不把 `_run_loop` 拆成拦截器框架。系统弹窗和登录链的搬迁放到 §5，且只处理 C 批仍标成 `tool_blocked` 的分支。不合并 `v5_case_exec.py`。不删除 `MINO_MILESTONE_V1` 等开关；取值未在运行进程确认前保持现状。

## 2. V8-B 通过只表示业务断言成立

目标：终态表达「用例要求的事实是否成立」。动作完成、页面切换、模型自证都留在事件里，不能升级成用例通过。

### B1 终态

`_leave` 的 `status` 改为固定原因，调用点逐一标注。自由文本只留在 `summary`。

| 终态 | 含义 | 现有出口怎么映射 |
|---|---|---|
| `pass` | 当前步骤全部必选预期已被证据消费，且整案步骤走完 | 仅 Check 阶段允许 |
| `product_fail` | 断言不成立，观察和证据完整 | 现有业务 `fail` |
| `tool_blocked` | 定位、挡屏误报、合同、编译计划或绑定错误 | 现有工具类 `blocked` |
| `env_blocked` | 包版本、账号、设备或登录前置不符合 | 现有资源类 `blocked` |
| `unverified` | 证据不够，禁止当成通过或产品失败 | 观察失败、比较失败、未知写入 |

未知写入继续停止后续业务写，终态为 `unverified`，沿用现有隔离，不重放。

### B2 登录提交确认

`loop/login_transition.py` 在页面比较成功时，现在同时写入：

- `login_evidence.authentication = logged_in`
- `login_evidence.login_state_verified = True`
- `session_fact.session = logged_in`
- `device_session = logged_in`
- 比较结果 `status = pass`

本版改为：比较成功只记 `login/submission_transition`，`passed=true` 表示已离开本次提交前的登录页，`business_context_verified` 保持 `false`。不得写 `logged_in`，不得把 `login_state_verified` 置真，不得把该结果当成用例 `pass`。

仍在原登录页记 `product_fail`，原因 `login_page_unchanged`。DOM 和截图都缺失记 `unverified`，停止确认，不重试、不补导航。

账号已登录需另有一条证据，二者满足其一：

1. 租约账号与当前界面可观测身份一致，身份来自应用配置中的可观测事实，不靠点击「我的」或固定文案证明。
2. 应用配置声明的登录事实在本次观察中成立，并写入 `login_evidence.identity`。

两条都不成立时，登录提交确认结束，账号状态保持未核实。后续业务步骤按自己的预期继续；预期依赖已登录时，整案终态为 `env_blocked`，原因 `login_identity_unverified`。

### B3 步骤校验

`loop/check_verify.py` 的 `synthesize_verdict`：

- 删除「`llm_self_pass` 且置信度 ≥ 0.72 即通过」。模型自证只产生 `unverified`，再交给已有视觉断言；视觉断言也必须对应本步必选项。
- `should_assert_visual_for_check` 不再因置信度 ≥ 0.72 跳过视觉断言。
- 必选工具证据全部 `pass` 时，终态才是 `pass`，摘要写明消费了哪些 `point_id`。
- 必选证据 `fail` 且观察完整时，终态是 `product_fail`。
- 缺证据、层级无法终裁、视觉比较失败时，终态是 `unverified`。

`agent_loop.py` 中 `check_programmatic_pass` 分支只负责调用上述判定。点击回执、`decision.status == done`、页面指纹变化停在动作完成事件，不能调用 `_leave(status=pass)`。

### B4 挡屏

依据 `case-1896d041` 的 `cr-4ab76c9f4123` seq597/606：带返回按钮、无弹窗结构的取景页被报成「拍摄引导弹窗」。

规则落在产生 `system_overlay` 的观察，而不是事后加一条恢复配置：

- 报 `system_overlay=yes` 必须带对话框节点标识，或截图上的对话框区域。二者都没有则保持 `no`。
- 页面存在返回且没有对话框证据时，走普通导航。
- 无法判断时终态 `tool_blocked`，原因 `overlay_evidence_missing`。禁止编造恢复规则让该步通过。

## 3. V8-C 五条用例的全量去向

每次开跑前，`session_meta` 记录：`expected_build`、实际包版本、`account_id`、`business_state_verified`、起始截图引用。缺包版本或账号标识时整案 `env_blocked`，原因 `fixture_incomplete`，不进入 Do。

`business_state_verified=false` 的账号不允许被下一条用例租用。清理失败或写入结果未知，同一账号停止续跑。

|---|---|---|
| `case-aafa9a70` | 原通过 `cr-efc8e3dde755` 在同一包版本可复现 | 业务断言仍成立才是 `pass` |
| `case-832dbc51` | 原通过 `cr-bffba5bc62c4` 可复现 | 同上 |
| `case-f195d70c` | 同上 | 同上 |
| `case-1896d041` | 取景页进入导航，并能再次走到原步骤 3 之后 | `pass` 或 `product_fail`。再出现无对话框证据的挡屏即 `tool_blocked`，本版不算完成 |
| `case-25e70e0b` | 账号初始状态是否匹配「选择形象页」 | 状态已核实后按预期给 `pass` 或 `product_fail`。未核实则 `env_blocked`，不改预期，不改历史 fail |

### 本轮已改

- `login_transition.py`：页面切换结果为提交观察 `completed`，事件仍为 `login/submission_transition`，`business_context_verified=false`；成功比较不写已登录。实际提交绑定时先失效旧身份，后续比较不会清掉另一次独立观察取得的身份。原页未变为 `product_fail/login_page_unchanged`；观察缺失或比较错误为 `unverified`，缺提交参考和无新观察也记录事件。
- `services/login_evidence.py`：拒绝历史 `login_page_transition` 证据；Android 的身份核实要求当前租约与界面身份一致，或已有明确配置、实际提交与当前登录专属内容证据。其他平台不自动套用 Android 的身份必选条件。
- `observe/session_persist.py`：移除沿用页面切换结论的旁路。提交时的状态失效保留已有提交绑定证据，仍不能将该绑定本身视为登录证据。
- `flow_block_runner_v2.py`：只用同一提交、同一作用域的页面切换结果完成提交里程碑，工具动作完成与整案通过分开。
- `agent_loop.py`：三处逻辑块消费者保留 `product_fail/unverified/env_blocked` 和原因码；Android 进入 Do 前对声明的已登录前置核验当前证据，缺失为 `env_blocked/login_identity_unverified`。
- Auth 八字段经 `login_transition.update_auth_state` 写入；已有 probe、persist、scope、navigation、submit、v1 宏和主循环改为调用该写者。v1 宏完成集合改用复制更新，避免原地 `.add()` 绕过写者。变更追加现有 `login/evidence` 事件，只记字段名，不记账号标识或凭据。
- `services/run_store.py`：识别四个新增非通过终态并纳入完成数，保留各类计数；`unverified` 不计为产品失败。
