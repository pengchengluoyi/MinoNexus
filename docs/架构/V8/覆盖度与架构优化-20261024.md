## 1. 覆盖度：两个轴，主分母是业务意图

| 轴 | 口径 | 入口 |
|---|---|---|
| 业务意图闭合率（主） | 需求点至少一条用例最近一次跑批通过，才算闭合 | `casework/coverage.py:intent_coverage` |
| 事件 × 渠道可达性 | 事件在 android/ios/web/mac/win/linux 或 api/rpc/websocket/db 上有没有实现 | `casework/coverage.py:event_channel_matrix` |

- **不再把随机事件组合当覆盖**；FSM/逻辑块以意图粒度进入覆盖。
- `ui_coverable` 只进统计：`catalog/skill_channel.capability_dispatch_ok` 与
  `registry.filter_capabilities` 都不再拿它拦派发/菜单。
- 旧 `compile_metrics`（编译率）保留，不冒充覆盖率。
- HTTP：
  - `GET /project/{pid}/apps/{aid}/understanding/coverage`
  - `GET .../intent-coverage`
  - `GET .../event-channel-matrix`
  - `GET .../intent-graph`
  - `GET .../failure-attribution`

## 2. 失败归因 A/B/C

`contract/attribution.py` 是唯一映射：

| 类 | 含义 | 例 |
|---|---|---|
| A 平台缺口 | 平台本来没有 | `platform_unsupported` / `channel_absent` |
| B 程序缺口 | 目录缺、绑定未提交、块空、引用缺失 | `unavailable_cap` / `block_empty` / `missing_ref` |
| C 守卫误拦 | 手能点、程序也有，策略挡了 | `skip_repeat_*` / `action_fuse` / `stage_menu_empty` |

写入点：

- `records/eventlog/writer.py`：失败类事件自动补 `reason_code` / `layer` /
  `attribution_class` / `attribution_label`；`first_blocker` / `latest_error` /
  `stop_reason` 同名字段向后兼容。
- `loop/execution/guard_skip.py`：守卫拒绝统一 C 类（layer=guard）。
- `contract/binding.py`：绑定诊断补类与层（layer=dispatch）。
- `loop/flow_block_executor.py`、`catalog/skill_channel.apply_channel_skip`。
- `casework/case_step_key_compiler.py` / `casework/case_preflight.py`：编译/预检条目补类。

Workbench 只展示，不再自己猜。

## 3. 意图图 + 单一事件解释器

- `knowledge/intent_graph.py`：域 → 意图节点 → 策略边（happy/fallback/reverse）。
  公共骨架覆盖 auth/commerce/social/community/banking/general；App 私有块按 `app_id` 追加。
- `loop/event_interpreter.py`：**唯一**解释器。输入意图/块/步骤，输出事件并派发；
  `prep` / `do` / `check` / `recover` 只是触发标签，不再是权限或工具菜单。
  `block_dispatch.run_block` 委托给它，`local_executors.run_flow_block` 支持
  `params.intent_id`（与 `block_id` 二选一）。
- 编译产物：每个 step 补 `intent_id` / `intent_domain` / `intent_label` / `intent_edge`；
  `meta.step_program_keys[n].intent_graph` 存切片，`meta.intent_summary` 存汇总。
- 业务意图先用目录 `keywords` 做最长匹配（`intent_for_text`），匹配不到才落到
  `general.*`；模型只做兜底，不把稳定的关键词分类也交给每次跑批的模型调用。
- 引用校验：`flow_block_seed.verify_referenced_blocks` 只报本用例真正引用、但解析不到
  步骤的块（B 类 `missing_ref`），不再要求全局九块同时存在。

## 4. 意图判断：用现有 LLM/VLM 顶替 Jev/Laya

- `ai/intent_router.py`：`choose` / `choose_domain` / `choose_intent` / `score_screen`。
- Prompt job：`prompts/jobs/intent-choice/`（`choice | noul` + `score` + `reason`）。
- 两级分流：先域（6 个），再意图（单次 ≤20 个候选），与 Jev 线协议语义一致。
- 不引入 Jev/Laya 运行时，不引本地决策模型；无 provider 时返回结构化失败，不伪造答案。
- API：`GET .../intent-options`（域/意图候选）与 `POST .../intent-choice`
  （问题 + 屏幕文本/截图 → 现有 LLM/VLM 选择），供编译、预演与 Workbench 复用。

## 5. 权限墙拆除（P0）

| 旧墙 | 现在 |
|---|---|
| `REQUIRED_GLOBAL_BLOCKS` 启动必填 | 只保留常量；启动不校验，改为引用可达 |
| `recovery_block_ids` 白名单 | `dispatchable_block_ids`：已启用且能解析到步骤的块都可派发 |
| 阶段 `phase_allows` 拦派发 | 恒真；阶段只缩 prompt（`menu_caller_ok` 仍按阶段裁剪） |
| 编译期能力硬阻断 | 能力缺口降为 `severity=risk`，不阻断整案；`ui_coverable` 不再参与 |
| 预检 `hard_blocked` 能力缺口 | 预检只保留场景/编译/绑定等真基础设施故障；能力缺口进 `risks` |
| 空菜单 → planner give_up | 绑定投影为空时回退到可用能力集合；派发仍由 binding 判定 |
| 里程碑不在菜单 → blocked | 能力目录有实现且平台支持即可，菜单不再是注册依据 |
| `skip_repeat`×3 整案停 | 只记录和提示，不再停整案 |
| `guard_skip×3` 整案停 | 同上 |
| `same_target_repeat:2` | 只在界面指纹未变时触发；`multi_tap` 不经过该守卫 |
| `action_fuse NO_PROGRESS` | 只有指纹无进展 + 熔断次数达阈值才停 |

## 9. 交付节奏调整：先最小时间线，再补完整闭环

> 2026-10-25 调整：方向不变，解除“归因完全展示 → 覆盖面板完成 → 才拆闸”的串行依赖。

### 9.1 时间线 P0（只读最小版）

- 数据源只用现有 `session_events`，不新增表、不改事件协议、不做编辑/重放/批量操作。
- Workbench `SessionDetail` 新增“时间线”默认视图：
  - 截图：`stream/emit` / `tool/result` 的 `thumb`，没有截图时明确显示“无截图”；
  - 步骤：优先 `case_step`，其次 `step`，前置显示“前置”；
  - 五态：`pass` / `fail` / `skipped` / `blocked` / `declined`，另有“执行中 / 未核验”兜底；
  - 归因 pill：读取 `session/attribution` 的 `stop_reason` / `first_blocker` / `latest_error`；
    行内已有 `attribution_class` 时同时显示。
- 首屏事件不足全量时，`/sessions/{id}/events` 额外带回末条 `session/attribution`，不为一个 pill 读全量事件。
- 验收只要求：打开一个真实会话，能看到上述四类信息，且只读不写。
- 不阻塞条件：不要求覆盖面板完成、不要求 A/B/C 全量统计、不要求需求点导入。

### 9.2 拆闸 P0（只绑“归因能看见”）

拆闸准入只看两条：

1. `session_events` 的 `session/attribution` 或时间线/详情里的归因 pill 能显示；
2. 失败会话能说明 A/B/C 哪一类，或至少给出具体 `stop_reason.kind` / `reason_code` 和阶段/步骤；
   未分类不阻塞拆闸，先让阻塞原因可见。

不再要求“覆盖面板完成”或“业务意图闭合率达到某阈值”才拆闸。覆盖面板、私有块挖掘、
需求点映射可以并行推进，不再作为拆闸前置。

### 9.3 并行关系

| 线 | 现在做什么 | 不阻塞谁 |
|---|---|---|
| 时间线 | `SessionDetail` 只读最小版 | 拆批 commit、归因后端 |
| 拆批 commit | 按现有批次/分片能力拆，不再等覆盖面板 | 时间线 |
| 拆闸 | 只等归因可见 | 覆盖面板、事件×渠道矩阵 |
| 覆盖面板 | 继续补需求点/私有块/矩阵 | 时间线与拆闸 |

原则：**先把“看得见”做出来，再逐步把“算得全”补上；不以完美闭环作为整条线的闸门。**
