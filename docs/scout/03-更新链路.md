# 03 — 更新链路

## 1. 三条更新路径

| 路径 | 谁停进程 | 谁装包 | 装完谁拉起 |
|------|----------|--------|------------|
| **Studio 本机** | Electron `ensureScoutStopped` | 每层 `install.sh`（完整 stop） | `startScoutService` / kickstart |
| **终端** `bin/mino-scout update` | `install.sh` 内 stop（独立进程时可停服务） | `self_update` → zip → `install.sh` | `install.sh` 注册并 kickstart |
| **Nexus 远程** `node.update` | **不 stop**（`MINO_SCOUT_UPDATING=1`） | 同上，但在 **当前 Scout 进程内**同步执行 | **`schedule_reexec`** → 新 `bin/mino-scout run` |

v0.1.28 修复的核心：**远程更新不能再在 `install.sh` 里 stop 自己**，否则 Nexus 504「节点未应答」、节点长期离线。

## 2. 更新计划（plan）

Scout：`mino_scout/install_plan.py`  
Studio：`electron/scoutLayers.cjs`（规则一致）

```text
manifest item.layers.*
        ↓
对比 bin/layers.txt 各层 key
        ↓
┌─ 全一致 → up-to-date
├─ 无 layers 字段 → combined 整包
├─ 增量体积 ≥ 合并包 → combined
└─ 否则 → layers 逐步：runtime → app → browser
              （browser：目录名与 manifest 一致则跳过；
               若要更 browser 且缺 runtime 步 → 先插 runtime 步）
```

**v0.1.28 指纹变化**：引入 `runtime.lock` 与 `RUNTIME_ABI=3` 后，**首次升到 0.1.28 常会拉 runtime（或合并包）**，不是纯 app 热更——属预期。

## 3. 进程内热更：`MINO_SCOUT_UPDATING`

`self_update._install_env(inplace=True)` 设置环境变量：

- `install.sh` / `install.ps1`：**跳过** `stop_running`、**跳过** launchd/计划任务重写与 kickstart。
- 文件仍按层替换；装完后由 **core + transport** 处理退出与拉起。

`inplace` 判定：`read_pid()` 存活且为本服务（远程 update 时一般为 true）。

## 4. reexec 与 install.sh 分工（v0.1.28+）

| 步骤 | 行为 |
|------|------|
| 1 | Nexus 发 `EXECUTE node.update` |
| 2 | Scout `run_update()` 下载并 `install.sh`（inplace） |
| 3 | 回 **RESULT**（summary + `update` 详情） |
| 4 | transport 见 `_scout_reexec` → **`schedule_reexec`** |
| 5 | 延迟后 **Popen** `$PREFIX/bin/mino-scout run`（新会话） |
| 6 | 旧进程 **shutdown**，WS 重连 REGISTER |

**不再**依赖 inplace 路径里 `install.sh` 的 kickstart，避免与 reexec 双拉起。

`MINO_SCOUT_NO_REEXEC=1` 可跳过 reexec（调试）。

## 5. 进度与超时

| 环节 | 说明 |
|------|------|
| Scout | `update_progress.emit` → transport → **`node.update_progress`** |
| Nexus | `NodeSession.update_job` → `/runtime/nodes` 的 `update_job` 字段 |
| Studio | 远程更新时 ~1.5s 轮询节点列表，按钮文案显示阶段与 **percent** |
| HTTP | `POST …/command` update：**660s** 客户端超时；Nexus 等 RESULT **~630s** |

进度 payload 字段：`stage`（plan/download/verify/install/done）、`label`、`percent`、`layer`、`bytes_*`、`active`。

## 6. 回滚

安装任一层失败：

- 已替换路径从 **`.old`** 恢复；
- `layers.txt` 从安装前临时快照恢复。

成功则删除所有 `.old`。

## 7. 失败模式（运维）

| 现象 | 常见原因 |
|------|----------|
| 504 节点未应答 | 旧 Scout：inplace 仍 stop；或下载超时 |
| 更新成功但版本不变 | 未 reexec；仍跑旧进程 |
| app 装完 ImportError | runtime 指纹与 app 的 `requires_runtime` 不一致 → 打 **合并包** |
| Permission denied install.sh | zip 丢 execute bit（0.1.28 已 chmod；仍可用本机 update 重试） |
