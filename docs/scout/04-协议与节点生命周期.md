# 04 — 协议与节点生命周期

协议版本：**v2**（两仓 `protocol.py` + golden fixtures）。完整表格见 [PROTOCOL.md](../基础框架/PROTOCOL.md)。

## 1. 连接序列

```text
Scout                          Nexus
  |---- REGISTER (token, devices, executors) ---->|
  |<--- REGISTERED (accepted, node_id, warnings) --|
  |---- HEARTBEAT (15s) ------------------------->|
  |<--- (Nexus 更新 last_seen, device_delta) -----|
  |<--- EXECUTE (能力 / node.*) ------------------|
  |---- RESULT ---------------------------------->|
```

- **心跳超时**：45s 无 HEARTBEAT → 节点 `alive=false`，设备连通性标 offline，**归属保留**。
- **重连**：Scout 指数退避；Nexus 不要求降级协议。

## 2. Nexus → Scout：节点指令

| capability_id | 作用 |
|---------------|------|
| `node.stop` | RESULT 后进程退出 |
| `node.sleep` | 不退出。放开睡眠抑制、关掉 Chromium，心跳继续 |
| `node.wake` | 仍连接时重新抑制睡眠。浏览器等下次任务再开 |
| `node.restart` | RESULT 后 **reexec** 再退出 |
| `node.update` | 本机 `run_update()`；有变更则 RESULT 带 `_scout_reexec` |
| `node.plugin_install` / `node.plugin_remove` / `node.plugin_config` | 插件安装、移除、写参数。密钥留在 Scout |
| `node.plugin_progress` | 插件安装进度，不写入自更新的 `update_job` |

HTTP 入口：`POST /runtime/nodes/{node_id}/command`  
body：`{ "command": "stop|restart|update", "reason": "…" }`  

**不支持远程 start**（400：离线专机无法远程启动）——进程已经退出时，需本机 `mino-scout start` 或桌面版 Studio。网页上的「休眠」走 `node.sleep`，节点仍在线，同一行「启动」走 `node.wake`。

## 3. Scout → Nexus：框架事件

| capability_id | Nexus 处理 |
|---------------|------------|
| `node.device_lost` / `device_found` / `channel_changed` | 更新设备连通性；可能 interrupt 在途 run |
| `node.engine_crashed` | 记录；按策略 interrupt |
| `node.shutting_down` | **立即失败**该节点 `active_runs` |
| **`node.update_progress`**（≥0.1.28） | 写入 `NodeSession.update_job`，供 Studio 展示 |

`update_progress` 的 `params.progress` 示例：

```json
{
  "active": true,
  "stage": "download",
  "label": "下载 app",
  "percent": 42,
  "layer": "app",
  "step_index": 1,
  "step_count": 1,
  "bytes_received": 38000,
  "bytes_total": 90000
}
```

## 4. 普通 EXECUTE（用例路径）

Nexus 在 `EXECUTE` 载荷中必须带 Scout 需要的字段（CLAUDE.md §2.1）：

- `executor_order`、`low_level`、`selected_impl`、`device_hint`

Scout `RouterProxy` 在 Nexus 侧等价物是 **loop 内 dispatch**；Scout 侧按 sn 选 executor。

## 5. 节点登记与 Studio 过滤

- `REGISTER.studio_id` + install token 的 `owner_user_id` → `nodes` 表 / 快照。
- `GET /runtime/nodes?studio_id=`：工作台只看到归属匹配的节点。
- `scout_version`：REGISTER 上报；与 `config.json` 的 `version`、**app 层指纹**可能并存——排障时以 **`bin/layers.txt` + 进程 REGISTER** 为准。

## 6. 与跑批的关系

- 派单前：`NodeRegistry` 提供 `node_id`、executor 可用性、`provides` 集合。
- 节点离线：在途 run 应 **快速失败**，不等 step 超时（WS 断开 / shutting_down）。
- **更新期间**：节点可能短暂 busy；进度见 `update_job`；完成后 reexec 会断线重连，属正常。
