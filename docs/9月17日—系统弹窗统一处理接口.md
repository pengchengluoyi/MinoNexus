# 9月17日 — 系统弹窗统一处理接口

> **维护说明**：现象与 unified 入口保留本文；**逻辑块化（fb.global.system_dialog）与 FSM 联用** 见 [`9月18日-fsm导航能力提升.md`](9月18日-fsm导航能力提升.md) §4.2.2。

**问题**：`recover_system_permission_dialog_while_using_deterministic` 等规则 **只走 catalog actions 固定文案**，屏上 hierarchy/VLM 已识别到「允许/取消」时仍可能 **不点或点错**；不同 rule id（`system_permission_dialog` vs `…_while_using_deterministic`）重复维护。**样例**：`cr-6461f827b22d::case-51fef028` — 登录后出现权限挡屏，recovery 未有效 dismiss/allow。

**目标**：**一个代码入口** 处理 AOSP / MIUI / 厂商变体的 **系统权限弹窗**，catalog 多条 recovery id **共用** 该入口；actions 列表仅作 fallback。

---

## 1. 统一入口

| 项 | 说明 |
|----|------|
| 模块 | `mino_nexus/loop/system_dialog_recovery.py` |
| 函数 | `try_unified_system_permission_recovery(...)` |
| 判定 | `is_system_permission_rule(rule_id)` — id 为 `system_permission_dialog*` 或白名单内 id |
| 调用点 | `recovery.apply_rule` **在遍历 rule.actions 之前** 先尝试 unified |

---

## 2. 决策顺序（单次 attempt）

1. **collect_evidence** + 合并 `nav_hierarchy_nodes` 与 `nav_vlm_hierarchy.nodes`。  
2. **allow**：`recovery_permission.pick_permission_allow_text`（match reasons / OCR / 节点文案，按 MIUI/AOSP 优先级排序）。  
3. 无 allow → **dismiss**：`pick_permission_dismiss_text`（可点击节点的 取消/拒绝/Deny…）。  
4. **tap_element(selector_text=…)** → wait → 刷新截图 → **rule.verify**。  
5. allow 已过 verify 失败且存在 dismiss → **再 tap dismiss** 一次并 re-verify。  
6. 仍失败 → 回落 catalog **actions** 链（原有 deterministic 文案序列）。

---

## 3. 与 catalog 的关系

| rule id（示例） | 角色 |
|-----------------|------|
| `system_permission_dialog_while_using_deterministic` | match「使用时允许」类挡屏；verify `app_foreground=yes` |
| `system_permission_dialog` | 同族 match 变体（前缀统一进 `is_system_permission_rule`） |
| `system_permission_dialog_unified` | 可选合并 id（未来 seed） |

**不**在 `nav_*` 硬编码 App 文案；allow/dismiss 词表在 `recovery_permission.py`（系统控件级）。

`recovery_seed.upgrade_system_permission_recovery_rules` 仍刷新 match/actions；`evidence_notes` 注明 **apply_rule 优先 unified**。

---

## 4. 与其它 recovery 的边界

| 类型 | 处理 |
|------|------|
| 系统相册/文档选择器 | `system_media_picker_dismiss` — **不走** unified permission |
| 锁屏/截图黑 | `screen_secure_or_no_capture` |
| App 内业务弹窗 | Nav FSM / tap_element / 业务 recovery |

`limit_recovery_retry` 对 `system_permission_dialog*` 与 media picker 共用「改用 BACK / 取消 / give_up」提示。

---

## 5. 验收

1. hierarchy 含「仅在使用中允许」→ unified **一次 tap** 后 `app_foreground=yes`。  
2. 仅「取消」可点、无 allow → unified **dismiss** 路径。  
3. `case-51fef028` 复跑：权限挡屏不占用整段 do 10 步预算仍失败。  
4. 新厂商文案：优先扩 `pick_permission_*` 词表，而非新增 recover_* 事件。

---
