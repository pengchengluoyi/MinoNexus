# 9月18日 — FSM 导航能力提升（方案真源）

**优先级**：**P0**（跑批 do 步默认走图；仅「未走过/无 nav 边」降级）  
**范围**：MinoNexus（主）、MinoStudio（逻辑块展示与覆盖编辑）、MinoScout（执行载荷，无规划逻辑）

**现象与复盘**：保留在 [`9月16日-用例执行调用fsmnavigate能力异常.md`](9月16日-用例执行调用fsmnavigate能力异常.md) §0.x；**本文件维护结论、目标架构与实施路线**。业务流壳层/布局问题见 [`9月16日—业务流逻辑块问题梳理.md`](9月16日—业务流逻辑块问题梳理.md)（现象），块模型扩展见本文 §4。

## 0.0 产品决策（2026-09-18，已锁定）

| 项 | 决策 |
|----|------|
| **D1 BACK** | **C**：仅当图上**最短路首 hop 为 system back** 时程序 `press_key BACK`；plan 失败 → **L1 降级**，不再 `recover_press_back` 循环 |
| **D2 登录** | **C**：`fb.global.login` 宏为主，`sms_auto` 并入宏；menu 隐藏 `request_sms_code` / `accept_legal_consent`（登录步/中断时） |
| **D3 数据** | **B**：表 `nav_flow_block_catalog`，`app_id=__global__`；override 在 `nav_fsm.meta.flow_block_overrides` |
| **D4 挡屏登录** | **A**：非登录步检测挡屏 → **中断**并跑登录逻辑块；`block_login_flow` 在宏执行时豁免 |
| **D5 BACK 冲突** | **A**：`limit_recovery_retry` 等 recovery 建议 BACK 时 **`recovery_allow_back` 优先**于 nav BACK 门闩 |

## 0. 目标（一句话）

**每个 do 步骤在决策前**：用 NavFSM 生成「本步可达的导航子路线」→ 结合当前截图（hierarchy + VLM）**按序执行路线上的 hop**；**除「图上无路」外禁止把系统 BACK 当默认导航**；登录/系统弹窗等横切能力收进 **通用逻辑块**，应用可覆盖、Studio 对应用隐藏通用块记录。

## 1. 现状与差距

### 1.1 已落地（保留，按需收紧语义）

| 能力 | 位置 | 说明 |
|------|------|------|
| 最短路 + 单步执行 | `local_executors._fsm_navigate`、`nav_route.plan_route*` | 模型每 turn 主动调 `fsm_navigate`，非「步骤级自动规划」 |
| 首 hop 选取 | `pick_fsm_first_step` | Tab 捷径、深页直点 Tab；仍可能选到内容边或 BACK 链 |
| plan 失败兜底 | `_skip_tab_fallback` → `press_key BACK` | 历史上退化成「BACK 机」（§0.8）；图连通后应 **极少触发** |
| assist【路线】 | `nav_compiler` + `nav_attempt` | 与 executor 部分同源，但 **未在步骤入口强制注入完整路线** |
| 业务流 assist | `nav_flow_blocks.build_flow_context` | 仅 **session 分段块**，无「登录/SMS/协议」宏步骤 |
| 结构 cap | `accept_legal_consent`、`request_sms_code` | `local_executors` + recovery_seed；**未挂逻辑块**，与 FSM 边无关 |
| 系统弹窗 | `system_dialog_recovery.py` | unified 入口在 `recovery.apply_rule`；**未作为逻辑块宏**供导航/assist 引用 |

### 1.2 与预期的核心差距

| # | 预期 | 现状 |
|---|------|------|
| A | **步骤前**生成路线，再 **看图定序** 执行 | 路线在 `fsm_navigate` 调用时才算；无「本步导航计划」合同 |
| B | 仅有 **无 nav 边 / 未采集** 才降级开环 | plan 失败、Tab 不可见、深页等仍大量 BACK |
| C | 有路线时 **跟边走**，BACK 仅当 **屏上无返回控件且边语义为 system/back** | `edge_is_system_back` + 启发式 BACK 兜底过宽 |
| D | 登录/SMS/协议/系统弹窗 = **通用逻辑块** | 散落 recovery + local cap；应用 Nav 发布可能 **覆盖/污染** 通用配置 |
| E | 应用 **覆盖** 通用登录流（无协议框、多步等） | 无 `scope=global` 块 + `app override` 数据模型 |

## 2. 目标运行时：「步骤导航计划 + 看图执行」

### 2.1 触发时机

```text
enter do step n（或 step n 内首次 mutate 前）
    → resolve 本步「导航目标集」（来自 instruction + step_intent + 可选 case nav_anchor）
    → localize（已有）→ from_state
    → plan_route_resolved（可能多目标：Tab 页 / 入口页 / 流内下一屏）
    → 写入 RunContext：step_nav_plan（见 §2.3）
    → agent-decide 上下文注入【本步导航计划】+ 当前 hop 索引
每 turn mutate 前：
    → 若 plan 存在且未耗尽：优先 cap ∈ { fsm_navigate(执行当前 hop), tap/press 与 hop 一致 }
    → VLM/hierarchy：校验 hop 锚点是否可见；不可见则 correction_hint，**不** silent 改 BACK
plan 状态：
    → hop 成功且 arrived_at_target → 标记 step 导航完成，交还 instruction 内非导航意图
    → plan_ok=false 且 reason=无连通边 → **降级 L1**（见 §3）
```

**与 LLM 分工**：FSM 负责 **拓扑与可执行边**；LLM/VLM 负责 **当前屏上哪一条 hop 可点、顺序是否需插入 wait/recovery**（看图决策），但 **不得** 用 BACK 替代图上已有的 Tab/入口边，除非 §3.2 允许。

### 2.2 连贯路线 vs 非连贯路线（与意图文档联动）

| 类型 | 判定 | 导航计划形态 |
|------|------|----------------|
| **连贯** | 本步 `instruction_required_intents` 可映射到 **同一 flow_block 内** 或 **单条 nav 最短路**（中间无交叉业务步） | `step_nav_plan.coherent=true`；`hops[]` 一次注入；do 内优先走完 hops 再收工 |
| **非连贯** | 含「先 A 页再 B 页再回」、或登录弹窗挡屏 + 主流程步 | `coherent=false`；`segments[]` 分段 plan；段间允许 `recover_*` / 通用逻辑块 |

连贯/非连贯 **在步骤 enter 时由 Nexus 程序判定**（`step_intent` + `flow_block` 归属 + plan 结果），写入 plan；细节见 [`9月18日-意图识别与大模型注意力集中.md`](9月18日-意图识别与大模型注意力集中.md) §1。

### 2.3 `step_nav_plan` 载荷（Nexus 内存 + session_log）

```json
{
  "step_index": 3,
  "coherent": true,
  "degrade_level": 0,
  "from_state": "page.sk…",
  "targets": ["我的", "page.sk9…"],
  "hops": [
    {"edge_id": "…", "dispatch": {"cap": "tap_element", "params": {}}, "pick": "tab_shell_terminal"},
    {"edge_id": "…", "dispatch": {"cap": "press_key", "params": {"key": "BACK"}}, "allow_back": true}
  ],
  "hop_cursor": 0,
  "plan_error": "",
  "source": "nav_fsm"
}
```

- `allow_back`：仅当 `edge_is_system_back` **且** `screen_has_nav_back(localized, hierarchy)==false` 时为 true；否则规划层应 **重选边** 或 `deep_page_direct_tab`，而不是默认 BACK。  
- Scout **不读** plan；Nexus 在 `local_executors` / `router_proxy` 已算好的 `dispatch` 原样进 `EXECUTE`。

### 2.4 BACK 策略（收紧，替代宽泛兜底）

| 条件 | 行为 |
|------|------|
| plan 有 hop 且非 system back | **禁止** 本步 `press_key BACK`（guard：`block_back_without_nav_back_semantics`） |
| hop 为 system back | 仅当 hierarchy **无** 可点「返回/Back/nav_up」类控件（结构推断，**禁止 App 文案表**） |
| plan_ok=false，reason=不连通 | **降级 L1**，不 BACK 循环 |
| Tab 可见且目标为 Tab 页 | 必须 **直点 Tab 边**（延续 `pick_fsm_first_step`，但 **去掉** plan 成功仍 BACK 的分支） |
| 深页 → Tab，最短路首跳为内容边 | **终端 Tab 边优先**（已有 `deep_page_direct_tab`，纳入步骤 plan 生成） |

现象依据：§0.10「去 Tab 却点白色拍照按钮」、§0.3「每轮只走 BACK 链」——见 fsm 异常文档。

## 3. 能力降级（仅两类）

| 级别 | 条件 | 行为 |
|------|------|------|
| **L0 正常** | `plan_ok=true` 或 hops 部分可执行 | 步骤 plan + fsm 执行 |
| **L1 无路线** | 两态 **无 nav 边** / `unknown_state_id` / Atlas 未采集该段 | assist【路线】与 menu 明示「未走过，请 tap/探索」；允许 LLM 开环；**写入 candidate**（`nav_feedback` / edge proposal）供 Studio |
| **L2 图有路但 tap 不可编译** | `missing_tap_compile` | 不降级为 BACK；提示补边 execute 或 VLM tap；可 **单次** recover 后再 plan |

**非降级**：localize 低置信、degraded hierarchy —— 用 VLM 补强（fsm 异常文档 P1），**不**因此切 BACK 机。

## 4. 通用逻辑块（flow_block v2）

### 4.1 概念

| 类型 | `block_origin` | `app_id` | Studio 架构图 |
|------|----------------|----------|----------------|
| **应用块** | `nav_graph` / `session` / `manual` | 当前 app | 照常展示（≥2 页壳层规则不变） |
| **通用块** | `global_catalog` | **`__global__`**（固定哨兵，非 UUID） | **默认不对应用项目列表展示**；Console「通用逻辑块库」单独管理 |

通用块 **不写入** 应用 `nav_fsm.meta.flow_blocks` 的发布快照，避免 `promote` / Atlas 重发 **覆盖** 通用宏。

### 4.2 首批通用块

#### 4.2.1 `fb.global.login`

**宏步骤（默认顺序，可配置）**：

1. `input_text` field=phone（或 lease 账号）  
2. `request_sms_code`（`ui_sms_request` 几何）  
3. `accept_legal_consent`（`ui_consent`）  
4. `tap_element` / `input_text` otp（`get_otp` 可选）  
5. 登录提交 tap（结构：主按钮 clickable）

实现形态：

- **不是** 新 Scout cap，而是 **Nexus 侧 `FlowBlockRunner`**：按宏展开为子事件 `router.dispatch`（与 `ai_persona_executor` 类似但 **确定性顺序**，LLM 仅在「当前宏步无法结构执行」时介入）。  
- 原 `local_executors._accept_legal_consent` / `_request_sms_code` **迁入** 宏实现，catalog recovery 条目保留 id，**evidence_notes** 指向 `fb.global.login`。

#### 4.2.2 `fb.global.system_dialog`

- 宏：`try_unified_system_permission_recovery` → verify → 失败再 catalog actions。  
- 触发：guard/recovery 匹配 `system_permission_dialog*` **或** assist 检测到系统挡屏 pattern（结构）。  
- 与 [`9月17日—系统弹窗统一处理接口.md`](9月17日—系统弹窗统一处理接口.md) 现象一致；**结论与块化路线以本文为准**。

### 4.3 应用覆盖（override）

```json
{
  "app_id": "<uuid>",
  "overrides": [
    {
      "global_block_id": "fb.global.login",
      "mode": "replace_steps",
      "steps": [ {"id": "phone"}, {"id": "sms"}, {"id": "login_tap"} ],
      "skip_step_ids": ["legal_consent"]
    }
  ]
}
```

| `mode` | 含义 |
|--------|------|
| `inherit` | 全用通用（应用未配块时 **兜底**） |
| `replace_steps` | 替换步骤列表 / 跳过某些 step_id |
| `replace_block` | 应用自建 `flow_block_id`，仅 inherit 通用中未覆盖的 recovery |

**运行时优先级**：应用 override > 应用自有块 > 通用块。  
**FSM 导航**：登录屏 state 的 `meta.flow_block_ref = fb.global.login`（或应用块 id）；`build_flow_context` 读 **解析后的有效块**（合并 override）。

### 4.4 数据落点

| 数据 | 表 / 文件 |
|------|-----------|
| 通用块定义 | 新表 `nav_flow_block_catalog`（`block_id`, `scope`, `steps_json`, `version`）或 `settings` 下固定 key（P0 可用 JSON seed + Console CRUD） |
| 应用 override | `nav_fsm.meta.flow_block_overrides` **或** 独立表 `nav_flow_block_overrides(app_id, …)` |
| 发布 | `promote` **合并** override 引用，**不复制** 通用块进 app 的 `flow_blocks[]` 列表（避免 Studio 误展示） |

## 6. 验收

1. **造物相机** 类用例：步骤含「进入我的」→ enter step 可见【本步导航计划】≥1 hop；**不出现** plan_ok=true 却连续 BACK（除非 hop 显式 `allow_back`）。  
2. 图不连通：assist 与 `step_nav_plan.degrade_level=1` 一致，**无** 伪造 `planned_hops`。  
3. 登录步：同一屏 **`request_sms_code` 走宏或 override**，不依赖 LLM 在 menu 里二选一（与稳定性文档验收对齐）。  
4. 权限挡屏：do 步内 **≤2 turn** 走 `fb.global.system_dialog`，不占满 10 步 fuse。  
5. Studio：应用架构图 **看不到** `fb.global.*` 块记录；Console 可编辑 override 后跑批生效。  
6. 回归：`tests/test_fsm_nav_semantics.py`、`tests/test_nav_localize.py` 扩展 step plan 用例。

## 7. 非目标

- 不用 FSM **替代** 用例步骤顺序（步骤仍由 case runner 驱动）。  
- 不在 Nexus 硬编码被测 App Tab/按钮文案（宏步骤仅结构 + catalog 几何）。  
- Scout 不做路径规划。  
- 通用块 **不** 自动 promote 进每个 app 的 `flow_blocks` 列表。
